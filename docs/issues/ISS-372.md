## Description
Prove that the real `examples/3d/volumetric_fog` `VolumetricFogUniform`
contains Bevy-equivalent numeric values field by field, not only Bevy-shaped
packing and dynamic offsets.

## Design
Compare Bevy `bevy_pbr/src/volumetric_fog/render.rs::prepare_volumetric_fog_uniforms`
against mgstudio `pbr/volumetric_fog/render.mbt` for the actual example camera
and fog volume. Audit `clip_from_local`, `uvw_from_world`, `far_planes`,
`fog_color`, `light_tint`, `ambient_color`, `ambient_intensity`, `step_count`,
`bounding_radius`, `absorption`, `scattering`, `density_factor`,
`density_texture_offset`, `scattering_asymmetry`, `light_intensity`, and
`jitter_strength`.

Do not count byte-layout tests as sufficient unless they also prove the source
numeric values for the real example.

## Acceptance Criteria
- [x] Every in-scope Bevy `VolumetricFogUniform` field is mapped to the
      mgstudio field and source expression.
- [x] Focused evidence records or asserts the real example numeric values for
      each field.
- [x] Any field-level divergence is assigned to ISS-375 with exact Bevy owner
      and mgstudio fragment.
- [x] If all fields match, close with enough evidence to rule out uniforms as
      the repair owner.

## Close Notes
Closed on 2026-07-05 after adding real-example numeric uniform evidence. No
renderer behavior or shader source changed.

Bevy source owner:

- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs::VolumetricFogUniform`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs::prepare_volumetric_fog_uniforms`.
- `bevy/crates/bevy_light/src/volumetric.rs::{VolumetricFog,FogVolume}` defaults.

Mgstudio implementation fragments:

- `mgstudio-engine/pbr/volumetric_fog/render.mbt::VolumetricFogUniform`.
- `mgstudio-engine/pbr/volumetric_fog/render.mbt::prepare_volumetric_fog_view_uniforms`.
- `mgstudio-engine/light/lib.mbt::{VolumetricFog,FogVolume}` defaults.
- `mgstudio-engine/examples/3d/volumetric_fog/main_wbtest.mbt` now asserts the
  real example's prepared uniform payload.

Field mapping and evidence:

- `clip_from_local`: Bevy uses the interior/fullscreen-plane path with
  `clip_from_view.w_axis[2]` as `z_near`; mgstudio stores the same first 16
  32-bit words in the real example payload.
- `uvw_from_world`: Bevy uses `UVW_FROM_LOCAL * local_from_world`; mgstudio
  stores the same next 16 words for the 35-unit `FogVolume` transform.
- `far_planes`: Bevy uses `get_far_planes(&view_from_local)`; mgstudio stores
  the same 12 words.
- `fog_color`, `light_tint`, `ambient_color`, and `ambient_intensity`: Bevy
  source defaults plus the example's `VolumetricFog { ambient_intensity: 0.0,
  ..default() }` are reflected in the payload.
- `step_count`: `64`.
- `bounding_radius`: `30.310888`, matching the 35-unit volume's
  `view_from_local.transform_vector3(Vec3::splat(0.5)).length()` result.
- `absorption`: `0.3`.
- `scattering`: `0.3`.
- `density_factor`: `0.1`.
- `density_texture_offset`: `(0.0, 0.0, 0.0)`.
- `scattering_asymmetry`: `0.5`.
- `light_intensity`: `1.0`.
- `jitter_strength`: `0.0`.

The focused test asserts the entire first 70-word WGSL host-layout payload, so
all in-scope fields above are covered together rather than as isolated scalar
spot checks. Validation:

- `moon -C mgstudio-engine test examples/3d/volumetric_fog --target native --release --filter 'volumetric_fog: camera and fog volume prepare Bevy interior view fog'`
  passed `1/1`; duplicate `-lobjc` and `-lz` linker warnings were emitted.

Conclusion:

- No field-level `VolumetricFogUniform` numeric divergence was found for the
  real `examples/3d/volumetric_fog` camera and fog volume.
- ISS-372 does not assign a repair owner to ISS-375. Continue with ISS-373 for
  light and shadow numeric inputs, and ISS-374 for post-pass composition.

## Description
Bevy `VolumetricFogPipeline` owns mesh-view layouts, volumetric fog bind group
layouts, shader handle, and `VolumetricFogBindGroupLayoutKey` combinations.

## Design
Audit resource fields, initialization, bind group layout variants, and layout
descriptions against Bevy before auditing specialization descriptors.

## Acceptance Criteria
- [x] `VolumetricFogPipeline` fields and initialization are classified.
- [x] `VolumetricFogBindGroupLayoutKey` bit combinations are classified.
- [x] Layout entries for dynamic uniform, depth texture, optional density
      texture, and sampler are classified.
- [x] Any renderer-local layout state that leaks above backend detail has a
      follow-up ISS or direct fix.

## Notes
- 2026-07-05: Split from ISS-239 so resource/layout ownership is independent
  from pipeline specialization.
- 2026-07-09: Audited and directly fixed the local source-owner gap. Bevy's
  `VolumetricFogPipeline` owns the shader handle, mesh-view layouts, and four
  `VolumetricFogBindGroupLayoutKey`-indexed bind-group layout descriptors.
  Mgstudio now keeps the shader path, `MeshPipelineViewLayouts`, and the four
  volumetric view `BindGroupLayoutDescriptor`s in
  `VolumetricFogPipeline`. The descriptors are generated from
  `VolumetricFogBindGroupLayoutKey` and match Bevy's entries: binding 0 dynamic
  uniform visible to vertex+fragment, binding 1 fragment depth texture with
  MSAA-dependent multisampling, and optional bindings 2/3 for filterable 3D
  density texture plus filtering sampler.
- 2026-07-09: Removed the backend-owned layout semantics leak. PBR now passes
  the `VolumetricFogPipeline` descriptor inventory through
  `host_gpu_prepare_mesh3d_volumetric_fog_pipeline`; the native renderer only
  materializes those descriptors into wgpu bind group layouts. The renderer
  still caches the resulting native layouts, which is backend detail and no
  longer owns Bevy layout semantics.

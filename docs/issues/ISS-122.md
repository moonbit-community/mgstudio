## Description
`mgstudio-engine/examples/3d/anti_aliasing/main.mbt` is only a partial source
migration of `bevy/examples/3d/anti_aliasing.rs`.

The current example has the visible outline of the Bevy control surface, but it
does not preserve the Bevy source owner. It uses global `AntiAliasingState`,
local mirror enums, one tracked camera entity, direct world mutation, and
world-space text. It also hard-disables SMAA, DLSS, and CAS in the example even
though mgstudio has anti-alias package owners for them, omits `MipBias` from
the TAA component set, never inserts a `ContrastAdaptiveSharpening` component on
the camera, and changes the light/cascade setup.

This is a local source-parity gap. Do not classify the local disabled CAS/SMAA
example paths as external blockers unless a concrete backend dependency is
proven missing while restoring the Bevy-shaped implementation.

## Design
Restore the example by following `bevy/examples/3d/anti_aliasing.rs`
symbol-by-symbol:

- Preserve the Bevy `main` shape: mutable `App`, cfg-gated DLSS resource,
  `DefaultPlugins`, startup `setup`, and separate update systems
  `modify_aa`, `modify_sharpening`, `modify_projection`, and `update_ui`.
- Replace local global state and mirror enums with camera component state and
  system params matching the Bevy source.
- Use Bevy-shaped camera component mutation for `Msaa`, `Fxaa`, `Smaa`,
  `TemporalAntiAliasing`, `TemporalJitter`, `MipBias`, `DepthPrepass`,
  `MotionVectorPrepass`, `ContrastAdaptiveSharpening`, and DLSS where supported.
- Preserve the `TaaComponents` and cfg-gated `DlssComponents` source shape.
- Wire CAS controls to real `ContrastAdaptiveSharpening` components; do not keep
  `HAS_CAS = false` as a workaround.
- Restore SMAA control behavior if mgstudio's SMAA runtime is sufficient; if a
  concrete backend/runtime dependency prevents it, record that as a blocker and
  keep the example source shape explicit.
- Preserve Bevy's UI `Text`/`Node` ownership and `draw_selectable_menu_item`
  behavior.
- Preserve setup values: `Hdr`, disabled CAS component, `FULL_DAYLIGHT`,
  Euler ZYX light rotation, cascade config, `WorldAssetRoot`, and the
  `uv_debug_texture` image format/sampler/render-usage semantics.

## Acceptance Criteria
- [ ] The example no longer uses global `AntiAliasingState` or local mirror AA
      enums for state that Bevy stores as camera components.
- [ ] `modify_aa`, `modify_sharpening`, `modify_projection`, and `update_ui`
      exist as separate Bevy-shaped systems with equivalent system params.
- [ ] TAA insertion includes `TemporalJitter`, `MipBias`, `DepthPrepass`, and
      `MotionVectorPrepass` through the same source semantics as Bevy.
- [ ] CAS controls mutate real `ContrastAdaptiveSharpening` components.
- [ ] SMAA and DLSS handling is either source-shaped or explicitly tied to a
      proven backend blocker.
- [ ] Camera setup includes `Hdr`, disabled CAS, environment map, distance fog,
      and the Bevy transform.
- [ ] Directional light setup preserves Bevy's illuminance, Euler rotation, and
      cascade config.
- [ ] UI text is a Bevy-shaped `Text` plus absolute `Node`, not a world-space
      `Text2dBundle`.
- [ ] A new reference screenshot is captured after the example first runs
      correctly.

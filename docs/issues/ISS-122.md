## Description
The source-shaped migration of
`mgstudio-engine/examples/3d/anti_aliasing/main.mbt` was completed on
2026-06-19, but the current native runtime gate no longer satisfies its visual
acceptance criterion. Supervised captures show the Bevy-shaped control UI over
the clear color while all intended 3D scene geometry is absent, despite the
checked-in `reference.png` containing the flight helmet, textured cubes,
ground plane, and shadows.

This initially presented as a local runtime/visual regression. A strict parent
A/B proves that it predates the ISS-086 downsample fix, and one-variable runtime
probes now isolate the blank scene to the valid Bevy `DISTANCE_FOG` shader
specialization. The existing ISS-405 dependency reproduction proves that the
external WGSL compose/IR pipeline cannot lower the fully qualified
`bevy_pbr::fog::linear_fog` call enabled by that specialization.

## Design
Preserve the completed symbol-by-symbol source migration from
`bevy/examples/3d/anti_aliasing.rs`, then trace why the scene root no longer
reaches the render world while the UI does:

- Preserve the Bevy `main` shape: mutable `App`, cfg-gated DLSS resource,
  `DefaultPlugins`, startup `setup`, and separate update systems
  `modify_aa`, `modify_sharpening`, `modify_projection`, and `update_ui`.
- Replace local global state and mirror enums with camera component state and
  system params matching the Bevy source.
- Use Bevy-shaped camera component mutation for `Msaa`, `Fxaa`, `Smaa`,
  `TemporalAntiAliasing`, `TemporalJitter`, `MipBias`, `DepthPrepass`,
  `MotionVectorPrepass`, `ContrastAdaptiveSharpening`, and DLSS where supported.
- Preserve the `TaaComponents` and cfg-gated `DlssComponents` source shape.
- Wire CAS controls to real `ContrastAdaptiveSharpening` components; do not keep
  `HAS_CAS = false` as a workaround.
- Restore SMAA control behavior if mgstudio's SMAA runtime is sufficient; if a
  concrete backend/runtime dependency prevents it, record that as a blocker and
  keep the example source shape explicit.
- Preserve Bevy's UI `Text`/`Node` ownership and `draw_selectable_menu_item`
  behavior.
- Preserve setup values: `Hdr`, disabled CAS component, `FULL_DAYLIGHT`,
  Euler ZYX light rotation, cascade config, `WorldAssetRoot`, and the
  `uv_debug_texture` image format/sampler/render-usage semantics.

## Acceptance Criteria
- [x] The example no longer uses global `AntiAliasingState` or local mirror AA
      enums for state that Bevy stores as camera components.
- [x] `modify_aa`, `modify_sharpening`, `modify_projection`, and `update_ui`
      exist as separate Bevy-shaped systems with equivalent system params.
- [x] TAA insertion includes `TemporalJitter`, `MipBias`, `DepthPrepass`, and
      `MotionVectorPrepass` through the same source semantics as Bevy.
- [x] CAS controls mutate real `ContrastAdaptiveSharpening` components.
- [x] SMAA and DLSS handling is either source-shaped or explicitly tied to a
      proven backend blocker.
- [x] Camera setup includes `Hdr`, disabled CAS, environment map, distance fog,
      and the Bevy transform.
- [x] Directional light setup preserves Bevy's illuminance, Euler rotation, and
      cascade config.
- [x] UI text is a Bevy-shaped `Text` plus absolute `Node`, not a world-space
      `Text2dBundle`.
- [x] A new reference screenshot is captured after the example first runs
      correctly.
- [ ] The current supervised native frame-90 capture contains the Bevy scene
      geometry and remains visually reviewable against `reference.png`.

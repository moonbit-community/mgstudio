## Description
`mgstudio-engine/examples/3d/lighting/main.mbt` is only a partial source
migration of `bevy/examples/3d/lighting.rs`, and the exposure controls are not
behaviorally correct.

Bevy stores physical camera parameters in an ECS resource, inserts a camera
`Exposure::from_physical_camera(**parameters)` component, and updates that
component whenever the 1/2/3/4/5/6/R controls mutate the parameters. The current
mgstudio example stores parameters in global `LightingState`, updates the text,
but never inserts or updates any camera `Exposure` component. The visual
exposure therefore cannot match Bevy.

The example also replaces Bevy's `Movable` component, child light marker
hierarchy, UI `Text`/`Node`/`TextSpan`, `TextUiWriter`, system params, and
directional cascade config with local state and direct world mutation.

This is a local source-parity gap, not an external blocker. Mgstudio already has
`Exposure`, `PhysicalCameraParameters`, and `CascadeShadowConfigBuilder` support.

## Design
Restore the example by following `bevy/examples/3d/lighting.rs`
symbol-by-symbol:

- Use a Bevy-shaped `Parameters` ECS resource with physical camera defaults.
- Use a real `Movable` component and query it in `movement`.
- Keep `setup` source-shaped around `Commands`, mesh/material assets, resource
  access, and asset server access.
- Preserve light marker children under the point/spot light entities, including
  sphere and capsule marker geometry.
- Preserve global ambient light and the Bevy toggle semantics.
- Insert camera `Exposure::from_physical_camera(parameters)` during setup and
  update the same component in `update_exposure`.
- Preserve Bevy's UI `Text`/`Node`/`TextSpan` hierarchy and span-index updates
  via `TextUiWriter`.
- Add the Bevy directional `CascadeShadowConfigBuilder` values to the
  directional light.
- Remove global tracked arrays and local duplicate state once equivalent ECS
  owners are in place.

If a Bevy-shaped system parameter is still missing from ECS, record that as a
separate ECS issue instead of keeping a global-state workaround.

## Acceptance Criteria
- [x] `Parameters` is an ECS resource with Bevy's physical camera values.
- [x] The camera receives an initial `Exposure::from_physical_camera` component.
- [x] Pressing 1/2/3/4/5/6/R updates both the `Parameters` resource and the
      camera `Exposure` component.
- [x] Movable objects use a `Movable` component and are moved through a query.
- [x] Point and spot light marker meshes are children of their light entities,
      with Bevy sphere/capsule geometry.
- [x] Directional light includes Bevy's cascade shadow config.
- [x] UI uses `Text`, absolute `Node`, `TextSpan` children, and span-specific
      updates matching Bevy.
- [x] A new reference screenshot is captured after the example first runs with
      corrected exposure controls.

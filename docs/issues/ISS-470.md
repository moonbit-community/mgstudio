# ISS-470: Revoke escaped table-batch mutable views

## Metadata
- Type: bug
- Status: closed

- Assignee: codex

## Description

`TableBatchWrite::update_inplace` and
`update_inplace_bypass_change_detection` pass a raw `MutArrayView[T]` to user
code. The view is copyable and retains the typed component column's backing
array. Invalidating `QueryTableBatch`, its `WorldLease`, or its column binding
cannot revoke an escaped view. It can therefore replace component values after
the update callback without the required lease, change ticks, callers, or
finalizers. After structural migration reuses a physical row, the stale view
can modify a different entity.

## Design

Replace the public raw mutable view callback parameter with a controlled
`TableBatchMutValues[T]`. Preserve the existing `values.length()` and
`values[index]` source shape through checked methods and custom `op_get` /
`op_set`. All aliases share one mutable active state, which is invalidated as
soon as the update callback returns; every indexed operation checks that state.
Never expose the backing array or a raw `MutArrayView`.

This intentionally changes a public callback parameter type. Record the
migration and regenerate the ECS interface. Existing inferred callbacks keep
the same indexing syntax; explicit `MutArrayView[T]` annotations must change
to `TableBatchMutValues[T]`.

## Acceptance Criteria

- [x] A mutable column capability retained past the update callback aborts on
      both read and write, even while the outer table callback remains active.
- [x] A retained capability cannot modify a different entity after structural
      migration reuses its old physical row.
- [x] In-scope indexed replacement and both ordinary/bypass tick semantics
      remain correct.
- [x] Custom-finalizer and filtered-batch rejection boundaries remain intact.
- [x] The public interface and migration document record the controlled-view
      callback type.
- [x] Focused tests run one at a time with `MOONBIT_NEW_NATIVE=1`.

## Notes

- 2026-07-18: MoonBit supports custom indexed access through `op_get` and
  `op_set`, so a revocable wrapper can retain the current indexing syntax
  without exposing the backing array.
- 2026-07-18: Before the repair, focused reproductions proved that an escaped
  raw view could replace a component immediately after its update callback and
  could overwrite a replacement entity after its original row was reused.
- 2026-07-18: The retained active check increases the 102,400-row visibility
  reset benchmark from the prior recorded `11.44 us` to `64.17 us` on the
  current machine. It remains about 73 times faster than the pre-batch
  `4.71 ms` result; this explicit cost is accepted for revocable write access.
- 2026-07-18: Follow-up ISS-471 retained the same public revocation boundary
  while moving the live-row `MutArrayView` behind the wrapper's private field.
  Removing the redundant manual-plus-array bounds checks reduced the benchmark
  from a same-turn `64.11 us` baseline to `45.23 us`.

## Close Notes

Closed on 2026-07-18. Both mutable table-batch update APIs now expose
`TableBatchMutValues[T]`, whose shared active state is invalidated with `defer`
as the callback exits. Four focused panic regressions cover escaped ordinary
write, escaped read, reused-row write, and the bypass API. Existing focused
tests separately retain ordinary and bypass change-tick behavior plus the
filtered-batch and custom-finalizer rejection boundaries. `moon check ecs
--target native --deny-warn` passes, the generated ECS interface records the
new callback type, and the public migration document explains the explicit
annotation change.

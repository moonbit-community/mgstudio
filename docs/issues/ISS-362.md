## Description
Bevy marks 3D camera depth textures with `TEXTURE_BINDING` when volumetric fog
is present and binds `ViewDepthTexture` into the volumetric-fog bind group.
Audit that mgstudio prepares and binds the same sampled depth texture for the
real `examples/3d/volumetric_fog` camera.

## Design
Compare Bevy
`prepare_view_depth_textures_for_volumetric_fog` and
`volumetric_fog` depth binding against mgstudio's camera collection,
depth-texture usage preparation, renderer pass state, and volumetric-fog bind
group creation. This issue should not inspect light resources, dynamic uniform
offsets, or density texture variants except where needed to identify the depth
binding slot.

## Acceptance Criteria
- [x] Bevy depth-texture preparation and binding anchors are mapped to
      mgstudio symbols.
- [x] Focused evidence proves the real example camera requests sampled depth
      usage before depth texture creation.
- [x] Focused evidence proves the volumetric-fog pass binds the current view's
      depth texture at the Bevy-equivalent slot.
- [x] Any local divergence is assigned to ISS-359.

## Close Notes
Closed on 2026-07-05 as an audit-only sampled-depth input boundary. No
production renderer, shader, asset, or example behavior was changed for this
issue.

Bevy owner anchors:

- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs::prepare_view_depth_textures_for_volumetric_fog`
  mutates every `Camera3d.depth_texture_usages` to include
  `TextureUsages::TEXTURE_BINDING` when at least one `VolumetricFog` view
  exists.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs::volumetric_fog` consumes
  `ViewDepthTexture` and binds `BindingResource::TextureView(view_depth_texture.view())`
  as binding 1 in the volumetric-fog bind group.
- `init_volumetric_fog_pipeline` selects `texture_depth_2d()` or
  `texture_depth_2d_multisampled()` for binding 1 from the MSAA layout key.

Mgstudio implementation fragments:

- `mgstudio-engine/pbr/volumetric_fog_execute.mbt::render3d_world_has_volumetric_fog_views`
  detects render-world `VolumetricFog` views.
- `mgstudio-engine/pbr/volumetric_fog_execute.mbt::render3d_prepare_view_depth_texture_usage_for_sampled_depth`
  returns `camera3d.depth_texture_usages().with_texture_binding()` when
  volumetric fog, SSAO, or atmosphere needs sampled depth.
- `mgstudio-engine/pbr/render_execute_collect.mbt::render3d_execute_collect_cameras`
  computes the sampled-depth usage before constructing `Camera3dViewPayload`.
  This preserves source-world `Camera3d` immutability while carrying the
  Bevy-required depth usage into render execution.
- `mgstudio-engine/render/renderer/pass_begin.mbt::GpuBackend::begin_pass_3d`
  stores the current view depth texture view in `GpuPassState.view_depth_view`.
- `mgstudio-engine/render/renderer/mesh3d_volumetric_fog_pass.mbt::mesh3d_pass_view_depth_view`
  reads that exact saved view depth view, and
  `mesh3d_volumetric_fog_bind_group` binds it at binding 1.
- `mgstudio-engine/render/renderer/texture.mbt::ensure_depth_view_for_target`
  currently creates the backend scene depth texture with
  `RENDER_ATTACHMENT | TEXTURE_BINDING | COPY_SRC`. This is broader than
  Bevy's conditional camera-usage mutation, but it still supplies the required
  sampled depth view and is not the missing-input cause for the current
  `volumetric_fog` visual failure.

Evidence:

- `mgstudio-engine/pbr/render_execute_collect_atmosphere_wbtest.mbt` proves
  camera collection prepares sampled depth from render-world volumetric fog
  without mutating the source-world `Camera3d`.
- `mgstudio-engine/pbr/volumetric_fog_execute_wbtest.mbt` proves the
  sampled-depth helper requests texture binding for volumetric fog, SSAO, and
  atmosphere users.
- `mgstudio-engine/render/renderer/gpu_wbtest.mbt` proves the volumetric-fog
  bind-group layout index mirrors Bevy's MSAA and density-texture flags.
- The `ISS-361` real-example white-box gate also proves the
  `examples/3d/volumetric_fog` pass reaches prepared `ViewVolumetricFog` and
  valid `ViewVolumetricFogPipelines`; this issue narrows only the sampled-depth
  input behind that pass.

Validation:

- `moon -C mgstudio-engine test pbr --target native --release --filter 'render3d collect cameras: volumetric fog depth usage is prepared from render world without source mutation'`
  passed `1/1`; duplicate `-lobjc` and `-lz` linker warnings were emitted.
- `moon -C mgstudio-engine test pbr --target native --release --filter 'pbr volumetric fog execute: prepares depth texture usage from sampled depth users'`
  passed `1/1`; duplicate `-lobjc` and `-lz` linker warnings were emitted.
- `moon -C mgstudio-engine test render/renderer --target native --release --filter 'renderer: volumetric fog bind group layout index mirrors Bevy flags'`
  passed `1/1`; duplicate `-lobjc` linker warnings were emitted.
- `moon -C mgstudio-engine test examples/3d/volumetric_fog --target native --release --filter 'volumetric_fog: runtime pass-local evidence reaches Bevy fog pass'`
  passed earlier in this audit turn and remains the real-example pass-local
  evidence for this input group.

Conclusion:

- The sampled depth texture preparation and binding chain required by Bevy is
  present for the `volumetric_fog` pass.
- The renderer's broader default depth texture usage is recorded, but it does
  not represent a missing sampled-depth input and does not need assignment to
  ISS-359.
- Continue with ISS-363 for mesh-view light and shadow inputs.

## Description

Current `Read[T]` construction eagerly loads added tick, changed tick, changed
caller, and derived flags even when the system only reads the component value.
Test a Bevy-shaped value-only read boundary distinct from change-aware `Ref<T>`
semantics.

## Acceptance Criteria

- [x] The API distinction is mapped to pinned-Bevy `&T` and `Ref<T>` semantics.
- [x] Value-only table reads do not load change metadata in the measured kernel.
- [x] Change-aware reads preserve existing tick and caller behavior.
- [x] One focused ECS test runs at a time with `MOONBIT_NEW_NATIVE=1`.
- [x] `examples/stress_tests/many_cubes` is the only runtime example gate.
- [x] The retained/rejected decision follows the `ISS-444` experiment protocol.

## Close Notes

Retained on 2026-07-15 because both the isolated kernel and the affected
runtime systems met the `ISS-444` gate without changing query semantics.

- The pinned Bevy source separates ordinary `&T` fetches, which bind only
  component data, from `Ref<T>` fetches, which also bind added ticks, changed
  ticks, and changed callers. `ReadValue[T]` implements the former boundary;
  `Read[T]` is unchanged.
- The focused 20,000-row, four-component dense query benchmark improved from
  `7.73 ms` to `3.72 ms`, a 51.9% reduction. The value-only fetch path does not
  call `query_data_tick_snapshot_at_table_row`.
- Before: `/tmp/mgstudio_iss446_many_cubes_before_20260715/frametime_breakdown.md`
  reported a `15.318 ms` steady-frame interval. The two light visibility
  systems cost `0.646 ms` and `0.638 ms`; camera visibility cost `0.541 ms`.
- After: `/tmp/mgstudio_iss446_many_cubes_after_20260715/frametime_breakdown.md`
  reported a `15.919 ms` steady-frame interval. The same systems cost
  `0.616 ms`, `0.613 ms`, and `0.492 ms`. Their combined cost improved from
  `1.825 ms` to `1.721 ms`, or 5.70%.
- Total frame time did not improve: render recovery moved from `9.823 ms` to
  `10.229 ms`, while PostUpdate moved only from `3.389 ms` to `3.418 ms`.
  The retained conclusion is therefore limited to the query kernel and target
  visibility systems; it is not a claim of whole-frame improvement.
- The new value-only test, the existing change-metadata test, one camera
  visibility test, and one light visibility test each passed separately with
  `MOONBIT_NEW_NATIVE=1`.

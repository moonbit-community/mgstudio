## Description
`examples/3d/clustered_decal_maps/main.mbt` currently documents that it keeps the runtime behavior model "using textured translucent proxy meshes." This is a local approximation, not a Bevy source-level port.

Bevy's `examples/3d/clustered_decal_maps.rs` uses `ClusteredDecal` components, normal-map, metallic-roughness, and emissive map channels, app settings, seeded `ChaCha8Rng`, UI radio buttons, gizmos, and animated decal state. The MoonBit example should be audited symbol-by-symbol against that owner instead of relying on proxy mesh behavior.

## Design
Port the example shape and any missing engine support required for clustered decal maps. Do not classify this as a dependency blocker unless exact Bevy behavior requires a real missing MoonBit language, backend, or external dependency capability.

## Acceptance Criteria
- [x] The example no longer uses proxy mesh approximation for clustered decals.
- [ ] Bevy's `AppTextures`, `ExampleDecal`, `ExampleDecalState`, `AppSetting`, `AppStatus`, and `SeededRng` source shapes have explicit MoonBit mappings or documented exclusions.
- [ ] Normal-map, metallic-roughness, and emissive decal map behavior is represented through the clustered decal path.
- [ ] The refreshed `reference.png` remains useful after the source-parity fix.

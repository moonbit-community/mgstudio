## Description

The Camera2d visibility regression in ISS-457 is fixed, but
`examples/stress_tests/many_animated_sprites` still does not faithfully match
the pinned Bevy example source. The mgstudio example uses deterministic index
patterns, a 28-by-28 custom sprite size, per-entity FPS values, zero initial
timer elapsed time, additive world-axis camera translation, and default window
configuration. Pinned Bevy uses random depth/rotation/scale, a 64-by-64 custom
size, one 0.1-second repeating timer with randomized elapsed time, local camera
transform composition, and a 1920-by-1080 no-vsync window.

These differences change the visual distribution, animation phase, culling
load, and performance workload even though the sprite field now renders.

## Design

Port the pinned Bevy example structure without deterministic substitutions:

- configure the primary window and diagnostics plugins as in Bevy;
- use a 320-by-320 grid with 64-by-64 sprite custom sizes;
- randomize translation depth, rotation, scale, and initial timer elapsed time
  through the project's source-equivalent random API;
- use one 0.1-second repeating animation period and derive atlas wrapping from
  the layout texture count;
- preserve Bevy's update ordering and local camera transform composition;
- keep the example suitable for the existing stress/performance workflow.

Do not tune the values to reproduce the current reference image. Validate
behavior and workload against the pinned Bevy source, then establish a new
human-reviewed reference only after source parity is complete.

## Acceptance Criteria

- [ ] Scene construction fields and randomization match pinned Bevy ownership
      and value ranges.
- [ ] Animation timer initialization and atlas advancement match pinned Bevy.
- [ ] Camera movement and update ordering match pinned Bevy.
- [ ] Window and diagnostics configuration match the fixed baseline where the
      corresponding mgstudio APIs exist.
- [ ] A native capture shows the expected moving sprite field after delayed
      frames, and a focused test covers deterministic structural invariants.
- [ ] Performance comparison uses the same 102,400-sprite workload as Bevy.

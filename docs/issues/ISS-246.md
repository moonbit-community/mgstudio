## Description
Before adding tests for `scrolling_fog` shadow target identity, audit the exact
Bevy and mgstudio source-owner path that creates directional shadow targets and
passes their frame data toward volumetric fog. The goal is to prove which
symbols own target texture id, target layer, cascade index, retained view keys,
and camera/light frame identity.

## Design
Compare Bevy's directional shadow preparation, shadow phase retained view, and
volumetric fog render inputs against the mgstudio equivalents. Record the
symbol-level mapping in this issue's notes or close notes. Do not fix shader
sampling math here; ISS-214 owns that.

## Acceptance Criteria
- [ ] Bevy source-owner symbols for directional shadow target identity and

- [ ] Mgstudio symbols that create, retain, queue, and bind the same frame data
      are listed.
- [ ] Any missing or approximate source-owner mapping is either turned into a

## Notes
- 2026-07-04: Split from ISS-220 to make source audit independently
  reviewable before adding tests or runtime gates.
- 2026-07-04: Bevy source-owner path:
  `bevy_pbr/src/render/light.rs::prepare_lights` creates the
  `directional_light_shadow_map_texture` as one D2-array depth texture,
  creates one per-cascade `TextureView` with
  `base_array_layer = directional_depth_texture_array_index`, inserts
  `ShadowView { depth_attachment, pass_name }`, `ExtractedView {
  retained_view_entity = RetainedViewEntity::new(light_main_entity,
  Some(camera_main_entity.into()), cascade_index) }`, and
  `LightEntity::Directional { light_entity, cascade_index }`, then inserts
  `ViewShadowBindings { directional_light_depth_texture,
  directional_light_depth_texture_view }` and `ViewLightEntities { lights }`
  on the camera view.
- 2026-07-04: Bevy shadow draw path:
  `bevy_pbr/src/render/light.rs::queue_shadows` indexes shadow render phases
  by the shadow view `ExtractedView.retained_view_entity`; `per_view_shadow_pass`
  iterates camera `ViewLightEntities.lights`; `view_shadow_pass` renders each
  `ShadowView.depth_attachment` into the retained shadow phase. This means the
  rendered target layer and the retained view key are both owned by the same
  per-cascade shadow view entity.
- 2026-07-04: Bevy volumetric fog input path:
  `bevy_pbr/src/render/mesh_view_bindings.rs::prepare_mesh_view_bind_groups`
  places `ViewShadowBindings.directional_light_depth_texture_view` into mesh
  view binding 5 and the directional comparison sampler into binding 6.
  `bevy_pbr/src/volumetric_fog/render.rs::volumetric_fog` then reuses
  `MeshViewBindGroup.main` as group 0 for the volumetric fog pass. It does not
  pass a separate shadow texture argument; the shadow identity is inherited
  from the camera view's mesh-view bind group.
- 2026-07-04: Mgstudio mapping:
  `pbr/render_execute_camera_directional_shadow.mbt::render3d_prepare_camera_directional_shadow_pass`
  creates a single directional/spot shadow target id, writes each directional
  `Render3dShadowView { target_id, target_layer = cascade_index, ... }`, and
  returns `Render3dDirectionalShadowBinding { texture_id = target_id,
  cascade_data, cascade_count }`. The retained key is produced by
  `Render3dLightEntity::shadow_phase_retained_view`, which maps directional
  lights to `RetainedViewEntity(main_entity = light_main,
  auxiliary_entity = camera, subview_index = cascade_index)`, matching the
  Bevy owner shape.
- 2026-07-04: Mgstudio consumption path:
  `pbr/render_execute_camera.mbt::render3d_execute_camera` executes all shadow
  phase views, then assigns `shadow_bindings = shadow_pass_plan.bindings`,
  then begins the main pass with `directional_shadow_texture_id =
  shadow_bindings.directional.texture_id` and the cascade data. The later
  `pbr/volumetric_fog_execute.mbt::render3d_execute_camera_volumetric_fog_pass`
  calls the renderer while the current `GpuPassState` is still the main pass
  state. `render/renderer/mesh3d_volumetric_fog_pass.mbt` resolves
  `pass_state.directional_shadow_texture_id` and rebuilds the Bevy-equivalent
  view bind group for volumetric fog group 0.
- 2026-07-04: ISS-247 should add a focused PBR white-box test that constructs
  a known camera, light, render light, and cascade set, calls
  `render3d_prepare_camera_shadow_passes` or
  `render3d_prepare_camera_directional_shadow_pass`, and asserts:
  binding texture id equals every directional `Render3dShadowView.target_id`;
  `Render3dShadowView.target_layer == cascade_index`; the
  `Render3dLightEntity::Directional.cascade_index` matches both values; and
  `shadow_phase_retained_view(camera)` uses the same light main entity,
  camera auxiliary entity, and cascade subview index that Bevy's
  `RetainedViewEntity::new(light_main, Some(camera_main), cascade_index)` uses.

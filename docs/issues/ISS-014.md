## Description
Bevy's `RenderPlugin` creates and configures the render sub-app, installs
render startup and recovery schedules, initializes GPU resources, extracts
shader and asset budget state, processes the pipeline cache, submits pending
command buffers, handles screenshot/readback commands, and presents windows.
Mgstudio has working renderer pieces, but the complete lifecycle is not yet
source-equivalent.

## Design
Use `bevy/crates/bevy_render/src/lib.rs` and
`bevy/crates/bevy_render/src/renderer/mod.rs` as the owner sources. Port the
startup, recovery, render-system, cleanup, and resource initialization behavior
directly. Keep render-device loss and recovery as first-class behavior, not as
incidental backend state.

## Acceptance Criteria
- [ ] `RenderStartup`, render recovery, render schedule order, and render sub-app update flow match Bevy's source ownership.
- [ ] `PendingCommandBuffers` and GPU resource initialization are owned by the render world and re-run on recovery where Bevy does so.
- [ ] Pipeline cache processing is chained with the render system in the Bevy-shaped render set.
- [ ] Screenshot and GPU readback commands are submitted in the same lifecycle phase as Bevy.
- [ ] Window present behavior follows Bevy's view-target `needs_present` and initial-present logic as closely as the window dependency allows.
- [ ] Recovery and frame-lifecycle tests cover startup, render, cleanup, and present ordering.

The app sub-app extract phase now exposes the current sub-app schedule so extract code can run Bevy-shaped startup work against the render world.
- 2026-06-04: Pipeline cache processing cannot be honestly closed by adding a no-op schedule system. Mgstudio's global `PipelineCache` is still a local facade and PBR/material specialization allocates cached IDs outside it. The remaining work is a real port of Bevy's descriptor queue/state machine plus migration of material/PBR specializers to queue descriptors into that resource.
- 2026-06-04: Replaced the global `PipelineCache` string-map facade with Bevy-shaped `Pipeline`, `CachedPipeline`, `CachedPipelineState`, descriptor queueing, stable cached IDs, state queries, descriptor access, and waiting-pipeline tracking. This is still not enough to close pipeline processing: `process_queue` must create real GPU pipelines through a general descriptor-to-wgpu builder before the render schedule can claim Bevy parity.
- 2026-06-05: Ported Bevy's render-recovery time handoff. The time package now exposes Bevy-shaped `TimeSender`, `TimeReceiver`, and `create_time_channels`; `time_system` consumes render-world sent instants in automatic mode; `RenderPlugin` installs the receiver in the main world and sender in the render world; render recovery now runs the render schedule only when ready and sends time every recovery tick afterward.
- 2026-06-05: Added a Bevy-shaped render-schedule slot for pipeline queue admission before render graph execution. This only wires descriptor queue admission into the render lifecycle; GPU pipeline creation and shader-cache-backed descriptor-to-wgpu building remain incomplete local parity work, not an external blocker.
- 2026-06-05: Moved material and PBR mesh pipeline specialization IDs/descriptors into the render-world `PipelineCache`. `SpecializedMeshPipelines` now deduplicates Bevy-style final vertex layouts and queues render descriptors into the cache instead of owning descriptors locally; PBR main, motion-vector prepass, and shadow prepass pipelines are prewarmed before pipeline queue admission instead of being registered from render execution. A render-system set after pipeline queue admission registers queued render descriptors for the current host backend. Remaining work is still true GPU pipeline creation from `PipelineCache`, not PBR-local descriptor storage.
- 2026-06-05: Tightened the temporary host-backend descriptor bridge so it drains `PipelineCache` waiting ids once instead of rescanning every cached pipeline every frame. This keeps the current bridge closer to queue-processing semantics while leaving GPU pipeline Ok/Err state unclaimed until real descriptor-to-wgpu creation is ported.

# ISS-018: Align PBR render-app system ordering

## Metadata

- Assignee: unassigned

- Updated: 2026-07-16
- External ref: none

## Description
PBR render systems must run in the same source-owned phases as Bevy: startup,
extract, create views, prepare resources, specialize, prepare views, queue,
prepare bind groups, render, and cleanup. Mgstudio has many Bevy-shaped system
set names and several completed schedule realignments, but the full PBR runtime
order is still not proven source-equivalent.

## Design
Use Bevy's `PbrPlugin`, `MaterialsPlugin`, `MaterialPlugin`, `PrepassPlugin`,
`MeshletPlugin`, and PBR render modules as the ordering source. Audit each
mgstudio system that owns PBR extraction, material specialization, light
preparation, cluster preparation, skin extraction, mesh preparation, queueing,
bind groups, and execution.

## Acceptance Criteria
- [ ] Each PBR system has a documented Bevy source owner and Bevy render-system set.
- [ ] Mgstudio system placement matches the Bevy owner set or has a recorded blocker.
- [ ] Material preparation, material bind-group allocation, specialization, queueing, and queue sweep run in Bevy-equivalent order.
- [ ] Light extraction, cluster preparation, shadow view creation, and GPU light preparation run in Bevy-equivalent order.
- [ ] Skin extraction, mesh preparation, GPU preprocess, and phase item queueing are ordered consistently with Bevy.
- [ ] A schedule-order test or generated report verifies the PBR render-app ordering.

## Description
Bevy `extract_volumetric_fog` copies `VolumetricFog`, `FogVolume`,
`GlobalTransform`, and `VolumetricLight` into the render world. When there are
no volumetric lights, it removes render-world fog view/pipeline state and fog
volumes instead of mutating the source world.

## Design
Port the Bevy extraction behavior against the render-world storage introduced
by ISS-175. Preserve the no-light cleanup branch, including view-side
`VolumetricFog`, `ViewVolumetricFogPipelines`, `ViewVolumetricFog`, and
fog-volume cleanup semantics. Keep cleanup scoped to render-world state.

## Acceptance Criteria
- [ ] Extraction copies camera/view `VolumetricFog` into render-world state.
- [ ] Extraction copies `FogVolume` plus transform data into render-world state.
- [ ] Extraction copies or counts `VolumetricLight` in render-world state before prepare.
- [ ] No-light cleanup removes only render-world fog state and is covered by focused tests.

## Close Notes
2026-07-04: Ported the Bevy `extract_volumetric_fog` copy and no-light cleanup
semantics into `pbr/volumetric_fog`. The plugin now registers the required
sync path for `FogVolume` and `VolumetricFog` and installs
`extract_volumetric_fog` in the render extract schedule when a `RenderApp`
exists. The extraction system copies source `VolumetricFog`, `FogVolume` plus
`GlobalTransform`, and `VolumetricLight` into typed render-world components
when source volumetric lights exist. When there are no source volumetric
lights, it removes render-world `VolumetricFog`, `ViewVolumetricFogPipelines`,
`ViewVolumetricFog`, and `FogVolume` state without mutating source-world
components, matching Bevy's cleanup branch.

## Description
Before investigating texture data or exposure, prove that mgstudio uses the
same skybox shader and pipeline/bind-layout shape as Bevy for
`examples/3d/volumetric_fog`.

## Design
Compare Bevy's skybox owner under `bevy_core_pipeline/src/skybox` against the
mgstudio `core_pipeline/skybox` and renderer fragments. Classify each
source-shape anchor as complete, partial, facade, or blocked. This issue should
not change the example scene or texture assets.

## Close Notes
Closed on 2026-07-05 by auditing Bevy's skybox source owner against mgstudio's
core-pipeline and renderer fragments.

Bevy source anchors:
- `bevy/crates/bevy_core_pipeline/src/skybox/mod.rs::SkyboxPipeline::new`
  defines `skybox_bind_group_layout` with bindings 0 through 3:
  filterable cube texture, filtering sampler, dynamic `ViewUniform`, and
  dynamic `SkyboxUniforms`.
- `bevy/crates/bevy_core_pipeline/src/skybox/mod.rs::specialize` defines the
  `skybox_pipeline` render pipeline with `skybox_vertex`, `skybox_fragment`,
  no color blend, `ColorWrites::ALL`, `depth_write_enabled=false`,
  `CompareFunction::GreaterEqual`, and the view's MSAA sample count.
- `bevy/crates/bevy_core_pipeline/src/skybox/skybox.wgsl` binds the cube
  texture/sampler/view/skybox uniforms at group 0 bindings 0, 1, 2, and 3 and
  samples `ray_direction * vec3(1.0, 1.0, -1.0)`.

Mgstudio implementation fragments:
- `mgstudio-engine/core_pipeline/skybox/top.mbt::skybox_bind_group_layout_descriptor`
  and `skybox_render_pipeline_descriptor` preserve the same descriptor shape:
  `TextureSampleType::Float(true)`, `TextureViewDimension::Cube`,
  `SamplerBindingType::Filtering`, dynamic uniform buffers for view and
  skybox uniforms, entry points `skybox_vertex`/`skybox_fragment`, no color
  blend, all color writes, `Depth32Float`, disabled depth writes, and
  `COMPARE_FUNCTION_GREATER_EQUAL`.
- `mgstudio-engine/render/renderer/gpu_skybox.mbt::ensure_skybox_resources`
  and `skybox_pipeline_get_or_create` materialize the same host-side WGPU
  layout and pipeline state. The backend view buffer is 1024 bytes, which is
  larger than the current Bevy-shaped `ViewUniform` minimum binding size
  represented by `@render_view.VIEW_UNIFORM_SIZE_BYTES == 784`.

Evidence:
- `diff -u bevy/crates/bevy_core_pipeline/src/skybox/skybox.wgsl mgstudio-engine/core_pipeline/skybox/skybox.wgsl`
  produced no diff.
- `shasum -a 256` for both skybox WGSL files is
  `37dccd40213ffa5690136f9defa7cdaf2d69e2f335b1ddde742f85014f3bd863`.
- Added white-box coverage in
  `mgstudio-engine/core_pipeline/skybox/top_wbtest.mbt` for the embedded WGSL
  anchors and render-pipeline descriptor shape.
- Validation: `moon -C mgstudio-engine test core_pipeline/skybox --target native --release`
  passed `7/7`; linker duplicate `-lobjc` warnings were emitted.

Conclusion: the skybox shader and pipeline descriptor path is classified as
complete for this audit and is not a remaining candidate root cause for the
current `examples/3d/volumetric_fog` near-grey visual failure. Cubemap
decode/view evidence remains tracked separately by ISS-352.

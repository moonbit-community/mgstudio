## Description
Bevy examples such as `bevy/examples/3d/contact_shadows.rs` rely on
`MeshPickingPlugin` plus entity-scoped `Pointer<Drag>`, `Pointer<Over>`,
`Pointer<Out>`, and `Pointer<DragEnd>` observers. The drag observer exposes
`event.delta`, which the example uses to rotate the FlightHelmet model while
also switching the primary window cursor between `Grab`, `Grabbing`, and
`Default`.

Mgstudio currently exposes pointer enter/leave/down/up/click/move observer
kinds and `PointerEvent` carries pointer id, kind, position, and target, but it
does not expose Bevy-shaped drag or drag-end observer kinds, drag delta payloads,
or a public `MeshPickingPlugin` registration surface that can be mirrored by
examples.

## Design
Extend the picking/input observer layer with Bevy-shaped mesh picking and drag
observer semantics. This should be implemented in the engine/picking API, not as
example-local mouse polling, keyboard fallback, or cursor-only approximation.
Once available, update `examples/3d/contact_shadows` to use the exact
FlightHelmet drag/over/out/dragend observer chain from the Bevy owner.

## Acceptance Criteria
- [ ] A public mesh picking plugin surface exists for examples that maps to
      Bevy's `MeshPickingPlugin` role.
- [ ] Pointer observer kinds include Bevy-shaped `Drag` and `DragEnd`
      equivalents.
- [ ] Drag events expose a delta equivalent to Bevy `event.delta`.
- [ ] Entity-scoped observers can register for drag and drag-end through
      `EntityCommands`.
- [ ] `examples/3d/contact_shadows` uses these observers for FlightHelmet
      rotation and drag cursor updates without keyboard, polling, or local
      fallback behavior.

## Description
Prove that the real `examples/3d/volumetric_fog` directional cascade records
carry Bevy-equivalent `clip_from_world`, texel size, and far-bound values into
the fog shader-visible data.

## Design
Use the source-anchor map from ISS-385 and the scalar ordering result from
ISS-386. Compare each real cascade record in source order against Bevy's
packing expressions. Keep the evidence field-level: `clip_from_world`,
`texel_size`, and `far_bound`.

## Acceptance Criteria
- [x] Bevy source expressions for `clip_from_world`, `texel_size`, and
      `far_bound` are cited in close notes.
- [x] Focused evidence records or asserts the corresponding real mgstudio
      example values for every active cascade.
- [x] Any divergence is assigned to ISS-375 with exact owner and field name.
- [x] If no divergence is found, close with evidence that rules out cascade
      record values.

## Close Notes
Closed on 2026-07-05 after adding focused real-example per-cascade record
evidence in `mgstudio-engine/examples/3d/volumetric_fog/main_wbtest.mbt`.

Bevy source expressions audited:

- `bevy/crates/bevy_pbr/src/render/light.rs::prepare_lights` fills each active
  `GpuDirectionalCascade` with `clip_from_world: cascade.clip_from_world`,
  `texel_size: cascade.texel_size`, and `far_bound: *bound`.
- The source iterator zips `light.cascades.get(&entity)`,
  `light.frusta.get(&entity)`, and `light.cascade_shadow_config.bounds`; this
  preserves source cascade order established in ISS-386.
- `bevy/crates/bevy_pbr/src/render/mesh_view_types.wgsl::DirectionalCascade`
  exposes the same three fields to the shader.
- `bevy/crates/bevy_pbr/src/render/shadows.wgsl` and
  `bevy/crates/bevy_pbr/src/volumetric_fog/volumetric_fog.wgsl` consume
  `clip_from_world`, `texel_size`, and `far_bound` through
  `world_to_directional_light_local`, `get_cascade_index`, and
  `sample_shadow_map_hardware`.

Mgstudio evidence:

- Added test

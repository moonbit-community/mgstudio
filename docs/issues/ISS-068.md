## Description
Bevy's `CiTestingPlugin` reads `CI_TESTING_CONFIG` or
`ci_testing_config.ron` and deserializes a `CiTestingConfig` with RON/serde.
Mgstudio currently only has explicit resource insertion and environment
variables for the screenshot runner convenience path. That cannot be counted as
source-level parity for `bevy_dev_tools/src/ci_testing/mod.rs`.

## Design
Use a real MoonBit RON parser/deserializer once one exists, then port Bevy's
file-loading path directly:

- use `CI_TESTING_CONFIG` when present;
- otherwise read `ci_testing_config.ron`;
- deserialize into the Bevy-shaped `CiTestingConfig`;
- preserve explicit resource insertion as the highest-priority config source.

Do not replace this with JSON, ad-hoc string parsing, or an mgstudio-only
configuration format.

## Acceptance Criteria
- [ ] A real MoonBit RON dependency exists and is added to the project.
- [ ] `CiTestingConfig` can be loaded from a RON file with Bevy-compatible
  field and enum syntax.
- [ ] The config loading precedence matches Bevy: pre-inserted resource first,
  then `CI_TESTING_CONFIG`, then `ci_testing_config.ron`, then default config.
- [ ] Tests cover Bevy's sample RON shape from `config.rs`.

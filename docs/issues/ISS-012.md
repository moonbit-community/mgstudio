## Description
The current render/PBR/mesh/light stack has broad file, shader, resource, and
example coverage, but it is not complete under the strict Bevy source-level
parity standard. Visual plausibility is not sufficient: each source owner,
struct, function, schedule edge, render-world resource, phase command, and
example data flow must be classified as complete, facade, partial, or blocked.

As of 2026-06-30, the best current planning estimate is:

- combined PBR/mesh/light source parity: about `89%`;
- PBR: about `90-92%`;
- mesh: about `85-88%`;
- light/shadow: about `92-94%`;
- remaining work: about `11%` total, split roughly into `7-8%` local
  source-owner/runtime/visual-parity work and `3-4%` true external or language
  blockers.

These numbers are not visual-quality scores and must not be used as completion
claims. They are a triage estimate for scheduling the remaining source-owner
audit and implementation work. A package or example only counts as complete
when its Bevy source anchors are classified symbol-by-symbol and the relevant
runtime path is verified by tests or visual evidence.

Older strict-roadmap scores such as `pbr=58%`, `pbr/render=71%`,
`pbr/prepass=59%`, and `pbr/meshlet=50%` were useful early baselines, but they
are no longer the right description after the later material, light probe,
shadow, mesh preparation, example, and shader-source work. They must not be
used as the current migration status.

This epic tracks the remaining high-level render/PBR parity work found by
comparing `mgstudio-engine/render`, `mgstudio-engine/pbr`,
`mgstudio-engine/mesh`, and `mgstudio-engine/light` against the current local
`./bevy` baseline.

## Design
Treat Bevy source ownership as the acceptance surface. Directory names, file
presence, WGSL presence, and plausible screenshots are not enough: plugin build
order, render sub-app lifecycle, render graph scheduling, resource
initialization, pass phase ownership, command execution, visual output, and
performance behavior must converge.

The largest remaining local gaps are PBR phase-command consumption, renderer
pass ownership, render-app system ordering, mesh preparation owner cleanup,
source-shaped visual gates, custom shader/custom material paths, skybox/OIT
paths, and volumetric fog/atmosphere ownership. The largest blocked gaps are
exact meshlet visibility-buffer runtime support, selected GPU
readback/feature-query surfaces, and source shapes that depend on missing
MoonBit or upstream-library features.

## Acceptance Criteria
- [ ] `render`, `render/renderer`, `pbr`, `pbr/render`, `pbr/prepass`, `mesh`, `light`, and unblocked `pbr/meshlet` items all reach at least `95%` in `docs/ROADMAP_CHECKLIST.md`.
- [ ] Every child issue is closed, deferred with an explicit blocker, or replaced by a more specific issue.
- [ ] Representative 2D, 3D, PBR, prepass/deferred, shadow, transmission, and meshlet examples have current visual parity evidence or explicit blockers.
- [ ] `docs/ROADMAP_CHECKLIST.md` no longer describes renderer ownership, render-graph integration, pass layout, PBR runtime consumption, or visual parity as major gaps without an open child issue.

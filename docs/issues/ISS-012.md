## Description
The current render and PBR modules have broad file and shader coverage, but they
are still far from source-level parity with the local Bevy baseline. The latest
strict roadmap scores are `render=51%`, `render/renderer=52%`, `pbr=58%`,
`pbr/render=71%`, `pbr/prepass=59%`, and `pbr/meshlet=50%`.

This epic tracks the remaining high-level render/PBR parity work found by
comparing `mgstudio-engine/render` and `mgstudio-engine/pbr` against
`./bevy/crates/bevy_render/src` and `./bevy/crates/bevy_pbr/src` at baseline
commit `1413bc4e3`.

## Design
Treat Bevy source ownership as the acceptance surface. Directory and WGSL
presence are not enough: plugin build order, render sub-app lifecycle, render
graph scheduling, resource initialization, pass phase ownership, command
execution, visual output, and performance behavior must converge.

## Acceptance Criteria
- [ ] `render`, `render/renderer`, `pbr`, `pbr/render`, `pbr/prepass`, and unblocked `pbr/meshlet` items all reach at least `95%` in `docs/ROADMAP_CHECKLIST.md`.
- [ ] Every child issue is closed, deferred with an explicit blocker, or replaced by a more specific issue.
- [ ] Representative 2D, 3D, PBR, prepass/deferred, shadow, transmission, and meshlet examples have current visual parity evidence or explicit blockers.
- [ ] `docs/ROADMAP_CHECKLIST.md` no longer describes renderer ownership, render-graph integration, pass layout, PBR runtime consumption, or visual parity as major gaps without an open child issue.

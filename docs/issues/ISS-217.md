## Description
After cascade inputs are proven, the next source-owner boundary is the shadow
target itself. Mgstudio must allocate and attach the directional shadow texture
layer in the same way Bevy does, including depth format, clear/load/store
semantics, layer selection, and per-cascade retained-view identity.

## Design
Compare Bevy's directional shadow texture allocation, per-cascade texture view
creation, depth attachment setup, and shadow render-pass descriptor with
mgstudio's shadow view and renderer pass setup. This issue should not inspect
which meshes are queued into the pass; it only proves the target and pass are
Bevy-shaped.

## Acceptance Criteria
- [x] Shadow texture array allocation and per-cascade layer views are mapped to
      Bevy source owners.
- [x] Depth clear/load/store operations and depth comparison conventions match
      Bevy or are fixed source-faithfully.
- [x] Retained-view identity for each directional cascade is stable and matches
      the later phase/binding lookup keys.
- [x] A focused test, capture artifact, or debug artifact proves the
      `scrolling_fog` directional cascade pass attaches the expected target.

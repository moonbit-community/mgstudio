## Description
`Milky2018/moon_rapier@0.5.0` updates the dependency-side constructor style for the current MoonBit toolchain, but mgstudio still calls the old `Type::new(...)` APIs throughout `physics2d`. Keeping `moon_rapier@0.5.0` requires migrating those call sites to the new published API before packages importing `Milky2018/mgstudio` can build reliably.

## Design
Use `moon ide doc` or `pkg.generated.mbti` from `Milky2018/moon_rapier@0.5.0` to discover the exact replacement names. Do a source-level migration of mgstudio physics2d call sites; do not add compatibility wrappers just to preserve `::new`.

## Acceptance Criteria
- [ ] `physics2d` no longer calls removed `moon_rapier` `Type::new(...)` APIs.
- [ ] `moon -C mgstudio-engine build --target native --release examples/3d/clustered_decal_maps` no longer reports `moon_rapier` constructor errors.
- [ ] Targeted `physics2d` tests pass with `--release`.
- [ ] `moon -C mgstudio-engine fmt` and `moon -C mgstudio-engine info` are run after the migration.

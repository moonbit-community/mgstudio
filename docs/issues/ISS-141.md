## Description
ISS-140 restored visible retained `GizmoAsset` usage for
`examples/gizmos/3d_gizmos`, but Bevy's full source owner shape lives in
`bevy_gizmos_render/src/retained.rs`, `pipeline_2d.rs`, `pipeline_3d.rs`, and the
`GizmoMeshConfig` extraction path. mgstudio currently extracts retained
`GizmoAsset` buffers directly into the existing 3D gizmo line mesh queue instead
of spawning a render-side `GizmoMeshConfig`/uniform entity and consuming it from
source-shaped 2D/3D gizmo render pipelines.

## Design
Port the retained gizmo render owner shape symbol-by-symbol from Bevy. The
target is not another example-level workaround: retained `Gizmo` components
should extract their transform, line config, depth bias, render layers, and
asset handle into a render-owned representation that matches Bevy's
`extract_linegizmos` and `GizmoMeshConfig` flow as closely as MoonBit permits.
If a language or dependency limitation blocks exact parity, record that blocker
explicitly instead of falling back silently.

## Acceptance Criteria
- [ ] mgstudio has source-shaped retained gizmo extraction corresponding to
      `bevy_gizmos_render/src/retained.rs::extract_linegizmos`.
- [ ] 2D and 3D gizmo rendering consume retained `GizmoMeshConfig`-shaped data
      instead of only pushing retained asset vertices into the global immediate
      line queue.
- [ ] `GizmoLineConfig` perspective, style, joints, width, depth bias, render
      layers, transform, and asset handle are all covered by tests.
- [ ] `examples/gizmos/3d_gizmos/reference.png` still shows both immediate and
      retained gizmos after the source-owner migration.

# ISS-451: Replace hot dense-ID maps with indexed arrays

## Description

World tables, archetypes, local component metadata, membership generations, and
several structural edges use `Map[Int, ...]` even though their IDs are dense and
monotonic. Replace only profile-proven hot dense-ID maps with direct indexed
arrays; signature-to-ID indexes remain maps.

## Design

Isolate `World.tables` as the first and only registry variable. The pinned Bevy
`Tables` owner stores tables in `Vec<Table>` indexed by `TableId` while keeping
the component-signature-to-ID index as a `HashMap`. Mgstudio will mirror that
split with `Array[RawTable?]`: bounds and `None` preserve explicit missing-ID
semantics, and lazy table construction fills the dense ID slot. No archetype,
component, signature, edge, or membership registry changes belong in this
experiment.

- [x] Only dense-ID registries are converted; associative signature indexes are

## Notes

- 2026-07-16: Source audit found more than forty `table_storage` call sites
  shared by query fetch, filters, component columns, table batches, structural
  moves, and change ticks. The storage owner itself has only four direct Map
  operations (`get`, `get_or_init`, and two iterations), so the registry can be
  isolated without changing callers or table payload ownership.
- 2026-07-16: Pinned Bevy `Tables` uses `Vec<Table>` for `TableId` lookup and a
  separate `HashMap<Box<[ComponentId]>, TableId>` for associative signature
  lookup. Mgstudio's existing `table_ids_by_signature` remains unchanged.
- 2026-07-16: `World.tables` now uses `Array[RawTable?]`. Bounds and empty slots
  preserve explicit missing-ID behavior, lazy construction fills the requested
  dense ID, and the array remains owned and released with its `World`. More than
  forty query, filter, batch, structural-move, and tick call sites now reach a
  bounds check plus array lookup without changing their APIs or payload owners.
- 2026-07-16: The focused table structural-migration invariant test passed as a
  native release invocation with `MOONBIT_NEW_NATIVE=1`. It covers raw and typed
  column row-count agreement after archetype/table moves and verifies that each
  occupied array slot owns the matching table ID.
- 2026-07-16: Two Map traces of `stress_tests/transform_hierarchy` measured
  `8.466` and `8.419 ms/frame` (`8.443 ms` mean); two Array traces measured
  `8.435` and `8.430 ms/frame` (`8.433 ms` mean, `0.12%` improvement).
  `mark_dirty_trees_system` improved from `2.540` to `2.432 ms` mean (`4.25%`),
  the example update system from `0.672` to `0.660 ms` (`1.86%`), and
  `propagate_parent_transforms_system` remained effectively flat (`0.621` to
  `0.621 ms`). This satisfies the directly removed lookup-class branch of the
  `ISS-444` gate with no frame regression.
- 2026-07-16: A detached Map baseline and the Array implementation produced
  byte-identical fixed-frame-90 captures with SHA-256
  `ba1a15bce58204d62576583693aae50a2ccd2ea28a707b48f71539b9028b3fa6`.
  The checked-in reference shows a later dynamic hierarchy phase, so the strict
  same-command A/B is the semantic regression oracle for this experiment.
- 2026-07-16: The native example build emitted only warning 0083 instances
  already deferred by `ISS-443`; no new warning class was introduced.

## Close Notes

Retained the Bevy-shaped dense table registry. Direct `TableId` access no longer
hashes an integer at more than forty shared hot call sites, signature lookup
remains associative, the focused structural invariant passed, and the runtime
gate improved slightly with byte-identical fixed-frame Map/Array output.

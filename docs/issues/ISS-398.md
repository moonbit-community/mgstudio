# ISS-398: Replace material runtime registry scans with entity-indexed material slots

## Description
`MaterialRuntimeRegistry` and `Material2dRuntimeRegistry` currently identify an
entity's material by linearly scanning registered material-type closures. Bevy
does not discover mesh materials this way; each typed extraction system knows
its `MeshMaterial3d<M>` or `MeshMaterial2d<M>` component and writes render-world
material instance data. The current registry scan is a local architecture debt,
not an external blocker.

## Design
Introduce an entity-indexed material slot or prepared-material lookup written by
typed extraction systems. Render mesh collection should consult the entity's
known material slot instead of asking every registered material type whether it
matches. Keep typed plugin registration, but make runtime resolution O(1) by
entity key where possible.

## Acceptance Criteria
- [x] 3D material resolution no longer scans every registered material type for

- [x] 2D material resolution no longer scans every registered material type for

- [x] Existing typed material extraction and pending-material behavior remain

- [x] many_foxes or another representative scene shows no material-resolution
      regression.
- [x] `moon fmt`, `moon info`, and `moon check` pass.

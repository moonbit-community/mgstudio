## Description
Bevy marks view depth textures with usage required by volumetric fog before the
pass samples depth. Mgstudio has a local helper for this behavior, but it
should be owned as a Bevy-shaped prepare step and ordered before the pass.

## Design
Audit Bevy `prepare_view_depth_textures_for_volumetric_fog` and align the
mgstudio owner and call site. The prepare step must derive its need from
render-world volumetric fog view state and must not mutate source-world camera
components.

## Acceptance Criteria
- [x] Depth texture usage is prepared before volumetric fog pass execution.
- [x] The decision to add texture-binding usage comes from render-world view fog state.
- [x] Source-world camera/depth components are not mutated by this prepare step.
- [x] Focused tests cover no-fog and fog-enabled view cases.

## Close Notes
2026-07-04: Aligned mgstudio's depth-texture usage prepare with Bevy's
`prepare_view_depth_textures_for_volumetric_fog`. The volumetric-fog decision
now comes from render-world `VolumetricFog` view state and no longer requires a
`VolumetricLight`; this matches Bevy's `Query<&VolumetricFog>` check.

`render3d_execute_collect_cameras` now receives both the source world and render
world. It still extracts camera data from the source world, but prepares the
extracted `Camera3dViewPayload.depth_texture_usages` from render-world
volumetric-fog state. This preserves source-world camera components instead of
mutating them during render prepare.

Focused tests cover:
- no volumetric-fog view state leaves depth texture usage unchanged;
- volumetric-fog view state without any volumetric light still adds
  texture-binding usage;
- collected camera payloads get texture-binding usage from render-world fog
  while the source-world `Camera3d` component remains unchanged.

# ISS-401: Replace 2D material runtime registry scans with entity-indexed slots

## Description
`Material2dRuntimeRegistry` and `CustomMesh2dRuntimeRegistry` still resolve
2D material ownership by scanning registered material-type closures during
runtime extraction and draw preparation. The 3D path was moved to
entity-indexed resolved material slots in ISS-398; the 2D path should receive
the same source-shaped treatment instead of keeping per-entity registry scans.

## Design
Introduce entity-indexed 2D material slots written by typed Material2d and
custom Mesh2d extraction systems. Runtime collection should consult the entity
slot directly and treat present-but-not-prepared slots as pending, matching the
3D `RenderMaterial3dResolvedSlots` pattern. Remove the 2D runtime registries
once all collection and custom pipeline paths use slots.

## Acceptance Criteria
- [ ] `Material2dRuntimeRegistry` is no longer used for per-entity material
      resolution.
- [ ] `CustomMesh2dRuntimeRegistry` is no longer used for per-entity custom
      mesh pipeline resolution.
- [ ] Typed 2D material extraction tests cover resolved and pending slots.
- [ ] Representative 2D material examples still match their references.
- [ ] `moon fmt`, `moon info`, and `moon check` pass.

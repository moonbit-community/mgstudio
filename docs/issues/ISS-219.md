## Description
Once the pillar is visible to the directional shadow caster, mgstudio still
must preserve the Bevy path from visible entity to specialized shadow pipeline,
queued shadow phase item, and executed shadow draw command. Failures in any
one of those stages can leave a valid shadow target empty even though
visibility data is correct.

## Design
Keep this issue as the group tracker. The executable child issues isolate the
pipeline into independently verifiable slices:

- ISS-232 proves the visible entity keeps the Bevy material, mesh instance,
  render mesh asset, and material asset inputs needed by shadow specialization.
- ISS-233 restores the Bevy `specialize_shadows` cache-entry and draw-function
  path.
- ISS-234 restores the Bevy `queue_shadows` phase-item construction path.
- ISS-235 tracks the smaller shadow-pass consumption children: validation
  minimization, shadow-compatible pipeline selection, retained target identity,
  and final no-retry visual capture.

## Close Notes
2026-07-04: Closed after the shadow phase queue and draw execution chain was
split, fixed, and verified through ISS-232, ISS-233, ISS-234, and ISS-235.

The completed chain now proves:

- visible `scrolling_fog` shadow caster inputs reach specialization;
- shadow specialization builds and caches a valid phase pipeline/draw-function
  pair;
- Bevy-shaped `queue_shadows` phase items are inserted with valid mesh slab,
  mesh asset, material-bind-group, draw-function, and pipeline metadata;
- the retained shadow pass consumes the queued item and draws it into the
  prepared directional shadow target without WGPU validation errors.

Remaining `scrolling_fog` final visual parity work is intentionally left to the
directional shadow-map content and volumetric fog shader-input issue groups
instead of being folded into this queue/draw execution group.

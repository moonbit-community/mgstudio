# ISS-165: Unblock feature-rich PBR WGSL composition for startup parity

## Metadata
- Type: bug
- Status: blocked
- Priority: 1
- Labels: pbr, render, shader, wgsl-compose, startup, screenshots, source-parity, cache
- Assignee: unassigned

## Description
Feature-rich PBR examples can fail the standard native screenshot gate before
any GPU validation or runtime error is emitted. The process reaches the render
schedule, then spends the capture window inside WGSL composition/import
planning rather than producing a capturable frame.

This currently blocks source-parity validation for `examples/3d/clearcoat` and
`examples/3d/transmission`. Both examples expose the same symptom: the run log
is empty, the RGBA8 blob is not produced within the documented 240s gate, and
sampling shows the main thread inside `load_wgsl_preprocessed` and
`moon_wgsl_naga_oil` import planning / semantic reference scanning.

Two separate issues are involved:

- `ISS-166` tracks the local Bevy-parity bug where missing mesh3d forward
  pipelines can still be created from draw execution instead of being selected
  by the material specialization / pipeline cache path before drawing.
- This issue tracks the remaining feature-rich PBR WGSL composition startup
  blocker. Independent `moon_wgsl/tools/compose_case` timings show that one
  `pbr/render/pbr.wgsl` fragment variant with descriptor-like forward PBR defs
  takes about 47 seconds, which is too slow for Bevy-style runtime pipeline
  specialization when several variants are needed before first frame.

This is not a reason to change example behavior or relax the gate. Bevy can
synchronously materialize pipelines on macOS, but its shader cache owns shader
assets, processed shader modules, shader-def keyed reuse, recursive import
registration, and queued pipeline specialization/materialization in a
source-shaped way. Mgstudio must keep the same ownership model; if the current
MoonBit WGSL ecosystem cannot make that model fast enough, the dependency
blocker must stay explicit.

## Design
Fix this as a shader compile/cache ownership and dependency capability problem:

- Preserve Bevy-shaped shader source and feature gates. Do not simplify the
  affected examples, remove shader imports, edit copied WGSL, or increase the
  visual gate timeout as a workaround.
- Do not introduce disk caches or generated-source rewrites to hide startup
  cost. The desired fix is an in-process Bevy-shaped shader cache and pipeline
  materialization path.
- Audit whether mgstudio is composing too many unique pipeline variants,
  missing the existing composed-WGSL cache, invalidating the cache too often,
  caching by the wrong owner, or asking `moon_wgsl_naga_oil` to redo global
  import graph work per pipeline. Do not mark this complete until the answer is
  backed by source-owner inventory and measurement, not by visual plausibility.
- Align the local shader cache with Bevy's ownership shape: shader asset/source
  identity plus shader-def values should determine processed shader reuse, and
  imported modules should not be reparsed as unrelated global work for each
  descriptor materialization.
- Move the renderer-local mesh3d forward pipeline path toward Bevy's
  queue/specialize/materialize model under ISS-166. The first draw call must
  not be the owner that composes WGSL and creates the missing forward render
  pipeline.
- Treat `moonbit-community/moon_wgsl#15` as the current external blocker for
  reusable/import-incremental PBR composition or an equivalent performance fix.
  Recheck this issue when the dependency changes; do not replace it with local
  shader rewrites or caches.

## Acceptance Criteria
- [ ] `ISS-166` is closed and draw execution no longer creates missing forward
      PBR pipelines as the normal path.
- [ ] `examples/3d/transmission` produces an RGBA8 screenshot with the standard
      90-frame native capture command.
- [ ] `examples/3d/clearcoat` produces an RGBA8 screenshot with the standard
      90-frame native capture command after selecting only the Bevy-equivalent
      `pbr_multi_layer_material_textures` feature.
- [ ] Sampling no longer shows the main thread spending the capture window in
      repeated `moon_wgsl_naga_oil` import planning for these examples.
- [ ] The fix keeps Bevy WGSL sources and StandardMaterial feature gates intact.
- [ ] No disk shader cache, timeout increase, copied-WGSL mutation, feature
      disabling, or generated-source rewrite is used as the solution.
- [ ] The implemented shader cache / pipeline materialization shape is audited
      against Bevy's `bevy_shader::ShaderCache` and
      `bevy_render::render_resource::PipelineCache` owner boundaries.
- [ ] If an upstream dependency change is required, the dependency issue is
      linked in `External ref` and the affected local parity criteria remain
      blocked until the dependency is available.

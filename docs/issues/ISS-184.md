## Description
Bevy prepares `ViewVolumetricFog` per extracted view by combining each
`ExtractedView`, `VolumetricFog`, `FogVolume`, and fog-volume
`GlobalTransform`. The prepared view data records each volume's uniform offset,
inside/outside hull selection, and optional density texture handle metadata.

Mgstudio currently computes similar data through camera-local render execution.
That hides the Bevy source owner and couples data preparation to draw-time
camera flow.

## Design
Create a Bevy-shaped per-view prepare step that consumes extracted render-world
`VolumetricFog`, `FogVolume`, `GlobalTransform`, and view transform/projection
state. It must insert or update `ViewVolumetricFog` on the render-world view
entity before the draw pass reads it. Preserve camera-inside-volume and hull
clip transform behavior by comparing directly against Bevy
`prepare_volumetric_fog_uniforms`.

## Acceptance Criteria
- [x] `ViewVolumetricFog` is inserted on render-world view entities by the prepare step, not by local camera draw execution.
- [x] Camera-inside-volume behavior and exterior/interior hull selection match Bevy's transform math.
- [x] Density texture handle metadata is copied from render-world fog-volume data into `ViewFogVolume`.
- [x] Focused tests cover camera-inside-volume, camera-outside-volume, and density-texture metadata cases.

## Close Notes
2026-07-04: Moved `ViewVolumetricFog` writes into the standalone volumetric-fog
uniform prepare owner. `render3d_prepare_volumetric_fog_uniform_buffer` now
matches Bevy's `commands.entity(view_entity).insert(ViewVolumetricFog(...))`
shape by writing the prepared view component directly onto the render-world
view entity after computing each view/volume uniform.

Removed the old camera-local `render3d_write_volumetric_fog_view_components`
path. Camera execution still invokes the prepare owner through a local adapter
until ISS-186 moves scheduling to the Bevy-shaped pre-draw prepare phase, but
the component mutation itself is now owned by the prepare step.

Focused coverage added in `pbr/volumetric_fog_execute_wbtest.mbt` verifies:
- inside-volume views produce `exterior=false`;
- outside-volume views produce `exterior=true`;
- density texture handles are copied into `ViewFogVolume`;
- dynamic uniform offsets remain stable while the prepared component is stored
  on the render-world view entity.

## Close Notes
Closed on 2026-07-05 by consolidating the skybox evidence from ISS-351 through
ISS-353.

Runtime evidence:
- ISS-351 proved that the embedded skybox WGSL is byte-identical to Bevy
  (`37dccd40213ffa5690136f9defa7cdaf2d69e2f335b1ddde742f85014f3bd863`) and
  that the mgstudio skybox pipeline descriptor preserves Bevy's cube texture,
  filtering sampler, dynamic view uniform, dynamic skybox uniform, no-blend
  color target, `GreaterEqual` depth compare, and view MSAA sample count.
- ISS-352 proved that the real
  `environment_maps/pisa_specular_rgb9e5_zstd.ktx2` asset bytes match Bevy
  (`b5eddbb37839319b5604a7bd97c6916e9351f73d872138d91b0917169285e42d`), decode
  as a six-face RGB9E5 cubemap, upload through the renderer as a cube sample
  view, and are required by the skybox bind-group preparation path.
- ISS-353 proved that the real `volumetric_fog` camera uses Bevy's Pisa skybox
  image, brightness `1000.0`, identity rotation, and default exposure fallback
  before binding the same view-uniform path used by Bevy's skybox shader.

Validation:
- `moon -C mgstudio-engine test core_pipeline/skybox --target native --release`
  passed after the skybox shader/pipeline and brightness/exposure tests were
  added.
- `moon -C mgstudio-engine test asset --target native --release --filter 'asset host io: bevy pisa specular environment map decodes as rgb9e5 cubemap'`
  passed.
- `moon -C mgstudio-engine test render/renderer --target native --release --filter 'renderer: rgb9e5 cube texture upload creates a cubemap sample view'`
  passed.
- `moon -C mgstudio-engine test examples/3d/volumetric_fog --target native --release --filter 'volumetric_fog: camera render entity prepares Bevy skybox draw state'`
  passed.
- `moon -C mgstudio-engine test examples/3d/volumetric_fog --target native --release --filter 'volumetric_fog: camera skybox and volumetric fog setup matches Bevy'`
  passed.

Conclusion: the skybox shader, cubemap texture-view, brightness/exposure, and
view-input paths are ruled out as the root cause of the current
`examples/3d/volumetric_fog` near-grey visual failure. No production code fix
belongs in the skybox/core-pipeline owner for this failure. The remaining
repair work should move to the volumetric-fog pass and renderer ownership
tracked by ISS-350 and its child issues.

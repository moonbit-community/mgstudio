## Description
`mgstudio-engine/render/renderer` contains substantial local architecture for
mesh3d, mesh2d, postprocess, surfaces, backend state, pass begin/finalize, and
draw execution. The roadmap still marks renderer ownership, pass layout, and
visual parity as substantially divergent from Bevy.

## Design
After `RenderGraph` and `RenderPlugin` are Bevy-shaped, move renderer pass
execution into the correct graph phases and owner resources. Avoid retaining
renderer-local compatibility layers whose only purpose is to preserve the old
architecture.

## Acceptance Criteria
- [ ] Main, shadow, motion-vector, postprocess, screenshot, readback, and present paths have Bevy-shaped graph or render-system ownership.
- [ ] Renderer state is split into owner resources matching Bevy concepts instead of one broad backend singleton carrying unrelated pass responsibilities.
- [ ] Pass timing reports distinguish graph phase, CPU command construction, submit, and present/wait costs.
- [ ] Existing mesh2d and mesh3d examples still render correctly after pass ownership changes.
- [ ] `docs/ROADMAP_CHECKLIST.md` no longer describes `render/renderer` ownership and pass layout as a major gap.

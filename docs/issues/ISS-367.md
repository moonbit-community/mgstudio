## Description
Prove that mgstudio specializes volumetric-fog shader definitions, pipeline
keys, and bind-group layout keys with the same owner semantics as Bevy's
`VolumetricFogPipeline::specialize`.

## Design
Compare Bevy's `VolumetricFogPipelineKey`, `MeshPipelineViewLayoutKey`, and
`VolumetricFogBindGroupLayoutKey` behavior against mgstudio's PBR and renderer
specialization fragments. Cover `SHADOW_FILTER_METHOD_HARDWARE_2X2`,
`MULTISAMPLED`, `ATMOSPHERE`, and `DENSITY_TEXTURE` explicitly. This issue
should prove key construction and layout selection, not final frame output.

## Acceptance Criteria
- [x] Bevy shader-def sources are mapped to mgstudio specialization symbols.
- [x] MSAA, atmosphere, shadow-filtering, and density-texture key bits are
      proven with focused source evidence or tests.
- [x] Textureless and density-textured layout variants are classified.
- [x] Any key/layout divergence is linked to ISS-370 for final assignment.

## Close Notes
Closed on 2026-07-05 after mapping Bevy's volumetric-fog specialization owner
to mgstudio's PBR key and renderer pipeline fragments.

Bevy owner anchors:

- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs::VolumetricFogPipelineKey`
  stores `mesh_pipeline_view_key`, `vertex_buffer_layout`, `target_format`, and
  `has_density_texture`.
- `VolumetricFogPipeline::specialize` always emits
  `SHADOW_FILTER_METHOD_HARDWARE_2X2`, adds `MULTISAMPLED` from
  `MeshPipelineViewLayoutKey::MULTISAMPLED`, adds `ATMOSPHERE` from
  `MeshPipelineViewLayoutKey::ATMOSPHERE`, and adds `DENSITY_TEXTURE` from
  `has_density_texture`.
- The same function builds `VolumetricFogBindGroupLayoutKey` from the
  multisampled and density-texture bits, producing textureless and textured
  layout variants.
- `prepare_volumetric_fog_pipelines` specializes both textureless and textured
  pipeline keys for each volumetric-fog view.

Mgstudio implementation fragments:

- `mgstudio-engine/pbr/volumetric_fog/render.mbt::VolumetricFogPipelineKey`
  stores the same key fields and exposes `shader_defs()` and
  `bind_group_layout_key()`.
- `mgstudio-engine/pbr/volumetric_fog/render.mbt::VolumetricFogBindGroupLayoutKey`
  stores the same two-bit layout key: bit 0 for MSAA and bit 1 for density
  texture.
- `mgstudio-engine/pbr/volumetric_fog_execute.mbt` creates textureless and
  textured keys and forwards the key fields to the renderer.
- `mgstudio-engine/render/renderer/mesh3d_pipeline_build.mbt` translates the
  forwarded key fields into the actual shader-def map and bind-group layout
  index consumed while building the native pipeline.

Evidence added or strengthened:

- `pbr volumetric fog execute: pipeline keys preserve Bevy texture variants and
  view dimensions` now also proves layout bits/index for a multisampled,
  atmosphere-enabled view: textureless is bit/index `1`, textured is bit/index
  `3`, matching Bevy's `MULTISAMPLED | DENSITY_TEXTURE` layout-key shape.
- `renderer: volumetric fog shader defs mirror Bevy specialization flags`
  proves the renderer always sets `SHADOW_FILTER_METHOD_HARDWARE_2X2`, omits
  optional defs for the base variant, and sets `MULTISAMPLED`, `ATMOSPHERE`,
  and `DENSITY_TEXTURE` for the full variant.
- Existing renderer tests prove layout indices `0`, `1`, `2`, and `3` for
  non-MSAA/MSAA and textureless/textured combinations, and prove MSAA affects
  the shader key without changing the volumetric color pipeline render sample
  count.

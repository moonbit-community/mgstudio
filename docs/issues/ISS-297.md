## Description
If the `volumetric_fog` input defaults and pipeline routing are correct, the
remaining likely local cause of the oversized hull/surface is camera-space
math: transform orientation, fog-volume clip matrix, dynamic uniform offsets,
depth texture binding, or depth reconstruction.

## Design
Compare Bevy transform/camera and volumetric fog uniform preparation against
mgstudio:

- `bevy/crates/bevy_transform/src/components/transform.rs`
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs`
- `mgstudio-engine/transform`
- `mgstudio-engine/pbr/volumetric_fog`
- `mgstudio-engine/render/renderer/mesh3d_volumetric_fog_pass.mbt`

Use source-level fixes only. Prefer focused tests that assert matrix/vector
values over visual-only conclusions.

## Acceptance Criteria
- [x] The example camera `looking_at` orientation is proven to match Bevy for
      the authored position and target.
- [x] Fog-volume inside/outside selection and `clip_from_local` data are proven
      to match Bevy for the authored volume.
- [x] `VolumetricFogUniform` packing and dynamic offsets match the Bevy source
      owner for the represented fields.
- [x] The pass binds and samples the same depth texture owner that Bevy uses for
      volumetric fog reconstruction.

  `looking_at`, inside-volume selection, clip calculation, blend state, and
  cull mode broadly Bevy-shaped, but this still needs focused value-level proof

- 2026-07-05: Added a white-box gate for the actual
  `examples/3d/volumetric_fog` camera and fog volume. The camera forward vector
  matches the normalized Bevy-authored `scene_focus - camera.translation`, and
  the 35m default `FogVolume` prepares one `ViewFogVolume` with
  `exterior=false`, no density texture, and one 512-byte uniform. This proves
  the example is taking Bevy's inside-volume/fullscreen-plane path.
- 2026-07-05: Rechecked Bevy
  `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs` against
  `mgstudio-engine/pbr/volumetric_fog/render.mbt`. The core math remains
  source-shaped for `local_from_view = local_from_world * world_from_view`,
  `view_from_local = inverse(local_from_view)`, inside-volume classification,
  `clip_from_local`, `uvw_from_world`, `far_planes`, bounding radius, uniform
  packing, and per-volume dynamic offsets.
- 2026-07-05: Rechecked the depth binding path. Bevy's render command consumes
  `ViewDepthTexture`; mgstudio's renderer stores the active 3D pass depth view
  in `GpuPassState.view_depth_view`, `draw_mesh3d_volumetric_fog` requires that
  view, and `mesh3d_volumetric_fog_bind_group` binds it at volumetric fog group
  1 binding 1. This source boundary does not explain the current gray/white
  visual failure by itself.

## Description
Bevy's `bevy_sprite_render/src/mesh2d/mesh.rs` computes a per-view
`Mesh2dPipelineKey` in `ViewKeyCache`, combining MSAA, target format,
compositing space, tonemapping, deband dither, primitive topology, strip index
format, and material alpha bits before `Material2dPipeline<M>::specialize`.

mgstudio now wires `Material2d::specialize` into host Mesh2d pipeline creation,
and draw-time keys include primitive topology and strip index format. The
remaining full key bits still come from render2d's immediate draw path instead
of a Bevy-shaped `ViewKeyCache` and render-phase specialization owner.

## Design
Port the Bevy source owner shape from `mesh2d/mesh.rs`: add a render-world
view-key cache, derive view key bits from extracted 2D camera state, combine
those bits with mesh topology/index-format and material alpha bits before
specializing material pipelines, and make phase queue/draw code consume the
cached pipeline ID rather than constructing view-dependent keys at immediate
draw time. This issue must coordinate with ISS-029, because the full fix spans
Core2d phase ownership rather than only `Material2d`.

## Acceptance Criteria
- [ ] Add a MoonBit `ViewKeyCache` equivalent for Mesh2d that records Bevy's
  target format, MSAA, compositing, tonemapping, and deband dither bits.
- [ ] Combine view key bits, primitive topology/strip index bits, and material
  alpha bits before `Material2dPipeline::specialize`.
- [ ] Ensure `Material2dKey[M]` receives the full Bevy-shaped mesh key, not a
  reduced alpha/topology-only key.
- [ ] Add tests covering at least target format, tonemapping/deband, primitive
  topology, and material alpha key separation.
- [ ] Validate with representative Mesh2d and shader material examples under
  `--release`.

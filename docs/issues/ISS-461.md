# ISS-461: Grow bindless material allocations across slabs

## Metadata
- Type: bug
- Status: closed
- Priority: 0
- Labels: pbr, material, bindless, render, visual-parity, regression
- Assignee: codex
- Created: 2026-07-16
- Updated: 2026-07-18
- External ref: none

## Description

`MaterialBindGroupBindlessAllocator` stored only one fixed-capacity slab. After
that slab filled, every later material allocation returned `None` permanently.
In `examples/3d/despawn3`, the first 256 StandardMaterials exhausted the
allocator before the shared physics debug materials were prepared, so their
15,372 transparent debug meshes never entered the render phase.

## Design

Match the pinned Bevy allocator model: a full bindless slab must be followed by
another slab, with `MaterialBindingId.group` identifying the slab and
`MaterialBindingId.slot` identifying the local slot. Freed entries must retain
those coordinates and be reusable. Bindless allocation itself cannot fail;
only the allocator enum may reject a bindless request when it contains a
non-bindless allocator. Construct the allocator with the material's declared
bindless slot count; StandardMaterial therefore uses its 31-slot slab size
instead of the unrelated default capacity.

Do not raise the global cap, discard later materials, or make the renderer fall
back to non-bindless allocation. Those alternatives would preserve the
single-slab ownership error instead of aligning with Bevy.

## Acceptance Criteria

- [x] A focused regression test fails when the third allocation of a two-slot
      allocator returns `None`.
- [x] The third allocation of a two-slot allocator receives group 1, slot 0.
- [x] Direct bindless allocation returns a binding rather than an optional
      result.
- [x] Freeing and reallocating a binding reuses its original group and slot.
- [x] StandardMaterial allocation honors its configured bindless slot count.
- [x] The focused tests pass with `MOONBIT_NEW_NATIVE=1`.
- [x] `examples/3d/despawn3` renders its physics debug geometry at frame 5
      without an uncaptured wgpu validation error.

## Notes

- 2026-07-16: Before the fix, frame 1 extracted and considered 1,281 visible
  meshes but queued exactly 256. On frame 2, 15,372 new material-bearing debug
  meshes were detected, but zero new phase items were queued.
- 2026-07-16: The pinned Bevy implementation searches existing slabs and
  creates a new `MaterialBindlessSlab` when all existing slabs are full. Its
  binding ID stores the slab index as `group` and the local allocation as
  `slot`.
- 2026-07-16: After the fix, frame 1 queued 1,281 items and frame 2 queued all
  15,372 new debug meshes. The frame-5 capture contains the physics debug
  geometry and produced no uncaptured wgpu validation error.
- 2026-07-18: Recorded the source-breaking return-type migration for direct
  `MaterialBindGroupBindlessAllocator::allocate` callers in
  [ECS_PERFORMANCE_API_MIGRATION.md](../ECS_PERFORMANCE_API_MIGRATION.md).
  Callers now use the returned `MaterialBindingId` directly instead of matching
  or unwrapping an optional value.

## Close Notes

Bindless material allocation now grows across Bevy-shaped slabs and reuses
freed global entries while preserving group/slot coordinates. StandardMaterial
installation now passes its declared slot count into the allocator. The
two-slot multi-slab regression test and the StandardMaterial slot-count test
both pass in native release mode, and a native `despawn3` frame-5 capture
restores the missing physics debug geometry. Direct-call migration is recorded
in [ECS_PERFORMANCE_API_MIGRATION.md](../ECS_PERFORMANCE_API_MIGRATION.md).

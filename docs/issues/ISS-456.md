## Description

Apply the retained `ISS-449` dense table-batch API to the remaining
performance-sensitive query call sites. A call site is eligible only after a
native trace shows material cost and the batch traversal can preserve its exact
query data, filter, change-detection, deferred-command, and source-owner
semantics.

## Acceptance Criteria

- [ ] Every matrix row has a retained, rejected, or externally blocked result.

      change-detection semantics.
- [ ] Every retained migration runs one focused test at a time with
      `MOONBIT_NEW_NATIVE=1`.
- [ ] Every retained migration uses the row's distinct example for its runtime
      gate and performs a valid visual comparison when the example renders.
- [ ] Every retained or rejected call-site experiment is committed separately.
- [ ] Unsupported per-row filters are not weakened or evaluated as table-wide
      predicates.

## Notes

- 2026-07-15: Created after the corrected first production migration improved
  `reset_view_visibility_system` by `22.38-23.44%` and steady frame interval by
  `10.97-13.42%`. The table deliberately separates directly supported dense
  queries from tick-filtered queries that require an exact API extension.
- 2026-07-15: `many_cubes` was rejected as the row-1 validation gate because
  `mark_newly_hidden_entities_invisible_system` measured only `0.018 ms/frame`.
  The distinct 102,400-entity `many_animated_sprites` gate measured
  `2.290 ms/frame` before and `0.919 ms/frame` after the batch migration, a
  `59.87%` system improvement. Steady frame interval improved from `251.876 ms`
  to `248.190 ms` (`1.46%`), and the adjacent visibility system remained flat.
- 2026-07-15: The focused semantic-transition test passed. Fresh row and batch
  frame-90 captures were byte-identical, proving no migration-specific visual
  change. Both diverge from the checked-in reference because of the pre-existing
  delayed-frame regression now owned by `ISS-457`; this result is not a claim
  that the example currently has official visual parity.

# ISS-150: Restore mirror example source shape

## Description
`ISS-084` removed the original mirror approximation: the example now uses a
real `ScreenSpaceTextureExtension`, the Bevy mirror shader path, and
inverted-culling mirror-camera rendering. The example still is not
source-complete against Bevy's `examples/3d/mirror.rs`, as recorded in the
symbol audit in `ISS-105`.

This issue tracks the remaining example-source migration, not the already
implemented extended-material or inverted-culling runtime path.

## Design
Port the remaining mirror example owner by Bevy source anchors:

- replace process-global `Ref[MirrorState]` with Bevy-shaped `AppStatus`,
  `MirrorImage`, marker components, query-owned camera/mirror/fox entities, and
  message-driven widget state where MoonBit ECS can express them;
- add source-shaped `MirrorCamera` and `Mirror` marker components and update
  resize, mirror-camera update, and render-target systems to query those
  markers instead of reading tracked entities from global state;
- preserve the Bevy `WidgetClickEvent<DragAction>` radio-button flow instead
  of keyboard-only drag-action switching;
- port `play_fox_animation` or record a precise animation-system blocker if the
  current animation API cannot express the Bevy source shape;
- keep mirror render-target image creation and resize semantics aligned with
  Bevy's `MirrorImage` resource and `WindowResized` message flow.

Do not change `mgstudio-engine/examples/3d/mirror/reference.png` unless a new
source-shaped implementation produces an equivalent or intentionally reviewed
visual result.

## Acceptance Criteria
- [ ] Every remaining source anchor from `bevy/examples/3d/mirror.rs` is
      classified as complete, partial, facade, blocked, or intentionally
      excluded after the implementation pass.
- [ ] The example no longer uses global `MirrorState` for Bevy resources,
      marker-owned entities, or widget state where typed ECS resources,
      components, queries, and messages can express the source shape.
- [ ] `MirrorCamera`, `Mirror`, `MirrorImage`, `AppStatus`, and `HelpText`
      ownership match Bevy's source roles as closely as MoonBit allows.
- [ ] Mirror resize and mirror-camera transform/projection updates are
      query-driven rather than tracked-entity driven.
- [ ] Fox animation playback is source-shaped or a precise blocker is recorded.
- [ ] The standard 90-frame native capture remains visually valid against
      `mgstudio-engine/examples/3d/mirror/reference.png`.
- [ ] Targeted `moon check --release`, `moon fmt`, and `moon info` pass for the
      touched packages.

## Notes
- 2026-06-23: Split from `ISS-084` so the original

  pretending the whole example is source-complete. Current known partial anchors
  are global `MirrorState`, missing queryable `MirrorCamera` and `Mirror`
  markers, local render-target state, keyboard shortcut UI instead of Bevy's
  widget-message flow, and missing Bevy-shaped `play_fox_animation`.
- 2026-06-23: Replaced the remaining sprite render-target helper usage with an
  explicit Bevy-shaped BGRA8 sRGB render-target allocation for `MirrorImage`.
  The standard 90-frame capture still shows a black mirror texture and missing
  foreground fox. Diagnostics confirmed both cameras and all three meshes are
  visible with matching render layers, so remaining work is in the image-target
  sampling/render path and skinned fox draw path, not entity ownership or layer
  filtering.
- 2026-06-24: Fixed a lower-level Bevy parity bug in
  `PerspectiveProjection3d` oblique near-clip handling found while auditing the
  mirror camera projection path. Bevy skips oblique projection adjustment when
  the clip-plane normal is `(0, 0, -1)` regardless of `w`; mgstudio had compared
  the full vector and incorrectly rewrote matrices for default-facing planes
  with a different distance. Targeted PBR release tests pass, but the fresh
  mirror capture at `/tmp/mgstudio_iss150_projection_clip_fix.png` still shows a
  black mirror surface and missing foreground fox, so this issue remains open.
- 2026-06-24: Restored the mirror-camera transform/projection calculation to
  the Bevy source shape: the transform is decomposed from the reflected affine
  matrix, and the mirror projection plane normal is computed from the inverse
  main-camera affine matrix instead of the local quaternion shortcut. Targeted
  mirror check passes, but `/tmp/mgstudio_iss150_affine_transform_fix.png`
  still shows the black mirror and missing foreground fox, so the remaining
  runtime fault is downstream of this source-shape correction.
- 2026-06-24: Fixed two lower-level Bevy/glam parity bugs exposed by the
  mirror camera path. `render3d_view_from_world_matrix` now derives
  view-from-world from the full affine inverse instead of dropping
  `Transform.scale`, and `Affine3::to_scale_rotation_translation` now matches
  glam by applying the determinant sign to the X scale only. Targeted
  `math`, `transform`, and `pbr/render` release tests pass, and
  `/tmp/mgstudio_iss150_affine_decomposition_fix.png` shows the mirror render
  target is no longer black. The visual still diverges from
  `examples/3d/mirror/reference.png`, with the fox absent and the mirror
  reflection framing incomplete, so this issue remains open.
- 2026-06-24: Fixed the glTF animation pending-asset semantics that made the
  mirror fox disappear. `scene_load_gltf_animation` now reserves an
  `AnimationClip` handle without inserting an empty zero-duration clip, matching
  Bevy's `Assets<AnimationClip>::get` behavior for not-yet-loaded clips. The
  regression test `scene: load gltf animation stays pending in the issuing
  frame` passes, `animation` release tests pass, and the 90-frame native mirror
  capture at `/tmp/mgstudio_iss150_animation_pending_fix.png` shows both the
  foreground fox and reflected fox. The checked-in `reference.png` still needs
  a separate visual/source-shape review before this issue can close.

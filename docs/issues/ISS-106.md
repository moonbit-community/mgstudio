## Description
`examples/3d/clustered_decals` is not a source-shaped port of Bevy's
`bevy/examples/3d/clustered_decals.rs`. The mgstudio example keeps a local
proxy-mesh approximation and global state while also attaching `ClusteredDecal`
components. Bevy's example demonstrates true clustered decals, the `tag` field
through a `CustomDecalExtension` shader, widget messages, gizmo bounds, and ECS
resource/query ownership.

This must not be counted as parity just because the checked-in reference is
non-empty.

## Design
Port the Bevy example owner symbol-by-symbol. Do not keep proxy meshes or local
shader/material fallbacks as the parity path. Any behavior that cannot be
implemented because clustered decal binding arrays are unavailable should remain
blocked by ISS-098 instead of being hidden behind a local approximation.

## Acceptance Criteria
- [ ] The example no longer renders clustered decals through textured proxy
      cuboid meshes.
- [ ] `AppStatus`, `Selection`, `DragMode`, `HelpText`, and
      `CustomDecalExtension` have source-shaped MoonBit mappings or documented
      language blockers.
- [ ] The example installs the material-extension/plugin, message, widget,
      gizmo, input, cursor, and visibility/update systems in Bevy-shaped owners.
- [ ] The `ClusteredDecal` entities use Bevy's texture, tag, and transform
      semantics without local proxy material tinting.
- [ ] `reference.png` is refreshed only after the source-shaped path is active
      on an adapter that passes the real clustered decal capability gate.

## Description
The standard no-retry `examples/3d/scrolling_fog` capture reaches a shadow draw
but aborts during `wgpuQueueSubmit`. The current set-0 bind group is
`mgstudio_mesh3d_shadow_view_bg`, while the pipeline id in the draw path expects
`mgstudio_pipeline_cache_render_bgl_0_prepass_view_layout_no_motion_vectors`.
That means the pass is no longer empty, but the queued item is carrying a
prepass-view-layout pipeline into a shadow-view render pass.

## Design
Keep this issue diagnostic-only. Preserve the failing command, the relevant
validation text, and the exact local/Bevy owner symbols that must be compared.
Do not fix the pipeline here; this issue exists to prevent the next fix from
being justified by a vague "shadow pass crash" symptom.

The validation error proves that the shadow phase item is consumed and reaches

Source anchors:

- Bevy `bevy/crates/bevy_pbr/src/render/light.rs:2428` through `2465` drains
  `ShadowSpecializationWorkItem`s, calls `prepass_specialize`, and stores the
  resulting `(pipeline_id, draw_function)` in
  `SpecializedShadowMaterialPipelineCache`.
- Bevy `bevy/crates/bevy_pbr/src/render/light.rs:2784` through `2815` begins
  `view_shadow_pass` with the shadow depth attachment and then renders the
  shadow phase using the retained light view.
- Mgstudio `mgstudio-engine/pbr/render_execute.mbt:1095` through `1147`
  mirrors the specialization loop but currently obtains the shadow phase
  pipeline id through `@material.material_specialize_prepass(...)`.
- Mgstudio `mgstudio-engine/pbr/render_shadow_phase.mbt:481` through `633`
  consumes the queued shadow phase item, emits positive
  `render_3d_shadow_phase_items` and `render_3d_shadow_binned_batches`
  counters, and passes `phase_item.cached_pipeline()` as
  `material_pipeline_id`.
- Mgstudio `mgstudio-engine/render/renderer/mesh3d_draw_runtime.mbt:194`
  through `201` routes shadow pass kinds into
  `draw_mesh3d_shadow_depth_pass`.
- Mgstudio `mgstudio-engine/render/renderer/mesh3d_pipeline_build.mbt:3160`
  through `3177` currently treats any non-default `material_pipeline_id` as a
  ready material render pipeline and returns it directly for shadow drawing.

Focused evidence:

- `moon -C mgstudio-engine test examples/3d/scrolling_fog --target native --release`
  passed with `Total tests: 6, passed: 6, failed: 0.`
- The `scrolling_fog: pillar produces queued directional shadow phase item`
  test observes positive shadow phase and binned-batch timeline counters, so
  the remaining failure is not missing queue consumption. It is the
  incompatible prepass-layout pipeline used inside the shadow-view render pass.

Follow-up: ISS-243 owns the source-level fix. It must restore a
shadow-compatible pipeline specialization path instead of binding a prepass
view group in the shadow pass or ignoring the cached phase pipeline id.

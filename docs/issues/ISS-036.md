# ISS-036: Align Commands spawn and insert APIs with Bundle semantics

## Metadata

- Updated: 2026-06-04

## Description
Bevy code commonly uses `commands.spawn((A, B, C))` and
`entity.insert((D, E))`. Mgstudio currently has a separate app-level
`CommandSpawnComponents` path and a distinct `spawn_bundle` API, which makes
ports change source shape even when the underlying ECS already has `Bundle`.

## Design
Make the command-facing spawn and insert APIs accept the same `@ecs.Bundle`
concept used by `World::spawn_bundle` and `EntityMut::insert`. Remove the
duplicated app-level spawn-components abstraction when it is no longer needed.
Tuple bundle support only needs to be expanded to eight elements; hand-written
impls are acceptable and preferred over introducing code generation solely for
DRY.

## Acceptance Criteria
- [x] `Commands::spawn` can spawn a Bevy-shaped tuple bundle without requiring
      callers to choose a separate `spawn_bundle` spelling.
- [x] `EntityCommands::insert` accepts tuple bundles through the same bundle
      path as direct world/entity insertion.
- [x] Tuple bundle impls cover two through eight elements plus `Unit`, using
      explicit hand-written code if needed.
- [x] Existing examples that only used `spawn_bundle` to work around API shape
      are migrated back to the Bevy-shaped command spelling where practical.
- [x] Relevant ECS/app tests pass with `--release` when native tcc lookup would
      otherwise interfere.

## Notes
- 2026-06-04: This is a local API-shape issue, not an external blocker.
- 2026-06-04: MoonBit does not allow a blanket `Bundle for A` impl over an
  arbitrary component type parameter, and it has no Rust-style unary tuple
  spelling. Single-component command insertion remains explicit through
  `spawn_component` and `insert_component`; normal Bevy tuple bundles should
  use `spawn` and `insert`.

## Close Notes
Closed on 2026-06-04. Removed the app-level `CommandSpawnComponents` trait and
all downstream implementations. `Commands::spawn`, `Commands::spawn_batch`, and
`EntityCommands::insert` now enqueue `@ecs.Bundle` insertion directly; the
`Commands::spawn_bundle` and `EntityCommands::insert_bundle` aliases were
removed and their remaining example/test callers were migrated to `spawn`.
Single-component command insertion remains explicit through `spawn_component`
and `insert_component` because MoonBit cannot express a blanket `Bundle for A`
implementation over arbitrary component type parameters. Verified with
`moon -C mgstudio-engine check --target native`,
`moon -C mgstudio-engine test app --release`, and
`moon -C mgstudio-engine test ecs --release`.

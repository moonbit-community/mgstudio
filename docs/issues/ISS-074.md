## Description
`examples/3d/decal/reference.png` is fully transparent, but a standard 90-frame native capture currently produces only a dark gray frame with no visible decal, floor, cube grid, or lighted scene content.

The mgstudio example also diverges from Bevy's `bevy/examples/3d/decal.rs` source shape. Bevy uses `ForwardDecalMaterial<StandardMaterial>` as a render asset containing both the base `StandardMaterial` and `ForwardDecalMaterialExt`, while mgstudio currently spawns a normal `StandardMaterial` plus separate `ForwardDecal` and `ForwardDecalMaterialExt` components. This may bypass the intended forward-decal material pipeline.

## Design
Audit and port the Bevy decal example and PBR decal material owner source-level shape before refreshing the reference. The MoonBit implementation should preserve Bevy's ownership model as closely as the language allows:

- the decal entity should use a decal material asset equivalent to `ForwardDecalMaterial<StandardMaterial>`,
- the example setup should match Bevy's camera, floor, obstacle grid, material, and light semantics,
- any real MoonBit or dependency limitation should be recorded as a blocker instead of hidden behind a fallback path.

## Acceptance Criteria
- [ ] `examples/3d/decal` renders visible floor, obstacle grid, and decal content.
- [ ] The decal material path is audited against Bevy's `ForwardDecalMaterial<StandardMaterial>` source owner.
- [ ] `examples/3d/decal/reference.png` is refreshed only after the visual output is useful.
- [ ] The refreshed reference is produced by `mgstudio-engine/scripts/p0_visual_capture_native.sh`.

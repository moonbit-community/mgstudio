# ISS-410: Release superseded SSAO GPU resources

## Metadata
- Type: bug
- Status: closed
- Priority: 0
- Labels: render, pbr, ssao, native, memory-leak
- Assignee: unassigned
- Created: 2026-07-12
- Updated: 2026-07-12
- External ref: none

## Description
`prepare_mesh3d_ssao_resources` replaces the full SSAO texture and buffer aggregate when viewport dimensions or thickness change, but never releases the previous aggregate. Repeated resize or interactive thickness changes can retain tens of megabytes of GPU memory per replacement.

## Design
Add an explicit release operation for `GpuSsaoResources`, invoke it before committing a successfully created replacement, and preserve the old aggregate if replacement construction raises.

## Acceptance Criteria
- [x] Every texture, texture view, mip view, and buffer in superseded SSAO resources is released exactly once.
- [x] A failed replacement does not discard the still-valid previous aggregate.
- [x] A native WGPU report regression test proves repeated replacement does not increase user-kept SSAO handles.

## Close Notes
- Added `GpuSsaoResources::release` covering the thickness buffer, all base and mip views, and all four textures.
- SSAO replacement now constructs the next aggregate, swaps it into the backend, and only then releases the previous aggregate.
- Converted the Hilbert LUT upload descriptors to lexical `defer` cleanup.
- Added WGPU GlobalReport coverage for repeated dimension/thickness replacement.

## Description
`examples/3d/decal` has a useful visual/runtime reference after ISS-074, but
it is still not source-shaped against `bevy/examples/3d/decal.rs`.

The current mgstudio example uses a world-style setup function, local asset
helper access, local `AssetServer::new()`, extra camera components, and a
deterministic sine/cosine obstacle rotation formula. Bevy's example uses
`Commands`, `ResMut<Assets<Mesh>>`, `ResMut<Assets<StandardMaterial>>`,
`ResMut<Assets<ForwardDecalMaterial<StandardMaterial>>>`, `Res<AssetServer>`,
`Name` components, `FreeCameraPlugin`, and a seeded `ChaCha8Rng` to generate
obstacle rotations.

This issue tracks source-writing parity only; it should not regress the working
forward decal visual path fixed by ISS-074.

## Design
Port the example setup shape symbol-by-symbol while preserving the verified
forward decal material path. Any missing engine API, such as a Bevy-shaped
`ForwardDecalMaterial<StandardMaterial>` asset parameter or plugin ownership
gap, should be recorded as a blocker only if it cannot be expressed with the
current MoonBit APIs.

## Acceptance Criteria
- [x] `setup` is expressed with Bevy-shaped system parameters rather than a
      world-only setup plus app-world helper calls.
- [x] The example uses the seeded `ChaCha8Rng` obstacle rotation behavior from
      Bevy instead of the local sine/cosine formula.
- [x] Bevy's `Name`, `FreeCameraPlugin`/free-camera ownership, camera
      component set, floor, decal, obstacle grid, and light source-shape
      anchors have explicit MoonBit mappings or documented exclusions.
- [x] The existing useful `reference.png` is preserved or refreshed only after
      the source-shaped path still renders correctly.

## Description
Bevy's `PbrPlugin` installs shader libraries, mesh rendering, materials,
standard material support, SSAO, fog, lightmaps, light probes, GPU preprocess,
volumetric fog, SSR, transmission, decals, contact shadows, medium, atmosphere,
GPU clustering, GLTF integration, deferred lighting, default material state,
embedded PBR resources, render startup systems, extract systems, render systems,
GPU resources, and light view observers.

Mgstudio installs many of these pieces, but the build flow is decomposed
differently and has not been proven source-equivalent in order, ownership, and
resource lifecycle.

## Design
Port `bevy/crates/bevy_pbr/src/lib.rs::PbrPlugin::build` and `finish` as the
source of truth. Keep package splits, but preserve plugin order, render-app
system placement, resource insertion conditions, default material initialization,
light extraction/sync behavior, and observer semantics.

## Acceptance Criteria
- [x] PBR shader library registration matches the Bevy source list, including dummy meshlet visibility resolve behavior.
- [x] Feature plugin installation order matches Bevy where order has semantic impact.
- [x] Default `StandardMaterial` handle initialization follows Bevy behavior.
- [x] Render startup systems for shadow samplers, clusterable object metadata, and fallback bindless resources are installed in the Bevy-shaped phase.
- [x] Light, ambient light, shadow filtering, shadow LOD origin, and material instance extraction systems are installed with Bevy-equivalent ordering.
- [x] Light view entity observers and sync-component targets are represented with source-equivalent behavior.
- [x] `PbrPlugin::finish` initializes global cluster settings from the render world as Bevy does.
- [x] `StandardMaterialPlugin` and generic `MaterialPlugin<M>` install material bind-group allocators in the Bevy-shaped `RenderStartup` phase.
- [x] `MaterialsPlugin` initializes `PendingMeshMaterialQueues` and `PendingShadowQueues` using Bevy's shared render-camera pending queue semantics.
- [x] `MaterialsPlugin` initializes `LightKeyCache` and `SpecializedShadowMaterialPipelineCache` for the Bevy shadow specialization path.
- [x] Device-driven bindless material allocator selection and static `AsBindGroup` bindless descriptors are source-audited or split into a precise blocker.
- [x] `GpuClusteringPlugin::finish` render systems are represented through the real `cluster_on_gpu` dispatch/raster pass path, or a precise local render-pipeline blocker is split out.

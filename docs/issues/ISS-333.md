## Close Notes
Closed 2026-07-06. Bevy source anchors:
`bevy/examples/3d/fog_volumes.rs` `setup` fog-volume spawn and
`bevy/crates/bevy_light/src/volumetric.rs` `FogVolume`.

Field-level mapping:
- Spawn bundle shape: Bevy spawns `(Transform, FogVolume)` for the bunny fog
  volume. Mgstudio `spawn_fog_volume` spawns `(Transform, FogVolume)`. Status:
  complete.
- Density texture: Bevy uses
  `density_texture: Some(asset_server.load("volumes/bunny.ktx2"))`. Mgstudio
  uses `asset_server.load(FOG_VOLUME_DENSITY_TEXTURE)` where
  `FOG_VOLUME_DENSITY_TEXTURE == "volumes/bunny.ktx2"`. Status: complete.
  GPU image decode/readiness remains owned by ISS-335 and ISS-336.
- `density_factor`: Bevy sets `1.0`; mgstudio sets `1.0F` through
  `with_density_factor`. Status: complete.
- `scattering`: Bevy sets `1.0`; mgstudio sets `1.0F` through
  `with_scattering`. Status: complete.
- Other `FogVolume` fields: Bevy uses `..default()`. Mgstudio starts from
  `FogVolume::FogVolume()`. The current Bevy `Default` implementation uses
  `absorption = 0.3`, `scattering = 0.3`, `density_factor = 0.1`,
  `density_texture = None`, `density_texture_offset = Vec3::ZERO`,
  `scattering_asymmetry = 0.5`, `fog_color = Color::WHITE`,
  `light_tint = Color::WHITE`, and `light_intensity = 1.0`; mgstudio defaults
  match those values. Status: complete.
- Material and visibility participation: this example does not author a
  material for the fog volume. Bevy's `FogVolume` component requires
  `Transform` and `Visibility`; mgstudio's example explicitly authors
  `Transform`, and engine-level visibility/default-component behavior is
  outside this authoring-mapping issue. No local approximation was found in the
  example source in this issue's scope.

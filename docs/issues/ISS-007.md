# ISS-007: Split and optimize render execution CPU work

## Description
`mgstudio.render.render` costs about `11.310 ms/frame`. The current spans mix
CPU collection, shadow phase construction, material and pipeline lookup, command
encoding, and possible GPU or presentation waiting.

## Design
First split render execution into source-owned CPU costs and GPU/pass/wait
costs. Then move shadow material pipeline prewarm and specialization work out of
per-item pass execution where the Bevy source model supports that.

## Acceptance Criteria
- [x] Render execution timing separates CPU collection, phase construction, pipeline lookup, command encoding, submission, and present/wait.
- [x] Shadow phase items, main pass draw items, pipeline-cache hits, descriptor registrations, and command counts are reported.
- [x] Shadow material pipeline prewarm is not performed redundantly in the per-item hot loop.
- [x] `execute_3d_collect_meshes` and pass construction costs have individual targets and evidence.
- [x] At `1000` foxes, CPU-owned render execution is reduced below `5 ms/frame` or remaining GPU/wait cost is separately identified.
- [x] Relevant render and PBR tests pass with `--release`.

## Description
`mgstudio.render.render` costs about `11.310 ms/frame`. The current spans mix
CPU collection, shadow phase construction, material and pipeline lookup, command
encoding, and possible GPU or presentation waiting.

## Design
First split render execution into source-owned CPU costs and GPU/pass/wait
costs. Then move shadow material pipeline prewarm and specialization work out of
per-item pass execution where the Bevy source model supports that.

## Acceptance Criteria
- [ ] Render execution timing separates CPU collection, phase construction, pipeline lookup, command encoding, submission, and present/wait.
- [ ] Shadow phase items, main pass draw items, pipeline-cache hits, descriptor registrations, and command counts are reported.
- [ ] Shadow material pipeline prewarm is not performed redundantly in the per-item hot loop.
- [ ] `execute_3d_collect_meshes` and pass construction costs have individual targets and evidence.
- [ ] At `1000` foxes, CPU-owned render execution is reduced below `5 ms/frame` or remaining GPU/wait cost is separately identified.
- [ ] Relevant render and PBR tests pass with `--release`.

## Description
`examples/3d/contact_shadows` is currently a local keyboard-driven rewrite of
Bevy's `bevy/examples/3d/contact_shadows.rs`, not a source-shaped port.

Bevy's owner is centered on radio-button widgets, `WidgetClickEvent` message
flow, an `AppStatus` resource, marker-query updates, a parent `LightContainer`,
pointer observers on the FlightHelmet scene, cursor icon updates, and
`TextUiWriter` radio state updates. Mgstudio instead stores all state in a
global `Ref`, tracks entity IDs manually, changes settings via keyboard
shortcuts, simulates light-type visibility with intensity rewrites, and uses a
`Text2dBundle` help overlay.

## Design
Port the example directly against the Bevy owner and the shared widgets helper.
Do not keep the keyboard/global-state implementation as the parity path. If a
specific ECS/UI/picking feature cannot express Bevy's observer or widget
message shape, record that missing feature as a precise blocker.

## Close Notes
Closed on 2026-06-19. `examples/3d/contact_shadows` now uses Bevy-shaped
`ExampleSetting`, `AppStatus`, `LightContainer`, and `GroundPlane` owners,
shared widget radio buttons, widget click messages, source-shaped camera/light
setup, fixed-speed parent light rotation, and query/command based setting
application. The previous global `Ref` state, keyboard controls, manual entity
tracking, intensity-based light switching, and `Text2dBundle` overlay were
removed.

During visual validation, the example exposed a real render/PBR bug: SSAO used
the view depth texture as a sampled binding while the created depth target only
had render-attachment/copy usage. `render3d` now marks depth textures with
`TEXTURE_BINDING` when a camera has an active
`ScreenSpaceAmbientOcclusion`, preserving the existing volumetric-fog path.

Exact Bevy `MeshPickingPlugin`, `Pointer<Drag>`, `Pointer<DragEnd>`, and
`event.delta` behavior is still blocked by missing picking/input API surface and
is tracked by ISS-133. No keyboard or mouse-polling fallback was kept.

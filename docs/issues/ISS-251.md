## Description
For `scrolling_fog`, Bevy writes per-view directional cascade transforms and
shadow metadata into `GpuDirectionalLight` after shadow view preparation.
Mgstudio must propagate the same current-frame cascade matrices, texel sizes,
far bounds, cascade count, overlap proportion, flags, and
`depth_texture_base_index` into the lights uniform consumed by volumetric fog.

## Design
Compare Bevy `prepare_lights` cascade fill and shadow flag logic against
mgstudio's `render3d_gpu_lights_with_directional_shadow_cascades` and camera
execution path. This issue owns the data transfer from shadow pass output into
the lights uniform, not the texture binding identity already covered by
ISS-246 through ISS-248.

## Acceptance Criteria
- [x] Directional light shadow and volumetric flags match Bevy's conditions for
      `scrolling_fog`.
- [x] `num_cascades`, `cascades_overlap_proportion`, and
      `depth_texture_base_index` match Bevy semantics for one directional light.
- [x] Cascade `clip_from_world`, `texel_size`, and `far_bound` values come from
      the same current-frame shadow cascade data used by the rendered shadow
      views.
- [x] A focused test proves the cascade override updates the same
      `GpuDirectionalLight3d` instance that will be packed by ISS-250's path.

## Notes
- 2026-07-04: Split from ISS-213 so shadow cascade data propagation can be
  verified independently from uniform byte layout and mesh-view binding slots.
- 2026-07-05: Audited Bevy
  `bevy_pbr/src/render/light.rs::prepare_lights`: the first loop initializes
  `GpuDirectionalLight` flags, cascade count, overlap, and
  `depth_texture_base_index`; the second directional-light loop fills
  `GpuDirectionalCascade { clip_from_world, texel_size, far_bound }` from the
  current view's cascade data before the shared `GpuLights` uniform is written.
  Mgstudio's matching single-light path is
  `pbr/render/light.mbt::render3d_gpu_lights_with_directional_shadow_cascades`,
  with flat cascade values produced by
  `pbr/render_execute_camera_directional_shadow.mbt::render3d_directional_shadow_cascade_data`.
  Multi-directional-light shadow view parity remains tracked separately by
  ISS-231.

## Close Notes
Closed after adding and passing the white-box test
`pbr/render light: directional shadow cascade override reaches packed gpu lights`
in `mgstudio-engine/pbr/render/light_wbtest.mbt`. The test constructs a
volumetric directional light, injects two current-frame shadow cascades through
`render3d_gpu_lights_with_directional_shadow_cascades`, and verifies that the
same packed `GpuLights3d` byte layout contains the Bevy-shaped cascade matrices,
texel sizes, far bounds, shadow flag, cascade count, overlap, depth texture base
index, and shadow bias fields.

Validation:

- `moon -C mgstudio-engine test pbr/render --target native --release --filter '*directional shadow cascade override reaches packed gpu lights*'`

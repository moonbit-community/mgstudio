# ISS-495: glTF loader drops KHR_materials_transmission and KHR_materials_volume

## Description

`scene/gltf_loader.mbt` contains no handling for
`KHR_materials_transmission` or `KHR_materials_volume` (grep
"transmission" over the file returns nothing): glTF materials carrying
those extensions build a `StandardMaterial` with
`specular_transmission = 0`, so transmissive surfaces classify as
Opaque and render solid.

Found while closing ISS-482's anisotropy half: the AnisotropyBarnLamp's
"Lamp Glass" material declares
`KHR_materials_transmission` + `KHR_materials_volume`, and pinned Bevy
renders the bulb as clear glass with the filament visible through it,
while mgstudio renders an opaque white-grey bulb. This is the dominant
term in the remaining mean_abs_rgb 3.07 delta against the Bevy frame-90
spot (artifacts under `.private/parity/artifacts/iss482/`:
`aniso_fixed2.png` vs `bevy_anisotropy_f90.png`).

Bevy parses the extensions in `bevy_gltf`'s material loader
(`specular_transmission`, `thickness`, `ior`, `attenuation_*` from the
volume extension; the texture variants sit behind the
`pbr_transmission_textures` cargo feature, mirrored by mgstudio's
`StandardMaterialTextureFeatureSet.pbr_transmission_textures`).
`StandardMaterial` already has the fields and the render path already
supports the Transmissive phase (`standard_material_render_phase_type`
routes `specular_transmission > 0` correctly) — only the loader-side
parse + `with_*` wiring is missing.

## Acceptance Criteria
- [x] The glTF loader parses `KHR_materials_transmission` (factor +
  feature-gated texture) and `KHR_materials_volume` (thickness factor +
  feature-gated texture, attenuation distance/color) into
  `StandardMaterial`, mirroring `bevy_gltf`.
- [x] The anisotropy example's bulb renders transmissive; the frame-90
  capture moves toward the pinned-Bevy spot.

## Fix

Commit `e5e8f2294` (2026-08-06), triggered by the user verdict on the
ISS-482 close-out pair: "The light glass is not transparent."

- `scene/gltf_loader.mbt`: new `gltf_parse_material_transmission`
  (`transmissionFactor` default 0 + `transmissionTexture`) and
  `gltf_parse_material_volume` (`thicknessFactor` default 0,
  `thicknessTexture`, `attenuationDistance` default +inf,
  `attenuationColor` default white), following the existing
  `gltf_parse_material_*` helper pattern and mirroring `bevy_gltf`
  `loader/mod.rs:1330-1399`. Values flow through `GltfMaterialDef` into
  `scene_build_material_component` via
  `with_specular_transmission/with_thickness/with_attenuation_distance/
  with_attenuation_color` plus the two texture loads.
- `material/lib.mbt`: added the missing
  `StandardMaterial::with_attenuation_distance` and
  `::with_attenuation_color` builders (fields and defaults already
  matched Bevy: +inf / white).
- Texture-index parsing is unconditional in the loader (matching the
  loader's existing clearcoat/anisotropy convention); runtime binding
  remains gated by
  `StandardMaterialTextureFeatureSet.pbr_transmission_textures`, the
  runtime mirror of Bevy's cargo feature (ISS-482 mechanism).
- `gltf_parse_specular_color_factor` renamed to
  `gltf_parse_rgb_color_factor` — it now parses both
  `specularColorFactor` and `attenuationColor` RGB triples.
- Regression wbtest: extension payload (factors, textures, attenuation)
  plus absent-extension defaults.

Companion fix in the same commit: ISS-496 (the loader also dropped
`KHR_materials_emissive_strength`, exposed on the same lamp's filament
once the bulb became clear).

## Verification (2026-08-06)

- `moon test --target native scene/gltf_loader_wbtest.mbt`: 35/35.
- Anisotropy frame-90 capture
  (`.private/parity/artifacts/iss495/aniso_transmission2.png`): bulb
  renders as clear glass with the filament visible through it, matching
  the Bevy spot's transmission; empty run log.
- mean_abs_rgb vs the pinned-Bevy spot: 3.07 → 2.82 after the
  transmission fix (2.87 after ISS-496 brightened the filament; the
  small rise is local contrast around the now-glowing filament).
- Remaining visible residual is tonemapping-class, not loader-class:
  our filament peaks at (254, 246, 235) while Bevy's TonyMcMapface
  shoulder tops out at (207, 203, 198), and the shade's anisotropic
  streak is correspondingly thin/clipped on our side vs Bevy's wide
  soft band. Same signature, one cause: SDR response for high HDR
  values diverges (ISS-483 SDR-topology debt; the user's standing
  "except the tonemapping" verdict). Ruled out LUT decode involvement:
  `tony_mc_mapface.ktx2` is vkFormat 123 (E5B9G9R9), untouched by
  ISS-482's RGB8 KTX2 change.
- Gate: atmospheric_fog byte-canon `aaacaca88b53a7e6` (Mountains.gltf
  uses only specular+ior, so material values are unchanged — proven,
  not assumed).

# ISS-025: Move camera and Core2d ownership out of sprite/render2d

## Description
`sprite/render2d.mbt` currently defines camera-adjacent types and behavior such
as `RenderLayers`, `Viewport`, `ClearColor`, `Camera`, `OrthographicProjection`,
`Projection`, `Camera2d`, `Camera2dBundle`, target sizing, viewport scaling,
camera extraction, and 2D camera render ordering. These owners map to Bevy's
`bevy_camera` and `bevy_core_pipeline/src/core_2d`, not to sprite rendering.

Keeping them in sprite render makes camera/core pipeline parity depend on a
sprite package and obscures Bevy's Core2d graph ownership.

## Design
Move camera data and conversion helpers to the camera package and Core2d phase
setup/extraction to `core_pipeline/core_2d`. Preserve public API names only
where they represent Bevy-equivalent authoring surfaces.

## Acceptance Criteria
- [ ] Camera data types and viewport math live under the camera/core pipeline owners instead of `sprite/render2d.mbt`.
- [ ] Core2d phase resources and camera extraction map to `bevy_core_pipeline/src/core_2d/mod.rs`.
- [ ] Sprite render depends on extracted Core2d view data rather than owning camera extraction itself.
- [ ] 2D viewport conversion examples pass after the move.

# ISS-034: Rehome motion blur pipeline ownership from renderer-local lazy state

## Description
`ISS-030` fixed the concrete runtime bug where motion blur skipped because no
settings buffer existed, and the example now captures a nonblank screenshot.
However, the source owner is still not complete. Bevy's
`bevy_post_process/src/motion_blur/{mod.rs,pipeline.rs}` owns
`MotionBlurPlugin`, `MotionBlur`, `MotionBlurUniform`, `MotionBlurPipeline`,
`MotionBlurPipelineKey`, `MotionBlurPipelineId`,
`init_motion_blur_pipeline`, `prepare_motion_blur_pipelines`,
`prepare_view_depth_texture_usages_for_motion_blur`, and the `motion_blur`
render system in render-app schedules.

Mgstudio's `post_process/motion_blur/top.mbt` is only a facade, while
`post_process/motion_blur/pipeline.mbt` owns the public `MotionBlur` component
and helper sample generation. The actual layouts, buffers, pipeline creation,
uniform writes, bind group creation, and draw call live in
`render/renderer/gpu_motion_blur.mbt` as `GpuBackend` lazy state. That is a
working local path, but not source-level owner parity.

## Design
Move motion blur pipeline/resource ownership into the Bevy-shaped post-process
owner and render-app schedule. Renderer APIs should execute prepared render
commands, not own the plugin resource lifecycle or specialize pipelines lazily
as a substitute for `RenderStartup`/`RenderSystems::Prepare`. If MoonBit lacks a
needed render-app resource or specialization abstraction, record the exact
language/engine blocker and avoid adding another fallback.

## Acceptance Criteria
- [ ] `MotionBlurPlugin` installs embedded WGSL, extraction/uniform handling, pipeline resource initialization, prepare systems, depth usage preparation, and Core3d postprocess ordering with explicit Bevy mappings.
- [ ] `MotionBlurPipeline`, `MotionBlurPipelineKey`, and `MotionBlurPipelineId` are represented in the post-process owner rather than hidden in `GpuBackend` fields.
- [ ] Pipeline specialization and bind group layout selection are driven by view target format and MSAA samples in the Bevy-shaped prepare path.
- [ ] Renderer-local motion blur code no longer creates missing pipeline/layout/resource state as a lazy fallback.
- [ ] `examples/3d/motion_blur` still passes the screenshot-exit gate and has a fresh visual parity note after the rehome.

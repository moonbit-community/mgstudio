## Description
`examples/3d/scrolling_fog` is source-shaped at the example layer, but it still
cannot render the Bevy visual result because mgstudio does not yet execute the
Bevy volumetric fog render path. Current code exposes `VolumetricFog`,
`FogVolume`, `VolumetricLight`, shader text, and several render-side helper
structs, but the render pipeline does not consume `FogVolume` as a post-main
volumetric pass. The existing renderer only folds camera `VolumetricFog` into
ordinary distance-fog-like mesh shading.

Bevy's owner is `bevy/crates/bevy_pbr/src/volumetric_fog/{mod.rs,render.rs}`:
`VolumetricFogPlugin` syncs `FogVolume`, extracts `VolumetricFog`/`FogVolume`/
`VolumetricLight`, prepares specialized pipelines, prepares per-view depth
textures, writes `VolumetricFogUniformBuffer`, and runs `volumetric_fog` after
`Core3dSystems::MainPass` and before early postprocess.

## Design
Port the Bevy source owner directly instead of approximating the effect as
distance fog:

- install a Bevy-shaped `VolumetricFogPlugin` render-app owner;
- extract/sync `VolumetricFog`, `FogVolume`, and `VolumetricLight` into render
  state with the same cleanup behavior when no volumetric lights are present;
- prepare `FogAssets` plane/cube meshes and `VolumetricFogPipeline`
  specializations for textureless and 3D-density-textured volumes;
- prepare `ViewVolumetricFog`, `ViewVolumetricFogPipelines`, and
  `VolumetricFogUniformBuffer` from camera/fog-volume transforms;
- prepare depth textures required by the pass before the Core3d depth texture
  owner;
- execute the volumetric fog pass after the main 3D pass and before bloom,
  tonemapping, and other early postprocess stages;
- keep `volumes/fog_noise.ktx2` as the actual density texture for the scrolling
  example.

Do not replace this with a fullscreen overlay, distance-fog color tweak, or
screenshot-only fallback. If a backend primitive is missing, record that as a
new precise blocker with the upstream API requirement.

## Acceptance Criteria
- [ ] `pbr/volumetric_fog` contains the Bevy source-owner systems and data flow,
      not only helper structs.
- [ ] `FogVolume` density texture and density offset affect rendered pixels.
- [ ] Directional lights with `VolumetricLight` and shadow maps produce visible
      light shafts through the volumetric fog pass.
- [ ] `examples/3d/scrolling_fog` capture shows the Bevy-shaped fog/light
      scattering signal instead of only pillar/ground distance fog.
- [ ] Focused PBR volumetric fog tests and the standard scrolling_fog native
      capture pass without validation, missing-resource, unsupported, or fatal
      output.

# ISS-188: Move volumetric fog draw to the explicit post-main boundary

## Description
Mgstudio currently routes volumetric fog through the camera main-pass execution
path. Bevy treats `volumetric_fog` as a separate `Core3d` system after
`MainPass` and before `EarlyPostProcess`. The local execution boundary should
match that shape instead of hiding the pass inside ordinary main-pass code.

## Design
Refactor the mgstudio 3D camera render flow so the main pass finishes its
opaque/alpha/transmissive/transparent work, then invokes an explicit
volumetric fog pass step, then continues into early postprocess work. Preserve
the already prepared render-world state and do not add overlays, fallback draws,
or distance-fog substitutions.

## Acceptance Criteria
- [x] The volumetric fog draw call is owned by an explicit post-main pass
      function or phase, not embedded as ordinary mesh main-pass logic.
- [x] The new boundary consumes the prepared `Render3dVolumetricFogPrepareOutput`
      without recomputing extraction or uniform state.
- [x] Focused tests prove the main pass can be reasoned about separately from
      the volumetric fog pass step.

## Close Notes
Closed on 2026-07-04.

Bevy source owner:
`bevy/crates/bevy_pbr/src/volumetric_fog/mod.rs::VolumetricFogPlugin::build`
installs the volumetric fog system after `Core3dSystems::MainPass` and before
`Core3dSystems::EarlyPostProcess`.

Mgstudio now mirrors that execution boundary in the camera render flow:

- `render3d_execute_camera_main_pass` no longer receives
  `Render3dVolumetricFogPrepareOutput` and no longer calls
  `render3d_draw_volumetric_fog`.
- `render3d_execute_camera` prepares volumetric fog state once, executes the
  main pass, then calls the explicit post-main
  `render3d_execute_camera_volumetric_fog_pass`, then enters early
  postprocess.
- `render3d_execute_camera_volumetric_fog_pass` consumes the already prepared
  output, draws volumetric fog, ends the pass, and emits the existing
  volumetric fog counters.

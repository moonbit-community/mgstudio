## Description
`examples/3d/mixed_lighting/reference.png` can now serve as a nontransparent
visual baseline, but the example is not source-level faithful to Bevy. The
current MoonBit source explicitly states that Bevy's per-mesh `Lightmap`
component pipeline and UI widget radio buttons are not exposed in the current
mgstudio runtime surface, and that the port uses keyboard-driven mode selection
and lighting proxies instead.

Bevy's `examples/3d/mixed_lighting.rs` loads
`models/MixedLightingExample/MixedLightingExample.gltf`, observes
`WorldInstanceReady`, writes `LightingModeChanged`, assigns and removes
`Lightmap` components with per-mesh UV rectangles, mutates material
`lightmap_exposure`, uses `MeshPickingPlugin` and `PointerInteraction` to move
the sphere, and uses the shared widgets/radio-button UI flow. Mgstudio needs
the same source shape or precise blockers for unavailable engine/API pieces.

## Design
Audit and port Bevy `examples/3d/mixed_lighting.rs` as the migration unit:

- preserve `WorldInstanceReady` observer behavior and initial
  `LightingModeChanged` dispatch;
- implement the real per-mesh `Lightmap` component path, including UV rects and
  material exposure;
- preserve the four lighting modes and the exact static/dynamic lightmap
  transitions;
- use Bevy-shaped picking data to move the sphere instead of a proxy movement
  path;
- use the shared widget/radio-button UI flow instead of keyboard-only mode
  selection, unless a precise UI blocker is recorded.

Do not count proxy lighting, keyboard-only mode selection, or missing lightmap
components as source parity.

## Acceptance Criteria
- [ ] Every source-shape anchor in Bevy `examples/3d/mixed_lighting.rs` is
      classified as complete, partial, facade, blocked, or intentionally
      excluded.
- [ ] Lightmaps are represented by real `Lightmap` components with Bevy-shaped
      UV rects and material `lightmap_exposure` behavior.
- [ ] The mode-change flow uses Bevy-shaped messages/observers and preserves
      baked, mixed-direct, mixed-indirect, and real-time semantics.
- [ ] Sphere movement uses Bevy-shaped picking input data or records the exact
      missing picking blocker.
- [ ] The approximation note in `examples/3d/mixed_lighting/main.mbt` is
      removed or replaced by precise blocker references.
- [ ] `examples/3d/mixed_lighting/reference.png` remains visually valid after
      the source parity fix.

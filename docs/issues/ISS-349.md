## Description
Even if the skybox draw path is reached, the `volumetric_fog` reference can
still diverge if cubemap sampling, texture view dimension, exposure/brightness,
or shader composition differs from Bevy. The source skybox texture is an
environment cubemap, so treating it as a loaded generic texture is insufficient
evidence.

Audit the skybox shader and texture sampling path used by this example. This
issue is only a grouping issue; the executable checks are split into smaller
source-owner and runtime-evidence issues.

## Design
Use these child issues as the working sequence:

- ISS-351 audits the Bevy skybox shader and pipeline/bind-layout anchors.
- ISS-352 proves the KTX2/RGB9E5 cubemap decode path and cube texture view.
- ISS-353 proves brightness, exposure, and camera view/projection inputs.
- ISS-354 records runtime evidence and either rules out this path or assigns a
  precise owner for a source-shaped fix.

The fix, if needed, belongs in the skybox/core-pipeline or renderer texture
owner. Do not change the `volumetric_fog` example or its assets to compensate.

## Acceptance Criteria
- [x] ISS-351, ISS-352, ISS-353, and ISS-354 are closed.
- [x] Bevy skybox shader and sampling anchors are mapped to mgstudio symbols.
- [x] The cubemap texture reaches the renderer as a cubemap view with the

- [x] Brightness/exposure and view direction inputs match Bevy or a precise

- [x] If this path is not the root cause, the issue records why it is ruled out.

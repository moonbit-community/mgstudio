## Description

After ISS-462 aligned `many_animated_sprites` with the pinned Bevy source,
comparable native-release runs show a severe performance gap on the same
102,400-sprite, 1920-by-1080, scale-factor-1.0, no-vsync workload.

Mgstudio's final diagnostic window reported `8.0271 FPS` average and a current
frame time of `121.4127 ms`. Pinned Bevy reported `410.3411 FPS` average and a
`2.7629 ms` average frame time. The FPS ratio is `51.12x`.

The state is `CAUSE_UNVERIFIED`. Source alignment rules out the previous
example-shape mismatch, but the measurement does not identify whether the
dominant gap belongs to ECS animation writes, transform/visibility work,
render-world extraction, sprite preparation/queueing, draw submission, or
another boundary.

## Design

Follow trace-first performance diagnosis:

- collect reusable mgstudio schedule/system/render traces after initialization;
- measure the animation, transform propagation, visibility, extraction,
  preparation, queue, and render boundaries separately;
- collect matching pinned-Bevy evidence, using a disposable measurement patch
  only if existing diagnostics cannot expose the required boundary;
- compare work counts as well as time so differences in culling or queued
  sprites cannot masquerade as implementation cost;
- promote a cause only after one boundary explains the measured gap.

Do not restructure the ECS, bypass change detection, disable culling, reduce
the workload, or add a renderer shortcut before the cause is verified.

## Acceptance Criteria

- [ ] A repeatable native-release harness excludes initialization and samples
      the same 102,400-sprite workload in mgstudio and pinned Bevy.
- [ ] Mgstudio evidence separates animation, transform, visibility, extraction,
      preparation, queue, and render costs.
- [ ] Matching Bevy evidence accounts for the same boundaries and work counts.
- [x] At least one evidence-based parity cause explains the severe gap.
- [ ] A focused optimization is validated against performance, animation,
      culling, and visual parity gates.
- [ ] Any remaining gap greater than 4x stays explicitly cause-unverified.

  valid Bevy sample explicitly used `RUST_LOG=info` and `BEVY_ASSET_ROOT`
  pointing at the pinned checkout. A macOS stack sample confirmed that the

  source-aligned 102,400-sprite workload unchanged and separates mgstudio
  schedule-stage, system, render-queue, and render-pass time after excluding
  initialization frames.
- 2026-07-17: Collected the first stable mgstudio stage trace with the existing
  reusable timeline tracer. The native-release run used the source-aligned
  102,400-sprite workload, a 40-frame trace flush interval, and excluded the
  first 10 frame markers. Across 28 steady frames, the mean frame interval was
  `134.470 ms` (`p50 133.971 ms`). `PostUpdate` averaged `85.181 ms` and
  `Update` averaged `32.045 ms`. The largest leaf systems were
  `sprite_calculate_bounds_2d` at `47.595 ms`, the example's
  `animate_sprites` system at `31.921 ms`, `check_visibility_visible_entities`
  at `14.880 ms`, `render3d_update_frusta` at `7.324 ms`,
  `reset_view_visibility` at `5.978 ms`, and
  `visibility_propagate_system` at `2.664 ms`. In contrast, the traced 2D
  render queue, execute, and pass spans averaged `0.081 ms`, `0.288 ms`, and
  `0.257 ms`. The trace and generated breakdown are under
  `/tmp/mgstudio_iss463_stage_trace_20260717d/`. A discarded probe with a
  one-frame flush interval proved that repeatedly serializing the growing JSON
  is an observer effect, so subsequent traces must use a delayed single flush.
  This narrows the next probe to sprite bounds, animation, and visibility but
  does not yet promote an evidence-based parity cause.
- 2026-07-17: Added reusable, trace-disabled-by-default subspans for sprite
  bounds change collection, Mesh2d scanning, Sprite scanning, SpriteMesh
  scanning, and Aabb application, plus changed-entity and pending-Aabb
  counters. The focused native-release `sprite/bounds_wbtest.mbt` run passed
  both tests; existing toolchain warnings remain tracked by ISS-443.
- 2026-07-17: The sprite-bounds subtrace at
  `/tmp/mgstudio_iss463_sprite_bounds_trace_20260717a/` sampled 28 steady
  frames with a `117.638 ms` mean interval. `sprite_calculate_bounds_2d`
  averaged `39.929 ms`: change collection averaged `14.032 ms`, Sprite table
  scanning and Aabb calculation averaged `11.180 ms`, and pending-Aabb
  application averaged `8.665 ms`. The Mesh2d and SpriteMesh scan branches
  were each below `0.001 ms`. Every sampled frame collected exactly `102400`
  changed Sprite-or-Anchor entities and produced `102400` pending Aabbs. These
  three measured phases account for about 84.8 percent of the bounds system.
  Pinned Bevy instead uses direct `Changed<Sprite>`/`Changed<Anchor>` queries
  and mutates the Aabb column in place. This is now a source-backed candidate
  for the bounds gap, but remains cause-unverified until matching Bevy timing
  proves its contribution to the end-to-end gap.
- 2026-07-17: A disposable patch on pinned Bevy `1413bc4e` measured the same
  animation and bounds boundaries, then was fully reverted. With ordinary real
  time, 4,000 post-warmup frames averaged `0.562 ms` in `animate_sprite` and
  `0.106 ms` in `calculate_bounds_2d`, while timers changed an average of
  `2939.161` sprites per frame. A second run fixed Bevy's simulated delta to
  `117 ms`, matching mgstudio's traced workload of exactly `102400` changed
  sprites per frame. Under that equal-workload probe, Bevy averaged `0.828 ms`
  in animation and `0.187 ms` in bounds, versus mgstudio's `28.146 ms` and
  `39.929 ms`: `34.00x` and `213.77x` gaps. Together these two boundaries use
  `68.075 ms` in mgstudio versus `1.015 ms` in Bevy and account for about
  `67.06 ms` of absolute per-frame loss. The bounds slice is now an
  evidence-based parity cause: mgstudio materializes a changed-entity HashSet,
  materializes a pending-Aabb array, and performs entity-keyed reads and
  writes, while Bevy applies its changed filter in the query and mutates the
  bound Aabb column directly with `par_iter_mut`. The animation throughput gap
  is measured but still needs an internal mgstudio breakdown before assigning
  its exact cause. Logs are
  `/tmp/bevy_iss463_bounds_timing_20260717a.log` and
  `/tmp/bevy_iss463_bounds_timing_fixed117ms_20260717a.log`. The overall issue
  remains cause-unverified because visibility and the remaining end-to-end gap
  have not yet received matching Bevy evidence.

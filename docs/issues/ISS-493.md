## Description

Human judgment on the ISS-481 chunk-2 capture: "mirror has no mirror."
The frame-90 capture of `examples/3d/mirror` was missing the example's
defining feature — the fox and ground rendered but the mirror mesh
itself was entirely absent. Both reference vintages were broken the
same way. Clean run log; nothing crashes.

## Root cause (probe-proven 2026-08-07)

Staged probes walked collect → queue → draw:

- The mirror mesh IS extracted with its extended-material metadata
  (`collect total=3 extended=1`) and the mirror-camera render-to-texture
  side is alive (per-frame draws show {fox, plane} x {main view, mirror
  view} = 4 pipelines).
- The mirror never becomes a main-view phase item: the queue candidate
  gate fails at the first guard, `fail=pipeline-id`, every frame — no
  specialized pipeline ever exists for the entity.
- Mechanism: the example spawned the mirror with the legacy untyped
  carrier plus extension metadata
  (`MeshMaterial3d::new(material).with_extended_material(...)`). The
  post-`05a64d8d5` typed material machinery
  (`extract_mesh_materials_system`) feeds `RenderMaterialInstances`,
  `RenderMaterial3dResolvedSlots`, specialization ticks, and therefore
  the `SpecializedMaterialPipelineCache` exclusively from typed
  `MeshMaterial3dTyped` carriers — an untyped-only entity is invisible
  to specialization and queueing. ISS-497 family; pinned Bevy's example
  uses the typed
  `MeshMaterial3d<ExtendedMaterial<StandardMaterial, ScreenSpaceTextureExtension>>`
  registered through `MaterialPlugin` (`examples/3d/mirror.rs:120`).

## Fix

Commit `d2fcd718c` (2026-08-07): ported the example to the typed
extended-material carrier, following the atmosphere example's working
idiom (the Water material):

- `ScreenSpaceTextureMaterial` =
  `ExtendedMaterial[StandardMaterial, ScreenSpaceTextureExtension]`
  with registered asset/material keys and a full
  `StandardMaterialExtension` impl (fragment shader =
  `shaders/screen_space_texture_material.wgsl`, defaults elsewhere).
- `MaterialPlugin[ScreenSpaceTextureMaterial]` added in `main`.
- `spawn_mirror` adds the extended material to its typed `Assets` and
  spawns `MeshMaterial3dTyped::new(material)`.
- The window-resize handler queries the typed carrier and updates the
  extended asset's base emissive texture.

the frame-90 CI config produces a 100% BLACK screenshot on this host —
three runs (two at frame 90, one at frame 150), all zero-content, no
errors in the log, "Test successful". This is a Bevy-side capture
anomaly specific to this example (screenshot machinery + the
render-to-texture mirror camera is the suspect), and it likely explains
why the ISS-481 sweep never had a Bevy anchor for the mirror row. The
acceptance judgment therefore rests on the human eyeball of the

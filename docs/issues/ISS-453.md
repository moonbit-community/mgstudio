# ISS-453: Move query lease checks out of row items

## Description

Mutable row items carry `World`, entity identity, key, table id, row index, and
local component id to emulate borrow safety without MoonBit ownership. Test a
query/table-scoped lease and validity boundary so row iteration does not repeat
the full lifecycle context.

## Acceptance Criteria

- [x] Use-after-scope, world close, structural invalidation, and nested-query
      behavior have focused regression coverage.
- [x] The optimized row representation does not retain `World` solely for a
      check already guaranteed by the active query/table scope.
- [x] One focused lifecycle test runs at a time with
      `MOONBIT_NEW_NATIVE=1`.
- [x] `examples/stress_tests/many_buttons` is the only runtime example gate.
- [x] The retained/rejected decision follows the `ISS-444` experiment protocol.

## Notes

- 2026-07-16: The pinned Bevy baseline initializes query fetch state from one
  borrowed `UnsafeWorldCell`, binds `D::Fetch` and `F::Fetch` once per table,
  and performs row fetches without revalidating the world lifetime
  (`bevy/crates/bevy_ecs/src/query/iter.rs`, `fold_over_table_range`). The
  MoonBit experiment therefore keeps public iterator calls lease-checked while
  testing one validated `Query::view` scope for its internal row loop; it does
  not cache a `World` in an iterator that can escape that scope.
- 2026-07-16: The pre-change `query mut for_each cached x20000` benchmark was
  `1.66 ms` and `1.67 ms` (mean `1.665 ms`). Two untraced
  `stress_tests/many_buttons` runs were `8.427 ms` and `8.467 ms` per frame
  (mean `8.447 ms`).
- 2026-07-16: A trace flushed every frame is not a valid frame-time gate for
  this example: trace serialization grew with the output and inflated `Main`
  to a `1051.558 ms` mean. The trace is useful only for attribution; it placed
  the example's `button_system` at a `0.026 ms` median on mostly unchanged
  frames. Retention will use the isolated query benchmark plus untraced frame
  time.
- 2026-07-16: The prototype validated the World once at `Query::view` entry
  and passed that World through the private dense and general row loops. Public
  `QueryMany::fetch_next` remained lease-checked so an escaped system query
  could not bypass its invocation scope. Four lifecycle tests passed one at a
  time: invalidated lease, World close during a view, structural cursor
  invalidation, and nested read-only views.
- 2026-07-16: The post-change mutable `for_each` benchmark was `1.66 ms` and
  `1.64 ms` (mean `1.650 ms`), only `0.90%` faster than the `1.665 ms`
  baseline. `many_buttons` was `8.514 ms` and `8.486 ms` per frame (mean
  `8.500 ms`), a `0.63%` regression from `8.447 ms`. The lease-scope
  optimization was therefore reverted under the ISS-444 retention rule.
- 2026-07-16: The experiment exposed independent lifecycle bugs rather than a
  material hot-path cost. ISS-459 separately retained structural-generation
  validation at the public cursor boundary and a World-close guard without
  adding checks to the internal `Query::view` row loop.

## Close Notes

Closed on 2026-07-16 as a rejected performance hypothesis. Moving lease checks
to the active view scope improved the isolated target by only `0.90%` and
regressed the only runtime gate by `0.63%`, so all scope-hoisting production
changes were removed. The focused lifecycle coverage and the two correctness
repairs discovered by the experiment were retained separately in ISS-459.

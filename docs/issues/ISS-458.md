## Description

The `examples/2d/sprite_slice` validation example rendered every text label but
no sprite textures when this issue was opened. This included the Original and
Stretched cases, which do not depend on `ComputedTextureSlices`, so the failure
was outside the changed-sprite slice query being evaluated by `ISS-456`.

Before the camera repair, native fixed-frame captures at both frame 90 and
frame 600 were byte-identical with SHA-256
`8981b5ccb1d2b478a5f88dcc815bae99b5f497f1df17c7c15f82343c43ddebd4`.
The actual owner was the stale Camera2d frustum repaired by `e908fa6fb`. The
sprite assets and extraction path were intact, but visibility rejected the
sprite entities before rendering. A fresh capture from the repaired branch
contains every expected texture and is pixel-identical to the checked-in
reference.

## Design

Retain the Bevy-shaped camera repair from `e908fa6fb`: derive Camera2d target
information from main-world Window/Image data, update the 2D frustum after
camera and transform updates, and run visibility checks after that frustum
stage. Do not add asset-readiness bypasses, sprite extraction exceptions, or a
slice-specific visibility workaround.

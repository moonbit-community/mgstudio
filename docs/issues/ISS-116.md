## Description
`examples/3d/clearcoat` renders a recognizable clearcoat material scene, but it
is not a symbol-level port of Bevy's `bevy/examples/3d/clearcoat.rs`.

The current implementation keeps many numeric material, lighting, camera,
skybox, and environment-map values, but replaces Bevy's source structure with a
global `ClearcoatState`, integer light-mode constants, tracked entity arrays,
world-space text, direct world mutation, and a local UV-sphere generator.

## Design
Port the example directly from the Bevy source owner. Keep only local changes
that are required by concrete MoonBit language/API limitations, and record each
such limitation as a precise blocker. Do not keep global state, helper arrays,
or direct world mutation as the parity path when Bevy has a resource, marker
component, command, query, or UI owner.

## Acceptance Criteria
- [x] `LightMode` is represented as a Bevy-shaped resource enum with `Point`
      default and `Directional` variant.
- [x] `ExampleSphere` is represented as a marker component, and sphere rotation
      uses a marker query instead of tracked entity arrays.
- [x] `main` preserves Bevy's resource initialization and update schedule,
      including the chained `(handle_input, update_help_text)` ordering.
- [x] `setup` exposes Bevy-shaped commands, mesh assets, material assets, asset
      server, and light-mode parameters where the ECS API can express them.
- [x] `create_sphere_mesh` preserves the `Sphere::new(1.0).mesh().build()` and
      `generate_tangents().expect(...)` anchors or records a precise
      mesh-builder/tangent blocker.
- [x] Normal-map textures for blue-noise and scratched-gold materials are
      loaded with the Bevy `is_srgb = false` semantics.
- [x] The four spawn helper functions preserve Bevy's helper boundaries,
      material fields, transforms, and marker insertion.
- [x] The golf-ball scene uses `WorldAssetRoot` semantics or records a precise
      scene-root blocker.
- [x] Help text uses UI `Text` plus absolute `Node`, and `update_help_text`
      mutates `Text` through a Bevy-shaped query.
- [x] `handle_input` uses Bevy-shaped `Commands`, light query, and mutable
      `LightMode` resource semantics.
- [x] Light animation and sphere animation use Bevy-shaped queries rather than
      global tracked entity handles.
- [x] `ClearcoatState`, integer light-mode constants, stored `TextHandle`, and
      tracked entity arrays are removed from the source-parity path unless
      precise blockers are documented.
- [x] The reference screenshot is refreshed after the source-shaped port still
      renders correctly.

## Description
`examples/3d/transmission` has broad runtime behavior coverage, but it is not a
symbol-level port of Bevy's `bevy/examples/3d/transmission.rs`.

The visible scene and many keyboard controls are represented. The strict gaps
are source-shape issues: Bevy's `ExampleControls` component/query, `Flicker`
marker queries, `Local<ExampleState>`, `ResMut<Assets<StandardMaterial>>`
mutation path, source mesh builders, UI `Text` plus `Node`, camera `Single`
mutation, and command-based component toggles are replaced by a global
`TransmissionState`, material handle arrays, tracked entity handles, local mesh
builders, direct world replacement, and a world-space text overlay.

## Design
Port the example directly from the Bevy owner. Keep only behavior that follows
Bevy's symbols. If exact source shape is blocked by a concrete ECS, mesh, or
asset capability gap, record that gap precisely; do not keep helper arrays or
global state as the parity path.

## Acceptance Criteria
- [ ] `main` preserves the Bevy resource insertion, startup system, and update
      system shape.
- [ ] `setup` exposes Bevy-shaped commands, mesh assets, material assets, and
      asset server parameters where the ECS API can express them.
- [ ] Mesh generation preserves the `Sphere::new(...).mesh().ico(7)` and
      `Cylinder::new(...).mesh().resolution(50)` anchors or records a precise
      mesh-builder blocker.
- [ ] Scene entities use `ExampleControls` and `Flicker` components instead of
      material handle arrays and tracked entity fields.
- [ ] Material control updates flow through the `ExampleControls` query and
      mutable `Assets<StandardMaterial>` path.
- [ ] `ExampleState` is represented as Bevy-shaped local system state rather
      than a global resource-like struct.
- [ ] Camera controls and transmission/HDR/depth/TAA toggles use Bevy-shaped
      `Single` query and `Commands` mutation semantics.
- [ ] Control text uses UI `Text` plus absolute `Node` and `ExampleDisplay`,
      preserving Bevy's formatting and cfg-specific status strings.
- [ ] `flicker_system` uses Bevy-shaped marker queries and in-place transform
      and point-light mutation.
- [ ] Local LCG color randomization, custom mesh builders, global
      `TransmissionState`, and world-space text overlay are removed from the
      parity path unless precise blockers are documented.
- [ ] The reference screenshot is refreshed after the source-shaped port still
      renders correctly.

## Notes
- 2026-06-16: Created from the ISS-105 symbol audit. This is local
  source-parity work; the current helper-array/global-state implementation is
  not an external blocker.
- 2026-06-19: Runtime blocker fixed for the current transmission path. The
  frame-view bind group validation failure was caused by depth prepass textures
  being sampled in the mesh view layout without `TEXTURE_BINDING`; Bevy's
  `prepare_core_3d_prepass_textures` creates depth, normal, and motion-vector
  prepass textures with sampled usage. Mgstudio now forces
  `TEXTURE_BINDING` into `create_depth_prepass_target`, and
  `examples/3d/transmission` captures cleanly at frame 90. The issue remains
  open because source-shape and final visual parity are still incomplete.

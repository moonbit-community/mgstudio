## Description
`examples/3d/transmission` has broad runtime behavior coverage, but it is not a
symbol-level port of Bevy's `bevy/examples/3d/transmission.rs`.

The visible scene and many keyboard controls are represented. The strict gaps
are source-shape issues: Bevy's `Local<ExampleState>`, `Commands`,
`Single<... With<Camera3d>>`, UI `Text` plus `Node`, and command-based component
toggles are still represented by a global `TransmissionState`, direct world
replacement, and a world-space text overlay.

## Design
Port the example directly from the Bevy owner. Keep only behavior that follows
Bevy's symbols. If exact source shape is blocked by a concrete ECS, mesh, or
asset capability gap, record that gap precisely; do not keep helper arrays or
global state as the parity path.

## Acceptance Criteria
- [ ] `main` preserves the Bevy resource insertion, startup system, and update
      system shape.
- [ ] `setup` exposes Bevy-shaped commands, mesh assets, material assets, and
      asset server parameters where the ECS API can express them.
- [x] Mesh generation preserves the `Sphere::new(...).mesh().ico(7)` and
      `Cylinder::new(...).mesh().resolution(50)` anchors or records a precise
      mesh-builder blocker.
- [x] Scene entities use `ExampleControls` and `Flicker` components instead of
      material handle arrays and tracked entity fields.
- [x] Material control updates flow through the `ExampleControls` query and
      mutable `Assets<StandardMaterial>` path.
- [ ] `ExampleState` is represented as Bevy-shaped local system state rather
      than a global resource-like struct.
- [x] Camera controls and transmission/HDR/depth/TAA toggles use Bevy-shaped
      `Single` query and `Commands` mutation semantics.
- [ ] Control text uses UI `Text` plus absolute `Node` and `ExampleDisplay`,
      preserving Bevy's formatting and cfg-specific status strings.
- [x] `flicker_system` uses Bevy-shaped marker queries and in-place transform
      and point-light mutation.
- [ ] Local LCG color randomization, custom mesh builders, global
      `TransmissionState`, and world-space text overlay are removed from the
      parity path unless precise blockers are documented.
- [x] The reference screenshot is refreshed after the source-shaped port still
      renders correctly.

## Notes
- 2026-06-16: Created from the ISS-105 symbol audit. This is local
  source-parity work; the current helper-array/global-state implementation is
  not an external blocker.
- 2026-06-19: Runtime blocker fixed for the current transmission path. The
  frame-view bind group validation failure was caused by depth prepass textures
  being sampled in the mesh view layout without `TEXTURE_BINDING`; Bevy's
  `prepare_core_3d_prepass_textures` creates depth, normal, and motion-vector
  prepass textures with sampled usage. Mgstudio now forces
  `TEXTURE_BINDING` into `create_depth_prepass_target`, and
  `examples/3d/transmission` captures cleanly at frame 90. The issue remains
  open because source-shape and final visual parity are still incomplete.
- 2026-06-19: Restored Bevy-shaped transmission mesh anchors for the sphere and
  candle: `SphereMeshBuilder::new(0.9, SphereKind::ico(7)).ico(7)` and
  `CylinderMeshBuilder::from_cylinder(Cylinder::new(0.5, 2.0)).resolution(50)`.
  This removed the example-local sphere/cylinder generators, restored generated
  normals, and fixed the black transmissive-sphere capture. The reference
  screenshot now uses the successful frame-90 capture. The issue remains open
  for ECS/source-shape gaps around global state, query ownership, commands,
  and UI text.
- 2026-06-19: Reworked `flicker_system` to use `Flicker` marker queries with
  `With<Mesh3d>` and `Without<Mesh3d>` filters, matching Bevy's split flame
  mesh and point-light query shape. Removed the flame mesh/light tracked entity
  fields from `TransmissionState`; the frame-90 capture still renders
  correctly.
- 2026-06-19: Removed the tracked camera entity from `TransmissionState`.
  Camera helpers now resolve the active camera through a `Camera3d` single
  query before reading or mutating `ScreenSpaceTransmission`, HDR, depth
  prepass, TAA, and transform state. The frame-90 capture still renders
  correctly. Remaining local gaps are `Commands`-based toggles, `Local`
  example state, and UI `Text`/`Node` ownership.
- 2026-06-19: Reworked `example_control_system` into a Bevy-shaped parameter
  system using `Commands`, `ResMut<Assets<StandardMaterial>>`, the
  `ExampleControls` query, a `Camera3d` single query with optional/has camera
  state, and `Time`. Material mutation now flows through the query plus mutable
  assets path, screen-space transmission and camera transform mutate through
  `Write` query items, and HDR/depth/TAA toggles use deferred
  `EntityCommands`. The frame-90 capture still renders correctly.

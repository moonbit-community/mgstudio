## Description
Several ECS, state, and time examples failed screenshot capture. Many are
console or schedule-behavior examples rather than visual examples, but each
failure needs explicit classification.

Failed packages:

- `examples/ecs/change_detection`
- `examples/ecs/custom_query_param`
- `examples/ecs/custom_schedule`
- `examples/ecs/ecs_guide`

- `examples/ecs/nondeterministic_system_order`
- `examples/ecs/one_shot_systems`
- `examples/ecs/relationships`
- `examples/ecs/send_and_receive_messages`
- `examples/ecs/startup_system`
- `examples/ecs/system_closure`
- `examples/ecs/system_param`

- `examples/ecs/system_stepping`
- `examples/ecs_json_move`
- `examples/state/computed_states`
- `examples/state/custom_transitions`
- `examples/state/states`
- `examples/state/sub_states`
- `examples/time/time`

## Design
Read each package and classify whether it is a visual example, a console/ECS
behavior example, or a broken visual capture. Do not add fake rendering just to
make console examples screenshotable. If a package is non-visual, document the
right non-screenshot validation path.

## Acceptance Criteria
- [x] Every listed package has a classification.
- [x] Non-visual examples are excluded from screenshot capture with a precise reason.
- [x] Visual examples produce `reference.png`.
- [x] Any ECS or state runtime bug discovered during triage is split into a follow-up issue or fixed before closure.

## Description
The roadmap still marks render/PBR visual parity as poor even though many
individual descriptors, shaders, and examples are present. Source-level parity
cannot be accepted from a plausible-looking single example; render and PBR need
representative gates that compare Bevy and mgstudio output.

## Design
Choose a compact set of examples covering 2D render, ordinary 3D PBR, shadows,
motion vectors/motion blur, prepass/deferred, transmission, lightmaps/probes,
postprocess, and meshlet where not externally blocked. Use Bevy source examples
as the expected behavior and record any dependency blocker separately.

## Acceptance Criteria
- [ ] A render/PBR visual gate list is documented with the Bevy example, mgstudio example, command, capture path, and acceptance owner for each gate.
- [ ] At least one gate covers each of: main PBR pass, shadow pass, prepass/deferred, motion vectors, transmission, lightmaps or probes, postprocess, and meshlet or its explicit blocker.
- [ ] Gates are not all based on `3d_shapes`; choose examples that expose the specific systems under audit.
- [ ] Captures distinguish build success, runtime behavior, visual parity, and performance.
- [ ] Any failed gate links to a specific issue rather than being left as a general visual mismatch.

# ISS-459: Reject query cursors invalidated by World lifecycle changes

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: ecs, lifecycle, query, borrow-safety
- Assignee: codex
- Created: 2026-07-16
- Updated: 2026-07-16
- External ref: none

## Description

MoonBit query cursors can escape the lexical call that created them. Before
this fix, a `QueryMany` cursor could retain table entities and a bound typed
column fetch across a structural World change, and `World::close` could run
inside an active `Query::view`. Both operations invalidate the same table and
World assumptions that Bevy protects with the lifetime of its borrowed
`UnsafeWorldCell`.

## Design

- Snapshot `World::structural_generation` when constructing `QueryMany`.
- Validate that generation once per public `QueryMany::fetch_next` call.
- Keep `Query::view`'s internal row loop unchanged; active query iteration
  already rejects structural mutation there.
- Reject `World::close` while a query view is active, just as existing spawn,
  insert, remove, and despawn guards reject invalidating structural changes.
- Preserve nested read-only query views through the existing counted query
  iteration state.

## Acceptance Criteria

- [x] An iterator with an invalidated World lease cannot fetch another row.
- [x] `World::close` is rejected during an active query view.
- [x] An escaped iterator is rejected after a structural generation change.
- [x] Nested read-only query views remain valid.
- [x] Each lifecycle regression test passes separately with
      `MOONBIT_NEW_NATIVE=1`.

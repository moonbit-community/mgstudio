## Description
The all-runnable-example screenshot batch completed with 381 successful
`reference.png` captures and 53 failures. Every failed package returned through
the capture harness without producing `MGSTUDIO_PARITY_CAPTURE_RGBA8_BLOB`.

These failures must be triaged before they are treated as engine regressions.
Some packages are expected to be screenshot-ineligible because they are
headless, audio-only, logging-only, or console/ECS examples. Other packages are
visual examples and should either produce a stable screenshot or have an
explicitly documented alternative validation gate.

## Design
Use the batch artifacts under
`.private/example_screenshots/20260605_193912/` as the starting evidence. For
each child issue, inspect the package source and run log, then classify each
package as one of:

- visual example that should produce `reference.png`;
- non-visual example that should be excluded from screenshot capture;
- interactive example that needs a deterministic capture setup;
- broken example or broken capture integration.

Do not paper over missing screenshots by adding fallback images. Update the
example gate, exclusion list, or runtime path according to the true package
behavior.

## Acceptance Criteria
- [ ] Every failed package from the batch is represented in exactly one child issue.
- [ ] Each failed package is classified as screenshot-required, screenshot-excluded, interactive-needs-fixture, or broken.
- [ ] Screenshot-required packages save a valid `reference.png` in the example source directory.
- [ ] Screenshot-excluded packages are documented in the capture policy or tracker with a precise reason.
- [ ] The capture manifest and failure list can be regenerated without losing these classifications.

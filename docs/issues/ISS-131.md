# ISS-131: Restore Bevy-shaped default UI overlay ownership for 3D examples

## Description
Several 3D examples with Bevy UI overlays cannot currently express the exact
Bevy source shape in mgstudio.

In Bevy, examples such as `examples/3d/shadow_biases.rs` can spawn UI as a
`Node`/`Text`/`TextSpan` hierarchy under `DefaultPlugins` without explicitly
creating a separate 2D overlay camera, `UiRoot`, or `UiTargetCamera`.

In mgstudio today, visible 3D UI overlays generally require explicit
`Camera2d`, `IsDefaultUiCamera`, `UiRoot`, and `UiTargetCamera` scaffolding.
That scaffolding is not equivalent to Bevy's source owner shape, even when the
UI widget/text hierarchy itself is otherwise source-shaped.

This is a local engine/UI architecture parity gap, not an external dependency
blocker.

## Design
Audit Bevy's current UI camera/root ownership path and mgstudio's UI render
entry points, then move the default UI overlay ownership into engine/plugin
infrastructure rather than requiring every 3D example to spell it out.

The desired outcome is that a Bevy-shaped example can spawn the UI
`Node`/`Text`/`TextSpan` tree directly and still render through the appropriate
camera target without local overlay-camera scaffolding.

## Acceptance Criteria
- [x] The Bevy source owner for default UI camera/root behavior is identified
      and documented in this issue.
- [x] Mgstudio has a default UI overlay path that works for 3D examples under
      `DefaultPlugins`.
- [x] Examples no longer need local `Camera2d` + `IsDefaultUiCamera` + `UiRoot`
      + `UiTargetCamera` scaffolding solely to make ordinary Bevy UI visible.
- [x] `examples/3d/shadow_biases` can remove its explicit UI overlay scaffolding
      while keeping the UI visible.
- [x] At least one additional existing 3D UI example is simplified through the
      same engine path.
- [x] Native visual captures confirm UI overlays remain visible after removing
      the local scaffolding.

## Notes
- 2026-06-18: Created while repairing `examples/3d/shadow_biases`. The example
  now uses `Text`/`TextSpan` and `TextUiWriter`, but still needs explicit UI
  camera/root scaffolding for visibility in mgstudio.
- 2026-06-18: Bevy source owner audit:
  `bevy/crates/bevy_ui/src/ui_node.rs` defines `UiTargetCamera`,
  `IsDefaultUiCamera`, and default UI camera selection; `bevy/crates/bevy_ui/src/update.rs`
  propagates `ComputedUiTargetCamera` and render target info through root UI
  nodes; `bevy/crates/bevy_ui/src/experimental/ghost_hierarchy.rs` treats
  unparented `Node` entities as UI roots; and
  `bevy/crates/bevy_ui_render/src/lib.rs::extract_ui_camera_view` creates a UI
  camera view for both `Camera2d` and `Camera3d`.
- 2026-06-18: Mgstudio already had Bevy-shaped root/default camera propagation
  in `ui` and extraction into `ui_render/runtime`; the missing local owner was
  the 3D render consumer. Added `ui_render.draw_extracted_ui_overlay_for_camera`
  so PBR camera execution can draw the extracted UI overlay for a `Camera3d`
  target after postprocessing.

## Close Notes
Closed 2026-06-18. `mgstudio-engine/ui_render/overlay_draw.mbt` now owns the
draw phase for extracted UI nodes targeted at a camera, and
`mgstudio-engine/pbr/render_execute_camera.mbt` calls it for every 3D camera
after postprocess/present. `examples/3d/shadow_biases` no longer spawns a
local `Camera2d`, `IsDefaultUiCamera`, `UiRoot`, or `UiTargetCamera`; its UI
panel is an unparented `Node` like the Bevy source shape. Verified with
`moon -C mgstudio-engine check --target native`, `moon -C mgstudio-engine fmt`,
`moon -C mgstudio-engine info`, and native reference captures for
`examples/3d/color_grading` and `examples/3d/shadow_biases`.

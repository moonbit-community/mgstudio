## Description
The current report shows `winit/lib.mbt:105` at about `3.364 ms/frame`, but the
name is too broad to assign the cost to windowing, redraw dispatch, app update,
or nested render work.

## Design
Clean up span naming and event-loop attribution so this cost can be assigned
accurately. This issue is diagnostic and should not change event-loop semantics.

## Acceptance Criteria
- [x] Redraw handling is split into event dispatch, app tick, render trigger, and platform wait spans where possible.
- [x] The broad `winit/lib.mbt:105` label no longer appears as an unowned top-level hotspot in the report.
- [x] The report states whether the remaining cost belongs to windowing, ECS update, render execution, or platform waiting.
- [x] No input responsiveness or window event behavior regresses.

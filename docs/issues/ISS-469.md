# ISS-469: Retain zero-column table entity rows

## Metadata
- Type: bug
- Status: closed
- Priority: 0

- Assignee: codex
- Created: 2026-07-18
- Updated: 2026-07-18
- External ref: none

## Description

Dense query planning includes table 0 for component-free archetypes, but
mgstudio does not create or populate `RawTable` storage when a table has zero
component columns. `Query::for_each_table` and
`Query::try_for_each_filtered_table` enumerate entities through
`World::table_entities_view`, so they silently skip live `spawn_empty()`
entities. This breaks legal dense query data such as `Entity` and `Has[T]`;
the filtered API can return `true` to report that its batch path was available
without visiting any of the live rows.

## Design

Match pinned Bevy's table ownership invariant: every table, including the
empty table, owns an entity row vector independently of whether it owns any
component columns. Create table 0 during World initialization and always move
entities into a non-negative target table during archetype migration. Do not
add table-batch-only fallback enumeration or reconstruct a table by merging
archetype arrays.

## Acceptance Criteria

- [x] `Query[Entity, All]::for_each_table` visits `spawn_empty()` entities.
- [x] `Query[Has[T], All]::for_each_table` visits both absent and present table
      rows with correct presence values.
- [x] `try_for_each_filtered_table` visits table-0 rows instead of reporting a
      silent empty success.
- [x] Empty-table rows remain correct across table migration, despawn, and
      swap-remove.
- [x] Focused tests run one at a time with `MOONBIT_NEW_NATIVE=1`, and the ECS
      public interface remains unchanged.

## Notes

- 2026-07-18: Pinned Bevy initializes `Tables` with a real empty `Table` at
  table ID 0. Mgstudio registers the empty table signature and archetype
  mapping but leaves `World.tables` empty and suppresses target-row creation
  when the target has zero component columns.
- 2026-07-18: Before the fix, `Entity` batch traversal returned zero of two
  empty entities, `Has[T]` returned `(None, Some(true), 1)` instead of the
  absent row plus present row, and filtered traversal returned
  `(used_batch=true, seen=false, count=0)`.

## Close Notes

Closed on 2026-07-18. `World::new` now materializes table 0, and archetype
migration appends an entity row for every non-negative target table regardless
of component-column count. Empty entities therefore have canonical table-0
locations and use the same append, migration, swap-remove, and despawn paths as
all other table entities. The table-batch loops and query-cache semantics were
not special-cased.

Five focused table-batch regressions separately verified `Entity`, `Has[T]`,
filtered traversal, component-table round trips, and empty-table despawn. Four
existing structural regressions verified typed-row migration, table-column
lengths, entity ID reuse, and ordinary dense batch writes; the component
membership despawn regression also remained green. Every test invocation
selected one test and used `MOONBIT_NEW_NATIVE=1`. `moon check ecs --target
native --deny-warn` completed cleanly, `moon info ecs --target native` produced
no generated interface diff, and `git diff --check` passed.

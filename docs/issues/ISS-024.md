## Description
The repository already contains Bevy-shaped `mgstudio-engine/sprite_render/*`
paths, but many of them are facades over the old `sprite` render2d owner rather
than real implementations. For example, `sprite_render/lib.mbt` declares the
Bevy source `bevy_sprite_render/src/lib.rs` but delegates plugin installation to
`@sprite.render2d_plugin`; `sprite_render/render/top.mbt` exposes render2d
APIs from the root sprite-render facade; `sprite_render/mesh2d/*.mbt` mostly
re-export types that are still backed by the monolithic implementation.

This makes the directory layout look Bevy-shaped while the runtime owner is
still not Bevy-shaped.

## Design
Move implementation code into the Bevy-shaped `sprite_render` packages and
delete facade-only forwarding once callers have been updated. Keep re-exports
only where Bevy has a comparable public prelude/export surface.

## Acceptance Criteria
- [x] `sprite_render/lib.mbt` owns the SpriteRenderPlugin build flow instead of delegating to `@sprite.render2d_plugin`.
- [x] `sprite_render/render/top.mbt` owns sprite extraction, queueing, batching, and draw setup corresponding to `bevy_sprite_render/src/render/mod.rs`.
- [x] `sprite_render/mesh2d/*` owns mesh2d material, mesh, color material, and wireframe behavior corresponding to Bevy's `mesh2d` files.
- [x] Facade-only wrappers are removed or reduced to Bevy-equivalent public re-exports.
- [x] Existing examples import and use the Bevy-shaped owner packages directly.

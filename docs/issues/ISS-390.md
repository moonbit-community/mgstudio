## Description
Map the Bevy source anchors that decide which color and depth resources the
volumetric fog pass reads or writes, and how that output is handed to later
postprocess stages.

## Design
Read the Bevy volumetric fog pass owner and relevant core pipeline target
owners. Record the paths and symbols for `ViewTarget`, depth texture use,
render-pass color attachment load/store state, MSAA or resolve behavior, and
postprocess write or read handoff. Do not prove runtime values here; ISS-382
uses this map for field evidence.

## Acceptance Criteria
- [x] Bevy color-target ownership anchors are listed with paths and symbols.
- [x] Bevy depth texture sampling and depth attachment anchors are listed with
      paths and symbols.
- [x] Bevy load/store, MSAA, resolve, and postprocess handoff anchors are
      listed or explicitly marked absent.
- [x] No production behavior is changed.

## Close Notes
Closed on 2026-07-05 with Bevy-only target and postprocess handoff mapping. No
production behavior was changed.

Color target ownership anchors:

- `bevy/crates/bevy_render/src/view/mod.rs:696`: `ViewTarget` owns
  `main_textures`, `main_texture_format`, the shared `main_texture` selector,
  optional `out_texture`, and `compositing_space`.
- `bevy/crates/bevy_render/src/view/mod.rs:824`: `ViewTarget::get_color_attachment`
  selects the current `main_textures.a` or `main_textures.b` color attachment.
  This is used by the main opaque/transparent passes, not by volumetric fog's
  own render pass.
- `bevy/crates/bevy_render/src/view/mod.rs:866`: `ViewTarget::main_texture_view`
  returns the current unsampled main texture view.
- `bevy/crates/bevy_render/src/view/mod.rs:906`: `ViewTarget::main_texture_format`
  records the internal main texture format; the comment documents HDR screen
  targets as `Rgba16Float` and render-to-texture targets as the target texture
  format.
- `bevy/crates/bevy_render/src/view/mod.rs:1259`: `prepare_view_targets`
  creates two single-sample main textures `a` and `b` with `sample_count: 1`.
- `bevy/crates/bevy_render/src/view/mod.rs:1288`: when `Msaa::samples() > 1`,
  Bevy additionally creates a multisampled `main_texture_sampled` render
  attachment used as the resolve source for main-pass color writes.
- `bevy/crates/bevy_render/src/view/mod.rs:1322`: both `main_textures.a` and
  `main_textures.b` are `ColorAttachment::new(..., sampled.clone(), ...)`, so
  main-pass calls to `get_color_attachment` may resolve from
  `main_texture_sampled` into the selected single-sample main texture.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs:393`: the volumetric fog
  pass does not call `ViewTarget::get_color_attachment`; it constructs its own
  `RenderPassColorAttachment`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs:394`: volumetric fog writes
  directly to `view_target.main_texture_view()`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs:523`: the specialized
  pipeline color target uses `key.target_format`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs:571`: the pipeline key
  obtains `target_format` from `ExtractedView::target_format`.

Depth texture and depth attachment anchors:

- `bevy/crates/bevy_render/src/view/mod.rs:976`: `ViewDepthTexture` owns a depth
  `Texture` plus a `DepthAttachment`.
- `bevy/crates/bevy_render/src/view/mod.rs:989`: `ViewDepthTexture::get_attachment`
  creates a depth-stencil attachment for passes that write depth.
- `bevy/crates/bevy_render/src/view/mod.rs:993`: `ViewDepthTexture::view` returns
  the sampled depth texture view.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs:284`: `volumetric_fog`
  queries `&ViewTarget` and `&ViewDepthTexture` together for the current view.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs:370`: the volumetric fog
  bind group includes the uniform buffer and `view_depth_texture.view()`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs:402`: the volumetric fog
  render pass has `depth_stencil_attachment: None`; it samples depth instead of
  attaching depth.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs:685`: the plugin prepares
  view depth textures by adding `TextureUsages::TEXTURE_BINDING` when any
  `VolumetricFog` exists.

Load/store, MSAA, resolve, and postprocess handoff anchors:

- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs:396`: the volumetric fog
  color attachment sets `resolve_target: None`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs:397`: the volumetric fog
  color attachment uses `Operations { load: LoadOp::Load, store:
  StoreOp::Store }`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs:362`: the pass still
  records MSAA in `VolumetricFogBindGroupLayoutKey::MULTISAMPLED` for depth
  texture binding and shader specialization.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs:491`: pipeline
  specialization adds the `MULTISAMPLED` shader def when the mesh view layout
  key contains `MeshPipelineViewLayoutKey::MULTISAMPLED`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs:528`: fog blends onto the
  existing main texture with `src = One`, `dst = OneMinusSrcAlpha`; alpha uses
  `src = Zero`, `dst = One`.
- `bevy/crates/bevy_render/src/view/mod.rs:945`: `ViewTarget::post_process_write`
  is the postprocess handoff primitive.
- `bevy/crates/bevy_render/src/view/mod.rs:952`: `post_process_write` flips the
  current main texture selector and returns source/destination texture views.
- `bevy/crates/bevy_core_pipeline/src/tonemapping/node.rs:61`: tonemapping calls
  `target.post_process_write()` after volumetric fog has written to the current
  main texture.
- `bevy/crates/bevy_core_pipeline/src/upscaling/node.rs:47`: final upscaling
  reads `target.main_texture_view()` after postprocess writes have updated the
  selector.

Explicitly absent in Bevy's volumetric fog pass:

- There is no color resolve target in the fog pass descriptor; Bevy writes to
  the single-sample current main texture view.
- There is no depth-stencil attachment in the fog pass descriptor; Bevy samples
  the prepared `ViewDepthTexture` instead.
- There is no `post_process_write` call inside volumetric fog; postprocess
  handoff is delayed until later systems such as tonemapping.

Runtime field evidence for the real mgstudio example is intentionally left to
ISS-382.

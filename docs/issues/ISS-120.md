## Description
`examples/3d/blend_modes` exercises the blend-mode render path, but it is not a
symbol-level port of Bevy's `bevy/examples/3d/blend_modes.rs`.

The current implementation keeps the five alpha-mode spheres, chessboard,
camera, light, labels, and keyboard controls. The strict gaps are source-shape
issues: Bevy's `ExampleControls`, `ExampleLabel`, `ExampleDisplay`,
`Local<ExampleState>`, material asset queries, camera `Single`, label query,
display text query, command-based HDR toggle, `rand::random`, and
`rotate_around` camera mutation are replaced by a global `BlendModesState`,
tracked arrays, direct world mutation, duplicated UI setup writes, deterministic
LCG randomization, and accumulated-angle camera orbit.

The sphere primitive also uses a local UV sphere instead of
`Sphere::new(0.9).mesh().ico(7).unwrap()`.

## Design
Port the example directly from the Bevy source owner. Keep only local changes
that are required by concrete MoonBit language/API limitations, and record each
such limitation as a precise blocker. Do not keep global state, tracked arrays,
direct world mutation, deterministic replacement randomization, or duplicated
UI setup as the parity path when the Bevy source has a specific owner.

## Acceptance Criteria
- [ ] `ExampleControls`, `ExampleLabel`, and `ExampleDisplay` are represented
      as ECS components with Bevy-shaped query ownership.
- [ ] `ExampleState` is represented with Bevy-shaped local system state
      semantics or a precise local-state blocker is recorded.
- [ ] `setup` exposes Bevy-shaped commands, mesh assets, material assets, and
      asset server parameters where possible.
- [ ] The five blend spheres use
      `Sphere::new(0.9).mesh().ico(7).unwrap()` semantics or record a precise
      primitive-builder blocker.
- [ ] The chessboard planes preserve Bevy's per-entity `ExampleControls`
      ownership rather than shared global material records.
- [ ] The camera spawn preserves `Hdr` plus the wasm-only `Msaa::Off` cfg shape
      where applicable.
- [ ] Controls text preserves the Bevy text content and UI tuple shape while
      following mgstudio branding rules where concrete user-facing brand names
      are involved.
- [ ] Labels preserve the Bevy label closure, parent/child hierarchy, label
      component, and no-wrap text layout semantics.
- [ ] `example_control_system` uses Bevy-shaped material query, camera single,
      label query, display text single, labeled transform query, local state,
      time, input, and commands where possible.
- [ ] Random color updates use source-equivalent random behavior rather than a
      deterministic LCG replacement, unless a precise random API blocker is
      recorded.
- [ ] Camera rotation uses source-equivalent `rotate_around` semantics rather
      than an accumulated-angle recomputation.
- [ ] Display text formatting preserves Bevy's `"{:.2}"` alpha formatting.
- [ ] `BlendModesState`, tracked material/label/camera/display arrays,
      duplicated UI writes, local LCG helpers, and direct world mutation helpers
      are removed from the source-parity path unless precise blockers are
      documented.
- [ ] The reference screenshot is refreshed after the source-shaped port still
      renders correctly.

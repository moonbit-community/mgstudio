## Description
`examples/shader_advanced/custom_shader_instancing/reference.png` is still an
unusable transparent baseline. A standard 90-frame native capture now produces
an opaque image, but the frame is only the default dark background. The run log
reports:

`[ERROR] No asset loader is registered for Handle<mgstudio_shader::Shader>; load the plugin that owns this asset type before calling AssetServer::load`

The generated image was discarded and the transparent reference was restored.

## Design
Audit the example and shader plugin/resource ownership against the current Bevy
`examples/shader_advanced/custom_shader_instancing.rs` source. Fix the missing
shader asset loader or plugin registration path directly instead of accepting a
background-only capture. Do not classify this as an external blocker unless the
audit proves a missing MoonBit or dependency capability.

## Acceptance Criteria
- [ ] The example registers the shader asset loader/plugin path required before
      loading custom shader handles.
- [ ] The standard native capture completes with no validation, fatal,
      missing-resource, unsupported, panic, abort, or asset-loader error output.
- [ ] The refreshed `reference.png` contains visible custom shader instancing
      scene content, not only the default background.
- [x] Any Bevy source-shape differences in the example, shader material, or
      render path are fixed or split into precise follow-up issues.

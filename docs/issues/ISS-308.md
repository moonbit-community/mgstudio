## Description
Prove that the `Cube` contributor identified by ISS-300 spawns into the same
runtime hierarchy Bevy would create: scene root, glTF node entity, primitive
child entity, mesh handle, material handle, name metadata, and visibility
components.

## Design
Use a focused white-box test or equivalent runtime evidence in
`examples/3d/volumetric_fog`. The test should run the normal scene load/spawn
systems enough to inspect entities, but it must not edit the glTF asset,
camera, screenshot timing, or render path.

## Acceptance Criteria
- [x] The runtime parent-child chain for the `Cube` node and primitive child is
      asserted or otherwise recorded.
- [x] The runtime mesh and material bindings for the visible primitive are
      asserted or otherwise recorded.
- [x] Runtime names and glTF metadata are compared against the Bevy semantics
      mapped in ISS-306.
- [x] `moon -C mgstudio-engine test examples/3d/volumetric_fog --target native
      --release` passes if a white-box test is added or changed.

## Description
The `volumetric_fog` reference depends on the camera skybox being visible behind
the imported GLB scene. The skybox image asset is loaded, but that does not
prove that the render-world view entity receives the Bevy-shaped skybox
pipeline, bind group, and draw execution.

Audit and prove the full skybox render-entity path for this example.

## Design
Use Bevy as the source of truth:

- `bevy/crates/bevy_core_pipeline/src/skybox/mod.rs`
- `bevy/crates/bevy_core_pipeline/src/core_3d/main_opaque_pass_3d_node.rs`
- `bevy/crates/bevy_light/src/probe.rs::Skybox`

Map those anchors to the mgstudio fragments:

- `mgstudio-engine/core_pipeline/skybox/top.mbt`
- `mgstudio-engine/core_pipeline/core_3d/main_opaque_pass_3d_node.mbt`
- `mgstudio-engine/render/renderer/gpu_skybox.mbt`
- `mgstudio-engine/pbr/render_execute_camera_main_pass.mbt`

Add focused evidence, preferably a white-box test or render counter, proving
that the `volumetric_fog` camera's render entity has the prepared skybox
pipeline and bind group and that the skybox draw path is reached.

## Close Notes
Closed with source-anchor mapping and focused `volumetric_fog` white-box
evidence.

Bevy source anchors:

- `bevy/crates/bevy_core_pipeline/src/skybox/mod.rs::extract_skybox` inserts
  `Skybox` plus `SkyboxUniforms` on the render entity, with brightness multiplied
  by camera exposure and inverse skybox rotation in the uniform transform.
- `bevy/crates/bevy_core_pipeline/src/skybox/mod.rs::prepare_skybox_pipelines`
  specializes `SkyboxPipelineId` for `(target_format, samples,
  CORE_3D_DEPTH_FORMAT)`.
- `bevy/crates/bevy_core_pipeline/src/skybox/mod.rs::prepare_skybox_bind_groups`
  inserts `SkyboxBindGroup` only when the skybox image resolves to a cubemap GPU
  image and view/skybox uniform bindings are present.
- `bevy/crates/bevy_core_pipeline/src/core_3d/main_opaque_pass_3d_node.rs`
  draws the skybox in the main opaque pass when both `SkyboxPipelineId` and
  `SkyboxBindGroup` are present.
- `bevy/crates/bevy_light/src/probe.rs::Skybox` is the source component used by
  extraction.

Mgstudio fragments:

- `mgstudio-engine/core_pipeline/skybox/top.mbt::extract_skybox` mirrors the
  Bevy extraction surface into `ExtractedSkyboxes`.
- `mgstudio-engine/core_pipeline/skybox/top.mbt::prepare_skybox_pipelines`
  writes `SkyboxPipelineId` on the render entity using
  `skybox_pipeline_key_for_render_entity`.
- `mgstudio-engine/core_pipeline/skybox/top.mbt::prepare_skybox_bind_groups`
  calls `host_gpu_prepare_skybox_bind_group` and writes `SkyboxBindGroup`.
- `mgstudio-engine/core_pipeline/core_3d/main_opaque_pass_3d_node.mbt`
  gates skybox drawing on the render entity having both prepared components.
- `mgstudio-engine/render/renderer/gpu_skybox.mbt` owns the native bind group
  and fullscreen triangle draw call.
- `mgstudio-engine/pbr/render_execute_camera_main_pass.mbt` calls
  `main_opaque_pass_3d_draw_skybox` during camera main-pass execution.

Focused evidence:

- Added `volumetric_fog: camera render entity prepares Bevy skybox draw state`
  in `mgstudio-engine/examples/3d/volumetric_fog/main_wbtest.mbt`.
- The test runs the example's Bevy-shaped app setup through startup plus three
  updates, reads the main-world camera's `RenderEntity`, then proves on the
  render world that:
  - `view_has_skybox_pipeline(render_world, render_entity)` is `true`;
  - `view_has_skybox_bind_group(render_world, render_entity)` is `true`;
  - `draw_prepared_skybox(render_world, render_entity)` returns `true`.

  passed: `Total tests: 15, passed: 15, failed: 0`.

Conclusion:

The `volumetric_fog` visual failure is not caused by the camera render entity
missing skybox extraction, prepared pipeline, prepared bind group, or the ECS
skybox draw gate. Remaining candidates are the main opaque pass ordering/depth
boundary in ISS-348 and skybox shader/cubemap sampling/exposure parity in
ISS-349.

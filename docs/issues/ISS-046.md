## Description
`ISS-028` still has an open acceptance item requiring render runtime APIs to
avoid authoring assets except where Bevy render extraction or preparation does
so. The `2d_shapes` fix corrected one concrete renderability bug, but did not
prove that all remaining render-runtime helpers have Bevy-equivalent ownership.

Any runtime path that constructs meshes, materials, images, or authoring bundles
inside a render owner must be audited. If Bevy owns the behavior in an authoring
or asset package, mgstudio should move it there. If Bevy owns the behavior in
render extraction or preparation, mgstudio should keep it in the matching render
owner and document the mapping.

## Design
Search the current `sprite_render/render`, `sprite`, `mesh/primitives`, and
related 2D packages for asset-authoring helpers and allocation paths. For each
path, map it to a Bevy source owner or remove it as stale local API. Do not keep
compatibility wrappers or fallback authoring helpers.

## Acceptance Criteria
- [ ] Audit remaining 2D render-runtime functions that call asset add/set APIs or construct mesh/material/image authoring data.
- [ ] Rehome authoring behavior to the Bevy-equivalent asset, mesh, sprite, camera, or UI owner where applicable.
- [ ] Keep only Bevy-equivalent extraction/preparation allocation in render owners.
- [ ] Remove stale public APIs that exist only to preserve the former `sprite/render2d.mbt` monolith.
- [ ] Validate representative sprite, mesh2d, `2d_shapes`, and UI-render examples after the cleanup.

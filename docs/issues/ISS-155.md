## Description
`ISS-153` classified the current mesh preparation source anchors. The remaining
`many_foxes` `prepare_meshes` cost is not repeated mesh upload:
`/tmp/mgstudio_many_foxes_iss152_direct_finish_aabb3d/frametime_breakdown.md`
reports `mgstudio.render.prepare_meshes=3.034 ms/frame` with
`prepared_meshes=1001`, `buffer_uploads=1`, `skipped_unchanged_meshes=1000`,
`mesh_upload_cache_hits=1000`, and `preprocess_static_cache_hits=1000`.

The true source gap is that mgstudio still builds render mesh queue data in the
monolithic `mgstudio-engine/pbr/render_execute_mesh_collect.mbt` path and then
stores a single `Map`-backed `RenderMeshInstances` resource. Bevy's current
owner in `bevy_pbr/src/render/mesh.rs` splits this into CPU/GPU building modes.
The GPU path uses changed queries, per-worker queues, `MeshesToReextractNextFrame`,
`RenderMeshInstanceGpuBuilder::prepare`, and
`collect_meshes_for_gpu_building` update/fast-path logic.

## Design
Port Bevy's owner shape directly:

- Replace the single-map `RenderMeshInstances` facade with a source-shaped
  `CpuBuilding` / `GpuBuilding` representation.
- Port `extract_meshes_for_gpu_building` changed-query semantics as closely as
  MoonBit ECS allows, recording a smaller blocker if query filters or removed
  component readers cannot express the source shape.
- Port `RenderMeshInstanceGpuQueue`, `RenderMeshInstanceGpuBuilder`,
  `RenderMeshInstanceGpuPrepared`, and `MeshesToReextractNextFrame`.
- Move mesh instance preparation out of the monolithic
  `render3d_extract_mesh_for_entity` / `render3d_execute_collect_meshes` path.
- Keep `RenderMeshAssets` and `MeshAllocator` as authoritative render-world
  resources instead of using host upload cache state as a substitute.

Do not add dirty-skip shortcuts that alter Bevy-visible mesh extraction
semantics.

## Acceptance Criteria
- [x] `RenderMeshInstances` has Bevy-shaped CPU and GPU building variants.
- [ ] GPU mesh instance extraction records changed, removed, and reextract-next
      frame entities through source-shaped resources or documented blockers.
- [x] Mesh instance preparation consumes `MeshAllocator`, material bindings,
      lightmaps, skin uniforms, morph indices, and frame count in the Bevy
      owner path.
- [ ] The monolithic PBR collect path no longer owns mesh upload/cache and mesh
      instance preparation together.
- [ ] `many_foxes` reports `mgstudio.render.prepare_meshes < 1 ms/frame` at
      `1000` foxes on the current development machine, or a more specific ECS
      blocker is recorded with exact evidence.
- [ ] Relevant `mesh`, `pbr/render`, and `pbr` release tests pass.

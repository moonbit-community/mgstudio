## Description
Bevy's atmosphere LUT compute passes consume `GpuScatteringMedium` density and
scattering LUT textures through bindings 5 and 6, plus
`ScatteringMediumSampler` at binding 7. Mgstudio currently has CPU-side
`pbr/medium.mbt` facades and generated arrays, but no renderer-owned
Rgba32Float density/scattering texture upload owner equivalent to
`bevy_pbr/src/medium.rs`.

## Design
Port Bevy's `bevy/crates/bevy_pbr/src/medium.rs` source owner directly. The
MoonBit implementation must preserve the render-asset ownership shape:
`ScatteringMediumPlugin`, `GpuScatteringMedium`, density LUT generation,
scattering LUT generation, Rgba32Float texture upload, default texture views,
and `ScatteringMediumSampler`. Do not use constant white/black medium textures,
empty LUTs, or atmosphere-specific fallback textures.

## Acceptance Criteria
- [x] Bevy `ScatteringMediumPlugin` and `GpuScatteringMedium` source symbols
      have explicit mgstudio mappings or documented blockers.
- [x] Density LUT and scattering LUT generation match Bevy's source logic for
      the in-scope `ScatteringMedium` model.
- [x] Renderer uploads density and scattering LUTs as Rgba32Float 2D textures
      with texture-binding usage and exposes their default views.
- [x] `ScatteringMediumSampler` maps to a real filtering clamp sampler used by
      atmosphere bind groups.
- [x] `ISS-065` atmosphere LUT bind groups consume the real medium texture
      views and sampler instead of placeholders.
- [x] `moon -C mgstudio-engine check --target native`, `moon -C
      mgstudio-engine fmt`, `moon -C mgstudio-engine info`, and focused PBR
      medium/atmosphere tests pass.

## Notes
- 2026-06-10: Discovered while preparing to port Bevy's
  `atmosphere_luts` compute pass. `transmittance_lut.wgsl` imports
  `sample_density_lut`, which samples `medium_density_lut` and
  `medium_scattering_lut`; therefore the atmosphere compute pass cannot be
  source-level equivalent until the medium render asset owner exists.
- 2026-06-11: Renderer-side `GpuScatteringMediumResources` now owns real
  Rgba32Float density/scattering textures, default texture views, a linear
  clamp sampler, and source byte snapshots. Repeated prepares with identical
  dimensions but changed source bytes rewrite the existing textures and bump
  the resource revision instead of returning early. Verified the current
  atmosphere example capture at
  `/tmp/mgstudio_atmosphere_iss066_medium_resources.png`; it produced a
  nonblack frame (`nonblack_ratio = 0.2391238064236111`) and no validation or
  missing-atmosphere-binding log output. Remaining gap: `ISS-065` has not yet
  created the Bevy-shaped atmosphere LUT compute bind groups, so bindings 5, 6,
  and 7 are not yet consumed by a real atmosphere compute pass. This issue
  stays open until that consumption path is implemented and verified.
- 2026-06-11: The renderer now requests `Float32Filterable` when the adapter
  exposes it, preserving Bevy's filtering sampler and filterable float texture
  layout for Rgba32Float scattering medium LUTs under the WebGPU C ABI.
  Re-ran `examples/3d/atmosphere` with the standard native capture command;
  `/tmp/mgstudio_atmosphere_iss065_float32_filterable.run.log` contains only
  the example controls and no validation/fatal output, proving the
  transmittance LUT bind group now consumes the real density/scattering views
  and sampler.

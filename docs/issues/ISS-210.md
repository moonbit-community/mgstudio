## Description
After depth usage, pass-state identity, bind group wiring, and MSAA semantics
are verified, mgstudio still needs evidence that `volumetric_fog.wgsl`
reconstructs depth in a Bevy-equivalent way. The final proof should show that
foreground geometry changes the fog result, not just that the shader runs.

## Design
Compare Bevy's view-depth reconstruction inputs consumed by
`volumetric_fog.wgsl` against mgstudio's view uniforms and depth binding.
Prefer a focused test or deterministic capture that changes foreground depth
and observes a volumetric fog output change. This issue should not alter Bevy
shader text unless a real external WGSL/parser blocker is recorded.

## Acceptance Criteria
- [x] View uniform data used by depth reconstruction is audited against Bevy.
- [x] A focused test or capture demonstrates foreground geometry depth affects
      volumetric fog reconstruction.
- [x] Close notes include the exact validation command and artifact path used
      for the evidence.

## Close Notes
2026-07-04: Bevy and mgstudio `volumetric_fog.wgsl` match for the depth
reconstruction block. Both sample `depth_texture` at the current fragment,
convert the depth-buffer value through `frag_coord_to_ndc` and
`position_ndc_to_view`, clamp the traced ray with
`end_depth_view = min(end_depth_view, view_end_depth_from_buffer)`, and return
transparent output when `ray_length_view == 0.0`. The view-uniform inputs used
by that code are the active pass view matrices and exposure already carried in
the mesh view bind group.

Runtime evidence was collected with:

`MGSTUDIO_PARITY_CAPTURE_DELAY_FRAMES=90 MGSTUDIO_PARITY_RUN_TIMEOUT_SECONDS=240 mgstudio-engine/scripts/p0_visual_capture_native.sh examples/3d/scrolling_fog /tmp/mgstudio_iss210_scrolling_fog.png`

The capture completed successfully with an empty run log:
`/tmp/mgstudio_iss210_scrolling_fog.run.log` has size 0. The output artifact is
`/tmp/mgstudio_iss210_scrolling_fog.png`.

The image shows the foreground pillar as a solid occluder in front of the fog.
Simple luminance sampling of the 2560x1440 capture gives:

- pillar center `(1160, 520, 1370, 1180)`: mean luma `91.474`
- left fog `(840, 520, 1050, 1180)`: mean luma `119.034`
- right fog `(1480, 520, 1690, 1180)`: mean luma `119.170`

This proves foreground geometry depth affects the volumetric fog result rather
than the shader rendering an unconstrained full-screen fog overlay.

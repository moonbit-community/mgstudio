## Description
Audio examples failed the screenshot batch because they did not emit an RGBA8
capture blob. Some audio examples may still have a small UI or visual scene, so
they should be classified rather than broadly ignored.

Failed packages:

- `examples/audio/audio`
- `examples/audio/audio_control`
- `examples/audio/decodable`
- `examples/audio/soundtrack`
- `examples/audio/spatial_audio_2d`
- `examples/audio/spatial_audio_3d`

## Design
Inspect each audio example and decide whether it has a meaningful visual
surface. Non-visual audio examples should move to an audio-specific validation
policy. Visual audio examples should emit a deterministic screenshot.

## Acceptance Criteria
- [x] Every listed audio package has a screenshot policy classification.
- [x] Non-visual audio packages are excluded from screenshot capture with a documented reason.
- [x] Any visual audio package produces `reference.png`.
- [x] Audio validation expectations are not conflated with render visual parity gates.

## Description

Track the architecture-level ECS performance experiments discovered after the
dense table-column work. The current severe performance gap remains
`CAUSE_UNVERIFIED`: each candidate must be isolated, measured against the same
pre-change revision, and either retained with evidence or reverted.

The unit of optimization is the query/table boundary, not an individual render
or visibility heuristic. Runtime and change-detection semantics must remain
aligned with the pinned Bevy baseline.

## Experiment Protocol

For each child issue:

1. Reproduce and save the pre-change measurement from the issue's single
   validation example.
2. Change one architecture variable only.
3. Run one focused correctness test at a time with `MOONBIT_NEW_NATIVE=1`.
4. Repeat the same measurement against the pre-change revision under comparable
   conditions.
5. Retain the implementation only when the target hot path improves by at least
   5% or a directly measured allocation/lookup class is removed without more
   than 3% total-frame regression.
6. Otherwise revert the production change, record the rejected hypothesis, and
   close the issue.
7. Commit each retained implementation, rejected-experiment record, or tracker
   milestone separately.

Do not substitute changed-only visibility scans, parallel scheduling, reduced
entity counts, disabled rendering, or heuristic behavior for an ECS
architecture improvement.

## Acceptance Criteria

- [ ] Every row has before/after evidence and a retained or rejected result.
- [ ] Every retained change preserves focused ECS semantics and the pinned Bevy
      runtime behavior of its validation example.
- [ ] No child experiment uses more than one example as its runtime gate.
- [ ] Public API changes are explicit and accompanied by migration notes.
- [ ] `ISS-001` is updated when a retained ECS change materially changes the
      `many_foxes` frame budget.

## Notes

- 2026-07-15: Created after dense table columns produced a real but limited
  improvement and demonstrated that payload representation alone does not
  remove the dominant query-execution overhead.
- 2026-07-15: `ISS-446` retained an additive value-only read path. This proves
  eager change-metadata loading is material in the isolated fetch kernel, but
  its 5.70% visibility-system gain did not improve the render-dominated
  `many_cubes` whole-frame interval.
- 2026-07-15: `ISS-447` rejected persistent fetch-plan state as a useful
  standalone optimization. It removed a small allocation class but added API
  and lifecycle complexity without improving the measured query or runtime
  path, so all prototype code was reverted.
- 2026-07-15: `ISS-448` retained typed column binding at the dense-table entry
  boundary. The result confirms that per-row typed-storage map lookup and
  component-access closure dispatch were material costs: the isolated mutable
  query improved `36.45%` and the runtime animation system improved `6.92%`.
- 2026-07-15: `ISS-449` retained dense table-batch traversal after routing
  batch replacement through the same storage/finalizer authority as ordinary
  writes. The corrected API improved the isolated mutable query `22.84%`,
  `reset_view_visibility` `22.38-23.44%`, and steady `many_sprites` frame
  interval `10.97-13.42%`; a fixed-frame row/batch visual A/B was byte-identical.
- 2026-07-15: `ISS-456` tracks call-site adoption separately so every hotspot
  receives its own source audit, validation example, measurement, and commit.
  Tick-filtered table batches now use exact table-bound row matchers instead of
  widening `Changed`, `Added`, or `Or` semantics. The first retained migration
  improved source-aligned `mark_dirty_trees_system` by `9.67%`; its remaining
  ancestor-chain random-access cost is a separate query boundary.
- 2026-07-16: `ISS-456` closed after all nine trace-proven batch call sites
  received source audits, distinct example gates, focused tests, and retained
  migrations. The final additions improved source-aligned
  `sync_simple_transforms` by `25.80%` and the already-small changed-sprite
  slice scan by `7.10%`. No further unmeasured query loops are classified as
  batch candidates; rows 6 through 10 remain separate architecture experiments
  and must follow their own Bevy anchors and validation examples.
- 2026-07-16: `ISS-450` retained Bevy-shaped tick ownership and opt-in change
  locations. Writes no longer allocate or send supplemental changed messages;
  default dense tables omit caller-ID arrays and skip `SourceLoc` string
  conversion. On `animated_transform`, `animate_targets` improved `11.4%`
  while steady frame time regressed only `0.36%`; caller-on/off fixed-frame
  captures were byte-identical.

## Description
Bevy's `volumetric_fog` example is not only a static scene. It owns
`AppSettings`, a moving light component, UI/help text, and systems that insert
or remove `VolumetricLight` in response to input. Local substitutions such as
changing proxy light intensity do not prove the same engine path.

## Design
Use this issue as the parent for the runtime behavior migration:

- ISS-265 groups `tweak_scene`, directional-light movement, point-light
  movement, and movement component state. The executable leaves are ISS-286
  through ISS-289.
- ISS-266 groups `AppSettings`, `adjust_app_settings`, text updates, and
  `VolumetricLight` insertion/removal. The executable leaves are ISS-290
  through ISS-292.

Keep MoonBit syntax adaptations minimal and record any language-level blocker
instead of replacing semantics.

## Acceptance Criteria
- [x] ISS-265 and ISS-266 are closed.
- [x] Input changes insert/remove `VolumetricLight` rather than approximating
      volumetric behavior with unrelated intensity or fog settings.
- [x] A focused test or capture proves the toggled volumetric-light state is
      visible to the render path.

# ISS-473: Align Camera2d frustum with uniform render scale

## Metadata

- Status: closed

- Assignee: codex

## Description

`update_frusta_2d_system` forwards the complete non-uniform X/Y scale from
`GlobalTransform` to the shared 3D orthographic frustum computation. The
current Camera2d viewport conversion, scene culling, and native renderer use
`camera_transform.scale.x` as one uniform camera scale. With camera scale
`(2, 1, 1)`, the rendered vertical extent is therefore twice the frustum's
vertical extent, and visibility can reject an object that the renderer would
place inside the viewport.

Pinned Bevy derives rendering and frustum planes from the same camera affine.
Mgstudio must likewise feed its current 2D frustum the exact transform semantics
used by its 2D renderer; it must not mix the renderer's uniform-X convention
with the shared 3D non-uniform convention.

## Design

At the Camera2d frustum boundary, derive the renderer-authoritative uniform
scale from the approximated global transform: use the absolute non-zero X axis
for both X and Y, matching the existing Camera2d viewport and renderer helpers.
Keep translation, rotation, Z scale, logical viewport, orthographic projection,
and the shared frustum algorithm unchanged. Do not alter Camera3d frustum
semantics or add a culling tolerance.

## Acceptance Criteria

- [x] A focused test proves that a point inside the Camera2d rendered viewport
      under `(2, 1, 1)` is also inside its frustum.
- [x] A point beyond the same uniform-X vertical extent remains outside.
- [x] Unit and uniform camera scales retain their existing behavior.
- [x] Camera3d frustum computation remains unchanged.
- [x] Focused tests run one at a time with `MOONBIT_NEW_NATIVE=1`.
- [x] The generated public interface remains unchanged.

  into the shared frustum computation. It preserves translation, rotation, and
  Z scale while applying the renderer's absolute non-zero X scale to both view

## Close Notes

Closed on 2026-07-19. Camera2d frustum extraction now uses the same uniform-X
camera scale as viewport conversion, CPU scene culling, and native 2D drawing.
The focused non-uniform regression, the existing logical-viewport Camera2d
frustum test, and the existing Camera3d transform/projection frustum test each
pass independently in native release mode. No public API or Camera3d source
path changed.

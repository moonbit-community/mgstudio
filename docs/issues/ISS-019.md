# ISS-019: Wire PBR prepass, deferred, shadow, main, and transmission phases to real runtime commands

- Assignee: unassigned

- External ref: moonbit-community/wgpu-mbt#24 (resolved by wgpu_mbt@0.14.0)

## Description
Mgstudio has made strong progress on descriptor-level PBR parity: material
pipeline specialization, mesh bind layouts, morph/skinning/lightmap bindings,
prepass descriptors, motion-vector descriptors, deferred planning, and phase
classification exist. The remaining gap is runtime consumption: the Bevy-shaped
decisions must drive actual prepass, deferred, shadow, main, and transmission
phase commands with visual parity.

## Design
Port Bevy's runtime phase ownership rather than adding local draw-path patches.
Use the current Bevy `material.rs`, `prepass/mod.rs`, `render/mesh.rs`,
`render/light.rs`, `transmission`, and shadow pass sources to connect phase
items, draw functions, bind groups, pipelines, and render graph nodes.

## Acceptance Criteria
- [ ] Opaque, alpha-mask, transparent, transmissive, deferred, prepass, shadow, and motion-vector phase items are consumed by Bevy-equivalent draw commands.
- [ ] Prepass and deferred-prepass runtime scheduling matches Bevy's early/late gating and material eligibility rules.
- [ ] Shadow passes use Bevy-equivalent material and depth-only draw function selection.
- [ ] Transmission phase ordering and target usage match Bevy's screen-space transmission owner model.
- [ ] Runtime commands consume the already ported descriptor layouts rather than rebuilding local fallback descriptors.
- [ ] Motion blur, contact shadows, lightmap, deferred rendering, transmission, and meshlet-related examples have parity screenshots or specific blocker issues.

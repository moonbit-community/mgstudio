## Description
After the shadow phase item's pipeline id is shadow-compatible, mgstudio still
must prove that the draw payload consumed by the renderer targets the same
directional shadow view/depth layer prepared for the light/camera frame. A
correct pipeline can still draw into the wrong retained target or with a stale
frame identity.

## Design
Audit Bevy `view_shadow_pass` against mgstudio's
`render3d_execute_shadow_phase_view`, shadow pass work-unit construction, and
`mesh3d_draw_shadow_depth_pass` payload path. Keep the scope to retained target
identity, pass label, phase item iteration, draw function, mesh slab, and
material bind-group payload. Do not change volumetric fog sampling in this
issue; ISS-220 owns final shadow target consumption by volumetric fog.

## Acceptance Criteria
- [x] The queued `scrolling_fog` pillar shadow phase item is consumed by
      `render3d_execute_shadow_phase_view`.
- [x] The draw command targets the same directional shadow view/depth layer
      prepared for the camera/light frame.
- [x] The draw payload carries the expected draw function, mesh slab, mesh asset
      id, and depth-only material bind-group semantics.
- [x] A focused test or trace artifact proves the pillar draw command reaches
      the shadow pass with the retained target identity used by that frame.

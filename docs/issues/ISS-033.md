# ISS-033: Port screenshot capture to Bevy render-app ownership

## Description
Motion blur's screenshot gate now exits successfully, but screenshot capture is
not source-level equivalent to `bevy_render/src/view/window/screenshot.rs`.
Bevy owns screenshots through `ScreenshotPlugin`, `CapturedScreenshots`,
`RenderScreenshotTargets`, `RenderScreenshotsPrepared`,
`RenderScreenshotsSender`, `trigger_screenshots`, `extract_screenshots`,
`prepare_screenshots`, and `submit_screenshot_commands` in the render app.
`ScreenshotCaptured` is an entity event triggered after readback.

Mgstudio currently splits the path across `render/screenshot.mbt`,
`render/view/window/screenshot.mbt`, and renderer-local global state in
`render/renderer/screenshot.mbt`. Readback queues, capture IDs, parity capture
environment variables, target preparation, copy-to-buffer, and completion live
inside `GpuBackend`/global runtime state rather than Bevy-shaped render-app
resources and systems. `ScreenshotCaptured` is modeled as a component inserted
onto the screenshot entity, not as a triggered event.

## Design
Use Bevy's screenshot owner as the source unit. Rehome screenshot target
extraction, preparation, readback, completion, and trigger/save behavior into
Bevy-shaped main-world/render-world resources and systems. Preserve MoonBit
package splits only where they reflect owner boundaries. Do not keep the
renderer-local global runtime as the normal screenshot path once the source
owner is ported.

## Acceptance Criteria
- [ ] `ScreenshotCaptured`, `Screenshot`, `Capturing`, `Captured`, screenshot target resources, prepared state, sender/receiver state, and screenshot-to-screen pipeline all have explicit Bevy-owner mappings.
- [ ] Screenshot target extraction and preparation run in Bevy-equivalent extract/render schedule positions, not hidden inside `GpuBackend::end_frame_binding`.
- [x] Screenshot completion triggers observer/event behavior equivalent to Bevy's `commands.trigger(ScreenshotCaptured { ... })`; component-observer modeling is removed or documented as a language-level blocker.
- [ ] Surface, image, and manual texture-view screenshot targets are supported through the same owner path.
- [ ] `examples/window/screenshot` and `examples/3d/motion_blur` screenshot gates save nonblank images and exit successfully.

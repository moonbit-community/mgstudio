## Description
Bevy's `bevy_sprite_render/src/mesh2d/material.rs` defines
`Material2d::specialize`, `Material2dKey<M>`, and
`Material2dPipeline<M>::specialize` so material bind-group data can affect the
final render pipeline descriptor. mgstudio currently preserves material alpha
mode, bind-group layout, bind-group data, and shader paths, but the
`Material2d` trait has no equivalent hook for material-specific pipeline
specialization.

## Design
Port the Bevy source shape instead of adding renderer-local special cases.
Expose a MoonBit representation of the Mesh2d render pipeline descriptor that is
usable by `Material2d`, pass a Bevy-shaped `Material2dKey[M]` through
specialization, and keep the renderer cache keyed by every descriptor-affecting
field. Do not add fallback behavior for custom materials that silently ignores a
specialization request.

## Acceptance Criteria
- [ ] Add a `Material2d` specialization hook whose call site mirrors Bevy's
  `Material2dPipeline<M>::specialize`.
- [ ] Ensure `Material2dKey[M]` carries mesh pipeline bits and bind-group data
  in a shape that custom material code can inspect.
- [ ] Make renderer pipeline cache keys include all fields that the hook can
  affect, without using ad hoc string replacements or hidden fallbacks.
- [ ] Add tests showing two materials with the same layout but different
  descriptor-affecting specialization data do not reuse an incorrect pipeline.
- [ ] Validate with `shader_material_2d` and at least one standard `ColorMaterial`
  Mesh2d example under `--release`.

## Notes
- 2026-06-12: This is a local source-shape gap, not an external dependency
  blocker. If MoonBit cannot express part of the API exactly, record that as a
  new blocker with the precise language limitation before introducing any
  approximation.
- 2026-06-12: MoonBit traits cannot provide default method bodies, so every
  `Material2d` impl must explicitly implement Bevy's default no-op
  `specialize` behavior unless it needs custom specialization. Added the trait
  method, `Material2dPipeline::specialize`, explicit no-op impls for current
  concrete materials, and a `DummyMaterialAsset` test hook that mutates the
  descriptor. Runtime host pipeline consumption of the specialized descriptor
  remains open.
- 2026-06-12: Connected the specialized descriptor into the Mesh2d host draw
  path. `Material2d` draw now queries the real uploaded mesh vertex layout and
  primitive topology before calling `Material2dPipeline::specialize`; the host
  pipeline key includes descriptor-affecting shader paths, shader defs,
  entry-points, vertex buffer layouts, primitive/depth/multisample/color target
  state, and pending batch matching includes the resulting pipeline cache key.
  Validation so far: `moon -C mgstudio-engine test render/renderer --release`
  and `moon -C mgstudio-engine test sprite_render/render --release`; sequential
  native captures for `examples/2d/2d_shapes` and
  `examples/shader/shader_material_2d` both matched their checked-in references
  with `magick compare -metric AE` = 0. Remaining source-shape gap:
  `Material2dKey` still carries mgstudio's reduced mesh key bits instead of
  Bevy's full `Mesh2dPipelineKey` view/topology/tonemapping state, and the
  broader `SpecializedMaterial2dPipelineCache`/pending queue owner boundary
  remains part of ISS-045.
- 2026-06-12: Advanced `Material2dKey` one step toward Bevy's
  `Mesh2dPipelineKey`: draw-time specialization now ORs in primitive topology
  bits and strip index-format bits derived from the uploaded host mesh, so a
  custom material no longer sees identical key bits for triangle-list and
  strip-topology meshes. Validation: `moon -C mgstudio-engine test
  sprite_render/mesh2d/material --release` and `moon -C mgstudio-engine check
  --target native --package-path sprite_render/render`. Remaining key gap:
  view target format, MSAA, SRGB/Oklab compositing, tonemapping, and deband
  dither bits still need a Bevy-shaped ViewKeyCache/specialization boundary
  instead of render2d's immediate draw path.

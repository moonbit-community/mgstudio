## Description
The final `scrolling_fog` capture can miss Bevy's diagonal directional
shadow/light-shaft structure if the example scene itself diverges: camera,
pillar mesh/material, fog volume, density texture, sun transform, volumetric
light component, cascade shadow config, or animation state.

## Design
Audit `bevy/examples/3d/scrolling_fog.rs` against
`mgstudio-engine/examples/3d/scrolling_fog`. Classify every source-shape anchor
as complete, partial, facade, or blocked. Fix local divergences
source-faithfully. Do not compensate in renderer code for an example authoring
bug.

## Acceptance Criteria
- [ ] Every scene-authoring anchor that affects fog, depth, or directional
      shadows is classified with evidence.
- [ ] The mgstudio example uses Bevy-equivalent camera, transforms, fog,
      density texture, directional light, volumetric light, and cascade config.
- [ ] Any remaining mismatch is recorded as a blocker only if it is not
      expressible in MoonBit or current dependencies.
- [ ] Focused example or white-box validation proves the corrected authoring
      values reach the source world before extraction.

## Notes
- 2026-07-04: Split from ISS-205 after the depth path was verified but the
  final capture still lacked the reference directional light-shaft structure.
- 2026-07-04: Started Bevy source-input audit. Bevy inserts
  `DirectionalLightShadowMap { size: 4096 }` during app construction, then runs
  `setup`; mgstudio currently inserts that resource inside `setup`, which is a
  local source-shape divergence to fix before blaming renderer code.
- 2026-07-04: Source-shape anchor classification:
  - `main` app construction: complete. Mgstudio now inserts
    `DirectionalLightShadowMap::new(4096)` in the app builder before startup
    systems, matching Bevy's `insert_resource` ownership. The title string uses
    the mgstudio brand by project rule.
  - startup camera authoring: complete. Mgstudio now spawns the camera as a
    tuple of `Camera3d`, `Transform`, `Msaa::Off`, `TemporalAntiAliasing`,
    `Bloom`, and `VolumetricFog` rather than hiding the source shape behind
    `Camera3dBundle`.
  - directional light authoring: complete. The directional light keeps
    `shadow_maps_enabled`, the Bevy transform, and `VolumetricLight`.
  - ground and pillar authoring: complete. Mesh dimensions, black materials,
    roughness override for ground, and transforms match the Bevy anchors.
  - density texture and fog volume authoring: complete. The image load uses a
    linear sampler with repeat address modes and the fog volume keeps the Bevy
    transform, scale, density texture, and `density_factor`.
  - fog animation system: complete. `scroll_fog` updates
    `density_texture_offset` by `(0, 0, 0.04) * delta_seconds`.
  No language or external dependency blocker was found for this example
  authoring layer.

## Close Notes

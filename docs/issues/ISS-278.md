## Description
Bevy's volumetric fog extraction observes `VolumetricLight` and clears
volumetric fog render state when no volumetric lights are present.

## Design
Audit the light extraction and no-light cleanup behavior separately from
`VolumetricFog` and `FogVolume`. Verify the behavior with a focused test or
file a precise follow-up.

## Acceptance Criteria
- [x] `VolumetricLight` extraction is classified.
- [x] No-volumetric-light cleanup behavior is classified.
- [x] A focused test or follow-up issue covers toggling the last volumetric
      light off.

## Notes
- 2026-07-05: Split from ISS-238 so light cleanup behavior has its own
  acceptance surface.
- 2026-07-09: Audited against
  `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs::extract_volumetric_fog`.
  Bevy extracts `Query<(RenderEntity, &VolumetricLight)>` and inserts
  `VolumetricLight` into the linked render-world entity when the source query
  is non-empty. Mgstudio mirrors that in `extract_volumetric_fog_from_worlds`
  by collecting source entities that have `VolumetricLight` and `RenderEntity`,
  then setting `ecs_key_volumetric_light` on the render entity.
- 2026-07-09: Bevy's no-light branch removes view-side volumetric fog state and
  `FogVolume`, then returns. It does not remove `VolumetricLight` from a
  render-world light entity in this function; `VolumetricLight` is also not
  registered through Bevy's `SyncComponentPlugin` in
  `volumetric_fog/mod.rs`. Mgstudio now has a focused white-box test,
  `pbr volumetric fog: last-light removal follows Bevy extract cleanup
  boundary`, that verifies the same cleanup boundary: removing the last source
  `VolumetricLight` clears render-world fog view/volume state but leaves the
  previously extracted render-world `VolumetricLight` component untouched.

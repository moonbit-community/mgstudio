## Description
Before auditing individual bind-group entries, prove that mgstudio's
`examples/3d/volumetric_fog` pass consumes the same high-level view resources
as Bevy: `ViewTarget`, `ViewDepthTexture`, `ViewVolumetricFogPipelines`,
`ViewVolumetricFog`, `MeshViewBindGroup`, and `Msaa`.

## Design
Compare Bevy `bevy_pbr/src/volumetric_fog/render.rs::volumetric_fog` pass query
and pass descriptor shape against mgstudio's PBR execute and renderer fragments.
This issue owns only the pass query/resource surface, color attachment target,
no-depth-attachment pass descriptor, and MSAA key routing. It does not audit
the contents of depth, light, uniform, or density bindings.

## Acceptance Criteria
- [x] The Bevy pass query anchors are mapped to mgstudio symbols.
- [x] Evidence proves the real example reaches the pass with the expected view
      target, fog pipelines, fog view data, mesh-view bind group, and MSAA key.
- [x] Color target, load/store, no-depth-attachment, and single-sample color
      pipeline semantics are classified.
- [x] Any local divergence is assigned to ISS-359.

## Close Notes
Closed on 2026-07-05 as an audit-only pass-input boundary. No production
renderer, shader, asset, or example behavior was changed for this issue.

Bevy owner anchors:

- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs::volumetric_fog` queries
  `ViewTarget`, `ViewDepthTexture`, `ViewVolumetricFogPipelines`,
  `ViewVolumetricFog`, `MeshViewBindGroup`, and `Msaa`.
- The Bevy pass begins a render pass labeled `volumetric lighting pass` with
  `view_target.main_texture_view()`, `LoadOp::Load`, `StoreOp::Store`,
  `resolve_target: None`, and `depth_stencil_attachment: None`.
- Bevy's volumetric-fog pipeline uses the MSAA state for the sampled-depth
  layout and shader key, while the color target remains the main view target
  used by `ViewTarget`.

Mgstudio implementation fragments:

- `mgstudio-engine/pbr/render_execute_camera.mbt` prepares
  `render3d_prepare_camera_volumetric_fog_state` before the main pass, executes
  `render3d_execute_camera_main_pass`, then executes the distinct
  `render3d_execute_camera_volumetric_fog_pass` before early postprocess.
- `mgstudio-engine/pbr/render_execute_camera_main_pass.mbt` calls
  `render3d_begin_pass_3d` for the current `scene_target_id`, passing the
  camera MSAA sample count and the same shadow/view resources later consumed by
  the volumetric-fog pass.
- `mgstudio-engine/render/renderer/pass_begin.mbt::GpuBackend::begin_pass_3d`
  records the current view target, view depth texture view, and MSAA sample
  count in `GpuPassState`.
- `mgstudio-engine/pbr/volumetric_fog_execute.mbt` looks up
  `ViewVolumetricFog` and `ViewVolumetricFogPipelines` from the render view
  entity and forwards the prepared pipeline ids and volume records to the
  renderer.
- `mgstudio-engine/render/renderer/mesh3d_volumetric_fog_pass.mbt` consumes the
  saved `GpuPassState`, resolves `target_view(pass_state.target_id,
  pass_state.target_layer)` as the Bevy-equivalent `ViewTarget` main view, ends
  the previous active pass, reopens a color-load pass with
  `begin_render_pass_color_load(color_view)`, binds the mesh-view group at
  group 0, and does not attach a depth attachment to the volumetric-fog pass.
- `mgstudio-engine/render/renderer/mesh3d_pipeline_build.mbt` keeps the
  volumetric-fog color pipeline single-sample while still using the MSAA sample
  count to select the sampled-depth bind-group layout and `MULTISAMPLED` shader
  definition.

Evidence:

- `mgstudio-engine/examples/3d/volumetric_fog/main_wbtest.mbt` runs the real
  example app shape. The focused pass-local test proves positive
  volumetric-fog view, volume, light, and uniform counters, and proves the real
  render view has `ViewVolumetricFog` plus valid textureless/textured
  `ViewVolumetricFogPipelines`.
- `mgstudio-engine/pbr/render_execute_camera_wbtest.mbt` proves the explicit
  schedule boundary: main pass, volumetric-fog pass, then early postprocess.
- `mgstudio-engine/render/renderer/gpu_wbtest.mbt` proves the volumetric-fog
  renderer uses the default mesh-view bind-group owner and preserves Bevy's
  single-sample color pipeline behavior when the MSAA key is active.

Validation:

- `moon -C mgstudio-engine test pbr --target native --release --filter 'render3d camera: volumetric fog has a distinct post-main boundary before early postprocess'`
  passed `1/1`; duplicate `-lobjc` and `-lz` linker warnings were emitted.
- `moon -C mgstudio-engine test render/renderer --target native --release --filter 'renderer: volumetric fog uses default mesh view bind group owner'`
  passed `1/1`; duplicate `-lobjc` linker warnings were emitted.
- `moon -C mgstudio-engine test render/renderer --target native --release --filter 'renderer: volumetric fog MSAA shader key keeps single-sample color pipeline'`
  passed `1/1`; duplicate `-lobjc` linker warnings were emitted.
- `moon -C mgstudio-engine test examples/3d/volumetric_fog --target native --release --filter 'volumetric_fog: runtime pass-local evidence reaches Bevy fog pass'`
  passed `1/1`; duplicate `-lobjc` and `-lz` linker warnings were emitted.

Conclusion:

- The high-level pass query, view target, fog view data, pipeline ids,
  mesh-view group ownership, MSAA key routing, color load/store behavior, and
  no-depth pass descriptor are source-shaped enough for this boundary.
- No local divergence from ISS-361 needs to be assigned to ISS-359. Continue
  with ISS-362 for the sampled depth texture input.

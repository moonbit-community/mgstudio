## Description
`examples/3d/specular_tint` exercises the specular tint render feature, but it
is not a symbol-level port of Bevy's `bevy/examples/3d/specular_tint.rs`.

The current implementation keeps the visible intent: a rotating reflective
sphere, solid specular hue cycling, a map toggle using `textures/AlphaNoise.png`,
skybox/environment lighting, and help text. The strict gaps are source-shape
issues: Bevy's `AppStatus` resource, `AppAssets::from_world`, material asset
queries, camera queries, UI text query, app-level ambient/window setup, source
sphere primitive, and color conversion anchors are replaced by a global
`SpecularTintState`, tracked handles, direct world mutation, local HSV math, and
a local UV-sphere generator.

The local sphere uses radius `1.0`, while Bevy's `Sphere::default()` radius is
`0.5`, so this is also a concrete visual/source mismatch.

## Design
Port the example directly from the Bevy source owner. Keep only local changes
that are required by concrete MoonBit language/API limitations, and record each
such limitation as a precise blocker. Do not keep global state, tracked handles,
direct world mutation, local primitive generation, or local color conversion as
the parity path when the Bevy source has a specific owner.

## Acceptance Criteria
- [ ] `AppStatus` is represented as a Bevy-shaped resource with `tint_type`
      and `hue`.
- [ ] `AppAssets` is represented as a Bevy-shaped resource loaded from world
      state, or a precise `FromWorld` capability blocker is recorded.
- [ ] `TintType` preserves Bevy's default and toggle order.
- [ ] `main` preserves Bevy's window setup, resource initialization, ambient
      insertion, startup system, update systems, chain ordering, and
      `shift_hue.after(toggle_specular_map)` ordering where the ECS API can
      express them.
- [ ] User-visible strings use mgstudio branding while preserving Bevy source
      meaning.
- [ ] `setup` exposes Bevy-shaped commands, asset server, app-status resource,
      mesh assets, and material assets where possible.
- [ ] The sphere mesh preserves `Sphere::default().mesh().uv(32, 18)` and
      therefore Bevy's default radius, or records a precise primitive-builder
      blocker.
- [ ] Solid tint creation uses the engine color API equivalent of
      `Color::hsva(app_status.hue, 1.0, 1.0, 1.0)` rather than local ad hoc HSV
      conversion.
- [ ] `rotate_camera` uses a Bevy-shaped camera query rather than a tracked
      camera entity.
- [ ] `shift_hue` uses Bevy-shaped mutable app status, material query, and
      mutable `Assets<StandardMaterial>` access.
- [ ] `toggle_specular_map` uses Bevy-shaped keyboard, app-status, app-assets,
      material query, and material asset access.
- [ ] Help text uses UI `Text` plus `Node`, and `update_text` mutates text
      through a Bevy-shaped query.
- [ ] `SpecularTintState`, tracked camera/material/noise/help handles,
      `wrap_hue_deg`, `tint_from_hue_deg`, and local `uv_sphere_mesh` are
      removed from the source-parity path unless precise blockers are
      documented.
- [ ] The reference screenshot is refreshed after the source-shaped port still
      renders correctly.

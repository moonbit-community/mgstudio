## Description
Map the Bevy source anchors that decide where volumetric fog executes relative
to Core3d main-pass work and postprocess systems.

## Design
Read Bevy's Core3d schedule and volumetric fog render plugin owners. Record the
paths and symbols for the Core3d system sets, main-pass boundary, volumetric
fog insertion point, and any skybox or atmosphere ordering constraints that are
explicitly visible in the source. Do not collect runtime evidence here.

## Acceptance Criteria
- [x] Bevy Core3d schedule and post-main system-set anchors are listed with
      paths and symbols.
- [x] Bevy volumetric fog insertion anchors are listed with paths and symbols.
- [x] Any explicit Bevy ordering relationship with skybox, atmosphere,
      transparent, or early postprocess work is classified.
- [x] No production behavior is changed.

## Close Notes
Closed on 2026-07-05 with Bevy-only source-owner schedule mapping. No
production behavior was changed.

Core3d schedule anchors:

- `bevy/crates/bevy_core_pipeline/src/schedule.rs:33`: `Core3d` is the 3D
  camera schedule label.
- `bevy/crates/bevy_core_pipeline/src/schedule.rs:37`: `Core3dSystems` defines
  the ordered 3D render sets: `Prepass`, `MainPass`, `EarlyPostProcess`,
  `PostProcess`.
- `bevy/crates/bevy_core_pipeline/src/schedule.rs:66`: `Core3d::base_schedule`
  chains `(Prepass, MainPass, EarlyPostProcess, PostProcess)`.
- `bevy/crates/bevy_core_pipeline/src/core_3d/mod.rs:146`: `Core3dPlugin`
  installs the `Core3d` schedule.
- `bevy/crates/bevy_core_pipeline/src/core_3d/mod.rs:148`: prepass systems are
  chained in `Core3dSystems::Prepass`.
- `bevy/crates/bevy_core_pipeline/src/core_3d/mod.rs:157`: Bevy chains
  `(main_opaque_pass_3d, main_transparent_pass_3d)` in
  `Core3dSystems::MainPass`.
- `bevy/crates/bevy_core_pipeline/src/core_3d/mod.rs:160`: `tonemapping` runs
  in `Core3dSystems::PostProcess`.
- `bevy/crates/bevy_core_pipeline/src/core_3d/mod.rs:161`: `upscaling` runs
  after `Core3dSystems::PostProcess`.

Volumetric fog insertion anchors:

- `bevy/crates/bevy_pbr/src/volumetric_fog/mod.rs:90`: the plugin extracts
  volumetric fog data in `ExtractSchedule`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/mod.rs:94`: pipeline preparation
  runs in `RenderSystems::Prepare`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/mod.rs:95`: uniform preparation
  runs in `RenderSystems::Prepare`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/mod.rs:96`: depth-texture usage
  preparation runs in `RenderSystems::Prepare` before
  `prepare_core_3d_depth_textures`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/mod.rs:101`: `volumetric_fog` is
  added directly to `Core3d`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/mod.rs:103`: `volumetric_fog`
  executes after `Core3dSystems::MainPass`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/mod.rs:105`: `volumetric_fog`
  executes before `Core3dSystems::EarlyPostProcess`.

Explicit in-MainPass ordering anchors relevant to the post-main boundary:

- `bevy/crates/bevy_core_pipeline/src/core_3d/main_opaque_pass_3d_node.rs:67`:
  `main_opaque_pass_3d` opens the `main_opaque_pass_3d` render pass.
- `bevy/crates/bevy_core_pipeline/src/core_3d/main_opaque_pass_3d_node.rs:83`:
  opaque phase renders first inside the opaque pass.
- `bevy/crates/bevy_core_pipeline/src/core_3d/main_opaque_pass_3d_node.rs:91`:
  alpha-mask phase renders after opaque phase.
- `bevy/crates/bevy_core_pipeline/src/core_3d/main_opaque_pass_3d_node.rs:99`:
  skybox draws inside `main_opaque_pass_3d` after opaque and alpha-mask phases.
- `bevy/crates/bevy_core_pipeline/src/core_3d/main_transparent_pass_3d_node.rs:73`:
  `main_transparent_pass_3d` opens the transparent pass after the opaque pass
  because `Core3dPlugin` chains the two main-pass systems.
- `bevy/crates/bevy_pbr/src/deferred/mod.rs:117`: deferred lighting runs in
  `Core3d` before `main_opaque_pass_3d` and in `Core3dSystems::MainPass`.
- `bevy/crates/bevy_pbr/src/ssr/mod.rs:217`: SSR runs after
  `deferred_lighting`, before `main_opaque_pass_3d`, and in
  `Core3dSystems::MainPass`.
- `bevy/crates/bevy_pbr/src/transmission/mod.rs:55`: transmission runs after
  `main_opaque_pass_3d`, before `main_transparent_pass_3d`, and in
  `Core3dSystems::MainPass`.
- `bevy/crates/bevy_core_pipeline/src/oit/mod.rs:110`: OIT resolve runs after
  `main_transparent_pass_3d` and remains in `Core3dSystems::MainPass`.

Atmosphere classification:

- `bevy/crates/bevy_pbr/src/atmosphere/mod.rs:196`: atmosphere LUT and
  environment compute work is chained after `Core3dSystems::Prepass` and
  before `Core3dSystems::MainPass`.
- `bevy/crates/bevy_pbr/src/atmosphere/mod.rs:200`: `render_sky` runs after
  `main_opaque_pass_3d` and before `main_transparent_pass_3d`.
- Therefore Bevy's volumetric fog post-main pass runs after atmosphere sky
  rendering and transparent/OIT work, because all of those anchors are inside
  `Core3dSystems::MainPass` while volumetric fog is explicitly after the whole
  MainPass set.

Postprocess boundary anchors:

- `bevy/crates/bevy_core_pipeline/src/tonemapping/node.rs:61`: tonemapping
  reads and writes through `ViewTarget::post_process_write`.
- `bevy/crates/bevy_core_pipeline/src/tonemapping/node.rs:105`: tonemapping
  opens its own `tonemapping` render pass.
- `bevy/crates/bevy_core_pipeline/src/upscaling/node.rs:67`: upscaling opens
  the final `upscaling` pass against the output attachment.
- `bevy/crates/bevy_pbr/src/volumetric_fog/mod.rs:105`: volumetric fog is
  before `EarlyPostProcess`; `Core3d::base_schedule` places EarlyPostProcess
  before PostProcess, so Bevy schedules fog before tonemapping and upscaling.

This issue does not map mgstudio fragments or runtime state. That belongs to
ISS-390 through ISS-392.

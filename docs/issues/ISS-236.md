## Description
`scrolling_fog` currently needs both the legacy erased `MeshMaterial3d` carrier
and the typed `MeshMaterial3dTyped[StandardMaterial]` carrier to satisfy all
local render paths. The erased carrier is still used by mesh visibility and
extraction fragments, while the typed carrier is required by
`MaterialPlugin[StandardMaterial]` and `material_runtime_registry_resolve_material`.

Bevy has a single generic `MeshMaterial3d<StandardMaterial>` component for this
case. Requiring examples to author both carriers is a local source-parity gap,
not an external blocker.

## Design
Audit Bevy `bevy_pbr/src/material.rs` and the mgstudio mesh/material extraction
owners. Port the render extraction path so the typed StandardMaterial component
is sufficient for visibility, render material instance extraction, material
runtime resolution, and mesh phase queueing. Remove example-level dual carrier
authoring once the owner is fixed.

## Acceptance Criteria
- [ ] StandardMaterial examples can author one Bevy-shaped typed mesh material
      component.
- [ ] Mesh visibility and shadow visibility do not require a separate erased
      material component for StandardMaterial meshes.
- [ ] `MaterialPlugin[StandardMaterial]` still resolves prepared materials for
      shadow and main-pass specialization.
- [ ] `scrolling_fog` no longer needs to spawn both `MeshMaterial3d` and
      `MeshMaterial3dTyped[StandardMaterial]`.

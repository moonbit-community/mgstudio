## Description
`examples/3d/lines` is now source-level faithful to Bevy's
`examples/3d/lines.rs` for the visual line-material case: it uses a real
`LineMaterial`, the Bevy `shaders/line_material.wgsl` asset, position-only
`LineList` and indexed `LineStrip` meshes, U16 primitive restart, and the
normal typed custom-material PBR path.

The remaining issue is not the lines example. It is the general typed material
lifecycle exposed by that example. Bevy marks entities for material
specialization when a material asset changes after it has already been
prepared. Mgstudio currently marks entities dirty when a typed material is
first prepared, but the post-preparation asset-change path still needs a
source-shaped implementation using asset event/message cursors rather than
per-frame dirty pollution or local fallback logic.

Current whitebox coverage proves that the isolated typed material path can:

- extract and prepare `MaterialPlugin[M]` / `MeshMaterial3dTyped[M]` assets;
- create render material instances and material bind-group data;
- apply the Bevy-shaped base material specialization hook;
- mark entities dirty when a typed material is first prepared;
- prewarm a mesh pipeline and queue a draw item with a pipeline id.

The native `examples/3d/lines` capture shows the expected green line list and
blue indexed line strip, with an empty WebGPU validation log. The previous
blank capture came from local mgstudio divergence in custom-material host
materialization: the renderer re-derived shader definitions from a fixed
forward-PBR default set instead of respecting the Bevy-shaped
`RenderPipelineDescriptor` produced by material specialization, and the example
used a local UV-bearing line mesh instead of Bevy's position-only `LineList` /
`LineStrip` mesh shape.

Do not restore the old unlit `StandardMaterial` approximation, add a
lines-specific path, mark material assets dirty every frame, or classify this
as an external blocker without new evidence. The correct remaining fix is to
port Bevy's asset-change-driven material specialization behavior into
mgstudio's ECS/message model.

## Design
Keep the completed Bevy `examples/3d/lines.rs` source shape intact:

- add a real `LineMaterial` asset owner with color uniform data;
- register the equivalent of `MaterialPlugin<LineMaterial>`;
- embed and bind `shaders/line_material.wgsl`;
- preserve `LineList` and `LineStrip` mesh construction, including primitive
  topology and the `u16::MAX` primitive restart index;
- keep the unlit `StandardMaterial` substitute removed.

For the remaining typed-material lifecycle gap, port the Bevy owner behavior
from `bevy_pbr/src/material.rs`:

- observe `AssetEvent<M>` / asset-change messages for typed material assets
  with a cursor so unchanged frames do not repeatedly dirty every user;
- when an already-prepared typed material is added, modified, or removed, mark
  entities using `MeshMaterial3dTyped<M>` with that asset id as needing material
  specialization;
- keep first-prepared material availability as a dirty event;
- keep extraction, preparation, prewarm, queueing, and draw binding on the
  normal typed custom-material path.

Do not solve this by polling every material every frame, restoring
`StandardMaterial`, special-casing the lines example, or adding a fallback path.
The correct fix is to make the typed custom material lifecycle match the
Bevy-shaped ownership model that the example exercises.

Source-shape anchors:

- `MaterialPlugin::<LineMaterial>`: partial. The mgstudio API surface exists
  and typed material extraction / preparation is covered by whitebox tests,
  including Bevy-shaped base material specialization and first-prepared
  material dirty propagation. A prepared typed material also prewarms and queues
  through the source-shaped PBR helper path in whitebox coverage, and the native
  line example renders through this path. The remaining partial piece is
  post-preparation typed material asset-change dirty tracking.
- `LineMaterial { color: LinearRgba }` plus `#[uniform(0)]`: complete for the
  current line example. The
  source-shaped asset and uniform bytes can be represented, and the prepared
  material binding is created and used by the native draw.
- `shaders/line_material.wgsl`: complete for the current line example. The Bevy
  shader asset exists byte-for-byte and can
  be selected by `LineMaterial`; a prepared material can specialize a mesh
  pipeline and queue a draw item with the material bind group layout in
  whitebox tests. The full native frame now proves collection, queueing, custom
  pipeline materialization, material bind-group use, and draw execution.
- `PrimitiveTopology::LineList`: complete.
- `PrimitiveTopology::LineStrip`: complete. Mgstudio preserves the indexed U16
  primitive restart mesh shape and now writes the strip index format into the
  final GPU pipeline descriptor.
- `Indices::U16([0, 1, u16::MAX, 2, 3, 4])`: complete at the mesh asset data
  model, validation, and native rendering level.

Native-frame anchors:

- render-app extraction and material instance collection: complete for the
  current failure boundary.
- render-app prewarm and phase queueing from collected entities: complete for
  the current failure boundary.
- host renderer material descriptor registration: complete for the current line
  example.
- custom pipeline creation for `pbr/render/mesh.wgsl` plus
  `shaders/line_material.wgsl`: complete for the current line example. The
  renderer now respects descriptor shader definitions from material
  specialization instead of reintroducing fixed forward-PBR vertex attribute
  defines.
- material bind-group creation and draw-command binding: complete for the
  current line example.

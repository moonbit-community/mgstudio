## Description
Map the exact Bevy source anchors and mgstudio fragments that prepare,
transport, and shader-sample directional shadow cascade data for the real
`examples/3d/volumetric_fog` path.

## Design
Read the Bevy owners before judging mgstudio. Cover the directional cascade
records, directional light depth texture base index, depth texture view or
array binding, and the fog shader's cascade selection and shadow sampling
helpers. This issue records ownership only; runtime scalar, matrix, and texture
evidence belongs to ISS-386 through ISS-388.

## Close Notes
Closed on 2026-07-05 as a source-owner mapping issue. No production code,
shader asset, or runtime behavior was changed.

Bevy source anchors and mgstudio fragments:

- Directional cascade source data:
  Bevy `bevy/crates/bevy_pbr/src/render/light.rs::prepare_lights` reads
  `ExtractedDirectionalLight.cascades`, `frusta`, and
  `cascade_shadow_config.bounds` for the active extracted view. Mgstudio maps
  this to
  `mgstudio-engine/pbr/render/light.mbt::Render3dLightingState` fields
  `directional_cascades`, `directional_cascade_bounds`, and
  `directional_cascade_overlap_proportion`.
- Cascade count and per-view texture budget:
  Bevy clamps `cascade_shadow_config.bounds.len()` to
  `MAX_CASCADES_PER_LIGHT` and only enables shadows when the current view's
  `num_directional_cascades_enabled_for_this_view + cascades` fits
  `max_texture_array_layers`. Mgstudio maps this to
  `render3d_directional_light_shadow_state`,
  `render3d_directional_light_requested_cascade_count`, and
  `render3d_collect_gpu_lights`, with `MAX_CASCADES_PER_LIGHT = 4`.
- `GpuDirectionalLight.depth_texture_base_index`:
  Bevy writes `num_directional_cascades_enabled_for_this_view` before adding
  the current light's cascade count. Mgstudio maps this to
  `render3d_collect_gpu_lights`, which writes
  `depth_texture_base_index: directional_shadow_texture_base_index` and then
  increments that local counter by `num_cascades`.
- `GpuDirectionalCascade` host layout:
  Bevy `GpuDirectionalCascade { clip_from_world, texel_size, far_bound }` and
  WGSL `mesh_view_types.wgsl::DirectionalCascade` map to
  `mgstudio-engine/pbr/render/light.mbt::GpuDirectionalCascade3d`,
  `render3d_lights_push_directional_cascade`, and the matching WGSL asset
  `mgstudio-engine/pbr/render/mesh_view_types.wgsl::DirectionalCascade`.
- Cascade record production for shadow pass:
  Bevy writes cascade records in the directional-shadow loop immediately
  before creating each cascade depth texture view. Mgstudio maps this to
  `mgstudio-engine/pbr/render_execute_camera_directional_shadow.mbt`:
  `render3d_directional_shadow_cascades`,
  `render3d_directional_cascade_pass`, and
  `render3d_directional_shadow_cascade_data`.
- Cascade records entering the lights uniform:
  Bevy fills the `GpuLights.directional_lights[light_index].cascades` array
  directly before the mesh-view bind group consumes it. Mgstudio maps this to
  `mgstudio-engine/pbr/render/light.mbt::render3d_gpu_lights_with_directional_shadow_cascades`,
  which overlays the pass-local flat cascade data onto directional light 0
  when `directional_shadow_texture_id >= 0` and the directional shadow binding
  is enabled.
- Directional shadow depth texture allocation:
  Bevy creates `directional_light_shadow_map_texture` as a D2 depth texture
  with `depth_or_array_layers = num_directional_cascades_enabled +
  spot_light_shadow_maps_count`, and creates an array view labelled
  `directional_light_shadow_map_array_texture_view`. Mgstudio maps this to
  `render3d_prepare_camera_directional_shadow_pass`, which allocates or reuses
  the directional/spot shadow target through
  `render3d_directional_spot_shadow_target_layers` and
  `render3d_directional_light_shadow_target_get_or_create`.
- Per-cascade depth attachment:
  Bevy creates one D2 texture view per cascade with
  `base_array_layer = directional_depth_texture_array_index` and
  `array_layer_count = Some(1)`, then increments the array index. Mgstudio maps
  this to `Render3dShadowView.target_layer = cascade_index` and
  `render3d_shadow_view_begin_pass`, which begins the shadow pass on the same
  target id and per-cascade layer.
- Camera-to-shadow binding handoff:
  Bevy passes `shadow_bindings.directional_light_depth_texture_view` into the
  mesh-view bind group at binding 5. Mgstudio maps this to
  `Render3dDirectionalShadowBinding.texture_id`, the
  `Render3dViewShadowBindings` value returned from
  `render3d_prepare_camera_directional_shadow_pass`, and
  `render3d_execute_camera_main_pass` /
  `render3d_execute_camera_volumetric_fog_pass` forwarding
  `directional_shadow_texture_id`.
- Mesh-view shader binding slots:
  Bevy `mesh_view_bindings.wgsl` declares
  `directional_shadow_textures` at group 0 binding 5,
  `directional_shadow_textures_comparison_sampler` at binding 6, and the PCSS
  linear sampler at binding 7 when available. Mgstudio's
  `mgstudio-engine/pbr/render/mesh_view_bindings.wgsl` has the same WGSL
  slots. The backend fragment is
  `mgstudio-engine/render/renderer/mesh3d_bind_groups.mbt::mesh3d_add_view_bind_group_layout_entry`,
  which binds the directional shadow texture view at binding 5 and a comparison
  sampler at binding 6.
- Sampler resource owner:
  Bevy `render/light.rs::{ShadowSamplers,init_shadow_samplers}` creates a
  directional comparison sampler with `CompareFunction::GreaterEqual` and
  linear min/mag filtering. Mgstudio maps this partially through
  `mesh3d_bind_groups.mbt::mesh3d_add_view_bind_group_layout_entry`: binding 6
  currently reuses the existing comparison sampler object supplied as
  `point_shadow_compare_sampler`. This is not an external blocker because the
  required sampler descriptor is expressible locally; ISS-388 must prove
  whether this descriptor-level reuse is behaviorally equivalent enough or
  whether a source-shaped local repair is needed.
- Fog shader cascade selection and sampling:
  Bevy `volumetric_fog/volumetric_fog.wgsl` calls
  `get_cascade_index(light_index, P_view.z)`,
  `world_to_directional_light_local`, computes
  `array_index = depth_texture_base_index + cascade_index`, and calls
  `sample_shadow_map_hardware`. Mgstudio's
  `mgstudio-engine/pbr/volumetric_fog/volumetric_fog.wgsl` has the same read
  and call anchors.
- Shadow helper functions:
  Bevy `render/shadows.wgsl::{get_cascade_index,
  world_to_directional_light_local,sample_directional_cascade}` and
  `render/shadow_sampling.wgsl::sample_shadow_map_hardware` map to
  `mgstudio-engine/pbr/render/shadows.wgsl` and
  `mgstudio-engine/pbr/render/shadow_sampling.wgsl`.

No hard external blocker was found. The only source-shape concern discovered
here is local sampler ownership reuse at binding 6, which remains an ISS-388
runtime/source evidence question rather than an external dependency issue.

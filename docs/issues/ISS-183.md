## Description
Bevy's `prepare_volumetric_fog_uniforms` owns the uniform-buffer lifecycle for
the current render prepare pass. It computes the required uniform count from
the number of volumetric-fog views and fog volumes, writes host-layout
`VolumetricFogUniform` values, and uses dynamic byte offsets consumed by the
volumetric fog draw pass.

Mgstudio already has uniform packing helpers, but the reset/allocation/upload
ownership is still mixed with local camera execution. That makes it hard to
prove Bevy source parity and risks stale or duplicate uniform entries.

## Design
Audit Bevy `prepare_volumetric_fog_uniforms` and move mgstudio's
`VolumetricFogUniformBuffer` reset, capacity/count decision, write path, and
upload into a standalone prepare owner that consumes render-world state. Keep
the WGSL host layout and dynamic offset arithmetic unchanged unless direct
Bevy source comparison proves a mismatch.

## Acceptance Criteria
- [x] Uniform count is derived from render-world volumetric-fog views multiplied by render-world fog volumes.
- [x] Uniform buffer reset/allocation/write/upload happens in the standalone volumetric-fog prepare owner.
- [x] Dynamic byte offsets are deterministic and match the existing WGSL host layout.
- [x] Focused tests cover zero-view, zero-volume, and multi-view/multi-volume offset cases.

## Close Notes
2026-07-04: Added a standalone render-world
`render3d_prepare_volumetric_fog_uniform_buffer` owner in
`pbr/volumetric_fog_execute.mbt`. It clears the shared
`VolumetricFogUniformBuffer`, derives uniform count from prepared volumetric-fog
views times render-world fog volumes, writes uniforms through the existing
Bevy-shaped packing helper, uploads the buffer once through the renderer host
API, and returns prepared per-view uniform metadata for the next source-owner
slice.

The old camera-local prepare path now delegates to this owner instead of
pushing directly into the shared uniform buffer. Camera execution still owns the
call site until ISS-186 moves prepare scheduling to the Bevy-shaped render
prepare phase.

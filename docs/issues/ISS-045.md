## Description
The `examples/2d/2d_shapes` failure exposed a real semantic bug: `Mesh2d`
assets backed by Bevy-shaped `Mesh` data were being uploaded through a legacy
3D mesh path that did not preserve the 2D material vertex layout. That path has
been corrected for the example, but the broader Mesh2d render chain has not yet
been audited against Bevy's source owners.

The relevant Bevy owners include `bevy_sprite_render/src/mesh2d/mesh.rs`,
`bevy_sprite_render/src/mesh2d/material.rs`,
`bevy_sprite_render/src/mesh2d/color_material.rs`,
`bevy_sprite_render/src/mesh2d/wireframe2d.rs`, and the render-phase integration
in `bevy_sprite_render/src/render/mod.rs`.

## Design
Use Bevy source owner files as the audit unit. Classify each source-shape anchor
as complete, facade, partial, or blocked, then replace any local upload/cache
behavior that is only visually plausible with Bevy-shaped extraction,
preparation, queueing, specialization, and draw-command behavior.

## Acceptance Criteria
- [x] Inventory the Mesh2d-related Bevy source owners listed in the description.
- [x] Map each owner to concrete mgstudio fragments under `sprite_render/mesh2d`, `sprite_render/render`, `sprite/sprite_mesh.mbt`, and related render packages.
- [ ] Verify that mesh extraction, material extraction, render asset preparation, pipeline specialization, phase item queueing, and draw setup are source-shaped rather than local immediate-mode behavior.
- [ ] Add tests that catch missing typed vertex layout, wrong primitive topology, stale mesh upload cache invalidation, and material specialization mismatch.
- [ ] Validate with targeted `sprite_render/mesh2d`, `sprite_render/render`, `sprite`, and representative mesh2d example gates under `--release`.

## Notes
- 2026-06-05: The current typed Mesh2d upload fix is directionally correct because Bevy's `Mesh2d` wraps `Handle<Mesh>`. It does not by itself prove that the full Mesh2d extraction, preparation, queueing, specialization, and draw-command chain is source-equivalent.
- 2026-06-12: Source-owner inventory:
  `bevy_sprite_render/src/mesh2d/mod.rs` maps to `sprite_render/mesh2d/top.mbt`;
  `mesh2d/mesh.rs` currently spans `sprite_render/mesh2d/runtime/top.mbt`,
  `sprite_render/render/runtime.mbt`, and `render/renderer/mesh2d_draw.mbt`;
  `mesh2d/material.rs` maps to `sprite_render/mesh2d/material/top.mbt` plus
  render-runtime queue/draw fragments; `mesh2d/color_material.rs` maps to
  `sprite_render/mesh2d/color_material/top.mbt`; `mesh2d/wireframe2d.rs` maps
  to `sprite_render/mesh2d/wireframe2d/top.mbt`; shader owners are embedded
  under `sprite_render/mesh2d/*.wgsl` and generated runtime source loaders.
- 2026-06-12: `Mesh2d` extraction and draw setup remain partial source-shape:
  mgstudio extracts Bevy-shaped `Mesh2d`, material, transform, render layers,
  and wireframe state, but the phase queue and renderer execute path still use
  the monolithic render2d runtime instead of Bevy's
  `RenderMesh2dInstances`, `ViewKeyCache`, `SpecializedMaterial2dPipelineCache`,
  pending queues, and render-command tuple owner boundaries.
- 2026-06-12: Material specialization is partial. mgstudio preserves
  `mesh_key`, material layout key, and material bind-group data in prepared
  assets/cache keys, but lacks Bevy's `Material2d::specialize` hook that can
  mutate the pipeline descriptor from `Material2dKey<M>`. Tracked separately in
  ISS-071.
- 2026-06-12: Added renderer whitebox tests for Mesh2d pipeline cache key
  separation across primitive topology, material layout, and shader paths, plus
  material bind-group cache separation between layout and data. Validation:
  `moon -C mgstudio-engine test render/renderer --release`,
  `moon -C mgstudio-engine test sprite_render/render --release`,
  `moon -C mgstudio-engine test sprite_render/mesh2d --release` (build passed,
  no test entry), `moon -C mgstudio-engine test sprite --release`,
  `moon -C mgstudio-engine check --target native --package-path render/renderer`,
  `moon -C mgstudio-engine check --target native --package-path sprite_render/render`,
  `moon -C mgstudio-engine info`, and 2D shapes capture compared against

## Description
`examples/3d/physics3d_sanity` still has a fully transparent checked-in
`reference.png`. A standard native capture run succeeds and passes the generic
nonblank image statistics, but manual review rejects the generated frame: the
source creates a red dynamic body, a gray floor, a point light, and ambient
light, while the capture shows the floor and body as nearly black silhouettes.

This should not be accepted as a reference image because it would preserve a
local render/material visibility bug as the baseline.

## Design
Audit the example and its render chain against the intended local source:

- the `StandardMaterial` color and lighting data should reach the PBR draw path;
- the floor mesh orientation and collider setup should not hide or backface the
  visible surface;
- the falling body should remain visibly colored at the capture frame or the
  capture timing/camera should be adjusted only if that matches the example's
  intended behavior;
- the fix must not use an unlit material or screenshot-only workaround unless
  the example is explicitly meant to test unlit rendering.

This is not an external dependency blocker unless investigation proves a
specific missing MoonBit, wgpu_mbt, or backend capability.

## Acceptance Criteria
- [ ] `examples/3d/physics3d_sanity` renders visibly colored scene content
      matching its material and lighting setup.
- [ ] The refreshed `reference.png` passes automated image sanity and manual
      visual inspection.
- [ ] The run log contains no validation, fatal, missing-resource, or renderer
      error output.
- [ ] ISS-060 is updated with the accepted refresh metrics.

## Description

Raw tables own entities and change metadata while `ComponentKey[T]` closures own
typed values. Structural insert, move, swap-remove, take, despawn, rollback, and
world close therefore coordinate two storage authorities. Test a table-owned
transaction boundary that moves payload and metadata together while preserving
typed MoonBit storage.

## Acceptance Criteria

- [x] The design is mapped source-by-source to pinned-Bevy table move and
      column ownership semantics.
- [x] Insert, replace, move, take, remove, despawn, rollback, and close preserve
      exactly-once finalization.
- [x] The retained path does not expose an intermediate raw/typed mismatch.
- [x] One focused ECS structural test runs at a time with
      `MOONBIT_NEW_NATIVE=1`.
- [x] `examples/3d/despawn3` is the only runtime example gate.
- [x] The retained/rejected decision follows the `ISS-444` experiment protocol.

## Notes

- 2026-07-16: The pinned Bevy baseline owns component payload, added/changed
  ticks, and changed caller metadata in one `Column`. During
  `Tables::move_row`, `Column::initialize_from_unchecked` swap-removes all four
  source buffers and initializes the destination row in one operation
  (`bevy/crates/bevy_ecs/src/storage/table/mod.rs` and
  `storage/table/column.rs`). Removed source-only columns use the same
  `swap_remove_unchecked::<DROP>` boundary.
- 2026-07-16: The isolated MoonBit variable is one combined typed payload
  transfer for shared columns. Today target append calls
  `ComponentOps::move_table_row`, then source removal separately calls
  `ComponentOps::swap_remove_table_row`, causing two typed per-world store
  lookups. The prototype will first finish every fallible raw target-column
  preparation, then transfer and source-swap-remove a shared typed payload in
  one component operation. Source raw metadata removal remains table-owned;
  source-only typed values still use the existing removal path.
- 2026-07-16: The pre-change `insert velocity migration x5000` benchmark was
  `25.65 ms` and `28.17 ms` (mean `26.91 ms`). Two instrumented
  `examples/3d/despawn3` runs crossed the first five-second despawn, printed
  one removal, and ended at `1614.70 ms` and `1615.72 ms` frame time (mean
  `1615.21 ms`). The instrumentation is measurement-only and is not committed.
- 2026-07-16: The example gate uses
  `MGSTUDIO_RENDER3D_DISABLE_GPU_PREPROCESS=1`, matching the repository's
  native capture default. Without it, the unchanged baseline aborts on frame
  three with `Missing MeshInputUniform for queued pbr GPU mesh instance`.
- 2026-07-16: A first coordination prototype allocated an `IntBitSet` per
  migration. Its final isolated measurements were `28.85 ms` and `27.72 ms`
  (mean `28.29 ms`), a `5.1%` regression, so that implementation was discarded.
  The retained implementation instead linearly merges the already sorted,
  unique source and target table signatures. It allocates no coordination
  container and performs no repeated raw-table component lookup.
- 2026-07-16: Shared typed payload transfer and source swap-remove now execute
  through one `ComponentOps` call and one `stores_by_world` lookup. Raw target
  rows and metadata are prepared first; typed ownership is then transferred;
  the source raw metadata is swap-removed without dispatching a second typed
  removal. There is no callback or public world access inside that transaction.
  Source-only columns retain the existing remove/take/finalizer path.
- 2026-07-16: The final `insert velocity migration x5000` measurements were
  `27.04 ms` and `26.72 ms` (mean `26.88 ms`) versus the `26.91 ms` baseline,
  effectively neutral at `0.11%` faster. The implementation is retained under
  the protocol's lookup-removal clause: every shared component migration
  removes one typed per-world Map lookup without introducing an allocation.
- 2026-07-16: The focused canonical-row migration, table-column length,
  finalizer ownership, remove-hook visibility, and archetype swap-remove tests
  each passed separately under native release. Together they cover insert,
  replace, move, take, remove, despawn, rejected stale insertion, rollback
  behavior, and idempotent world close.
- 2026-07-16: Two final `examples/3d/despawn3` runs both crossed the first
  five-second timer and printed exactly one tagged-cube removal. Final frame
  times were `1645.77 ms` and `1642.38 ms` (mean `1644.08 ms`), a `1.79%`
  regression from the `1615.21 ms` baseline and below the protocol's `3%`
  total-frame limit. Measurement-only diagnostics were removed before commit.

## Close Notes

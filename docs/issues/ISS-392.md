# ISS-392: Map mgstudio volumetric fog postprocess and final-copy anchors

## Description
Map the mgstudio fragments that consume the volumetric fog pass output after
the fog draw and carry it through postprocess, tonemapping, color conversion,
and final surface copy.

## Design
Use the Bevy and mgstudio camera maps from ISS-389 through ISS-391. Record the
mgstudio paths and symbols for postprocess entry, exposure, tonemapping,
upscaling or final-copy work, and final surface presentation. Classify each
anchor as complete, partial, facade, blocked, or missing so ISS-383 and
ISS-384 can collect targeted evidence instead of rediscovering ownership.

## Acceptance Criteria
- [x] Mgstudio postprocess entry anchors are listed with paths and symbols.
- [x] Mgstudio exposure, tonemapping, color-space, and final-copy anchors are
      listed with paths and symbols or marked missing.
- [x] Each mapped anchor is classified as complete, partial, facade, blocked,
      or missing.
- [x] No production behavior is changed.

## Notes
- 2026-07-05: Split from ISS-381 so downstream color/final-copy ownership is
  ready before ISS-383 and ISS-384 collect runtime evidence.
- 2026-07-05: Bevy comparison anchors:
  `bevy/crates/bevy_core_pipeline/src/tonemapping/node.rs::tonemapping` calls
  `ViewTarget::post_process_write`, reads `PostProcessWrite.source`, writes
  `PostProcessWrite.destination`, and therefore flips the main texture selector.
  `bevy/crates/bevy_core_pipeline/src/upscaling/node.rs::upscaling` then reads
  `ViewTarget::main_texture_view` and writes `ViewTarget::out_texture_color_attachment`.
  `bevy/crates/bevy_render/src/renderer/mod.rs::render_system` presents a
  window when any matching view target reports `needs_present`.
- 2026-07-05: Mgstudio postprocess entry anchor:
  `mgstudio-engine/pbr/render_execute_camera_postprocess.mbt::render3d_execute_camera_postprocess`
  is the real 3D postprocess owner. It receives `scene_target_id` after the
  volumetric fog call from `render3d_execute_camera`, carries a mutable
  `final_source_texture_id`, and runs motion blur, TAA, auto exposure, bloom,
  effect-stack, custom postprocess, tonemapping, FXAA, CAS, and final-present
  fallback branches by directly opening renderer passes through host GPU calls.
  Classification: partial. The ordering is explicit and inspectable, but the
  owner shape is a monolithic immediate camera runner rather than Bevy render
  graph nodes.
- 2026-07-05: Mgstudio postprocess ping-pong anchor:
  `render3d_postprocess_stage_target` chooses between `scene_target_id`,
  `render3d_transmission_source_target_get_or_create`, and `camera.target_id`
  from a stage index and stage count. `render3d_postprocess_ping_target_get_or_create`
  allocates the ping target as an RGBA16F render target. Classification:
  facade/partial. This approximates Bevy's `ViewTarget::post_process_write`
  source/destination alternation, but there is no `ViewTarget` selector, no
  `PostProcessWrite` contract, and no single main-texture owner at this boundary.
- 2026-07-05: Mgstudio tonemapping facade anchors:
  `mgstudio-engine/core_pipeline/tonemapping/node.mbt` mirrors Bevy node names,
  state predicates, and bind-group cache shapes. Classification: facade for 3D
  runtime execution, because the actual 3D path does not execute this node; it
  calls `render3d_draw_camera_tonemapping_stage` inside the camera postprocess
  runner.
- 2026-07-05: Mgstudio tonemapping execution anchors:
  `render3d_draw_camera_tonemapping_stage` maps `Exposure`, `Tonemapping`,
  `DebandDither`, `ColorGrading`, and LUT handles to
  `@render.host_gpu_draw_tonemapping3d`. The renderer implementation is
  `mgstudio-engine/render/renderer/gpu_tonemapping.mbt::GpuBackend::draw_tonemapping3d`
  and `draw_tonemapping3d_fullscreen`: it ends the active pass, reads the source
  texture by id, chooses the current pass target format, writes the tonemapping
  view uniform, begins a color-load pass on `target_view(pass_state.target_id,
  pass_state.target_layer)`, draws a fullscreen triangle, then reopens the
  saved pass. Classification: partial. Shader/pipeline input shape is close to
  Bevy's tonemapping pass, but target handoff and pass lifetime are renderer
  local and do not use `ViewTarget::post_process_write`.
- 2026-07-05: Mgstudio exposure anchor:
  `render3d_apply_camera_auto_exposure` maps `AutoExposure`, color grading,
  metering mask, compensation curve data, and viewport size to
  `@render.host_gpu_apply_auto_exposure`; the tonemapping stage calls
  `@render.host_gpu_activate_auto_exposure_view_state` before drawing when auto
  exposure is present. Classification: partial. Data flow exists, but ownership
  is inside the immediate postprocess runner rather than Bevy's render systems.
- 2026-07-05: Mgstudio final-copy anchors:
  When there are no later postprocess stages, or when only a final source
  texture remains, `render3d_execute_camera_postprocess` begins a pass on
  `camera.target_id` and either reroutes bloom through
  `render3d_draw_camera_tonemapping_stage` or draws the source with
  `@render.host_gpu_draw_sprite_uv`. `host_gpu_draw_sprite_uv` reaches
  `mgstudio-engine/render/renderer/gpu_sprite.mbt::GpuBackend::draw_sprite_uv`,
  which batches a sprite draw rather than using Bevy's blit/upscaling path.
  Classification: partial/facade. This is not Bevy-shaped final copy and should
  be treated as a local parity gap, not an external blocker.
- 2026-07-05: Mgstudio blit/upscaling facade anchors:
  `mgstudio-engine/core_pipeline/upscaling/node.mbt` and
  `mgstudio-engine/core_pipeline/blit/top.mbt` mirror Bevy-facing node/plugin
  surfaces, and `mgstudio-engine/render/renderer/gpu_blit.mbt::GpuBackend::draw_blit`
  provides a fullscreen blit implementation. Classification: facade for this 3D
  path unless a caller is wired into the camera graph. The current 3D
  postprocess final-present branches mostly do not use `draw_blit`.
- 2026-07-05: Mgstudio present anchors:
  `mgstudio-engine/render/schedule.mbt::render_system` runs the render graph,
  prepares active frame submissions, flushes pending command buffers, and
  presents active frames. `mgstudio-engine/render/renderer/window_surface.mbt`
  marks a frame as needing present from `target_view`, submits encoded frame
  command buffers in `prepare_frame_submission_binding`, and calls
  `surface.present()` from `present_frame_binding` when the frame binding says
  it should present. Classification: partial. It mirrors Bevy's submit/present
  phase shape but does not ask `ViewTarget::needs_present`; present intent is
  derived from renderer target-view access and initial-present state.
- 2026-07-05: Local missing anchor, not external blocker: there is no source-level
  Bevy `ViewTarget` postprocess owner for 3D. The missing owner must be repaired
  locally before ISS-383 and ISS-384 can claim Bevy-level pass ordering,
  exposure, tonemapping, and final-copy parity.

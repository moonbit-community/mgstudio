# ISS-243: Restore shadow pipeline specialization to shadow view layout

## Description
The `scrolling_fog` shadow phase item currently reaches draw execution with a
cached material descriptor id whose already-materialized WGPU pipeline has the
prepass view layout. Bevy's shadow pass binds the light-view shadow bind group,
so the WGPU pipeline selected for a shadow draw must be specialized through a
shadow-compatible pipeline layout.

## Design
Compare Bevy `specialize_shadows` and material prepass specialization against
mgstudio's `render3d_shadow_specialization_apply_work_item` and renderer
material-pipeline registry. Mgstudio's `CachedRenderPipelineId` is also used as
a renderer descriptor key, so the fix must keep the phase item's cached id while
making shadow draw select a shadow-depth WGPU pipeline derived from the
registered descriptor. Do not make the pass bind a prepass view group, clear the
cached phase pipeline id, or silently fall back to a default depth-only
pipeline.

## Acceptance Criteria
- [x] Shadow draw no longer reuses an already-materialized prepass/main
      material WGPU pipeline for non-default cached material descriptor ids.
- [x] The selected shadow pipeline layout is compatible with the shadow view
      bind group used by the render pass.
- [x] Depth-only shadow materials preserve Bevy's material bind-group
      semantics instead of introducing a local workaround.
- [x] A focused regression test or native capture fails before the fix and
      passes after the fix by asserting the shadow phase item's pipeline/layout
      owner is shadow-compatible.

## Notes
- 2026-07-04: Split from ISS-235 because pipeline specialization is a distinct
  source owner from pass iteration and final screenshot validation.
- 2026-07-04: During implementation, the local source boundary was clarified:
  mgstudio keeps Bevy's phase cached-pipeline id as a renderer descriptor key,
  while the host renderer owns materializing the pass-specific WGPU pipeline.
  The bug was therefore in shadow draw pipeline selection, not in erasing the
  cached phase id.

## Close Notes
2026-07-04: Closed after changing renderer shadow pipeline selection so
non-default cached material descriptor ids no longer return the already
materialized material/prepass render pipeline. `mesh3d_shadow_depth_pipeline_for_draw`
now routes through `mesh3d_shadow_depth_pipeline_for_current_pass`, which builds
or reuses a shadow-depth WGPU pipeline with `mgstudio_mesh3d_shadow_view_bgl`.
If a non-default cached descriptor id has not been registered yet, the shadow
pipeline remains pending instead of falling back to an unrelated default
pipeline.

This preserves the Bevy-shaped shadow phase item pipeline id while fixing the
host renderer materialization boundary. Depth-only material bind-group
selection remains owned by the existing shadow phase queue semantics; the fix
does not bind a prepass view group, clear the phase pipeline id, or install a
fallback draw path.

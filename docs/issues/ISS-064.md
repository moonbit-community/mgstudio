# ISS-064: Port Bevy Wireframe3d phase and pipeline source owners

- Assignee: unassigned

- Updated: 2026-06-11
- External ref: none

## Description
`examples/3d/wireframe` now captures a usable reference, but mgstudio's 3D
wireframe implementation is still not source-level equivalent to Bevy's
`bevy/crates/bevy_pbr/src/wireframe.rs`. The current mgstudio path converts
triangle meshes into generated line-list meshes and draws them through the
regular PBR main pass. Bevy owns a dedicated `WireframePlugin`,
`Wireframe3d` binned phase, thin and wide wireframe draw commands, specialized
wireframe pipelines, extracted render resources, and a `wireframe_3d` Core3d
node that runs after the main pass and before early postprocess.

## Design
Audit the Bevy source owner symbol by symbol before editing mgstudio. Replace
the local generated-line-list approximation with Bevy-shaped ownership where
the current MoonBit renderer can express it. If an exact symbol requires a real
backend or language capability that does not exist, record that blocker
explicitly; do not classify local approximations as blockers.

## Acceptance Criteria
- [ ] Every in-scope struct, resource, component, system, render command,
      pipeline key, and plugin hook in `bevy_pbr/src/wireframe.rs` is classified
      as complete, partial, blocked, facade, or intentionally excluded.
- [ ] `WireframePlugin` installs Bevy-equivalent main-world and render-world
      resources and systems instead of only initializing `WireframeConfig`.
- [ ] `Wireframe3d` is represented as its own render phase or an explicitly
      documented equivalent phase boundary, not as extra regular main-pass
      mesh draws.
- [ ] Thin and wide wireframe pipeline specialization are ported or blocked
      with exact missing backend capability notes.
- [ ] `examples/3d/wireframe` still captures a nonblank checked-in
      `reference.png` after the source-owner migration.

## Notes
- 2026-06-10: Created after fixing the immediate `examples/3d/wireframe`
  capture crash. The crash fix only corrected the generated-line-list upload
  ABI so the current approximation can render; it did not port Bevy's dedicated
  `Wireframe3d` phase, render commands, wide-line vertex pulling path, or
  pipeline specialization ownership.
- 2026-06-11: Source-owner inventory started against
  `bevy/crates/bevy_pbr/src/wireframe.rs`. Current classification:
  `Wireframe`, `NoWireframe`, and `WireframeColor` are partial authoring
  mappings; `WireframeLineWidth`, `WireframeTopology`, `WireframeMaterial`,
  `RenderWireframeMaterial`, `Mesh3dWireframe`, and
  `WireframeEntitiesNeedingSpecialization` were added as source-shaped data
  symbols. `WireframeConfig` now carries Bevy's `default_line_width` and
  `default_topology` fields, and mesh extraction now preserves optional
  per-entity line width/topology data. Remaining major local gap: mgstudio still
  draws generated line-list meshes through the regular PBR main pass instead of
  Bevy's dedicated `Wireframe3d` binned phase, thin/wide render commands,
  `Wireframe3dPipeline`, `SpecializedWireframePipelineCache`, and `wireframe_3d`
  Core3d node.
- 2026-06-11: Ported the main-world material application part of
  `bevy_pbr/src/wireframe.rs`: `WireframePlugin` now initializes a
  `GlobalWireframeMaterial` from `WireframeConfig`, registers a PostUpdate
  material application system, maps explicit `Wireframe` entities to
  `Mesh3dWireframe(Handle<WireframeMaterial>)`, applies global wireframe
  material to `Mesh3d` entities when `WireframeConfig.global` is true, and
  removes `Mesh3dWireframe` from `NoWireframe` entities. Targeted validation:
  `moon -C mgstudio-engine check --target native --package-path pbr` and
  `moon -C mgstudio-engine test pbr --release` passed. Remaining local gap:
  change-driven material refresh, removed-component cleanup, and the dedicated
  render-world `Wireframe3d` phase/pipeline were still partial at this point.
- 2026-06-11: Ported the change-driven main-world material refresh systems:
  `WireframeConfig` changes now update the shared global material and refresh
  explicit wireframe material handles, `WireframeColor`, `WireframeLineWidth`,
  and `WireframeTopology` changed-component streams refresh existing
  `Mesh3dWireframe` handles, and removed `Wireframe` components remove the
  internal material before the global pass can reapply it when global wireframe
  is enabled. Targeted validation:
  `moon -C mgstudio-engine check --target native --package-path pbr` and
  `moon -C mgstudio-engine test pbr --release` passed with 148 tests.
  Remaining local gap: the dedicated render-world `Wireframe3d` phase,
  thin/wide render commands, pipeline cache, and Core3d node are still partial.
- 2026-06-11: Added source-shaped render-world wireframe phase data owners:
  `Wireframe3d`, `Wireframe3dBatchSetKey`, `Wireframe3dBinKey`,
  `WireframePhaseItemExtraIndex`, `WireframePipelineKey`,
  `SpecializedWireframePipelineCache`,
  `SpecializedWireframeViewPipelineCache`, and `PendingWireframeQueues`.
  The batch key preserves Bevy's thin indexed path versus wide non-indexed path
  split, and the pipeline key preserves the `wide`, `quads`, and `line_mode`
  rules derived from `RenderWireframeMaterial`. Targeted validation:
  `moon -C mgstudio-engine check --target native --package-path pbr` and
  `moon -C mgstudio-engine test pbr --release` passed with 153 tests.
  Remaining local gap: these structures are not yet wired into
  `specialize_wireframes`, `queue_wireframes`, thin/wide render commands, or a
  `wireframe_3d` Core3d node.
- 2026-06-11: Replaced the render extraction/main-pass wireframe decision with
  a real `Mesh3dWireframe` material instance path. Mesh extraction now carries
  the internal wireframe material asset id and resolved `RenderWireframeMaterial`
  from the `Assets<WireframeMaterial>` store, and the draw path only treats a
  mesh as wireframe-capable when that extracted instance exists. This removes
  the previous render-side need to infer wireframe visibility from
  `WireframeConfig.global` or rebuild a temporary wireframe material from
  authoring components. Remaining local gap: the current drawing backend still
  feeds the extracted instance into the legacy generated-line-list main-pass
  path instead of Bevy's dedicated `Wireframe3d` phase and commands.

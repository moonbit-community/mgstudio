## Description
Bevy's volumetric fog pass reuses `MeshViewBindGroup.main` as group 0, so the
lights uniform, directional shadow texture array, comparison sampler, view
uniform, and dynamic offsets must be exactly the same resources that the mesh
view pipeline prepared for the camera view. Mgstudio must not use a separate
renderer-local reinterpretation that happens to make the shader run.

## Design
Compare Bevy `prepare_mesh_view_bind_groups`, `MeshViewBindGroup`, and
`volumetric_fog` render command setup against mgstudio renderer pass state and
`mesh3d_volumetric_fog_pass`. Fix binding-slot or dynamic-offset divergence
source-faithfully.

## Acceptance Criteria
- [x] Mgstudio's volumetric fog group 0 binding slots match Bevy's mesh-view
      layout for lights, view, directional shadow texture, and directional
      shadow sampler.
- [x] Dynamic offsets used for the view uniform and any per-view uniform data
      match Bevy's render command semantics.
- [x] The pass uses the Bevy-shaped PBR lights uniform bytes from the active
      camera view when available; any fallback path is either unreachable for
      PBR volumetric fog or tracked as a separate cleanup issue.
- [x] A focused renderer or PBR white-box test proves the bind group receives
      the same lights uniform and directional shadow resource identity prepared
      for the camera view.

## Notes
- 2026-07-04: Split from ISS-213 because Bevy's mesh-view bind group ownership
  is a separate source boundary from PBR light uniform packing.
- 2026-07-05: Audited Bevy
  `bevy_pbr/src/render/mesh_view_bindings.rs::prepare_mesh_view_bind_groups`
  and `bevy_pbr/src/volumetric_fog/render.rs::volumetric_fog`. Bevy stores
  `MeshViewBindGroup { main, main_offsets, binding_array, empty }`, builds
  `main_offsets` as `[ViewUniformOffset, ViewLightsUniformOffset,
  ViewLightProbesUniformOffset, ...optional dynamic offsets]`, and the
  volumetric fog pass calls
  `render_pass.set_bind_group(0, &view_bind_group.main,
  &view_bind_group.main_offsets)`. Mgstudio's matching renderer path is
  `render/renderer/mesh3d_volumetric_fog_pass.mbt`, which obtains group 0
  through `mesh3d_frame_view_bg_cache_get_or_create`, passes the resulting
  `view_offsets` to `set_bind_group(0U, view_bg, view_offsets)`, and uses
  `mesh3d_lights_uniform_bytes(pass_state)` from the frame-local pass uniform
  state.

## Close Notes
Closed after locking the source-owner boundary with renderer white-box tests.
The implementation now exposes the active-pass shadow texture selection through
small private helpers used by the production draw path, so tests cover the same
resource identity decision as the volumetric fog pass itself.

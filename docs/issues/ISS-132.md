## Description
Several Bevy examples require a standalone 3D custom material family:
`MaterialPlugin<M>`, `Assets<M>`, `MeshMaterial3d<M>`, `impl Material for M`,
and `AsBindGroup`-owned shader bindings. Mgstudio currently has standard
material support and a local `ExtendedMaterial<StandardMaterial, E>` metadata
path, but that path is not the same source owner. It cannot faithfully express
examples such as `ColorGradientMaterial` in `examples/3d/tonemapping.rs` or
`LineMaterial` in `examples/3d/lines.rs`.

## Design
Port the Bevy 3D custom-material owner before fixing examples that depend on
it. The implementation should preserve the source-level roles:

- a `Material` trait surface with shader hooks and material specialization;
- a generic `MaterialPlugin<M>` registration path for the main app and render
  app;
- `Assets<M>` extraction/prepare/queue ownership;
- `MeshMaterial3d<M>` or an equivalent typed material handle that does not
  collapse custom materials into `StandardMaterial`;
- bind group layout and binding ownership corresponding to Bevy `AsBindGroup`;
- compatibility with existing standard and extended material paths without
  replacing them with local workaround semantics.

Do not implement example-local substitutes. If MoonBit cannot express one of
the Bevy generic or derive-shaped anchors, record that exact language/API gap
instead of hiding it behind erased JSON payloads or standard-material metadata.

## Acceptance Criteria
- [x] `MaterialPlugin<M>` has a Bevy-shaped mgstudio owner for standalone 3D
      material families.
- [x] `MeshMaterial3d<M>` or its exact mgstudio equivalent can reference
      `Assets<M>` without routing through `StandardMaterial`.
- [x] Fragment shader hooks can load Bevy WGSL assets such as
      `shaders/tonemapping_test_patterns.wgsl` and `shaders/line_material.wgsl`.
- [x] Uniform and texture bindings can be represented without JSON-erased
      payloads.
- [x] `ISS-128` and the custom-material part of `ISS-083` can be implemented
      without example-local workarounds after this closes.

## Close Notes
Closed on 2026-06-19.

Implemented a Bevy-shaped standalone 3D custom material owner in
`mgstudio-engine/pbr/material_plugin.mbt`:

- `Material` trait hooks for shader paths, alpha/render method, prepass/shadow
  enablement, typed bind group ownership, and specialization;
- `MaterialPlugin<M>` registering `Assets<M>`, prepared render assets, typed
  material instances, and a 3D runtime registry;
- `MeshMaterial3dTyped<M>` as the mgstudio equivalent of Bevy
  `MeshMaterial3d<M>` because the legacy non-generic `MeshMaterial3d` name is
  already occupied by the standard-material path;
- `MaterialBindGroup`/`MaterialBinding` for uniform, texture, and sampler
  payloads backed by `MaterialBindGroupResolvedData`, not JSON-erased payloads;
- 3D extraction now accepts optional legacy `MeshMaterial3d` and resolves typed
  custom materials through the runtime registry.

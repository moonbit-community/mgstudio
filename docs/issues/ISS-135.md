## Description
While closing ISS-122, `examples/3d/anti_aliasing` exposed two cross-owner
source-shape gaps that should not be hidden inside the anti-alias example:

- Bevy's `examples/3d/anti_aliasing.rs` spawns UI as `Text::default()` plus an
  absolute `Node`; mgstudio currently needs an explicit `Camera2d`,
  `IsDefaultUiCamera`, `UiRoot`, and `UiTargetCamera` for the UI text to render
  in the 3D example.
- Bevy now uses `WorldAssetRoot(asset_server.load(...))` for the FlightHelmet
  scene. mgstudio's scene runtime currently exposes `SceneRoot` for this path.

These are source-owner parity gaps in UI/scene infrastructure, not local
anti-aliasing state-machine behavior.

## Design
Audit the current Bevy owners for implicit UI camera/root targeting and
`WorldAssetRoot`, then map the exact mgstudio owners that should provide the
same authoring surface. Do not keep example-local compatibility code as the
final solution. If MoonBit or dependency limits prevent exact ownership, record
the blocker with evidence; otherwise implement the missing UI/scene source
shape and simplify examples back toward the Bevy source.

## Acceptance Criteria
- [ ] The Bevy owner for implicit UI camera/root target selection is audited and
      each source-shape anchor is classified.
- [ ] 3D examples can use Bevy-shaped `Text` plus `Node` UI without adding
      example-local UI camera/root scaffolding solely to make text visible.
- [ ] The Bevy `WorldAssetRoot` owner is audited and mapped to mgstudio scene
      runtime without pretending `SceneRoot` is source-identical.
- [ ] `examples/3d/anti_aliasing` is simplified after the underlying UI/scene
      owners are restored.
- [ ] A representative screenshot gate proves the simplified example still
      renders UI and the FlightHelmet scene.

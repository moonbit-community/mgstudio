## Description

Table-stored component values currently live in `Array[T?]`. A stable table
row is therefore represented as an optional value even though table membership
already proves that the component exists. Required table queries unwrap this
optional value for every entity, and value components are boxed by the generated
native code. Structural moves also temporarily create holes and coordinate the
typed value move separately from raw table rows and change ticks.

Replace this representation with dense typed columns while preserving the
existing public `World`, `ComponentKey`, and query APIs and the current Bevy
change-detection and component-finalization semantics.

## Design

- Keep sparse-set component storage separate from table columns.
- Represent every stable typed table column as `Array[T]`; absence remains a
  lookup result and is never stored as a stable row value.
- Make structural mutation a two-phase operation: all fallible preparation
  happens before commit, and commit moves payloads and ticks as one coordinated
  transaction.
- Make component writers one-shot values whose unconsumed payload is finalized
  during rollback.
- Distinguish shared moves, replacement, destructive removal, transferring
  removal, despawn, and world close so every owned value is finalized exactly
  once.
- Fetch required table components through a non-optional internal path after
  archetype/table membership has established presence.
- Preserve sparse-set behavior and all public APIs. Do not introduce a second
  ECS category or a generic `#valtype` contract.
- After the generic dense representation is verified, evaluate one audited
  scalar component (`InheritedVisibility`) as a concrete `#valtype` experiment;
  retain that declaration only if a fresh benchmark demonstrates a benefit.

Stable table invariants:

1. Entity row count, every typed column length, and every change-tick column
   length are equal.
2. A table component value has exactly one owner; staged and stable copies do
   not coexist after commit.
3. Shared moves preserve payload and ticks without finalization.
4. Replacement, destructive removal, despawn, close, and rollback finalize each
   discarded value exactly once.
5. Queries and observers cannot observe an intermediate structural state.

## Acceptance Criteria
- [x] Focused regression tests cover dense-length invariants across insert,
  replace, archetype move, remove/take, despawn, and world close.
- [x] Stable table component columns no longer use `Array[T?]`.
- [x] Component payload and change ticks move in one coordinated structural
  transaction with no observable holes.
- [x] Required table queries fetch `T` directly after membership validation.
- [x] Existing component hooks, change detection, sparse-set storage, and
  finalizer behavior remain unchanged.
- [x] One representative ECS test is run at a time with
  `MOONBIT_NEW_NATIVE=1`, and the package remains warning-free.
- [x] A before/after native benchmark records query cost and many-entity
  behavior; any concrete `#valtype` conversion is kept only when supported by
  that evidence.
- [x] Public interface output is unchanged unless an intentional compatibility
  change is documented.

## Notes

- 2026-07-15: Implementation isolated on branch
  `milky/ecs-dense-table-columns` so the experiment can be discarded without
  changing `main`.
- 2026-07-15: The pinned Bevy table-move model is the semantic baseline. The
  optimization must not infer lifecycle or change-detection behavior from
  benchmarks.
- 2026-07-15: Two native-release runs of the 20,000-entity required-query
  benchmark averaged 7.39 ms on this branch versus 8.10 ms on `main`, an 8.8%
  reduction. The 5,000-entity structural-migration benchmark averaged 35.58 ms
  versus 35.25 ms, a 0.9% difference within observed run-to-run noise.
- 2026-07-15: A fresh `many_foxes` trace rejected the optional
  `InheritedVisibility #valtype` experiment. Average steady frame time rose
  from 68.585 ms to 70.414 ms and the audited visibility systems all became
  2-3% slower, so the declaration was reverted and not committed.
- 2026-07-15: The updated MoonBit toolchain reports unrelated warning 83
  migrations outside ECS. Their warning-zero cleanup is isolated in ISS-443.

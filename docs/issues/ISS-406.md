## Description
The pinned Bevy `examples/3d/wireframe` executable builds and runs on the
current macOS development machine, but the real application window is created
outside the current Space and cannot be captured for the official side of the
visual-parity packet. This blocks human approval of the final wireframe visual
comparison. It does not block source-level wireframe migration or mgstudio's
native screenshot capture.

The failure is external to the repository implementation. CoreGraphics reports
the live window as `owner=wireframe`, `name=wireframe`, with a valid window id
and bounds, but it is absent from `optionOnScreenOnly`. Activating and raising
the process does not move it to the current Space. `screencapture -l` returns
`could not create image from window`; ScreenCaptureKit's desktop-independent
window capture returns `SCStreamErrorDomain Code=-3811`.

## Design
Obtain a nonblank screenshot of the unmodified pinned Bevy wireframe window on
the current machine. Preserve Bevy commit, Rust toolchain, application source,
window output, and capture metadata. Do not substitute an mgstudio artifact, a
web image from another Bevy revision, or a hand-edited expected image.

An acceptable solution may repair macOS Space placement, use a working
ScreenCaptureKit capture host with Screen Recording permission, or use another
deterministic system-window capture path. It must capture the actual unmodified
Bevy window.

## Acceptance Criteria
- [ ] The pinned Bevy `examples/3d/wireframe` produces a nonblank native window screenshot on the current macOS machine.
- [ ] The run uses Rust 1.95.0 and Bevy commit `1413bc4e3632233b8fa610a6cf14b90258556c51` without modifying the Bevy working tree.
- [ ] The artifact records the window id, bounds, capture command, dimensions, and SHA-256.
- [ ] The official artifact and the mgstudio artifact are retained in a human-reviewable visual-parity packet.
- [ ] ISS-064 is updated with the accepted official baseline and human visual judgment.

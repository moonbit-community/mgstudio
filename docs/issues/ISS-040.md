# ISS-040: Document read-only ECS access as an API contract

## Metadata

- Created: 2026-06-04
- Updated: 2026-06-04

## Description
MoonBit cannot enforce Bevy's Rust aliasing rule that read-only component or
resource access cannot mutate the value. If a component or resource contains
mutable internal fields, a caller can mutate through `Comp[T]` or `Res[T]`
without going through `Mut[T]` or `ResMut[T]`, bypassing change detection.

## Design
Treat this as an API contract and migration-audit rule rather than a framework
feature to emulate. Documentation should state when to use `Mut` and `ResMut`,
what read APIs promise, and why read-side mutation is invalid even if MoonBit
allows it. Do not add copy-based read wrappers, erased payload wrappers, or
changed-on-read behavior to hide the limitation.

## Acceptance Criteria
- [ ] ECS user documentation clearly states that `Comp[T]` and `Res[T]` values
      must be treated as read-only.
- [ ] ECS user documentation clearly states that all state changes that should
      affect `Changed<T>` must go through `Mut[T]`, `ResMut[T]`, or explicit
      set/modify APIs.
- [ ] Migration guidance calls out this difference from Bevy's Rust type
      system.
- [ ] No workaround is introduced that marks values changed merely because a
      mutable-capable handle was fetched.

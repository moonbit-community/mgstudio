# ISS-450: Make changed messages and caller metadata demand-driven

## Metadata

## Description

Every component write records ticks and changed-caller metadata and also sends a
changed-component message. Determine which push notifications are required by
registered observers and make unused notification/caller work demand-driven
without changing Bevy tick semantics.

## Design

Evaluate two independent costs in order. First, retain component ticks as the
source of truth and remove mgstudio's supplemental changed-message queues when
the consumer can scan those ticks directly, matching Bevy's `Changed<T>`
ownership. Second, evaluate a Bevy-shaped change-location gate separately; it
must not be bundled into the message experiment.

## Acceptance Criteria

- [x] The pinned Bevy component-tick, observer, and hook owners are inventoried
      before changing behavior.
- [x] Components without interested consumers perform no changed-message queue
      allocation or send.
- [x] Change filters, hooks, observers, and `changed_by` retain their required
      behavior when enabled.
- [x] One focused ECS change-detection test runs at a time with
      `MOONBIT_NEW_NATIVE=1`.
- [x] `examples/animation/animated_transform` is the only runtime example gate.
- [ ] The retained/rejected decision follows the `ISS-444` experiment protocol.

## Notes

- 2026-07-16: Pinned Bevy stores added and changed ticks in table columns and
  sparse sets; `Changed<T>` reads those ticks directly. It does not enqueue a
  changed-component message on every write. Lifecycle hooks and observers are
  separate add/insert/replace/remove/despawn paths and are not a replacement
  for tick change detection.
- 2026-07-16: Pinned Bevy change-location storage is controlled by the
  non-default `track_location` feature. Without it, `MaybeLocation` is a
  zero-sized type and caller capture/storage operations compile away. Mgstudio
  currently always converts `SourceLoc` to `String` and stores caller IDs, so
  caller gating will be measured only after changed-message demand is
  classified.
- 2026-07-16: The changed-message experiment was retained. All four component
  write boundaries (`World`, `Write`, `TableBatchWrite`, and `ComponentColumn`)
  now update authoritative ticks without allocating a per-component message
  queue, looking it up, or appending an entity. `World::changed_components`
  scans live values and their stored ticks on demand, preserving first reads,
  repeated reads for the same tick interval, and subsequent writes.
- 2026-07-16: Focused native release tests passed independently for the new
  first/repeated/subsequent tick-scan contract and the existing dense
  `TableBatchWrite` change-detection contract. Hooks, observers, and caller
  metadata paths were not changed by this subtask.
- 2026-07-16: On `animation/animated_transform`, the pre-change steady trace was
  `8.334 ms/frame`; two post-change traces were `8.344` and `8.352 ms/frame`
  (`8.348 ms` mean, `+0.17%`). The trace-visible animation system remained at
  the measurement floor (`0.017 ms` before, `0.018` and `0.017 ms` after).
  This satisfies the allocation/lookup-class removal branch of the `ISS-444`
  retention gate with far less than `3%` frame regression.
- 2026-07-16: The final frame-90 capture rendered the animated sphere and cube
  at `2560x1440`. Its different cube position relative to the checked-in
  reference is an expected animation-phase difference and confirms that the
  transform animation still advances. Existing toolchain warning 0083 remains
  tracked by `ISS-443` and is outside this experiment.
- 2026-07-16: Change-location/caller gating remains the second, separately
  committed experiment before this issue can close.

# ISS-440: Add compiler-known value-component constraints to MoonBit

## Description

The current MoonBit toolchain cannot constrain a generic type parameter to
`#valtype`, and `#valtype` does not imply deep immutability: a value type may
contain mutable reference values such as `Array`. Downstream packages can also
implement an open marker trait for an arbitrary non-valtype type. Mgstudio
therefore cannot expose an ordinary generic registration API that statically
guarantees an arbitrary user-defined component has value representation and no
storage-visible interior mutation.

This is a MoonBit language-expressibility blocker for the strongest ECS-B
contract. It does not block an explicitly weaker marker-trait contract or a
restricted source-generated component schema, but those alternatives must not
be described as compiler-enforced arbitrary valtype support.

## Design

Expose compiler-known constraints or witnesses for value representation and
deeply immutable observable state. The constraints must be usable by generic
library APIs across package boundaries and must not be forgeable by downstream
implementations. Value representation and deep immutability should remain
separate properties because current standard-library valtypes may intentionally
encapsulate reference-shaped storage.

## Acceptance Criteria
- [ ] A generic MoonBit API can require that `T` has compiler-verified value representation.
- [ ] A separate generic constraint can require that copying `T` exposes no mutable alias reachable through its public API.
- [ ] Downstream arbitrary component declarations can satisfy the constraints without placing generated code inside the library package.
- [ ] A non-valtype and a valtype containing a publicly mutable array are rejected by focused compile-fail tests.
- [ ] Scalar and audited immutable valtypes pass focused compile tests.

The compiler capabilities remain absent; this status does not claim that the
upstream language limitation was fixed. Reopen only if a future accepted design
actually depends on compiler-known value-representation or deep-immutability
constraints.

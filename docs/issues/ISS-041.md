# ISS-041: Expose Bevy-shaped stage system param APIs

## Metadata
- Type: task
- Status: closed

- Assignee: codex

- Updated: 2026-06-04
- External ref: none

## Description
MoonBit cannot express Bevy's generic `IntoSystemConfigs` conversion or overload
`App::add_systems` by function arity. Without a stage-aware convenience API,
ports with five to eight system parameters must call `system_config_paramN`
directly before registering a stage system. That leaks a lower-level helper into
user-facing Bevy-shaped app code and makes source-owner migration noisier.

## Design
Expose explicit `add_systems_paramN(stage, fn)` helpers on both `App` and
`SubApp`, covering arities one through eight. Keep `system_config_paramN` as the
lower-level adapter for manually composing `SystemConfig` values, but do not
require it at ordinary app call sites. Do not introduce a fake generic
conversion facade or function-overload workaround; MoonBit rejected those
shapes in local experiments.

## Acceptance Criteria
- [x] `App` exposes stage-aware `add_systems_param` helpers through
      `add_systems_param8`.
- [x] `SubApp` exposes the same stage-aware helpers for render-app and custom
      sub-app registration.
- [x] A regression test registers an eight-parameter system against explicit
      startup and update-loop stages without calling `system_config_param8` at
      the call site.
- [x] Validation passes with `moon -C mgstudio-engine check --target native`,
      `moon -C mgstudio-engine test app --release`, `moon -C mgstudio-engine
      fmt`, and `moon -C mgstudio-engine info`.

# ISS-466: Restore standard Camera2d sprite picking

## Description

The sprite-picking camera query reads mgstudio's 3D `Projection` component,
while standard `Camera2d` required-component registration installs the separate
2D `Projection` component. A missing 3D projection is replaced with the default
perspective projection, and the hit-test system subsequently rejects every
non-orthographic camera. Standard `Camera2d` sprite picking therefore produces
no hits.

Pinned Bevy has one `Projection` component type, and `Camera2d` installs its
`OrthographicProjection::default_2d()` variant. Mgstudio's split projection
representation must preserve that source data flow at the picking boundary.

## Design

Query the 2D `Projection` component required by `Camera2d`; do not fall back to
a 3D perspective projection. Convert the implemented 2D WindowSize subset into
the source-equivalent `OrthographicProjection3d::default_2d()` runtime value,
copying its scale before the existing viewport update and exact-affine ray
construction. Keep the public 2D/3D projection API split unchanged.

## Acceptance Criteria

- [x] A camera created through standard `Camera2d` required components is
      collected as an orthographic sprite-picking camera.
- [x] Sprite picking reads the 2D projection key and has no perspective
      fallback for `Camera2d`.
- [x] Ray length, near-plane depth, viewport scaling, and exact-affine
      transform semantics match pinned Bevy's 2D orthographic path.
- [x] Existing camera-marker and affine-shear regressions remain green without
      manually installing a 3D projection on `Camera2d`.
- [x] The picking package compiles with no unintended public API change.

## Close Notes

Closed on 2026-07-18. Sprite camera collection now requires the 2D Projection
installed by standard `Camera2d`. The implemented 2D WindowSize subset is
bridged to `OrthographicProjection3d::default_2d()` with its scale preserved,
so the existing viewport update and exact-affine ray path receive the same
near/far and scaling semantics as pinned Bevy. The incorrect Perspective
fallback is gone. Existing marker and affine-shear tests now create cameras
through standard required components instead of installing a fake 3D
projection.

The standard-Camera2d, marker, and affine-shear tests each passed independently
with `MOONBIT_NEW_NATIVE=1`. `moon check picking --target native` and
`moon info picking --target native` completed with zero errors and no generated
interface change; the 43 displayed warnings are pre-existing toolchain
migration warnings tracked by ISS-443. The native frame-90
`examples/picking/sprite_picking` capture completed at the requested frame and
was pixel-identical to its checked-in reference (AE=0, RMSE=0).

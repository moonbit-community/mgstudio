# ISS-208: Bind active view depth texture in volumetric fog renderer group

## Description
Bevy's `volumetric_fog` render command binds the current view's
`ViewDepthTexture` into the volumetric fog bind group. Mgstudio's renderer must
consume the active pass-provided depth view at that bind group entry and must
not fall back to a backend-global depth texture.

## Design
Compare the Bevy bind group layout and render command entries against
mgstudio's `draw_mesh3d_volumetric_fog` renderer path. Keep the fix at the API
boundary that constructs group 1 for volumetric fog: the bind group should
receive an explicit depth texture view from the current pass data.

## Acceptance Criteria
- [x] The renderer group-1 volumetric fog bind group uses the active camera
      depth texture view.
- [x] No renderer helper silently replaces a missing active depth view with a
      global fallback.
- [x] Focused renderer coverage fails if the pass-provided depth view is not
      the one bound for volumetric fog.

## Close Notes
2026-07-04: Bevy binds `BindingResource::TextureView(view_depth_texture.view())`
as the second sequential entry of the volumetric fog bind group. Mgstudio's
`mesh3d_volumetric_fog_bind_group` mirrors that binding order:
binding 0 is the volumetric fog uniform buffer, binding 1 is the explicit
`depth_view` parameter, and bindings 2/3 are the optional density texture and
sampler.

The renderer no longer has a backend-global depth fallback for this path.
`draw_mesh3d_volumetric_fog` obtains `depth_view` through
`mesh3d_pass_view_depth_view(self, pass_state)`, and that helper now returns
`pass_state.view_depth_view`. If the active pass did not provide a view depth
texture, volumetric fog draw returns instead of substituting `backend.depth_view`.
The focused renderer coverage added for ISS-207 records the active
`view_depth_texture_id` in `GpuPassState`; together with the direct helper
audit this proves the bind group consumes the pass-provided view identity.

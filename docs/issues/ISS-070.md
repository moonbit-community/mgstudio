# ISS-070: Unblock Bevy Meshable associated builder output shape

## Description
Bevy's `bevy_mesh` primitive API defines `Meshable` with an associated
`Output` builder type. For example, `Circle::mesh()` returns
`CircleMeshBuilder`, so callers can use source-shaped builder chains such as
`Circle::new(radius).mesh().resolution(n).build()`.

Mgstudio currently defines `Meshable` as a MoonBit trait whose `mesh(Self)`
returns `Mesh3dGeometry` directly. That lets examples render, but it collapses
the Bevy source shape: per-primitive builder outputs and builder-specific
methods are no longer part of the trait contract.

## Design
Do not add workaround overloads or fake source parity. Either wait for a
MoonBit trait feature that can express associated output types, or replace the
trait usage with explicit per-primitive builder APIs and classify the generic
`Meshable` trait surface as intentionally partial until the language can encode
the Bevy shape.

## Acceptance Criteria
- [ ] The exact Bevy `Meshable::Output` source shape is expressible in
  MoonBit, or a documented non-generic per-type API plan is accepted.
- [ ] ISS-044 classifies each affected primitive builder as complete, partial,
  or blocked against this constraint.
- [ ] Public examples no longer rely on local-only `*_to_mesh2d_geometry`
  helpers as a substitute for Bevy-shaped primitive mesh authoring.

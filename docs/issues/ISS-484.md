# ISS-484: Fixed-frame sim phase shifts on cold-start stalls (first-run capture nondeterminism)

## Description

Under the fixed-frame capture harness (`CI_TESTING_FIXED_FRAME_TIME_US`,
frame-90 screenshot), examples whose content depends on simulated time can
render a DIFFERENT animation phase on a cold run (fresh Metal shader-cache
state for newly introduced pipeline variants) than on warm runs. Warm runs
are byte-deterministic; the cold run is the outlier. With a fixed timestep,
startup stalls must not change how much simulated time has elapsed by
presented frame N — Bevy's `bevy_ci_testing` fixed-frame captures do not
exhibit this.

Discovered while re-baselining the fog-less byte gates after ISS-483's
tonemapping fixes introduced new pipeline variants (fresh cold paths).

## Evidence (2026-08-04, motion_blur frame-90 captures, same binary)

- Run 1 (cold, first run after the ISS-483 rebuild): `6c544ab0dac0d3c7...`
  — moving cars at a visibly different track position.
- Runs 2 and 3 (warm): `1769770807e43c9f...` BYTE-IDENTICAL — and the car
  positions match BOTH the pinned-Bevy frame-90 capture and the pre-ISS-483
  committed reference, so the warm phase is the correct phase.
- Static-scene controls: atmospheric_fog cold+warm runs byte-identical
  (`aaacaca88b53a7e6...` twice), ssao cold+warm byte-identical
  (`4eaf5a6585dc926b...` twice) — phase-insensitive scenes cannot detect
  the shift, which is why the fog work never tripped it.

## Suspected mechanism

Startup stalls (first-use pipeline compilation against a cold OS shader
cache, possibly async asset IO) cause the app to tick simulation a
different number of times before the 90th PRESENTED frame, i.e. presented
frames and fixed-timestep sim ticks are not locked 1:1 under stalls.
The owner of frame/tick accounting in the capture path
(`MGSTUDIO_PARITY_CAPTURE_DELAY_FRAMES` counting vs the fixed-timestep
loop) needs a Bevy-shaped audit against `bevy_ci_testing`'s model, where
`fixed_frame_time` fixes the delta seen by every update regardless of
wall-clock stalls.

## Capture-protocol rule (interim, for ISS-481 and the byte gates)

After any change that introduces new shader/pipeline variants, discard the
FIRST capture of any time-animated example and byte-compare the second and
third runs instead. Static scenes are unaffected. Canonical gate hashes
are warm-run hashes.

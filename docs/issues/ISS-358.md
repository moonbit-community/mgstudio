## Description
The pass can receive correct data while still producing the wrong frame if the
composed WGSL, shader definitions, pipeline key, color target, blend state, or
MSAA/atmosphere/density-texture specialization differs from Bevy. Audit the
actual variant used by `examples/3d/volumetric_fog`.

## Design
This issue is a grouping issue only. Complete the child audits in source-owner
order:

- ISS-366 compares the static `volumetric_fog.wgsl` import closure against
  Bevy's source.
- ISS-367 proves shader definitions, pipeline keys, and layout-key variants.
- ISS-368 classifies render target, blend, color format, and depth/no-depth
  attachment semantics.
- ISS-369 proves the actual `examples/3d/volumetric_fog` runtime variants.
- ISS-370 assigns any proven local divergence to ISS-359 or records a precise
  external blocker.

The audit should prove the active variant, not only static source similarity.
Do not fix code from this umbrella issue; implementation belongs in ISS-359
after the owner is proven.

## Close Notes
Closed on 2026-07-05 after ISS-366 through ISS-370 were closed.

Summary:

- ISS-366 proved the static `volumetric_fog.wgsl` source and import closure.
- ISS-367 proved shader definitions, pipeline keys, and bind-group layout-key
  variants.
- ISS-368 proved color target, blend, MSAA color sample-count, no-resolve, and
  no-depth attachment semantics.
- ISS-369 proved the real `examples/3d/volumetric_fog` runtime variant:
  textureless and textured pipelines are both prepared, MSAA is enabled,
  atmosphere is disabled, density texture is variant-specific, and hardware
  2x2 shadow filtering is enabled.
- ISS-370 concluded that this shader/pipeline audit group does not assign any
  local repair to ISS-359 and does not expose an external or language blocker.

The volumetric-fog shader composition and specialization boundary is therefore
not the proven owner of the remaining `volumetric_fog` visual divergence.

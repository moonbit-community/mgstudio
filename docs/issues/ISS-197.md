## Description
Bevy's volumetric fog shader only accumulates directional-light scattering for
directional lights whose GPU flags include the volumetric bit. The shader loop
also assumes Bevy's light collection ordering, where volumetric and
shadow-enabled lights appear before the first non-volumetric light that causes
the loop to stop.

`scrolling_fog` lacks the expected directional light-shaft structure, so the
first source-owner check is whether the example's `VolumetricLight` reaches the
GPU directional-light array with Bevy-shaped flags and ordering.

## Design
Audit Bevy `bevy_pbr/src/render/light.rs` directional light collection,
volumetric flag assignment, and sorting against mgstudio's PBR light upload
path. Add focused tests around the GPU light data used by the view bind group.
Do not patch the shader or tweak scene values to hide missing flags.

## Close Notes
Closed on 2026-07-04.

Bevy source audited:

- `bevy/crates/bevy_pbr/src/render/light.rs` computes
  `directional_volumetric_enabled_count` from the first
  `MAX_DIRECTIONAL_LIGHTS` directional lights.
- It sorts `directional_light_entities` by
  `(light.volumetric, light.shadow_maps_enabled, entity)`.
- It sets `DirectionalLightFlags::VOLUMETRIC` only when
  `light.volumetric && light.shadow_maps_enabled &&
  index < directional_volumetric_enabled_count`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/volumetric_fog.wgsl` still breaks
  directional-light iteration at the first non-volumetric directional light.

Mgstudio matches this source behavior:

- `render3d_collect_extracted_directional_light_entries` sorts by
  `volumetric`, then `shadow_maps_enabled`, then entity id/generation.
- `render3d_collect_gpu_lights` sets the directional volumetric bit only when
  the light is volumetric, shadow-enabled, and the visible directional index is
  below `render3d_directional_lights_volumetric_enabled_count`.
- `examples/3d/scrolling_fog` has exactly one directional light, with
  `DirectionalLight.shadow_maps_enabled = true` and `VolumetricLight`, so this
  path does set both shadow and volumetric bits and is not the root cause of
  the missing light-shaft reference difference.
- A mixed list with non-volumetric lights before the volumetric light preserves
  the current Bevy bool-key behavior; mgstudio should not "fix" that locally
  as part of source-level parity.

Verification:

- Added focused tests in `pbr/render/light_test.mbt`:
  `pbr render light: scrolling fog directional light keeps shadow and volumetric GPU flags`
  and
  `pbr render light: mixed directional GPU list preserves Bevy bool key flag behavior`.
- `moon -C mgstudio-engine test pbr/render --target native --release` passed:
  97 tests.

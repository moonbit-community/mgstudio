## Description
Debug output from the failing `volumetric_fog` capture reported one view and
one fog volume, but both textureless and textured volumetric fog pipeline
variants were requested. This initially looked suspicious, but Bevy's pinned
source prepares both pipeline variants per volumetric-fog view and chooses the
actual variant per fog volume during drawing.

## Design
Compare Bevy `prepare_volumetric_fog_pipelines` and draw routing in
`bevy/crates/bevy_pbr/src/volumetric_fog/render.rs` against mgstudio's
`pbr/volumetric_fog_execute.mbt` and
`render/renderer/mesh3d_volumetric_fog_pass.mbt`.

Keep pipeline variant selection source-shaped:

- both textureless and textured pipelines are specialized for each
  volumetric-fog view;
- each fog volume is drawn once;
- the pass chooses the textured pipeline only for volumes whose density texture
  resolves to an available GPU image, and otherwise chooses the textureless
  pipeline.

## Acceptance Criteria
- [x] The Bevy source behavior for pipeline preparation is recorded.
- [x] Mgstudio's pipeline preparation is checked against that Bevy behavior.
- [x] Mgstudio's render pass is checked to draw each fog volume through the
      matching variant.
- [x] The earlier assumption that `needs_textured=true` was spurious is
      corrected in the issue notes.

## Notes
- 2026-07-05: Split from ISS-293 after debug output showed
  `volumes=1`, `needs_textureless=true`, and `needs_textured=true` for the
  failing capture. This is suspicious because Bevy only needs the textured
  variant when a volume has a density texture.
- 2026-07-05: Corrected the initial assumption after reading pinned Bevy
  `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs`. Bevy
  `prepare_volumetric_fog_pipelines` specializes both the textureless and
  textured pipeline IDs for every extracted volumetric-fog view. It does not
  inspect `FogVolume::density_texture` during pipeline preparation.
- 2026-07-05: The per-volume texture decision happens in Bevy's
  `volumetric_fog` render command: it resolves
  `view_fog_volume.density_texture` through `RenderAssets<GpuImage>` and uses
  the textured pipeline only when the GPU image exists. Mgstudio mirrors that
  shape in `mesh3d_volumetric_fog_pass.mbt`: it resolves
  `volume.density_texture_id`, selects `textured_pipeline` for `Some(_)`, and
  otherwise selects `textureless_pipeline`. The existing wbtest already asserts
  the two pipeline key variants and shader definitions.

## Description
`scrolling_fog` can have valid directional light uniforms and a valid shadow
texture while still sampling the wrong cascade, wrong texture-array layer, or
wrong light-space position. This issue isolates the Bevy directional cascade
sampling math from broader visual acceptance.

## Design
Compare Bevy's WGSL cascade selection and directional shadow sampling helpers
against the composed mgstudio shader and the host-packed `GpuLights` fields.
Verify the meaning and byte layout of `clip_from_world`, `texel_size`,
`far_bound`, `depth_texture_base_index`, cascade count, and overlap at the exact
shader read sites. If the local host representation cannot express Bevy's data
shape, record that as a local source-parity bug rather than accepting a visual
approximation.

## Acceptance Criteria
- [x] Cascade index selection reads the same per-light cascade bounds and
      overlap semantics as Bevy.
- [x] Directional light-space coordinate construction uses the same
      `clip_from_world` matrix semantics as Bevy.
- [x] Shadow texture array layer selection combines
      `depth_texture_base_index + cascade_index` the same way Bevy does.
- [x] A focused test or audit note ties each shader read to the mgstudio
      host-packed field that provides it.

## Close Notes
Closed on 2026-07-05.

Audited Bevy:

- `bevy/crates/bevy_pbr/src/volumetric_fog/volumetric_fog.wgsl`
- `bevy/crates/bevy_pbr/src/render/shadows.wgsl`
- `bevy/crates/bevy_pbr/src/render/mesh_view_types.wgsl`

The Bevy volumetric fog direct directional-shadow path performs:

- `get_cascade_index(light_index, P_view.z)`, which reads
  `DirectionalLight.num_cascades` and each cascade `far_bound`;
- `world_to_directional_light_local(light_index, cascade_index, ...)`, which
  reads `DirectionalCascade.clip_from_world`;
- `sample_shadow_map_hardware(..., i32(depth_texture_base_index +
  cascade_index))`, which combines `DirectionalLight.depth_texture_base_index`
  and the selected cascade index.

Bevy's general `fetch_directional_shadow` path also uses `texel_size` and
`cascades_overlap_proportion` for surface shadow sampling and cascade overlap
blending. The volumetric fog direct path imports the same helper module but does
not perform the overlap blend itself; mgstudio keeps those fields in the Bevy
host layout so both imported helper paths remain representable.

Added/extended focused gates:

- `pbr volumetric fog: composed runtime wgsl keeps Bevy directional shadow import closure`
  now checks that the runtime-composed volumetric fog shader contains the Bevy
  cascade and shadow helper anchors: `get_cascade_index`,
  `world_to_directional_light_local`, `num_cascades`, `far_bound`,
  `clip_from_world`, `depth_texture_base_index`, `array_index`, and
  `cascade_index`.
- `pbr/render light: volumetric cascade shader reads map to Bevy host fields`
  checks the packed `GpuLights` bytes against Bevy `mesh_view_types.wgsl`
  offsets: cascade matrix columns at offsets 0..60 and 80..140, `texel_size`
  at 64/144, `far_bound` at 68/148, `flags` at 348, `num_cascades` at 364,
  `cascades_overlap_proportion` at 368, `depth_texture_base_index` at 372, and
  `n_directional_lights` at 4048.

Validation:

```sh
moon -C mgstudio-engine test pbr --target native --release --filter '*composed runtime wgsl keeps Bevy directional shadow import closure*'
moon -C mgstudio-engine test pbr/render --target native --release --filter '*volumetric cascade shader reads map to Bevy host fields*'
```

Both commands passed with `Total tests: 1, passed: 1, failed: 0.` No external
blocker was found for this cascade sampling math slice. Runtime execution
evidence remains tracked by ISS-257.

## Description
ISS-142 now owns `GpuLineGizmo` render assets, phase item planning, vertex
buffer layouts, and 2D/3D pipeline key planning, but retained gizmos still draw
through the old immediate line bridge. Bevy does not draw line gizmos from the
queue system directly: it registers `DrawLineGizmo*` render commands for
`Transparent2d` and `Transparent3d`, then the phase executor binds the view
bind group, line uniform bind group, `GpuLineGizmo` vertex buffers, and issues
the instanced draw call.

Mgstudio currently lacks that source-shaped render-command consumer for line
gizmo phase items. This is a local render architecture gap, not a wgpu_mbt,
wgpu-native, or MoonBit language blocker.

## Design
Port the Bevy render-command behavior from
`bevy_gizmos_render/src/lib.rs::{SetLineGizmoBindGroup, DrawLineGizmo,
DrawLineJointGizmo}` into mgstudio's render phase execution model. Reuse the
source-shaped `GpuLineGizmo`, `LineGizmoPhaseItem`, pipeline keys, and vertex
buffer layouts already introduced by ISS-142.

The implementation must bind buffers exactly like Bevy:
- list lines bind list position/color buffers and draw 6 vertices for
  `list_vertex_count / 2` instances;
- strip lines bind shifted position/color slices and draw 6 vertices for
  `strip_vertex_count - 1` instances;
- joints bind three shifted position slices plus the middle color slice and
  draw 6, 3, or `resolution * 3` vertices for miter, bevel, or round joints.

Do not replace this with another immediate-mode bridge. If the current host
renderer cannot execute such phase commands, split the minimal render phase
executor support needed and keep that as local implementation work.

## Acceptance Criteria
- [x] `LineGizmoPhaseItem` execution binds the Bevy-shaped view and line-gizmo
      uniform bind groups before drawing.
- [x] `DrawLineGizmo` list and strip behavior matches Bevy's buffer slice and
      instance-count logic.
- [x] `DrawLineJointGizmo` behavior matches Bevy's joint buffer slice,
      vertex-count, and skip conditions.
- [x] The old `queue_line_gizmos_2d` / `queue_line_gizmos_3d` immediate bridge
      is removed from the active retained gizmo visual path.
- [x] `examples/gizmos/3d_gizmos/reference.png` remains visually valid after
      the render-command path replaces the bridge.

## Notes
- 2026-06-20: Created after auditing Bevy `bevy_gizmos_render` against
  mgstudio. The blocker is local: mgstudio has phase item data, but no
  source-shaped draw-command consumer for line gizmo phase items yet.
- 2026-06-20: Started by porting Bevy's line and joint buffer-slice and draw
  count rules into explicit draw-command planning data. The next step is to
  feed these plans into a real active render-pass executor with view and line
  uniform bind groups.
- 2026-06-20: Added byte packing for `LineGizmoUniform` using Bevy's
  `Affine3Ext::to_transpose` / `ShaderType` layout, so the eventual line
  uniform bind group can upload the same 80-byte payload expected by
  `bevy_gizmos_line.wgsl`.
- 2026-06-20: Added `LineGizmoRenderCommandPlan`, combining the Bevy command
  tuple inputs for `SetItemPipeline`, view bind group slot 0, line uniform bind
  group slot 1, and the line/joint draw plans. This gives the future active
  render-pass executor a source-shaped input, but does not yet replace the
  immediate bridge.
- 2026-06-20: Registered the retained line gizmo WGSL assets through MoonBit
  `:embed`, mirroring Bevy's `embedded_asset!` calls for `lines.wgsl` and
  `line_joints.wgsl`. The active executor can now resolve the exact source
  paths used by the pipeline plans.
- 2026-06-20: Added a renderer-owned generic line gizmo queue/executor. The
  gizmos render queue now submits retained `GpuLineGizmo` draw commands into
  that queue, and the PBR/sprite main-pass hooks execute them inside active
  render passes instead of drawing through the old immediate line bridge.

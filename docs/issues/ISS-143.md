## Description
ISS-142 now owns `GpuLineGizmo` render assets, phase item planning, vertex
buffer layouts, and 2D/3D pipeline key planning, but retained gizmos still draw
through the old immediate line bridge. Bevy does not draw line gizmos from the
queue system directly: it registers `DrawLineGizmo*` render commands for
`Transparent2d` and `Transparent3d`, then the phase executor binds the view
bind group, line uniform bind group, `GpuLineGizmo` vertex buffers, and issues
the instanced draw call.

Mgstudio currently lacks that source-shaped render-command consumer for line
gizmo phase items. This is a local render architecture gap, not a wgpu_mbt,
wgpu-native, or MoonBit language blocker.

## Design
Port the Bevy render-command behavior from
`bevy_gizmos_render/src/lib.rs::{SetLineGizmoBindGroup, DrawLineGizmo,
DrawLineJointGizmo}` into mgstudio's render phase execution model. Reuse the
source-shaped `GpuLineGizmo`, `LineGizmoPhaseItem`, pipeline keys, and vertex
buffer layouts already introduced by ISS-142.

The implementation must bind buffers exactly like Bevy:
- list lines bind list position/color buffers and draw 6 vertices for
  `list_vertex_count / 2` instances;
- strip lines bind shifted position/color slices and draw 6 vertices for
  `strip_vertex_count - 1` instances;
- joints bind three shifted position slices plus the middle color slice and
  draw 6, 3, or `resolution * 3` vertices for miter, bevel, or round joints.

Do not replace this with another immediate-mode bridge. If the current host
renderer cannot execute such phase commands, split the minimal render phase
executor support needed and keep that as local implementation work.

## Acceptance Criteria
- [ ] `LineGizmoPhaseItem` execution binds the Bevy-shaped view and line-gizmo
      uniform bind groups before drawing.
- [ ] `DrawLineGizmo` list and strip behavior matches Bevy's buffer slice and
      instance-count logic.
- [ ] `DrawLineJointGizmo` behavior matches Bevy's joint buffer slice,
      vertex-count, and skip conditions.
- [ ] The old `queue_line_gizmos_2d` / `queue_line_gizmos_3d` immediate bridge
      is removed from the active retained gizmo visual path.
- [ ] `examples/gizmos/3d_gizmos/reference.png` remains visually valid after
      the render-command path replaces the bridge.

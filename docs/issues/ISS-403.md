# ISS-403: Split deferred opaque main-phase exclusion behind real deferred phase consumption

## Description
Bevy `bevy_pbr/src/material.rs::queue_material_meshes` does not add deferred
opaque meshes to the main `Opaque3d` phase. It only updates the opaque phase
cache and expects the separate deferred prepass and deferred lighting runtime
path to produce the visible result.

Mgstudio still cannot apply that source behavior directly. During the
`ISS-155` retained main-view phase work, moving deferred opaque exclusion from
`render3d_execute_camera_main_pass.mbt` into `Render3dMainViewPhases`
preparation made `examples/3d/deferred_rendering` capture only UI over a blank
background, while the current checked-in reference shows the full 3D scene.
This proves the current visual success still depends on the old main-pass
payload-oriented draw path compensating for incomplete deferred phase
consumption.

This is a local render/PBR source-parity gap, not an external blocker.

## Design
Fix this by completing the real Bevy phase split before removing the main-pass
deferred-opaque skip:

- Keep `Render3dPreparedCameraQueue` available to prepass/deferred paths until
  those paths have their own Bevy-shaped phase resources.
- Port the deferred prepass and deferred lighting consumption required by Bevy
  so deferred opaque meshes render through deferred targets, not through the
  main opaque phase.
- Once `examples/3d/deferred_rendering` renders correctly without main-pass
  deferred opaque draws, move the exclusion into the retained phase queue
  resource and remove the main-pass compensating skip.
- Do not classify the current skip as an external blocker or permanent
  workaround; it is a local incomplete phase-consumption dependency.

## Acceptance Criteria
- [ ] A test proves deferred opaque entries are retained for deferred/prepass
      queues but excluded from the main `Opaque3d` phase resource.
- [ ] `examples/3d/deferred_rendering` renders the full 3D scene when deferred
      opaque meshes are not drawn by the main opaque pass.
- [ ] Main-pass deferred opaque filtering is owned by queue/phase preparation,
      matching Bevy `queue_material_meshes`, not by a late draw-loop skip.
- [ ] Validation includes `MOONBIT_NEW_NATIVE=1` release capture for
      `examples/3d/deferred_rendering` and comparison against its reference.

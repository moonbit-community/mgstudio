# ISS-475: Stop requiring Tonemapping and DebandDither on Camera3d

## Metadata
- Type: bug
- Status: closed
- Priority: 0
- Labels: camera, pbr, core_pipeline, tonemapping, visual-parity, source-parity, bevy-sync
- Assignee: unassigned
- Created: 2026-08-02
- Updated: 2026-08-02

## Description

`register_render3d_required_components` registered `Tonemapping` and
`DebandDither` as required components of `Camera3d`, defaulting to
`Tonemapping::default()` (`TonyMcMapface`) and `DebandDither::Enabled`.
`Camera3dBundle::new` and `Camera3dBundle::new_with_projection` carried the same
defaults.

In the pinned Bevy baseline neither component is required anywhere.
`bevy/crates/bevy_camera/src/components.rs` declares
`#[require(Camera, Projection)]` for `Camera3d`, and
`bevy/crates/bevy_core_pipeline/src/tonemapping/mod.rs` reads both as
`Option<&T>`, defaulting an absent `DebandDither` to `DebandDither::Disabled`.
A plain Bevy `Camera3d` spawn therefore has no tonemapping and no deband dither.

Because the components were *required*, `Camera3dBundle::with_tonemapping(None)`
could not turn them off: the required-components pass reinserted them after the
bundle omitted them. A capture taken with the bundle overrides applied was
byte-identical to one taken without them.

Effect on parity: every 3D example that spawns a camera through
`Camera3dBundle::new` rendered through `TonyMcMapface` plus deband dither where
Bevy renders through neither. 66 example packages use `Camera3dBundle::new` and
only 4 previously overrode tonemapping.

## Evidence

`examples/gizmos/3d_text_gizmos`, frame 90, fixed frame time 16667us, 2560x1440,
compared against the pinned Bevy example captured with `bevy_ci_testing`
`ScreenshotAndExit`:

| Surface | Bevy | mgstudio before | Status |
| --- | --- | --- | --- |
| "Hello" stroke core | `(255, 0, 0)` x5299 | `(215, 46, 32)` x1900 | OBSERVED |
| "Text" stroke core | `(255, 165, 0)` | `(208, 144, 49)` | OBSERVED |
| "Gizmos" stroke core | `(255, 255, 0)` | `(198, 194, 73)` | OBSERVED |
| Background | flat `(43, 44, 47)` x126084 | `(45,46,49)`/`(45,46,50)`/`(46,46,49)`/`(45,47,49)`... | OBSERVED |
| Stroke run widths | `[5, 4]` | `[4, 5]` | OBSERVED |

The background spread of plus or minus one per channel is the deband dither
signature; Bevy's background is a single flat colour. Stroke geometry, glyph
shapes, layout and rotation already matched, which isolated the divergence to
the camera post-process components rather than the gizmo owner.

## Design

Match the Bevy required-component set: drop both registrations from
`register_render3d_required_components` and default both bundle fields to
`None`. Consumers already read the components as options through
`render_execute_collect`, so an absent component flows through unchanged.

## Follow-up: stale tests left behind

Closing this issue missed three expect tests that still asserted the old
behaviour, so they failed on `main` from the moment the change landed until they
were corrected:

- `pbr/camera_bundle_test.mbt` "Camera3dBundle injects Bevy-style tonemapping
  defaults" asserted the bundle injects `TonyMcMapface` and `Enabled`. Renamed
  to assert both are unset, with a second test covering the explicit
  `with_tonemapping` / `with_deband_dither` path.
- `pbr/camera_bundle_test.mbt` "required components align PBR-owned Camera3d
  authoring" asserted tonemapping and deband dither were present, and then
  asserted it a second time further down the same test on the same entity. Both
  blocks corrected; the duplicate removed.
- `pbr/mod_test.mbt` "Mesh3d tuple insert receives visibility required
  components" expected `ViewVisibility` `bits: 1`. Bevy derives `Default` over
  the bit-packed field, so a freshly required component starts not-visible and
  `CheckVisibility` recomputes it each frame. Expectation corrected to `bits: 0`.

The lesson is narrow and worth stating: a change to required components or to
bundle defaults will not show up in `moon check`, only in the expect tests, so
run the owning package's tests before closing an issue of this shape.

## Acceptance Criteria
- [x] `Camera3d` requires only the components Bevy requires; `Tonemapping` and
  `DebandDither` are not among them.
- [x] `Camera3dBundle::new` and `new_with_projection` default both fields to `None`.
- [x] `moon check --target native` is clean with no new warnings.
- [x] `moon test -p pbr` is clean; the three stale expect tests are corrected.
- [ ] Checked-in `reference.png` files for 3D examples are re-judged by a human
  before regeneration; they were captured with the old tonemapped defaults.

## Notes

Bevy removed `Camera3dBundle`/`Camera2dBundle` entirely in favour of required
components. mgstudio's `Camera3dBundle` is a legacy convenience layer whose
defaults were modelled on an older Bevy; converting call sites to bare
`Camera3d` spawns remains open work.

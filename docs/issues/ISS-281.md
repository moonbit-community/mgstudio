## Description
Bevy `prepare_volumetric_fog_uniforms` writes `ViewVolumetricFog`,
`ViewFogVolume`, and `VolumetricFogUniformBuffer` with byte offsets and matrix
packing consumed by WGSL.

## Design
Audit the view/fog-volume prepared data, uniform host layout, matrix order,
and dynamic offset semantics against Bevy. This issue does not cover depth or
density texture inputs.

## Acceptance Criteria
- [x] `ViewVolumetricFog` and `ViewFogVolume` fields are classified.
- [x] `VolumetricFogUniform` host layout and matrix packing are classified.
- [x] Dynamic uniform byte offsets are classified.
- [x] Any remaining public facade or wrong lifecycle has a follow-up ISS or
      direct fix.

## Close Notes
Closed 2026-07-09. Bevy `ViewVolumetricFog(Vec<ViewFogVolume>)`,
`ViewFogVolume { density_texture, uniform_buffer_offset, exterior }`, and
`VolumetricFogUniformBuffer(DynamicUniformBuffer<VolumetricFogUniform>)` map to
the mgstudio typed component/resource owner without a facade. Uniform packing is
column-major, has a 288-byte host struct payload, and is padded to the 512-byte
dynamic uniform stride before the next volume. Prepared view data preserves
Bevy's one dynamic offset per volume, and renderer draw binding passes
`[uniform_buffer_offset]` for bind group 1.

Existing evidence:
- `pbr/volumetric_fog/render_wbtest.mbt` covers column-order matrix packing,
  512-byte dynamic stride offsets, 288-byte field layout positions, far-plane
  helpers, inside/outside classification, and transformed volume metadata.
- `pbr/volumetric_fog_execute_wbtest.mbt` covers multi-view offset ordering
  `0/512/1024/1536`, per-view `ViewVolumetricFog` insertion, density texture
  IDs, and exterior flags.
- `render/renderer/gpu_wbtest.mbt` covers Bevy draw-time dynamic offsets via
  `mesh3d_volumetric_fog_dynamic_offsets`.

Verification:

- `moon -C mgstudio-engine test --release render/renderer`

# ISS-285: Fix volumetric fog MSAA color attachment sample-count parity

## Description
Enabling Bevy-shaped `VolumetricLight` and `FogVolume` in
`examples/3d/volumetric_fog` activates the volumetric fog pass and currently
triggers a WebGPU validation failure:

`RenderPass uses textures with sample count 1 but RenderPipeline uses
attachments with sample count 4`.

This indicates that mgstudio's volumetric fog pass is not matching Bevy's
color-attachment/MSAA ownership. Current Bevy opens the volumetric lighting
pass over `view_target.main_texture_view()` with `resolve_target: None`, while
the `MULTISAMPLED` key only selects shader/layout/depth-texture variants. The
local renderer must mirror that boundary instead of forcing the example to
disable MSAA or selecting a multisampled color pipeline by accident.

## Design
Compare Bevy `bevy_pbr/src/volumetric_fog/render.rs::volumetric_fog` and
Bevy's `ViewTarget::main_texture_view` implementation against
`mgstudio-engine/render/renderer/mesh3d_volumetric_fog_pass.mbt` and the
volumetric fog pipeline specialization path.

Fix the root ownership mismatch at the render pass or pipeline key boundary.
Do not work around the failure by changing `examples/3d/volumetric_fog` to
`Msaa::Off`; Bevy does not do that in this example.

## Acceptance Criteria
- [x] The volumetric fog pass writes to the single-sample main texture view
      with no resolve target, matching Bevy's current render pass.
- [x] The selected pipeline MSAA key matches Bevy for the active view target.
- [x] The selected volumetric fog render pipeline keeps actual color pipeline
      sample count `1` even when the shader/layout key is `MULTISAMPLED`.
- [x] `examples/3d/volumetric_fog` native capture with Bevy-shaped
      `VolumetricLight` and `FogVolume` completes without the sample-count
      validation error.
- [x] Focused renderer or PBR coverage proves the MSAA attachment/pipeline
      contract so this cannot regress silently.

## Close Notes
Closed on 2026-07-05.

Bevy source owner audited:

- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs::volumetric_fog` opens
  `RenderPassDescriptor { label: "volumetric lighting pass", color_attachments:
  [view_target.main_texture_view(), resolve_target: None], ... }`.
- `VolumetricFogPipeline::specialize` uses the `MULTISAMPLED` key for shader
  definitions and bind group layout selection, but leaves the render pipeline
  multisample state at the default single-sample value.

Mgstudio change:

- `mesh3d_build_volumetric_fog_pipeline` now uses actual render pipeline
  sample count `1` for volumetric fog color output, while preserving
  `msaa_sample_count` for shader defs, bind group layout selection, labels, and
  cache keys.
- Added a renderer white-box test proving that MSAA input still enables the
  `MULTISAMPLED` shader/layout path while the volumetric fog color pipeline
  remains single-sample.

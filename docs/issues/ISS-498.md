# ISS-498: Reflected-view invert culling does not reproduce Bevy's winding behavior

## Description

Bevy's mirror example (`examples/3d/mirror.rs`) uses NO RenderLayers:
the mirror camera's `invert_culling` alone removes the mirror surface
from its own reflection, because the reflected view (det<0 view matrix)
flips every triangle's projected winding — the quad's back side
presents as front-facing and `FrontFace::Cw`-style inversion culls it,
while ordinary geometry's outward faces survive.

mgstudio implements invert culling as a cull-mode swap at
specialization (`pbr_standard_material_cull_mode`: `(cull_back, invert)
-> CULL_MODE_FRONT`, front_face pinned CCW), which is winding-
equivalent on paper. In practice it does not behave like Bevy: with the
mirror example ported to Bevy's exact no-layers shape
(`.private/parity/artifacts/iss493/fixed2.png`), the mirror camera
renders the mirror quad into its own render target (feedback black)
and the reflected fox/ground disappear — the opposite survival set
from Bevy. With the quad excluded via RenderLayers, the reflected
fox and ground render fine, so the reflected view matrices are correct.

The inputs were verified exactly against Bevy during the ISS-493
session: reflected camera transform (scale (-1,1,1)), the view-space
oblique `near_clip_plane` `(0.679042, 0.225638, -0.698562, -333.333)`,
and the oblique-adjusted infinite-reverse clip matrix all match the
Bevy formulas to float precision, and the composed `clip_from_world`
carries the reflection (positive-determinant projection x negative-
determinant view). The defect is therefore in how the specialized
cull mode reaches (or fails to reach) the actual per-view pipelines
used by the reflected pass, or in the backend's application of it —
NOT in the math.

Suspect surface for the probe session:
- Whether the mirror-view draws of each mesh really use pipelines
  specialized with `MESH_PIPELINE_KEY_INVERT_CULLING` (dump per-draw
  pipeline id -> cull mode in the backend registry for both views).
- `mesh3d_material_pipeline_layout_get_or_create` / descriptor
  materialization: confirm the registered descriptor's cull mode
  survives to the created `wgpu` pipeline.
- Note `GpuBackend::draw_mesh3d_main_pass` receives a `cull_mode`
  parameter and ignores it (`cull_mode |> ignore`) — decide which side
  owns culling and delete the dead parameter while fixing.

## Description
`ISS-005` restored the source-shaped dynamic skinned-bounds algorithm and the
hot path now uses joint table-row caches with zero misses in the current
`many_foxes` profile. The remaining gap is not the local bounds algorithm:
current Bevy updates all `DynamicSkinnedMeshBounds` entities every frame using
`par_iter_mut`, while mgstudio still runs the same per-entity and per-joint work
sequentially in the main ECS world.

The current short release profile at
`/tmp/mgstudio_many_foxes_iss005_close_current/frametime_breakdown.md` reports
`mgstudio.visibility.update_skinned_mesh_bounds=5.389 ms/frame` for `1000`
foxes, with `22000` joint bounds processed, `22000` joint transform cache hits,
and `0` cache misses.

## Design
Do not add a dirty-driven shortcut that diverges from Bevy. The next fix must
provide a Bevy-equivalent execution improvement: either a safe parallel query
iteration model for this disjoint mutable query shape, or a source-acceptable
batch/SIMD row-processing path that preserves Bevy's every-frame recompute
semantics and produces the same `Aabb` values.

Until mgstudio has that ECS/runtime capability, `ISS-005` can be closed but the
`many_foxes` CPU budget cannot honestly claim parity for this path.

## Acceptance Criteria
- [x] A safe engine-level plan exists for Bevy-equivalent parallel or batched
      skinned-bounds iteration without JSON payloads, global fallback state, or
      source-divergent dirty skipping.
- [x] `update_skinned_mesh_bounds` preserves Bevy's every-frame recompute
      semantics for `DynamicSkinnedMeshBounds`.
- [x] The `1000`-fox many_foxes release profile reports
      `mgstudio.visibility.update_skinned_mesh_bounds < 3 ms/frame` on the
      current development machine, or a narrower upstream/language blocker is
      recorded with exact evidence.
- [x] Relevant mesh, camera/primitives, and camera/visibility release tests
      pass.

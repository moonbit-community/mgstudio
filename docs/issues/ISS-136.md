## Description
`bevy/examples/3d/tonemapping.rs` configures `DefaultPlugins.set(AssetPlugin {
unapproved_path_mode: UnapprovedPathMode::Allow, ..default() })` so the example
can load drag-and-dropped local HDR/EXR files.

Mgstudio's current `AssetPlugin` exposes sampler, asset mode, asset root, and
processed asset root settings, but does not expose a Bevy-shaped
`UnapprovedPathMode` policy. `AssetServer::load(path)` currently accepts the
path used by the tonemapping example without this explicit safety knob, so the
runtime can work while the source shape is still not faithful to Bevy.

## Design
Audit Bevy's current asset path approval owner and add the equivalent mgstudio
policy surface in the asset package. The tonemapping example should then express
the same plugin graph as Bevy instead of relying on the current implicit path
acceptance behavior.

## Acceptance Criteria
- [ ] Bevy's `UnapprovedPathMode` owner is audited and mapped to mgstudio asset
      code.
- [ ] `AssetPlugin` exposes a source-shaped unapproved-path policy.
- [ ] `AssetServer::load` applies or records that policy at the same ownership
      boundary as Bevy.
- [ ] `examples/3d/tonemapping` uses the Bevy-shaped asset-plugin
      configuration for drag-and-drop image loading.
- [ ] A targeted asset package test covers the default policy and explicit
      `Allow` behavior.

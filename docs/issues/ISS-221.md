## Description
ISS-216 restored the source-world projection update needed before directional
cascade construction, but Bevy's `bevy_render/src/camera.rs::camera_system`
owns a broader camera update surface. Mgstudio still needs a symbol-level audit
for the remaining computed camera fields and event-driven behavior before the
camera-system owner can be called complete.

## Design
Compare Bevy `camera_system` against mgstudio's camera/PBR implementation.
Port the remaining in-scope pieces source-faithfully: render-target change
detection, viewport resize on scale-factor changes, viewport clamping,
`computed.clip_from_view`, `old_viewport_size`, and `old_sub_camera_view`.
Do not move this logic into shadow or example code.

## Acceptance Criteria
- [ ] Every in-scope branch of Bevy `camera_system` is classified as complete,
      partial, facade, or blocked.
- [ ] `Camera.computed` carries the Bevy-equivalent fields needed by downstream
      camera, visibility, light, and render users.
- [ ] Projection update, viewport clamping, and computed clip matrix updates
      run in the Bevy-shaped `CameraUpdateSystems` schedule.
- [ ] Existing camera, light, and PBR focused tests continue to pass.

## Description
Bevy prepares `ViewVolumetricFogPipelines` for each volumetric-fog view so the
draw pass can choose the correct pipeline variant for textureless fog volumes,
density-textured fog volumes, atmosphere-enabled views, MSAA, and target format.

Mgstudio has pipeline keys and cache plumbing, but the prepared per-view
pipeline state still needs to be source-shaped and verified independently from
uniform data.

## Design
Audit Bevy's volumetric fog pipeline specialization and view preparation. Move
mgstudio pipeline variant selection into a prepare owner that reads the same
render-world view and fog-volume facts as the uniform prepare step. Do not
hide missing variants by falling back to a generic pipeline; a missing variant
must be represented as an unfinished local parity gap or a real external
blocker.

## Acceptance Criteria
- [x] `ViewVolumetricFogPipelines` is inserted on render-world view entities before the draw pass.
- [x] Textureless and density-textured fog-volume variants are both represented.
- [x] Atmosphere, MSAA, and target-format key dimensions match the Bevy source owner.
- [x] Focused tests cover at least one textureless variant and one density-texture variant.

## Close Notes
2026-07-04: Moved `ViewVolumetricFogPipelines` insertion into
`render3d_prepare_volumetric_fog_pipelines`. The function now mirrors Bevy's
per-view `prepare_volumetric_fog_pipelines` owner: it derives the textureless
and density-textured `VolumetricFogPipelineKey` variants from the same
mesh-view layout bits, target format, MSAA state, atmosphere bit, and plane
mesh vertex stride, then writes `ViewVolumetricFogPipelines` directly to the
render-world view entity when both backend-specialized pipeline IDs are
available.

Removed the separate camera-local pipeline component writer. Backend-less
whitebox tests do not fabricate pipeline IDs; the real insertion path is
covered by the native `examples/3d/atmosphere` runtime capture.

Focused coverage added in `pbr/volumetric_fog_execute_wbtest.mbt` verifies the
textureless and density-textured key variants preserve the Bevy source key
dimensions and shader defs, including `MULTISAMPLED`, `ATMOSPHERE`, and
`DENSITY_TEXTURE`.

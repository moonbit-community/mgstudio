## Description
Current Bevy `bevy_light/src/atmosphere.rs` extends `ScatteringMedium` beyond the
Earth medium shape. `ScatteringMedium::mars` requires a custom dust falloff
stored as `Falloff::Curve(Arc<dyn Curve<f32> + Send + Sync>)`, a dust phase
stored initially as `PhaseFunction::ChromaticTexture(Handle<Image>)`, and an
asset-event system that resolves the loaded `Rgba32Float` Nx1 image into
`PhaseFunction::ChromaticCurve(Arc<dyn Curve<LinearRgba> + Send + Sync>)`.

Mgstudio currently ports the Earth terms, analytic `Linear`/`Exponential`/`Tent`
falloffs, and analytic `Isotropic`/`Rayleigh`/`Mie` phase functions. It does not
have a Bevy-equivalent asset-safe representation for arbitrary typed curve trait
objects or for resolving chromatic phase textures into cloneable curve values.

## Design
Do not add a Mars-specific numeric shortcut or a fixed lookup table and count it
as parity. Exact source parity needs one of these real capabilities:

- a Bevy-shaped curve owner that can represent `Curve<f32>` and
  `Curve<LinearRgba>` values in MoonBit assets without JSON-erased payloads;
- a typed, cloneable sampled-curve representation that is explicitly accepted as
  the MoonBit equivalent for Bevy's curve asset path;
- an asset event path that watches `Image` loads, validates `Rgba32Float` Nx1
  textures, samples them into the chromatic phase curve, and mutates every
  referencing `ScatteringMedium` term like Bevy's
  `extract_chromatic_phase_textures`.

Until that exists, leave `ScatteringMedium::mars`,
`Falloff::from_curve`, `PhaseFunction::from_curve`,
`PhaseFunction::from_chromatic_curve`, `PhaseFunction::from_chromatic_texture`,
and `extract_chromatic_phase_textures` unported or explicitly marked incomplete.

## Acceptance Criteria
- [ ] `Falloff` has a source-level mapping for Bevy's custom curve variant or a
      recorded language-level reason why it cannot be expressed.
- [ ] `PhaseFunction` has source-level mappings for scalar curve, chromatic
      curve, and chromatic texture variants, including the `sample` behavior for
      unavailable textures.
- [ ] `ScatteringMedium::mars(falloff_resolution, phase_resolution, dust_phase)`
      matches Bevy's constants, dust falloff equation, two scattering terms, and
      `"mars_atmosphere"` label.
- [ ] The image asset event resolver matches Bevy's
      `extract_chromatic_phase_textures` behavior for `Rgba32Float` Nx1 images.
- [ ] PBR medium LUT tests cover a chromatic curve or texture-resolved phase
      path without using JSON-erased payloads or local workaround data.

# ISS-402: Unblock meshlet example on MoonBit new native backend

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: meshlet, moonbit, native-backend, external-blocker, visual-gate
- Assignee: unassigned
- Created: 2026-07-06
- Updated: 2026-07-21
- External ref: none

## Description
With the 2026-07-06 toolchain, `examples/3d/meshlet` could not serve as the
required native visual gate because the MoonBit compiler ICEd during the native
release build. The error happened before mgstudio runtime startup, so it was a
hard toolchain blocker rather than a Bevy parity bug in the meshlet render path.

Observed command:

```sh
MOONBIT_NEW_NATIVE=1 MGSTUDIO_PARITY_CAPTURE_DELAY_FRAMES=90 \
  MGSTUDIO_PARITY_RUN_TIMEOUT_SECONDS=240 \
  mgstudio-engine/scripts/p0_visual_capture_native.sh \
  examples/3d/meshlet /tmp/mgstudio_iss394_meshlet.png
```

Observed compiler error:

```text
Machine_error(kind=unsupported; who="Machine_of_clam_lower.lower_scalar_runtime_pccall"; message="unit runtime pccall cannot be used as a scalar value"; function="@_M0MP49Milky20188mgstudio3pbr7meshlet18MeshletMeshManager25queue__upload__if__needed")
```

## Design
Keep the meshlet source path faithful to Bevy and do not add a mgstudio-side
workaround just to avoid this compiler path. Reduce the ICE to a minimal
MoonBit reproducer if it remains reproducible, file it upstream against the
MoonBit compiler, and re-enable the meshlet visual gate only after the backend
can compile the real `MeshletMeshManager::queue_upload_if_needed` path.

## Acceptance Criteria
- [x] The full meshlet build is rechecked before filing an upstream compiler
      issue; the ICE no longer reproduces on the current toolchain, so no stale
      compiler report is filed.
- [x] `moon -C mgstudio-engine run --build-only examples/3d/meshlet --target
      native --release` builds without compiler ICE on the current default
      native backend.
- [x] The standard meshlet visual capture command succeeds without selecting a
      different backend or adding a local workaround.
- [x] The meshlet screenshot is compared against the current local reference
      and pinned Bevy baseline expectation; the remaining visual failure is
      explicitly retained under ISS-020 rather than claimed as parity here.

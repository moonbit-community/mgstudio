# ISS-198: Verify volumetric fog directional shadow binding path

## Description
Bevy's volumetric fog pass samples directional shadow information through the
same view/light resources used by the `volumetric_fog` shader. A capture can
render plausible fog while still missing the shadowed light-shaft signal if
directional shadow cascades, depth texture ids, or view bind group bindings are
not carried into the volumetric pass.

## Design
Audit the path from directional shadow cascade preparation to the mesh-view bind
group consumed by `draw_mesh3d_volumetric_fog`. Compare the mgstudio data flow
against Bevy's `ViewLights`, shadow texture views, cascade metadata, and
`MeshViewBindGroup` usage. Add tests or instrumentation that fail when the fog
pass sees no directional shadow binding for a `scrolling_fog`-shaped scene.

## Acceptance Criteria
- [x] The volumetric fog pass receives the same directional shadow texture and
      cascade metadata required by Bevy's shader path.
- [x] A focused test or white-box assertion covers non-empty directional shadow
      binding data reaching the fog pass.
- [x] `scrolling_fog` capture no longer lacks the pillar shadow/light-shaft
      structure because of missing shadow bind data; this issue proves the
      missing signal must be downstream of light flags and shadow binding.
- [x] Any backend limitation is recorded as a separate external blocker with
      the exact missing primitive.

## Close Notes
Closed on 2026-07-04.

Bevy source audited:

- `bevy/crates/bevy_pbr/src/render/light.rs` fills
  `GpuDirectionalLight.cascades`, `num_cascades`, and
  `depth_texture_base_index` for shadow-enabled directional lights.
- `bevy/crates/bevy_pbr/src/render/mesh_view_bindings.rs` binds
  `ViewShadowBindings`, `ViewLightsUniformOffset`, and shadow textures into
  `MeshViewBindGroup`.
- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs::volumetric_fog` consumes
  that same `MeshViewBindGroup` as group 0.

Mgstudio audit result:

- `render3d_prepare_camera_directional_shadow_pass` returns a
  `Render3dDirectionalShadowBinding` with the directional shadow target id,
  `enabled = 1.0`, cascade count, and packed cascade data.
- `render3d_begin_pass_3d` rewrites `mesh3d_lights_uniform_bytes` by calling
  `render3d_gpu_lights_with_directional_shadow_cascades`, so the pass-state
  lights buffer contains the cascade matrices and bounds.
- `draw_mesh3d_volumetric_fog` resolves `pass_state.directional_shadow_texture_id`
  and calls `mesh3d_frame_view_bg_cache_get_or_create` with the current
  `pass_state`, so the volumetric fog group-0 view bind group uses the same
  directional shadow texture and lights uniform override as the main pass.
- No external backend primitive blocker was found in this slice.

Verification:

- Added
  `pbr directional shadow binding carries cascades for volumetric fog pass` in
  `pbr/render_shadow_view_wbtest.mbt`. It preloads the directional shadow
  target cache and verifies target id `77`, `enabled = 1.0`, `cascade_count = 4`,
  packed cascade data length `80`, and four queued shadow phase views.
- `moon -C mgstudio-engine test pbr/render_shadow_view_wbtest.mbt --target native --release`
  passed: 13 tests.
- `moon -C mgstudio-engine test pbr --target native --release` passed:
  422 tests.

Conclusion: the `scrolling_fog` light-shaft gap is not explained by a missing
directional shadow texture or cascade binding. Continue with ISS-199 for
volumetric fog shader input and sampling parity.

# ISS-468: Prevent same-reference bypass replacement destruction

## Metadata
- Type: bug
- Status: closed
- Priority: 0
- Labels: ecs, change-detection, finalizer, ownership, correctness
- Assignee: codex
- Created: 2026-07-18
- Updated: 2026-07-18
- External ref: none

## Description

`Write::bypass_change_detection` and the row-level
`TableBatchWrite::bypass_change_detection` obtain the stored component, pass it
to an update closure, and route the returned value through the ordinary
replacement setter. The setter finalizes the old component before storing the
replacement. When a reference component is mutated in place and the closure
returns that same reference, the live object is finalized immediately,
reinserted, and finalized a second time when it is later removed or its World
is closed.

## Design

Preserve the current public closure API and Bevy-equivalent bypass tick
semantics. Compare the old and returned values with MoonBit's exact
`physical_equal` operation. If they are the same object, keep the already
stored reference and do not invoke replacement/finalization. If they are
different, retain the ordinary setter so the displaced value is finalized
exactly once. Apply the same rule to ordinary `Write` and table-batch row
bypass paths; do not weaken normal replacement ownership or the bulk
`MutArrayView` custom-finalizer guard.

## Acceptance Criteria

- [x] Returning the same reference from `Write::bypass_change_detection` does
      not finalize it before World shutdown and finalizes it exactly once at
      shutdown.
- [x] Returning the same reference from table-batch row bypass has the same
      lifetime behavior.
- [x] Returning a distinct replacement continues to finalize the displaced
      component exactly once.
- [x] Bypass writes continue to preserve component change ticks.
- [x] Focused tests run one at a time with `MOONBIT_NEW_NATIVE=1`, and the ECS
      public interface remains unchanged.

## Notes

- 2026-07-18: Source trace confirmed that both row-level bypass APIs reach the
  finalizing component setter even when their update closures return the
  exact object already stored in the component column.
- 2026-07-18: Both focused regressions failed before the fix with
  `(finalized_before_close=1, finalized_values=[1, 1])` and passed afterward
  with `(0, [1])`.
- 2026-07-18: Pinned Bevy `1413bc4e3632233b8fa610a6cf14b90258556c51`
  returns the stored `&mut` directly from `DetectChangesMut::bypass_change_detection`;
  it does not perform a replacement or drop. The physical-identity guard is
  the MoonBit adaptation required by the existing closure-return API.

## Close Notes

Closed on 2026-07-18. Ordinary and table-batch row bypass writes now compare
the stored value and closure result with `physical_equal`. Returning the same
reference leaves the live ECS value in place, while a distinct result still
uses the existing finalizing replacement setter. No public signature changed.

Focused native-release tests separately verified ordinary same-reference
ownership, ordinary distinct replacement, table-batch same-reference
ownership, table-batch distinct replacement, ordinary bypass ticks,
table-batch bypass ticks, and the valtype `ViewVisibility` production path.
Every test invocation selected one test and used `MOONBIT_NEW_NATIVE=1`.
`moon check ecs --target native --deny-warn` completed cleanly, `moon info ecs
--target native` produced no generated interface diff, and `git diff --check`
passed.

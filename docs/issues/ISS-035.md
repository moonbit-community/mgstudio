## Description
Mgstudio's typed ECS storage is no longer blocked by the old erased payload
model, but several ECS API surfaces still force Bevy ports to change source
shape. This epic tracks the high-priority ECS work needed to make render,
mesh, PBR, examples, and future Bevy-owned modules migrate through Bevy-shaped
systems, bundles, queries, resources, and deferred commands.

## Design
Preserve the current typed-key storage model. Do not reintroduce JSON payloads,
erased runtime component values, downcast-style key recovery, or compatibility
fallbacks. Fix local API shape where MoonBit can express the Bevy concept.
Where MoonBit cannot enforce Bevy's Rust type-system guarantees, document the
API contract explicitly and audit ports against that contract.

## Acceptance Criteria
- [ ] `Commands`, bundles, query filters, and common system params no longer
      force routine Bevy ports to rewrite source ownership or split normal
      Bevy tuples.
- [ ] Deferred command state is owned by the current world/schedule execution
      context rather than process-global runtime state.
- [ ] Generic ECS key-family conventions are documented and used consistently
      by new generic component/resource families.
- [ ] Read-only ECS access constraints are documented as API contracts, with no
      attempt to emulate Rust aliasing through erased payloads or copies.
- [ ] Child issues are closed, blocked with a real language/external blocker,
      or replaced by more specific issues.

## Description
Mgstudio currently has renderer backend pipeline caches and helper functions
for volumetric fog, but Bevy owns this through a first-class
`VolumetricFogPipeline` render resource containing mesh-view layouts,
volumetric fog bind group layouts, the shader handle, and specialization
behavior. The current renderer-local lazy state makes later parity work hard to
audit and caused layout ownership to drift.

## Design
Port the source shape of Bevy's `VolumetricFogPipeline` owner into mgstudio:
resource initialization, bind group layout preparation, shader registration, and
specialized pipeline key construction. Keep renderer backend calls as the final
GPU implementation detail, but drive them from a PBR render resource that maps
to Bevy's owner instead of ad hoc renderer-local state.

## Acceptance Criteria
- [ ] `pbr/volumetric_fog` exposes a Bevy-shaped `VolumetricFogPipeline` owner with mesh-view layouts, fog bind group layouts, and shader identity.
- [ ] Pipeline specialization takes an explicit Bevy-shaped key rather than unrelated renderer arguments.
- [ ] Existing renderer pipeline caches are either removed or reduced to backend implementation details behind the owner.
- [ ] Focused volumetric fog pipeline tests pass with `--release` where needed.

## Close Notes
2026-07-04: Restored the first-class PBR-side volumetric fog pipeline owner
shape. `pbr/volumetric_fog` now exposes `VolumetricFogPipeline`,
`VolumetricFogPipelineKey`, and `VolumetricFogBindGroupLayoutKey` with shader
identity, mesh-view layout key, target format, hull vertex stride, density
texture bit, Bevy shader defs, and the volumetric bind group layout key. The
plugin installs the `VolumetricFogPipeline` resource alongside `FogAssets`.
Renderer-side caches remain as backend materialization details, but PBR now
constructs the Bevy-shaped pipeline key and passes key fields into the renderer
instead of asking the renderer to infer specialization semantics from unrelated
arguments. `render/mesh_view_layout` now exposes the MSAA and atmosphere layout
bits needed by the PBR owner.

# ISS-260: Align volumetric fog shadow-resource pass ownership with Bevy

## Description
If ISS-259 shows that mgstudio loses the real directional shadow texture before
the volumetric fog draw, the pass ownership and data flow must be aligned with
Bevy instead of relying on stale renderer-local state or fallback textures.

## Design
Read Bevy's volumetric fog node/pass, view bind group, shadow binding, and
render graph source owners. Then map the same owner boundary into mgstudio.
Prefer explicit Bevy-shaped data ownership over implicit renderer pass-state
coupling when that is what the source shape requires.

## Acceptance Criteria
- [x] The corrected mgstudio ownership is mapped to specific Bevy source owners.
- [x] Volumetric fog receives directional shadow resources through the same
      logical owner boundary as Bevy, within MoonBit's language constraints.
- [x] Any renderer-local compatibility state made obsolete by the corrected
      ownership is removed rather than kept as a fallback.
- [x] Targeted native release tests cover the corrected data path.

## Notes

- 2026-07-05: Started after ISS-259. Bevy source owners read:
  `bevy/crates/bevy_pbr/src/render/light.rs::prepare_lights`,
  `bevy/crates/bevy_pbr/src/render/mesh_view_bindings.rs::prepare_mesh_view_bind_groups`,
  and `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs::volumetric_fog`.
  The immediate shadow-resource leak is fixed by threading
  `Render3dViewShadowBindings` explicitly into the volumetric fog host draw.
  Remaining source-shape work is to decide whether mgstudio should introduce a
  first-class render-world `MeshViewBindGroup` owner instead of renderer-local
  bind-group caches.

## Close Notes
- 2026-07-05: Closed the focused shadow-resource ownership slice. Bevy owner
  mapping: `prepare_lights` creates per-view `ViewShadowBindings`,
  `prepare_mesh_view_bind_groups` builds `MeshViewBindGroup` from those
  bindings, and `volumetric_fog` consumes the view's `MeshViewBindGroup`.
  Mgstudio now mirrors this logical boundary by carrying
  `Render3dViewShadowBindings` into `render3d_execute_camera_volumetric_fog_pass`
  and passing explicit point/directional shadow texture ids into
  `draw_mesh3d_volumetric_fog`.
- 2026-07-05: The renderer-side volumetric fog draw now resolves point and
  directional shadow textures from the explicit view-shadow inputs instead of
  reading shadow ids from `GpuPassState`. The active pass state is still used
  for view target, depth texture, viewport, lighting bytes, and other current
  view data; no obsolete fallback state was added.
- 2026-07-05: Validation:
  `moon -C mgstudio-engine test render/renderer --target native --release --filter '*volumetric fog resolves explicit view shadow texture identities*'`
  passed with `Total tests: 1, passed: 1, failed: 0`.

  `moon -C mgstudio-engine test examples/3d/scrolling_fog --target native --release --filter '*runtime volumetric fog pass receives directional shadow resources*'`

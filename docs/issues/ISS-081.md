## Description
`examples/3d/ssr/reference.png` is still an unusable transparent baseline. A
standard native capture of the current example produced a numerically nonblank
image, but manual review rejected it: the frame is effectively a dark scene with
only a sparse diagonal line, not the visible Bevy SSR scene.

This is not just a screenshot artifact. Bevy's `examples/3d/ssr.rs` is a rich
deferred-rendering example built around `ScreenSpaceReflections`,
`DefaultOpaqueRendererMethod`, `ExtendedMaterial<StandardMaterial, Water>`, a
custom water WGSL extension, sky/environment lighting, model/base selection, and
UI controls. Mgstudio's current `examples/3d/ssr/main.mbt` explicitly states
that Bevy's custom deferred water material extension is represented by closest
available standard-material behavior. That is a local approximation and must not
be counted as source or visual parity.

## Design
Audit and port Bevy `examples/3d/ssr.rs` and the required PBR/render owners as
the migration unit. Preserve Bevy's source shape as closely as MoonBit allows:

- `ScreenSpaceReflections` component setup and runtime updates;
- `DefaultOpaqueRendererMethod::deferred()` behavior for the camera and
  materials;
- `ExtendedMaterial` / `MaterialExtension` support needed by the custom
  `Water` material;
- `WaterSettings` uniform data and `shaders/water_material.wgsl` binding shape;
- skybox/environment lighting and displayed model/base setup;
- Bevy-shaped UI control state and input flow.

Do not accept a dark capture, standard-material water approximation, or
SSR-disabled render path as parity. If a MoonBit language or dependency
capability truly prevents a direct port, record that blocker precisely before
leaving the source shape partial.

## Acceptance Criteria
- [x] Every source-shape anchor in Bevy `examples/3d/ssr.rs` is classified as
      complete, partial, facade, blocked, or intentionally excluded.
- [x] The custom deferred water material extension is ported, or a precise
      language/dependency blocker records why it cannot be expressed yet.
- [x] The rendered scene visibly contains the Bevy-equivalent base, model, and
      screen-space reflection signal instead of a dark sparse-line frame.
- [ ] `examples/3d/ssr/reference.png` is refreshed only after the visual signal
      is present and the approximation note is removed or replaced by a precise
      blocker.
- [x] The standard native capture command succeeds without validation, fatal,
      or missing-resource output.

## Source-Shape Anchor Classification
- `SHADER_ASSET_PATH`, camera movement constants, roughness/edge step values:
  complete. Mgstudio carries equivalent constants, with roughness and edge
  adjustment steps kept at the Bevy call sites.
- `Water`, `WaterSettings`, and `MaterialExtension for Water`: complete for the
  SSR example owner. The custom deferred shader path and bindings 100/101/102
  are represented through mgstudio's material-extension metadata and renderer
  bind group path.
- `AppSettings`, `DisplayedModel`, `DisplayedBase`, `ExampleSetting`,
  `Adjustment`, marker components, and `RangeValueText`: complete. MoonBit uses
  separate float fields for Bevy `Range<f32>` values, but ownership and runtime
  state match the example.
- `ModelQueries`: partial. The marker-query ownership has replaced cached local
  entity handles, but mgstudio does not yet have a Bevy-shaped custom
  `SystemParam` aggregate for this example, so the queries are distributed
  across helper systems/functions.
- `main`: partial. Plugin/resource/message registration and update flow are
  present, but mgstudio still needs explicit UI camera/target setup and split
  settings-application systems where Bevy has one `adjust_app_settings` system.
- `setup`: partial. Scene/model/base/camera setup is aligned, but button setup
  remains a separate startup system because current widget helpers require an
  `@app.Commands` system param while the scene setup is world-based.
- `spawn_cube`, `spawn_flight_helmet`, `spawn_capsules`,
  `spawn_metallic_base`, `spawn_non_metallic_base`, and `spawn_water`:
  complete for in-scope example behavior after the material, unit-plane,
  scale, roughness, visibility, and scene-node fixes recorded below.
- `spawn_camera`: partial. Camera, SSR, SSAO, environment map, and skybox data
  are present, but mgstudio camera/light setup should still be symbol-audited
  against Bevy's camera bundle/prepass ownership before refreshing the checked
  reference.
- `spawn_buttons`, `range_row`, `range_controls`, and `adjustment_button`:
  partial. The widget tree, marker placement, radio state, and range-value
  child text shape now follow Bevy, but border constants, side-specific range
  button borders, and explicit UI-camera wiring still differ from the upstream
  helper shape.
- `rotate_model` and `move_camera`: complete for current example behavior.
  `rotate_model` is implemented as marker-query helpers because current
  MoonBit ECS query composition cannot express Bevy's `Or` query in one
  system param without losing source ownership.
- `adjust_app_settings`: partial. Event handling, SSR insertion/removal,
  visibility writes, radio refresh, and range text refresh are implemented, but
  mgstudio currently splits the Bevy system into several scheduled systems
  because the example would otherwise exceed available system-param shape and
  lacks `TextUiWriter` as a system param.
- `adjust` and `AppSettings` default construction: complete.

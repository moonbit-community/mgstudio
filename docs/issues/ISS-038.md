# ISS-038: Move deferred command state into world and schedule execution context

## Description
Deferred command execution should be scoped to the active world and schedule
run. A process-global runtime queue can work for simple single-world examples,
but it is not Bevy-shaped and risks cross-world, sub-app, nested schedule, or
future parallel execution contamination.

## Design
Introduce an explicit deferred command execution context owned by the current
world/schedule run path. `Commands` should enqueue into that context, and
`apply_deferred` should drain the context belonging to the schedule being
executed. Do not preserve a compatibility layer around package-global command
state.

## Acceptance Criteria
- [ ] Deferred command queues are no longer stored in package-global runtime
      state.
- [ ] Each world or schedule execution context owns the queued deferred actions
      it will later apply.
- [ ] Existing command ordering semantics remain covered by tests.
- [ ] Sub-app/render-app command paths do not share deferred queues by
      accident.
- [ ] Any MoonBit language limitation that prevents the Bevy-shaped context
      model is recorded as a blocker instead of being hidden by fallback state.

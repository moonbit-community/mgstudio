# ISS-145: Expose storage binding-array capability queries through wgpu_mbt

## Description
Bevy's `StandardMaterial` derives `AsBindGroup` with
`#[data(0, StandardMaterialUniform, binding_array(10))]` and
`#[bindless(index_table(range(0..31)))]`. Its material allocator path calls
`material_uses_bindless_resources::<M>(&RenderDevice)`, which must only return
true when the material has a bindless slot count and the render device actually
supports the required binding-array features.

Mgstudio can represent the static StandardMaterial slot count (`31`) and can
query texture binding-array related features, but the current exposed
`wgpu_mbt` surface does not provide the storage/resource binding-array feature
query needed for the `binding_array<StandardMaterialUniform>` data path. Enabling
StandardMaterial bindless from texture binding-array support alone would be an
incorrect local approximation.

## Design
Do not infer storage binding-array support from texture binding arrays. Keep
StandardMaterial bindless disabled until `wgpu_mbt` exposes the missing feature
query and device-request support, then port Bevy's generated `AsBindGroup`
capability decision directly.

## Acceptance Criteria
- [ ] `wgpu_mbt` exposes the native/WebGPU feature query needed to determine
      storage/resource binding-array support for material data binding arrays.
- [ ] `wgpu_mbt` can request that feature when the adapter supports it.
- [ ] Mgstudio's `standard_material_bindless_supported(RenderDevice)` checks the
      real device capability instead of returning the current blocked value.
- [ ] `StandardMaterialPlugin` enables the bindless allocator only when the
      Bevy-equivalent StandardMaterial bindless feature set is supported.

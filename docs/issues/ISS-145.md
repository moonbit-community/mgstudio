# ISS-145: Expose bindless sampler binding-array limits through wgpu_mbt

## Metadata
- Type: task
- Status: closed
- Priority: 1
- Labels: wgpu_mbt, pbr, material-bind-groups, bindless, external-blocker, source-parity
- Assignee: unassigned
- Created: 2026-06-21
- Updated: 2026-06-30
- External ref: https://github.com/moonbit-community/wgpu-mbt/issues/30

## Description
Bevy's `StandardMaterial` derives `AsBindGroup` with
`#[data(0, StandardMaterialUniform, binding_array(10))]` and
`#[bindless(index_table(range(0..31)))]`. Its material allocator path calls
`material_uses_bindless_resources::<M>(&RenderDevice)`, which must only return
true when the material has a bindless slot count and the render device actually
supports the required binding-array features.

Mgstudio can represent the static StandardMaterial slot count (`31`) and can
query texture, buffer, and storage-resource binding-array related features in
`wgpu_mbt@0.14.3`. The remaining missing dependency surface is the exact Bevy
limit used by the generated `AsBindGroup::bindless_supported` implementation:
`max_binding_array_sampler_elements_per_shader_stage`.

Bevy does not require storage/resource binding arrays for StandardMaterial's
`#[data(...)]` path. The derive macro promotes uniform data to a storage buffer
in bindless mode and requires `TEXTURE_BINDING_ARRAY`; it requires
`BUFFER_BINDING_ARRAY` only when the material actually has buffer binding-array
resources. It always also requires
`limits().max_storage_buffers_per_shader_stage > 0` and enough sampler binding
array elements. Enabling StandardMaterial bindless without that sampler limit
would be an incorrect local approximation.

## Design
Do not infer the sampler binding-array limit from unrelated limits such as
`max_bindings_per_bind_group`. Keep StandardMaterial bindless disabled until
`wgpu_mbt` exposes the exact limit, then port Bevy's generated `AsBindGroup`
capability decision directly.

## Acceptance Criteria
- [x] `wgpu_mbt` exposes the native/WebGPU feature query needed to determine
      texture, buffer, and storage/resource binding-array support.
- [x] `wgpu_mbt` can request those features when the adapter supports them.
- [x] `wgpu_mbt` exposes
      `max_binding_array_sampler_elements_per_shader_stage` or an exact
      equivalent.
- [x] Mgstudio's `standard_material_bindless_supported(RenderDevice)` checks the
      real Bevy-equivalent feature and limit set instead of returning the
      current blocked value.
- [x] `StandardMaterialPlugin` enables the bindless allocator only when the
      Bevy-equivalent StandardMaterial bindless feature set is supported.

## Notes
- 2026-06-21: Created while auditing
  `bevy_pbr/src/material.rs::add_material_bind_group_allocator<M>` and
  `bevy_pbr/src/pbr_material.rs::StandardMaterial`. Mgstudio now routes
  StandardMaterial allocator installation through `RenderDevice` and records
  Bevy's `31` bindless slot count, but `standard_material_bindless_supported`
  remains blocked because storage binding-array capability cannot be queried
  from the current dependency surface.
- 2026-06-21: Filed upstream as
  https://github.com/moonbit-community/wgpu-mbt/issues/30.
- 2026-06-22: Rechecked against `wgpu_mbt@0.14.3`. Storage/resource binding
  array feature queries and device-request helpers now exist, but the original
  blocker description was too broad. The actual remaining Bevy blocker is the
  missing sampler binding-array element limit used by the `AsBindGroup` derive
  macro. Mgstudio now requests the available binding-array features during
  backend initialization, but keeps StandardMaterial bindless disabled until the
  exact sampler limit is available.
- 2026-06-30: Rechecked while closing ISS-162 against `wgpu_mbt@0.14.4`. The
  request-device sampler and sampled-texture per-stage limits are now available,
  but the current macOS adapter still reports `max_samplers_per_shader_stage =
  16`. Enabling both non-bindless `pbr_anisotropy_texture` and
  `pbr_multi_layer_material_textures` creates a 17-sampler material layout, so
  mgstudio now matches the Bevy `examples/3d/anisotropy` feature shape by
  enabling anisotropy texture support without multi-layer material textures.
  Full StandardMaterial multi-layer texture parity still depends on the
  bindless capability decision tracked here.
- 2026-06-30: `wgpu_mbt@0.14.6` exposes adapter/device
  `max_binding_array_sampler_elements_per_shader_stage` and request-device
  limit overrides. Mgstudio now requests the adapter binding-array element and
  sampler-element limits during backend initialization and implements
  `standard_material_bindless_supported(RenderDevice)` with the Bevy derive
  macro shape: texture binding arrays, nonzero storage-buffer-per-stage limit,
  and enough sampler binding-array elements for the 31-slot
  `StandardMaterial` bindless table.

## Close Notes
Closed after updating to `Milky2018/wgpu_mbt@0.14.6`, wiring the newly exposed
sampler binding-array limit through backend initialization and `RenderDevice`,
and replacing the blocked `false` return with the Bevy-shaped capability check.
Verified with `moon -C mgstudio-engine check --target native --deny-warn` and
`moon -C mgstudio-engine test --release pbr --deny-warn`.

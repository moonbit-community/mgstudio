## Description
After the WGSL read map, host layout, cascade propagation, and bind-group
ownership are verified, add one focused white-box gate that models the
`scrolling_fog` directional light and shadow input set end to end. This test is
the executable acceptance artifact for ISS-213 before shader sampling math
continues in ISS-214.

## Design
Build the smallest PBR/render test that creates a `scrolling_fog`-shaped camera,
directional light, shadow cascade set, and volumetric fog pass input. Assert the
exact fields consumed by `volumetric_fog.wgsl`: directional light count, flags,
cascade count, cascade matrix/scalar data, depth texture base index, lights
uniform bytes, shadow texture binding identity, sampler slot, and dynamic
offsets. Do not use runtime screenshot appearance as the only proof.

## Acceptance Criteria
- [x] The test fails if the lights uniform uses renderer fallback bytes instead
      of the Bevy-shaped PBR uniform bytes.
- [x] The test fails if cascade count, cascade data, shadow flags, or
      `depth_texture_base_index` diverge from Bevy semantics.
- [x] The test fails if the volumetric fog pass binds a different directional
      shadow texture identity than the current camera view's shadow pass.
- [x] The relevant `moon -C mgstudio-engine test ... --target native --release`
      command passes and is recorded in close notes.
- [x] Closing this issue provides enough evidence to close ISS-213 and unblock
      ISS-214.

## Close Notes
Closed with a gate composed from one PBR white-box test and the renderer
white-box tests that own the downstream bind-group boundary. The PBR test
`pbr/render light: scrolling_fog pass bytes preserve volumetric shadow inputs`
constructs a `scrolling_fog`-shaped `Render3dLightingState`, injects active
directional shadow cascade data through the production pass helper, and verifies
directional light count, shadow+volumetric flags, cascade count, overlap,
`depth_texture_base_index`, cascade matrices/scalars, and shadow bias fields in
the packed `GpuLights3d` uniform bytes. The renderer tests prove those bytes
win over renderer fallback bytes and that volumetric fog group 0 uses the active
view's shadow texture identity and Bevy mesh-view dynamic-offset order.

Validation:

- `moon -C mgstudio-engine test pbr/render --target native --release --filter '*scrolling_fog pass bytes preserve*'`
- `moon -C mgstudio-engine test render/renderer --target native --release --filter '*volumetric fog group zero*'`
- `moon -C mgstudio-engine test render/renderer --target native --release --filter '*volumetric fog resolves active pass shadow texture identities*'`
- `moon -C mgstudio-engine test render/renderer --target native --release --filter '*mesh3d lights uniform prefers*'`

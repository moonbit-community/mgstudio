## Description
`examples/3d/anisotropy` has broad runtime behavior coverage, but it is not a
symbol-level port of Bevy's `bevy/examples/3d/anisotropy.rs`.

The current implementation keeps the major visible features: barn-lamp scene,
anisotropic sphere, light-mode cycling, anisotropy toggle, scene toggle, skybox,
and environment map. The strict gaps are source-shape issues: Bevy's
`AppStatus` resource, `MaterialVariants` component, `Scene` component,
`Local<Stopwatch>`, UI `Text` plus `Node`, command/query mutation, and
Bevy-shaped sphere/tangent construction are replaced by a global
`AnisotropyState`, tracked entities, direct world mutation, `Text2d`, and a
local UV-sphere generator.

The example also still uses the user-visible string `"Bevy Anisotropy Example"`;
mgstudio code should preserve source meaning while using mgstudio branding for
concrete UI/window strings.

## Design
Port the example directly from the Bevy source owner. Keep only local changes
that are required by concrete MoonBit language/API limitations, and record each
such limitation as a precise blocker. Do not keep global state, tracked entity
arrays, direct world mutation, or Bevy-branded local strings as the parity path.

## Acceptance Criteria
- [x] `AppStatus` is represented as a Bevy-shaped resource with `light_mode`,
      `anisotropy_enabled`, and `visible_scene`.
- [x] `LightMode` preserves the Bevy default and variant transition order.
- [x] `MaterialVariants` is represented as an ECS component attached to each
      material-bearing mesh, not as a global array.
- [x] `Scene` is represented as an ECS component with default, `next`, and
      display/name semantics.
- [x] `main` preserves Bevy's app resource initialization, window plugin shape,
      startup system, update systems, and chained `(handle_input,
      update_help_text)` ordering where the ECS API can express them.
- [x] User-visible strings use mgstudio branding while preserving Bevy source
      meaning.
- [x] `setup` exposes Bevy-shaped commands, asset server, and app-status
      parameters where possible.
- [x] The barn-lamp scene uses `WorldAssetRoot` semantics or records a precise
      scene-root blocker.
- [x] The sphere mesh preserves `Mesh::from(Sphere::new(0.1))` plus
      `with_generated_tangents().unwrap()` or records a precise mesh/tangent
      blocker.
- [x] `create_material_variants` uses Bevy-shaped added-material and
      without-variant query semantics, then inserts `MaterialVariants`.
- [x] `rotate_camera` uses resource state plus local stopwatch semantics
      rather than global elapsed angle.
- [x] `handle_input` uses Bevy-shaped commands, asset-server access, camera,
      light, material, and scene queries, keyboard input, and mutable resource
      state.
- [x] Help text uses UI `Text` plus absolute `Node`, and `update_help_text`
      mutates text through a Bevy-shaped query.
- [x] `AnisotropyState`, tracked scene entities, stored `TextHandle`,
      `material_variants` array, manual scene ownership inference, and local
      UV-sphere generator are removed from the source-parity path unless
      precise blockers are documented.
- [x] The reference screenshot is refreshed after the source-shaped port still
      renders correctly.

## Description

`mgstudio-engine/color/palettes` held only a fraction of the pinned Bevy
palettes: 15 of 132 CSS colours and 16 of 242 Tailwind colours. `basic` was
complete at 16 of 16.

Two consequences:

1. Examples could not name the colour the Bevy source names, so many invented
   approximate literals instead. `examples/gizmos/3d_text_gizmos` used
   `srgb(0.9, 0.2, 0.2)` where Bevy uses `css::RED`, `srgb(0.95, 0.5, 0.15)`
   where Bevy uses `css::ORANGE`, and `srgb(0.95, 0.85, 0.25)` where Bevy uses
   `css::YELLOW`.
2. Two of the 16 ported Tailwind values were wrong, not merely rounded:
   - `SLATE_950`: was `(0.007843, 0.090196, 0.188235)`,
     Bevy has `(0.007843138, 0.023529412, 0.09019608)`
   - `ROSE_700`: was `(0.745098, 0.129412, 0.235294)`,
     Bevy has `(0.74509805, 0.07058824, 0.23529412)`

## Design

Generate all three palette files directly from
`bevy/crates/bevy_color/src/palettes/{basic,css,tailwind}.rs`, preserving Bevy's
exact f32 literals and source ordering, and keeping the established
`pub fn <module>_<snake_name>() -> @color.Color` shape. `basic` is not
re-emitted under a `css_` prefix because Bevy's `css` module re-exports `basic`
rather than redefining it.

## Acceptance Criteria
- [x] `basic` 16/16, `css` 132/132, `tailwind` 242/242.
- [x] No previously exported function name is removed.
- [x] Previously correct values are unchanged apart from gaining Bevy's full
  f32 precision; the two wrong values are corrected.
- [x] `moon check --target native` is clean.
- [x] The examples carrying invented literals are converted to palette calls
  wherever the mgstudio port has a site for the constant (see Notes for the
  recorded port gaps).

## Conversion results

All 37 remaining examples were swept against the pinned Bevy example sources.
Roughly 60 sites across 30 packages now call the palette constants Bevy names,
including constants the original survey missed (`ssr` had four palette sites;
`animation_graph` gained `DARK_GREEN` and `ANTIQUE_WHITE`; `light_gizmos` had
five constants, not two; `generic_font_families` also uses `WHEAT` and
`YELLOW`). Sites where Bevy writes `Color::WHITE`/`Color::BLACK` or raw
literals keep their constructors, and `animation_events` threads its fade alpha
through `with_alpha` on the palette colours.

Constants with **no corresponding site in the mgstudio port** were left
unconverted and are port gaps, not colour defects:

- `testbed/3d`, `testbed/full_ui`, `testbed/ui`: the ports are simplified
  placeholder scenes; none of the Bevy sub-scenes carrying the constants exist.
- `transforms/align` (GRAY/RED/WHITE): Bevy colours gizmo arrows; the port has
  no gizmo systems.
- `picking/debug_picking`, `usage/context_menu` (WHITE/RED),
  `ui/text/text_background_colors` (DARK_CYAN border),
  `ui/layout/display_and_visibility` (DARK_GRAY/YELLOW),
  `ui/scroll_and_overflow/scroll` (RED/BLUE sticky headers),
  `shader_advanced/compute_mesh` (SKY_400 second mesh user),
  `shader_advanced/render_depth_to_texture` (LIME camera gizmo),
  `math/custom_primitives` (WHITE bounding gizmos),
  `ui/navigation/directional_navigation_overrides` (the other two per-page
  colour triples): each constant belongs to an entity, observer or outline the
  port does not spawn.
- `ui/ui_material` (DARK_BLUE): Bevy's only site is the banner's `Outline`,
  which the port lacks. A first pass moved the constant onto the invented root
  backdrop -- a different object -- and was reverted; the backdrop keeps its
  literal and the missing `Outline` is the recorded gap.
- `ui/layout/display_and_visibility` DARK_CYAN *was* converted onto the target
  panels' border: the port substitutes a 4px border for Bevy's 4px `Outline` on
  the same panels, so the mechanism differs but the object and width match.

Values changed visibly where Bevy's constant differs from the invention (css
GREEN is (0, 0.502, 0); several soft invented colours became full-saturation
basics). Affected reference screenshots are covered by the one-shot
regeneration task recorded in the tracker.

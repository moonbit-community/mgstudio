## Description
Bevy prepares sampled depth texture usage for volumetric fog and carries
density texture handles, density texture offset, and density texture scale
through `ViewFogVolume` into the pass.

## Design
Audit `prepare_view_depth_textures_for_volumetric_fog` plus density texture
metadata separately from uniform packing. Do not accept fallback textures as
source parity.

## Acceptance Criteria
- [x] View depth texture usage and binding readiness are classified.
- [x] Density texture handle lookup and missing-asset behavior are classified.
- [x] Density texture offset/scale animation inputs are classified.
- [x] Any fallback texture or late allocation divergence is fixed or filed as
      a narrower ISS.

## Close Notes
Closed 2026-07-09. Bevy `prepare_view_depth_textures_for_volumetric_fog` marks
camera depth textures as shader-readable when any `VolumetricFog` view exists;
mgstudio maps this through `render3d_world_has_volumetric_fog_views` and
`render3d_prepare_view_depth_texture_usage_for_sampled_depth`. Density texture
metadata is carried as the optional image handle in `ViewFogVolume`, and the
renderer resolves it through the render texture registry. Missing density
assets return `None` and select the textureless pipeline, matching Bevy
`RenderAssets<Image>::get(...).and_then(...)` behavior rather than using a
fallback texture. Bevy's current owner carries `density_texture_offset`; there
is no separate density texture scale field in the audited source.

Existing evidence:
- `pbr/volumetric_fog_execute_wbtest.mbt` covers depth texture usage promotion
  when volumetric fog, SSAO, or atmosphere need sampled depth.
- `pbr/volumetric_fog/render_wbtest.mbt` covers
  `density_texture_offset` packing into the uniform bytes.
- `pbr/volumetric_fog_execute_wbtest.mbt` covers density texture handle IDs in
  per-view prepared metadata.
- `render/renderer/gpu_wbtest.mbt` covers missing density textures selecting
  `None`, and valid registered 3D textures selecting `Some(_)`.

## Description
After the `scrolling_fog` pillar has all Bevy-required specialization inputs,
mgstudio must create the same shadow pipeline cache entry that Bevy creates in
`specialize_shadows`. Without that cache entry, `queue_shadows` cannot enqueue
the draw even if visibility and assets are correct.

## Design
Compare Bevy `specialize_shadows` pipeline-key construction, material
specialization key, mesh key, draw-function selection, and
`SpecializedShadowMaterialPipelineCache` insertion against mgstudio's shadow
specialization code. Preserve Bevy's pending-queue behavior for genuinely
missing data, but do not leave source-shaped complete data stuck as pending.

## Acceptance Criteria
- [x] The `scrolling_fog` pillar produces a shadow specialization cache entry
      for each relevant retained shadow view.
- [x] The cache key includes the Bevy-equivalent light key, mesh key, material
      specialization key, lightmap flag, alpha mode flags, and render pipeline
      identity.
- [x] The selected draw function matches Bevy's depth-only versus material
      shadow draw selection.
- [x] A focused test proves the specialized cache entry is present before
      queueing.

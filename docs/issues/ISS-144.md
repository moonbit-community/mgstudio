## Description
Bevy's GPU clustering readback path schedules the CPU map callback on the
active command encoder with `CommandEncoder::map_buffer_on_submit`. The
callback decodes the copied `ClusterMetadata`, updates per-view clustering
readback capacities and statistics, unmaps the staging buffer, and recycles it
after the submitted GPU work completes.

Mgstudio can currently encode the metadata `copy_buffer_to_buffer` and can map a
buffer synchronously after submission. The original upstream `wgpu_mbt` request
has since been closed, so this issue should no longer be described as a missing
dependency API by default. The remaining work is to audit the available native
mapping surface, prove which helper is equivalent to Bevy's
`command_encoder.map_buffer_on_submit(...)`, and wire GPU clustering readback
through that path without reaching through private renderer state.

## Design
Do not add a project-local native callback bridge in mgstudio. Keep the
Bevy-shaped staging buffer pool and command sequence intact, then wire the
callback through the exposed native API only after its ordering and recycling
semantics are audited against Bevy.

## Acceptance Criteria
- [ ] The available native mapping API is audited and either proven equivalent
      to Bevy's `CommandEncoder::map_buffer_on_submit` for this use case or
      split into a precise dependency blocker.
- [ ] Mgstudio schedules GPU clustering metadata readback through that API
      instead of using synchronous post-submit mapping.
- [ ] `ViewClusteringReadbackData` updates and recycles staging buffers from the
      submit-time callback.
- [ ] ISS-016 can remove the map-on-submit caveat from the GPU clustering
      command path.

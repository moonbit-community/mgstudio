## Description
`examples/3d/atmosphere` currently logs
`draw_mesh3d_volumetric_fog: Fatal(wgpu: material pipeline descriptor is missing group 0 view layout)`
after the deferred SSR reflection fix. This indicates that the volumetric fog
draw path can reach the renderer, but the specialized pipeline descriptor does
not carry the Bevy-shaped mesh-view bind group layout needed for group 0.

## Design
Audit Bevy `bevy_pbr/src/volumetric_fog/render.rs` around
`VolumetricFogPipeline`, `VolumetricFogBindGroupLayoutKey`, and
`SpecializedRenderPipeline`. Repair the mgstudio mapping in the renderer
pipeline/build path so a volumetric fog pipeline always has a valid view layout
for the active `MeshPipelineViewLayoutKey`, target format, MSAA state,
atmosphere bit, and density-texture bit. Do not suppress the fatal, skip the
pass, or add a fallback pipeline.

## Acceptance Criteria
- [ ] `examples/3d/atmosphere` capture no longer logs the missing group 0 view layout fatal.
- [ ] `mesh3d_volumetric_fog_pass.mbt` selects a pipeline descriptor whose bind group 0 layout matches the Bevy volumetric fog view layout requirements.
- [ ] Focused tests or assertions cover the layout-key-to-pipeline-descriptor path.
- [ ] `moon -C mgstudio-engine check --target native`, `moon -C mgstudio-engine fmt`, and `moon -C mgstudio-engine info` complete.

## Close Notes
2026-07-04: Fixed the local owner mapping bug in
`mesh3d_volumetric_fog_pass.mbt`: the volumetric fog pass now asks the view
bind-group cache for `MESH3D_DEFAULT_MATERIAL_PIPELINE_ID` instead of the
literal `0UL`. Bevy's volumetric fog pass binds `MeshViewBindGroup.main` at
group 0 and does not have a material pipeline descriptor; using `0UL` made the
local renderer treat the pass as a non-default material pipeline with no
descriptor, which triggered `wgpu: material pipeline descriptor is missing
group 0 view layout`. Added a renderer white-box regression test for the
default owner id.

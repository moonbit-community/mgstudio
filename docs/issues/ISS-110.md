## Description
`examples/3d/atmospheric_fog` is functional, but it is not a source-shaped port
of Bevy's `bevy/examples/3d/atmospheric_fog.rs`.

The core visual behavior is close: the camera transform, `DistanceFog` values,
terrain asset path, sky cuboid, cascade shadow values, and Space/S controls are
represented. The remaining gaps are local architecture and API shape issues:
startup systems are collapsed into one world system, `AssetServer` and asset
stores are obtained locally instead of through system params, terrain uses
`SceneRoot` rather than `WorldAssetRoot`, UI instructions are implemented as a
2D text bundle instead of `Text` plus `Node`, and toggles rewrite fog through
global state instead of mutating `Single<&mut DistanceFog>`.

## Design
Port the example directly from the Bevy owner. Do not treat the current global
state/status-text implementation as parity. Keep the already matching fog,
camera, terrain, sky, and key values, but restore the source owner shape for
systems, component/resource parameters, UI text, and in-place `DistanceFog`
mutation.

## Acceptance Criteria
- [x] `main` registers the same startup tuple and update system structure as
      Bevy, subject only to MoonBit system-param syntax.
- [x] `setup_camera_fog`, `setup_terrain_scene`, `setup_instructions`, and
      `toggle_system` expose Bevy-shaped parameters rather than local global
      state where the ECS API can express them.
- [x] Terrain loading preserves the `WorldAssetRoot` owner semantics or records
      a precise local ECS/API gap if that owner cannot be expressed yet.
- [x] Instructions use the UI `Text` plus `Node` ownership shape instead of a
      world-space `Text2dBundle`.
- [x] Space/S toggles mutate the camera's `DistanceFog` component in place
      rather than reconstructing it from `AtmosphericFogState`.
- [x] Local status text and global tracked entity state are removed from the
      parity path.
- [x] The reference screenshot is refreshed after the source-shaped port still
      renders correctly.

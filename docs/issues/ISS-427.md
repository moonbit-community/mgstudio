## Description
Native render resource validation cannot currently run under AddressSanitizer or LeakSanitizer on this machine. With macOS 26.5.1 and Homebrew LLVM 21.1.8, even a C program whose `main` immediately returns hangs before entering `main` when compiled with `-fsanitize=address`. The same startup hang prevents the focused MoonBit renderer shutdown test from reaching project code.

## Design
Treat this as a sanitizer runtime/toolchain compatibility blocker rather than an mgstudio renderer failure. Select or obtain an ASan runtime that starts successfully on this macOS version, then rerun the existing single-test sanitizer command with MoonBit's bundled mimalloc disabled so ASan can intercept allocations. Do not replace sanitizer evidence with heuristic handle tracking or disable leak detection to claim completion.

## Acceptance Criteria
- [ ] A minimal C executable built with `-g -fsanitize=address -fno-omit-frame-pointer` starts and exits successfully with `ASAN_OPTIONS=detect_leaks=1:fast_unwind_on_malloc=0`.
- [ ] `MOONBIT_NEW_NATIVE=1` is set while running the focused native MoonBit sanitizer test.
- [ ] `render/renderer/gpu_wbtest.mbt` test `renderer: complete backend shutdown releases every report category` completes under ASan with LSan leak detection enabled.
- [ ] Any sanitizer diagnostics are classified and fixed or recorded in follow-up issues with exact stacks.
- [ ] Temporary package configuration changes and `libmoonbitrun.o` replacement are restored after the run.

## Notes
- 2026-07-12: Reproduced with Moon `0.1.20260710 (791eba8 2026-07-10)`, Homebrew clang `21.1.8`, and macOS `26.5.1 (25F80)` on arm64.
- 2026-07-12: Minimal reproduction: `printf 'int main(void) { return 0; }\n' | /opt/homebrew/opt/llvm/bin/clang -g -fsanitize=address -fno-omit-frame-pointer -x c - -o /tmp/asan-smoke`, followed by `ASAN_OPTIONS=detect_leaks=1:fast_unwind_on_malloc=0 /tmp/asan-smoke`.
- 2026-07-12: A three-second process sample shows the main thread recursively entering `wrap_malloc_default_zone`, `AsanInitFromRtl`, `AsanInitInternal`, and `StaticSpinMutex::LockSlow` during dyld/libSystem initialization. CPU remains near 100 percent and project `main` is never reached.
- 2026-07-12: The same stack occurs when running only `renderer: complete backend shutdown releases every report category`; the test process was terminated after the external startup hang was confirmed.
- 2026-07-12: Both attempted runs restored `render/renderer/moon.pkg`, `.mooncakes/Milky2018/wgpu_mbt/src/c/moon.pkg`, and `/Users/zhengyu/.moon/lib/libmoonbitrun.o` in the sanitizer runner's `finally` block.

## Close Notes
- 2026-07-05: Closed after ISS-389, ISS-390, ISS-391, and ISS-392 were closed.
  This group changed tracker documentation only.
- Bevy owner map: Core3d chains Prepass, MainPass, EarlyPostProcess, and
  PostProcess. Bevy inserts `volumetric_fog` after `Core3dSystems::MainPass`
  and before `Core3dSystems::EarlyPostProcess`. The fog pass writes directly to
  `ViewTarget::main_texture_view()` with no resolve target and no depth
  attachment, while reading `ViewDepthTexture::view()`. Bevy downstream
  postprocess uses `ViewTarget::post_process_write()` for tonemapping and
  `ViewTarget::main_texture_view()` plus `out_texture_color_attachment()` for
  upscaling/final output.
- Mgstudio owner map: `render3d_execute_camera` is the current real 3D camera
  owner. It prepares volumetric fog state before the local main pass, calls
  `render3d_execute_camera_main_pass`, then calls
  `render3d_execute_camera_volumetric_fog_pass`, then calls
  `render3d_execute_camera_postprocess`. The renderer fog draw uses saved
  `GpuPassState`, `target_view(pass_state.target_id, pass_state.target_layer)`,
  and `pass_state.view_depth_view`, ends the active main pass while preserving
  state, and opens color-load passes for fog volumes.
- Missing or partial local anchors: mgstudio does not yet have a source-level
  Bevy `ViewTarget` owner for 3D postprocess handoff. Its postprocess path is a
  monolithic immediate runner with `final_source_texture_id`,
  `render3d_postprocess_stage_target`, renderer-local target ids, and final
  sprite/blit facades. The core_pipeline tonemapping/upscaling/blit node files
  mirror Bevy-facing surfaces, but the real 3D path is not driven by those nodes.
- These are local parity gaps, not external blockers. Runtime evidence and
  concrete repair assignment now belongs to ISS-382, ISS-383, ISS-384, and
  ISS-375.

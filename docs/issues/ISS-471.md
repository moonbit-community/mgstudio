## Description

ISS-470 made callback-scoped table-batch mutation revocable, but the initial
wrapper stored the complete backing `Array[T]`, then performed a manual
live-row bounds check before the array performed its own bounds check. The
102,400-row `ViewVisibility` reset benchmark increased from the previously
recorded `11.44 us` raw-view result to a current `64.11 us`. Preserve revocation
and live-row bounds while removing redundant work from the hot indexed path.

## Design

Store a live-row-bounded `MutArrayView[T]` as a private field inside
`TableBatchMutValues[T]`. Keep the shared active state and check it before every
public indexed operation, but delegate bounds enforcement to the private view
instead of repeating it against the backing array. The raw view must never be
returned or passed to user code.

An engine-driven value-mapping callback was prototyped first because it exposed
no storage capability. It was slower due to one dynamic callback per row, so it
must not be retained or used as the default performance path.

## Acceptance Criteria

- [x] `TableBatchMutValues` exposes no raw view or backing array while escaped
      capabilities still abort after callback exit.
- [x] Indexed access remains bounded to the current live table rows.
- [x] Ordinary and bypass replacement/change-tick semantics remain unchanged.
- [x] A same-machine native-release benchmark compares the retained path with the
      `64.11 us` controlled-view baseline.
- [x] The slower engine-driven mapping prototype is removed and its rejected
      performance result is recorded.
- [x] The generated public interface remains unchanged and implementation
      documentation records the private bounded-view representation.
- [x] Focused MoonBit tests and benchmarks run one at a time with
      `MOONBIT_NEW_NATIVE=1`.

## Notes

- 2026-07-18: Current same-machine native-release baseline is `64.11 us` for
  102,400 `ViewVisibility` rows (`50 x 1508` runs).
- 2026-07-18: `ViewVisibility` is an immutable `#valtype` and is eligible for
  replacement mapping. The current many_animated_sprites `AnimationTimer` is
  a mutable reference struct, despite containing a valtype `Timer`, so it was
  not treated as the same confirmed representation case.
- 2026-07-18: The engine-driven mapping prototype measured `85.00 us`; adding
  `#inline` measured `85.35 us`. Both are slower than the `64.11 us` controlled
  view because the value callback remains dynamic for every row. The complete
  prototype and its tests were removed.
- 2026-07-18: Inline hints on the controlled view and caching `length()` at the
  visibility call site remained within the `63.4-64.5 us` noise band and were
  removed.
- 2026-07-18: Keeping the live-row `MutArrayView` private inside the revocable
  wrapper measured `45.76 us`, then `45.23 us` without ineffective inline
  hints. This is `29.45%` below the same-turn `64.11 us` safe baseline and about
  `104x` faster than the pre-batch `4.71 ms` result.

## Close Notes

Closed on 2026-07-18. `TableBatchMutValues` now holds a private
live-row-bounded `MutArrayView` instead of a complete backing `Array` plus a
second manual bound. Public access remains limited to active-checked
`length`/index operations, so no raw capability becomes escapable. Focused
native-release tests independently passed escaped write, escaped read,
reused-row write, bypass escape, live-row bounds, ordinary replacement ticks,
and bypass tick preservation. `moon check ecs --target native --deny-warn`
passes, and `moon info ecs --target native` confirms no public interface
change. The retained benchmark is `45.23 us` for 102,400 rows; the slower
`85.00-85.35 us` mapping prototype was fully removed.

## Description
The current `volumetric_fog` capture is dominated by a large camera-adjacent
surface or fog hull. Before debugging lower-level render math, prove that
mgstudio's `VolumetricFog`, `FogVolume`, `VolumetricLight`, and example scene
inputs match Bevy's source defaults and authored values.

## Design
Compare Bevy `bevy/crates/bevy_light/src/volumetric.rs` and
`bevy/examples/3d/volumetric_fog.rs` against the mgstudio light/PBR/example
definitions. Fix only source-level mismatches in defaults or authored inputs,
and add focused tests for the values that are render-visible.

Do not compensate for render bugs by changing the example camera, asset scale,
capture delay, or fog enablement.

## Acceptance Criteria
- [x] `VolumetricFog` default values match Bevy, including ambient intensity and
      any jitter or falloff fields represented in mgstudio.
- [x] `FogVolume` default values match Bevy, including absorption, scattering,
      density factor, scattering asymmetry, and light intensity.
- [x] The example's camera, fog volume, lights, and toggled `VolumetricLight`
      inputs match Bevy source shape.
- [x] Focused tests prove these values through public or package-local APIs.

## Notes
- 2026-07-05: Split from ISS-293. This issue owns high-level render-visible
  input parity only; pipeline routing and uniform math are tracked separately.
- 2026-07-05: Audited Bevy
  `bevy/crates/bevy_light/src/volumetric.rs` and
  `bevy/examples/3d/volumetric_fog.rs` against
  `mgstudio-engine/light/lib.mbt` and
  `mgstudio-engine/examples/3d/volumetric_fog/main.mbt`. Defaults are
  source-aligned: `VolumetricFog` uses white ambient color, intensity `0.1`,
  jitter `0.0`, and step count `64`; `FogVolume` uses white fog color,
  density factor `0.1`, no density texture, zero texture offset, absorption
  `0.3`, scattering `0.3`, scattering asymmetry `0.5`, white light tint, and
  light intensity `1.0`. The Bevy doc comment mentions `0.8` for
  `scattering_asymmetry`, but the actual `Default` implementation is `0.5`;
  mgstudio follows the implementation.
- 2026-07-05: Removed a local semantic divergence in
  `VolumetricFog::with_step_count`: it no longer clamps non-positive values to
  `1`. Bevy exposes a plain `u32` field without setter-side validation; the
  MoonBit constructor/helper now preserves the authored value instead of adding
  local policy.
- 2026-07-05: Added focused tests for volumetric fog/fog volume defaults,
  plain setter semantics, camera fog fields, spot-light default color, and the
  example's default fog-volume fields.

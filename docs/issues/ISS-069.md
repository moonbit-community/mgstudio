## Description
Bevy's `ci_testing` owner conditionally integrates screen recording when the
`screenrecording` feature is enabled. `StartScreenRecording` and
`StopScreenRecording` write `RecordScreen::Start` and `RecordScreen::Stop`,
and `CiTestingPlugin` adds `EasyScreenRecordPlugin` when a start event is
configured. Mgstudio currently has the event variants, but no real
screen-recording plugin or `RecordScreen` runtime owner.

## Design
Port `bevy_dev_tools/src/easy_screenshot.rs` screen-recording owner once the
required native/backend recording capability exists. Then wire
`CiTestingPlugin` and `ci_testing_send_events_system` to that owner exactly as
Bevy does.

Do not keep local no-op handling as parity.

## Acceptance Criteria
- [ ] A real mgstudio `EasyScreenRecordPlugin` owner exists.
- [ ] A `RecordScreen` message exists with `Start` and `Stop` variants.
- [ ] `CiTestingPlugin` adds the screen-recording plugin when a configured
  event starts screen recording and the plugin is not already added.
- [ ] `ci_testing_send_events_system` writes the `RecordScreen` messages for
  start and stop events.
- [ ] Tests prove configured start/stop events reach the recording owner.

## Description

ISS-475 (closed 2026-08-02) removed the wrong required-component registration
that forced `Tonemapping::TonyMcMapface` and `DebandDither::Enabled` onto every
`Camera3d`. The pinned Bevy baseline requires neither, so a plain `Camera3d`
spawn now renders with no tonemapping and no dither — matching Bevy. That
change was validated against an actual pinned-Bevy capture on
`examples/gizmos/3d_text_gizmos` (mean_abs_rgb 2.608 -> 0.186).

Every checked-in `reference.png` captured before that change with a `Camera3d`
in the scene still shows the old forced-tonemapped output. No reference has
been regenerated since (`git log --since=2026-08-01 -- '*reference.png'` is
empty). ISS-475 left exactly this as its one open acceptance criterion:
the stale references must be re-judged by a human and regenerated.

Enumeration at de16299c2:

- 405 `reference.png` files are tracked in total.
- 170 example packages mention `Camera3d` in `main.mbt`; 169 of them have a
  tracked `reference.png` (`examples/gizmos/transform_gizmo` has none).
- 13 packages set `Tonemapping` explicitly and none of them set
  `DebandDither`, so even those changed output through the dither default
  (`Enabled` -> absent -> `Disabled`): `3d/atmosphere`, `3d/bloom_3d`,
  `3d/clearcoat`, `3d/color_grading`, `3d/contact_shadows`,
  `3d/depth_of_field`, `3d/post_processing`, `3d/reflection_probes`,
  `3d/rotate_environment_map`, `3d/tonemapping`, `3d/transmission`,
  `3d/volumetric_fog`, `math/sampling_primitives`.
- Category split of the 169: 73 `examples/3d`, 16 `examples/shader`,
  11 `examples/shader_advanced`, 9 `examples/animation`, 7
  `examples/stress_tests`, 7 `examples/gltf`, 5 `examples/transforms`,
  5 `examples/camera`, the rest spread across tools/math/gizmos/asset/window/
  picking/large_scenes and others.

A second staleness class rides along in the same references: the old UI text
scale, already observed during the `motion_blur` and `deferred_rendering`
triage in ISS-019. Regeneration resolves both classes at once.

The tonemapping source owner itself needs no further porting for this work:
`tonemapping.wgsl`, `tonemapping_shared.wgsl`, and `lut_bindings.wgsl` are
byte-identical to `bevy/crates/bevy_core_pipeline/src/tonemapping/`, the three
LUT KTX2 assets are byte-identical to Bevy's `luts/`, and the plugin, pipeline
key, node, and renderer execution surfaces are in place (ISS-128, ISS-137,
ISS-424 closed).

## Design

Regenerate in small human-reviewable batches rather than one blind sweep, per
the open ISS-475 criterion that a human re-judges the references.

Method per example:

1. Capture with the standard command from `mgstudio-engine`:
   `MGSTUDIO_PARITY_CAPTURE_DELAY_FRAMES=90 MGSTUDIO_PARITY_RUN_TIMEOUT_SECONDS=240
   scripts/p0_visual_capture_native.sh <package> <out.png>` (2560x1440,
   frame 90, GPU preprocess off — the same convention as all recorded gates).
2. Require a clean run log (the capture script deletes the log on clean runs)
   and a passing `scripts/visual_image_sanity.py` check.
3. Compare old vs new reference and record a review-packet row in this issue
   with the visible delta class; anything outside the expected
   tonemapping/dither/UI-scale classes stops the batch and gets its own
   triage.
4. Copy the capture over `<package>/reference.png` and commit the batch as
   `Refresh <scope> references (ISS-481)`.

Batch 1 (this issue's first slice) is the active-gate set already under
discussion: `examples/3d/tonemapping` (the tonemapping owner's representative
example), `examples/3d/motion_blur`, `examples/3d/deferred_rendering`,
`examples/3d/ssao`. The remaining ~165 wait until the batch-1 review confirms
the delta class is what ISS-475 predicts.

Out of scope: references whose examples are themselves blocked or visually
wrong for tracked non-tonemapping reasons — those stay pinned to their own
issues and are refreshed there, not here. Excluded set for batch 2 (13):
`3d/anti_aliasing` (ISS-122), `3d/atmosphere` (ISS-107), `3d/clearcoat` and
`3d/transmission` (ISS-164 unchecked criteria), `3d/contact_shadows`
(ISS-114), `3d/fog_volumes` (ISS-109), `3d/occlusion_culling` (ISS-086),
`3d/order_independent_transparency` (ISS-123), `3d/pcss` (ISS-089),
`3d/scrolling_fog` (ISS-091), `3d/shadow_biases` (ISS-129), `3d/skybox`
(ISS-092), `3d/volumetric_fog` (ISS-108). Batch 2 therefore covers 152
references, chunked ~15 at a time (examples/3d first, then the remaining
categories), one commit per chunk.

Amendment (2026-08-04, from the batch-2 review): two more exclusions found
during the sweep itself — `3d/anisotropy` (ISS-482, feature-variant meshes
vanish) and `3d/atmospheric_fog` (ISS-483, terrain color and distance fog
both dead). The atmospheric_fog case exposes a method limit this issue must
carry: old-vs-new delta screening cannot catch references that were ALREADY
broken the same way — there the delta looks like the benign class while both
images are wrong vs Bevy. The sweep therefore refreshes only what a human
has flagged or passed, and suspicious-looking scenes get a pinned-Bevy
spot capture (`CI_TESTING_CONFIG` + `bevy_ci_testing`, as ISS-483 did)
before acceptance.

Amendment (2026-08-04, resumed sweep — REVISED PREMISE): ISS-475's claim
that pinned Bevy requires no Tonemapping/DebandDither is disproven (see
the correction in ISS-475 and the ISS-483 fifth fix): `Core3dPlugin`
requires BOTH on every `Camera3d`, and mgstudio now matches, with the
curve applying exactly once. The expected delta class for this sweep is
therefore the REVERSE of the original description: scenes GAIN the filmic
TonyMcMapface curve + deband dither. The class is Bevy-certified, not
self-referential: atmospheric_fog matches pinned Bevy at mean abs diff
0.01/0.02/0.01, ssao at sampled-point byte-equality, motion_blur at the
matching warm-run car phase.

Two new sweep rules from the same investigation:

1. HOLD gizmo-heavy and clear-color-dominant scenes. mgstudio tonemaps at
   a fullscreen fp16 resolve, so gizmo lines and clear-color backgrounds
   get tonemapped+dithered; Bevy tonemaps per-mesh in-shader and leaves
   both raw (`bevy_gizmos_render` has no tonemap path). Until ISS-483's
   recorded topology debt lands, refreshing such references would bake in
   a known non-Bevy state. Mesh-dominated scenes are mathematically
   equivalent between the two topologies (same curve per covered pixel;
   fp16 storage; UI composites after the resolve) — the atmospheric_fog
   0.01-mean result is the proof.
2. ISS-484 warm-run rule: for time-animated scenes, discard the first
   (cold) capture after any shader/pipeline-variant change and
   byte-compare the second and third runs.

Batch-2 chunk 1 enumeration (2026-08-05, `examples/3d` alphabetical,
minus exclusions/installed/held): `3d_scene`, `3d_shapes`,
`3d_viewport_to_world`, `animated_material`, `auto_exposure`,

`light_textures`, `mesh_ray_cast` (gizmo usage does not always mean
gizmo-dominant output; each gets a per-case call when its turn comes).
Note for the 13-explicit-Tonemapping packages (e.g. `bloom_3d`,
`color_grading`, `depth_of_field` in this chunk): their expected delta
now includes the removal of the former DOUBLE tonemap (explicit method
in-shader plus the resolve's second application) in addition to the
dither default change.

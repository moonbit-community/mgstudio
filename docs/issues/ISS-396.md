# ISS-396: Replace public string material bind-group keys with structured keys

## Description
`Material.bind_group_data()` currently returns `String`, and
`material_default_material_key` hashes that string. This makes the public
material API weaker than Bevy's `M::Data: Eq + Hash + Clone` material key and
allows each material implementation to invent its own unstable string encoding.
MoonBit cannot directly copy Bevy's associated `M::Data` shape, but the local
API can still expose a structured key object instead of arbitrary strings.

## Design
Introduce a small `MaterialBindGroupKey` value with bytes and stable helpers.
Keep text construction only as a compatibility constructor inside the material
module. Change the `Material` trait and `MaterialPipelineKey` construction to
consume the structured key. Leave full Bevy `M::Data` parity out of scope for
this issue.

## Acceptance Criteria

# ISS-061: Fix atmosphere frame view bind group binding 31 failure

## Metadata

- Status: closed

## Description
`examples/3d/atmosphere` now runs and produces a capture blob, but the captured image is opaque black. The run log repeatedly reports that the renderer cannot build the mesh3d frame view bind group because binding 31 is unsupported.

## Design
Strictly compare the atmosphere/PBR/render view bind group layout against the Bevy source owner before changing code. The fix must align the frame view bind group entries and shader expectations; do not mask the error with a fallback black pass or an example-specific workaround.

## Acceptance Criteria
- [x] `examples/3d/atmosphere` no longer logs `unsupported binding 31`.
- [x] The standard native capture command produces a non-black `reference.png`.
- [x] The fixed binding layout is source-audited against the relevant Bevy render/PBR atmosphere code.
- [x] Relevant render/PBR checks and targeted tests pass with `--release` where applicable.

  MGSTUDIO_PARITY_RUN_TIMEOUT_SECONDS=600
  MGSTUDIO_PARITY_CAPTURE_RETRY_TIMEOUT_SECONDS=600

  /tmp/mgstudio_atmosphere_iss061_before.png`. The PNG was fully black
  (`non_black_ratio=0.0`, `mean_luma=0.0`) and
  `/tmp/mgstudio_atmosphere_iss061_before.run.log` repeatedly reported
  `unsupported binding 31`.
- 2026-06-10: Source audit: Bevy only sets
  `MeshPipelineViewLayoutKey::ATMOSPHERE` and writes bindings 31/32/33 when the
  view has `ExtractedAtmosphere`, `AtmosphereTextures`, `AtmosphereBuffer`,
  `AtmosphereSampler`, and an atmosphere buffer binding. Mgstudio currently
  sets `MESH_PIPELINE_KEY_ATMOSPHERE` from `camera.atmosphere is Some(_)`, but
  `GpuPassState` and `GpuBackend` have no atmosphere texture/sampler/buffer
  owner. The local `pbr/atmosphere` package embeds WGSL and facade structs, but
  does not port Bevy's render-side systems that prepare LUT textures, uniforms,
  bind groups, atmosphere buffer writes, or sky rendering. The real prerequisite
  is tracked as ISS-065.
- 2026-06-10: After the first ISS-065 renderer layout step, the same capture
  command no longer reports `unsupported binding 31`; it reports
  `wgpu: missing atmosphere transmittance texture`. The image remains fully
  black. This confirms the immediate switch-table bug is no longer the leading
  error, but the issue remains open because the real Bevy atmosphere texture
  and LUT owner is still missing.
- 2026-06-10: After the second ISS-065 resource-owner step, the standard
  atmosphere capture no longer reports `unsupported binding 31` or
  `missing atmosphere transmittance texture`, and
  `/tmp/mgstudio_atmosphere_iss065_resources.png` is non-black. The issue
  remains open because the expected checked-in `examples/3d/atmosphere/reference.png`
  and Bevy-equivalent sky scattering still require the remaining ISS-065 LUT
  compute and render-sky owner work.
- 2026-07-04: Rechecked with the current source-shaped atmosphere path. The
  standard 90-frame native capture completed at
  `/tmp/mgstudio_atmosphere_after_medium_handle.png`, and its SHA256 matches
  `examples/3d/atmosphere/reference.png`.

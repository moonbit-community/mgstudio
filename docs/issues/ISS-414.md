## Description
`GpuBackend` lacks an idempotent lifecycle boundary, global replacement discards the previous backend, and initialization errors can abandon already-created instance or adapter handles.

## Design
Add private lifecycle state and the shutdown orchestration seam. Make global replacement call shutdown before discarding the previous backend. Use lexical `defer` rollback guards while acquiring the instance, adapter, device, and queue, transferring ownership only after the complete backend is constructed.

## Acceptance Criteria
- [x] Calling backend shutdown twice does not double-release a native handle.
- [x] Replacing or clearing the global backend invokes shutdown on the previous backend.
- [x] Failed initialization releases every successfully acquired prerequisite handle.
- [x] Native lifecycle tests cover idempotence and global replacement.

## Notes

Tests that previously restored a backend after replacing it were updated to clear the temporary backend instead. Under explicit ownership, replacement shuts down the old owner, so restoring that value would revive invalid native handles; the full-suite SIGSEGV exposed and confirmed this boundary.

## Close Notes

Added a private idempotent shutdown state and ordered area-owner orchestration seam. Backend construction now acquires instance, adapter, device, and queue under lexical `defer` rollback guards and transfers ownership only after the complete backend value exists. Global backend replacement stores the new owner before shutting down the previous one. Native tests cover double shutdown, global replacement, core device/queue release counts, and forced failures after adapter/device/queue acquisition.

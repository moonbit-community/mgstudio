# ISS-023: Split sprite/render2d.mbt into Bevy-shaped source owners

## Description
`mgstudio-engine/sprite/render2d.mbt` is a 9553-line file that combines logic
from many Bevy owners instead of mapping to one Bevy source file. Evidence in
the file includes `RenderLayers`, `Viewport`, `Camera`, `Camera2d`, shape mesh
builders, `SpriteBundle`, `Camera2dBundle`, `Mesh2dBundle`, `TilemapChunk`,
`TilemapChunkMaterial`, sprite extract/queue/runtime state, UI overlay payloads,
bloom/CAS/tonemapping helpers, and the large `render_execute_system`.

Bevy distributes these owners across `bevy_camera`, `bevy_core_pipeline`,
`bevy_sprite_render/src/render`, `bevy_sprite_render/src/mesh2d`,
`bevy_sprite_render/src/texture_slice`, `bevy_sprite_render/src/tilemap_chunk`,
`bevy_ui_render`, and postprocess/core pipeline modules.

## Design
Use this as the umbrella task for removing the file-level monolith. Move code
out by Bevy owner, keep behavior intact during each move, and delete the old
sections instead of leaving forwarding compatibility layers in `render2d.mbt`.

## Acceptance Criteria
- [ ] `sprite/render2d.mbt` no longer contains camera, core 2D, UI render, tilemap, shape conversion, bundle construction, material, and runtime execute ownership in one file.
- [ ] Each moved section has a MoonBit file/package whose path clearly maps to its Bevy owner.
- [ ] Callers import the owner package directly rather than using `sprite.render2d_*` as the cross-module hub.
- [ ] `moon -C mgstudio-engine check --target native`, `moon -C mgstudio-engine fmt`, and `moon -C mgstudio-engine info` pass after the split.
- [ ] At least one 2D sprite example and one UI-render example pass a screenshot gate after the split.

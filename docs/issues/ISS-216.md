## Description
The first directional shadow-map content question is whether mgstudio builds the
same cascade inputs that Bevy would build for the `scrolling_fog` camera and
directional light. If the cascade projection differs, later shadow-pass and
volumetric-fog checks can all receive valid data while sampling the wrong
shadow region.

## Design
Compare Bevy `bevy_light/src/cascade.rs` and the relevant PBR extraction path
against mgstudio's directional-light and shadow-view preparation. Verify the
active camera view, directional light transform, cascade config, shadow-map
size, cascade count, view-projection matrices, and near/far ranges for the
`scrolling_fog` scene. This issue does not inspect draw phase contents.

## Acceptance Criteria
- [x] Every Bevy source-shape anchor involved in directional cascade
      construction is classified as complete, partial, facade, or blocked.
- [x] The `scrolling_fog` active camera and directional light produce the
      expected cascade count, shadow-map size, and projection inputs.
- [x] A focused white-box test or debug artifact records the cascade metadata
      used by the frame.
- [x] Any divergence is fixed source-faithfully or recorded as a blocker.

# ISS-037: Expand Bevy-shaped SystemParam and QueryFilter coverage

## Description
Render, mesh, PBR, UI, and example ports should not rewrite system signatures
only because mgstudio lacks a common Bevy `SystemParam`, query data tuple, or
filter tuple shape. Current tuple support and parameter coverage are uneven,
which creates local source-shape drift during Bevy migration.

## Design
Audit Bevy source owners as they are migrated and add the missing ECS/app
parameter surfaces directly. Expand tuple impls to eight elements for query
data, query filters, and system-param tuple composition where MoonBit requires
manual impls. Prefer explicit hand-written impls over generator machinery.
Do not use facades that hide missing behavior or rewrite system logic around
the gap.

## Acceptance Criteria
- [x] Query data tuple support covers the common Bevy shapes up to eight
      elements.
- [x] Query filter tuple support covers the common Bevy shapes up to eight
      elements.
- [x] SystemParam tuple composition covers the common Bevy shapes up to eight
      elements.
- [x] Missing high-value Bevy params encountered by render/PBR/example ports
      are implemented as real params or recorded as blockers when MoonBit
      cannot express them.
- [x] Param access validation continues to detect read/write conflicts after
      tuple coverage is expanded.

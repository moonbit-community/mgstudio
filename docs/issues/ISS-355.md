## Description
After ISS-349 ruled out the skybox path, the next step is to capture a compact
evidence packet that identifies what the real `examples/3d/volumetric_fog`
frame is doing inside the volumetric-fog pass and its immediate inputs. This
issue should not repair code; it should produce the evidence needed to pick the
next Bevy source owner precisely.

## Design
Run the standard native capture and collect pass-local evidence from existing
runtime counters or narrowly scoped white-box tests. The evidence should state
whether the example reaches the volumetric-fog pass, how many fog volumes are
drawn, whether the pass uses a real depth texture, whether directional shadow
resources are present, and whether the output remains the near-grey failed
frame.

Do not add visual heuristics or screenshot-only fixes. If new diagnostic hooks
are required, keep them as tests or debug-only evidence and do not change
runtime behavior.

## Acceptance Criteria
- [x] A fresh `examples/3d/volumetric_fog` capture path, hash, and run-log
      status are recorded.
- [x] The evidence records volumetric-fog pass reachability, draw count, depth
      texture identity, and shadow/light input presence for the real example.
- [x] The issue states which Bevy source owner should be audited next.
- [x] No production behavior is changed for this diagnostic issue.

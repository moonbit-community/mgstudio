# ISS-465: Preserve exact affine transforms in sprite picking

## Metadata

## Description

The `ISS-456` sprite-picking migration queried `GlobalTransform` as required by
the pinned Bevy source, but immediately converted each value with
`to_transform_approx()`. Parent non-uniform scale composed with child rotation
can produce shear that cannot be represented as translation, rotation, and
scale, so sprite-local ray intersection, world hit position, camera-space
depth, and hit normal diverged from Bevy.

The same path also reapplied decomposed world scale to a point that was already
in sprite-local coordinates. Pinned Bevy instead lets
`Sprite::compute_pixel_space_point` own the complete local-space bounds test.

## Design

Keep each queried sprite and camera transform as the exact `Affine3` returned
by `GlobalTransform::affine()`. Transform the finite cursor segment through the
exact affine inverse, matching the pinned
`bevy_sprite::picking_backend::sprite_picking` data flow. Compute world hit
position, camera-space depth, and the normalized transformed local Z axis from
the same affine values.

Use the pinned glam cofactor/determinant inverse formula locally. Do not route
through TRS decomposition or the project `Affine3::inverse()` identity fallback,
and do not add or change public API.

## Acceptance Criteria

- [x] Sprite collection retains `GlobalTransform::affine()` without TRS
      decomposition.
- [x] Sprite-local ray intersection uses the exact inverse affine and the
      transformed near/far segment endpoints used by pinned Bevy.
- [x] Sprite bounds are decided only by `compute_pixel_space_point`, without
      reapplying decomposed world scale.
- [x] World hit position, camera-space depth, and hit normal use exact affine
      data with pinned Bevy semantics.
- [x] A focused parent-scale plus child-rotation shear regression fails before
      the fix and passes after it with `MOONBIT_NEW_NATIVE=1`.
- [x] The picking package compiles after formatting and exposes no unintended
      public API changes.

## Close Notes

Closed on 2026-07-18. Sprite and camera collection now retain exact affine
values. Cursor rays are generated from the camera affine, the finite ray segment
is transformed through the exact sprite inverse, pixel-space bounds are owned
solely by `Sprite::compute_pixel_space_point`, and hit position, depth, and
normal are derived without TRS decomposition.

The shear regression failed before the change and passed afterward as one
focused native release test with `MOONBIT_NEW_NATIVE=1`. The existing focused
camera-space-depth and collection/sort tests each passed independently.
`MOONBIT_NEW_NATIVE=1 moon check picking --target native` completed with zero
errors, specific-file formatting passed after applying `moon fmt`, and
`MOONBIT_NEW_NATIVE=1 moon info picking --target native` produced no public
interface diff. Toolchain deprecation warnings remain in unrelated packages;
this change introduced no picking warning.

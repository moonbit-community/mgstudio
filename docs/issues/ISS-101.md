## Description
`examples/3d/pccm` now uses Bevy's `LightProbe + EnvironmentMapLight +
ParallaxCorrection` source shape, but the reflective inner cube remains flat
gray. The root cause is in mgstudio's PBR light-probe owner, not the example:
`pbr/light_probe/top.mbt` currently exposes data types and plugin resources,
while the render path only forwards environment maps attached directly to the
camera into pass state.

Bevy's `bevy_pbr/src/light_probe/mod.rs` gathers visible probes per view,
builds `RenderViewLightProbes<EnvironmentMapLight>`, uploads a
`LightProbesUniform` containing reflection-probe arrays, and writes real
reflection-probe indices into cluster bindings. Mgstudio currently writes
`0xFFFF_FFFF` for reflection-probe cluster entries and never uploads real
per-view reflection-probe data, so PCCM cannot render Bevy-style reflection
probes.

## Design
Port the Bevy light-probe source owner before accepting PCCM visual parity:

- map Bevy `RenderLightProbe`, `LightProbesUniform`,
  `ViewLightProbesUniformOffset`, `LightProbeInfo`, and
  `RenderViewLightProbes<EnvironmentMapLight>` into mgstudio's package split;
- gather in-scope `LightProbe + EnvironmentMapLight + ParallaxCorrection`
  entities for each 3D camera/view using Bevy's transform, distance sorting,
  parallax bounds, falloff, intensity, and flags semantics;
- bind both diffuse and specular cubemap arrays for view environment maps and
  reflection probes without falling back to camera-attached environment maps;
- replace the placeholder `0xFFFF_FFFF` reflection-probe cluster indices with
  the per-view render probe indices;
- keep PCCM as the representative visual gate.

Do not workaround this by attaching the PCCM environment map directly to the
camera. That would only exercise Bevy's view environment-map path and would not
port reflection probes.

- 2026-06-14: Source-shape anchor classification against Bevy:
  - `mod.rs` constants `MAX_VIEW_LIGHT_PROBES` and
    `STANDARD_MATERIAL_FRAGMENT_SHADER_MIN_TEXTURE_BINDINGS`: complete.
  - `LightProbePlugin`: partial. Shader source registration and public plugin
    resource shape exist, but exact Bevy RenderApp scheduling through
    `ExtractSchedule` and `RenderSystems::PrepareResources` is still represented
    by mgstudio's render-execute path.
  - `RenderLightProbe`: complete for field shape after adding
    `bounding_sphere_radius` and `world_position` to
    `pbr/light_probe/top.mbt`; runtime packing lives in
    `pbr/render_scene_resources.mbt`.
  - `LightProbesUniform`: complete for the concrete runtime packing path. The
    owner shape includes Bevy's reflection-probe and irradiance-volume arrays,
    view environment fields, counts, view cubemap index, rotation, intensity,
    and lightmapped-mesh diffuse flag.
  - `LightProbesBuffer` and `ViewLightProbesUniformOffset`: partial. Component
    and resource anchors exist, but mgstudio still writes backend uniform bytes
    directly instead of Bevy's `DynamicUniformBuffer` resource ownership.
  - `LightProbeInfo<C>` and `RenderViewLightProbes<C>`: partial. Reflection
    probe sorting, texture-index mapping, and main-entity mapping are ported in
    concrete MoonBit fragments; generic Bevy owner shape is not fully mirrored.
  - `LightProbeComponent` trait: intentionally excluded as a generic trait
    source shape until MoonBit can express the same trait-associated-type
    pattern cleanly; concrete `EnvironmentMapLight` behavior is mapped.
  - `gather_light_probes::<EnvironmentMapLight>`: complete for concrete
    reflection-probe behavior. The gather path now reads the current camera's
    `VisibleClusterableObjects` reflection-probe list, filters unloaded
    cubemaps, sorts by camera distance, preserves texture binding indices, and
    feeds real render probe indices into the cluster path. The exact generic
    Bevy system owner remains covered by the `LightProbeInfo<C>` and
    `RenderViewLightProbes<C>` partial anchors above.
  - `gather_light_probes::<IrradianceVolume>` and irradiance upload: complete
    for the concrete runtime path. The gather path reads the current camera's
    `VisibleClusterableObjects` irradiance-volume list, filters unloaded voxel
    textures, sorts by camera distance, packs the second `LightProbesUniform`
    array, sends 3D texture IDs to renderer binding-array group bindings 3/4,
    and writes real irradiance-volume cluster indices.
  - `upload_light_probes`: partial. The reflection-probe uniform layout is
    packed, but the Bevy command insertion of per-view
    `ViewLightProbesUniformOffset` and all-probe `LightProbesBuffer` ownership
    is not yet source-equivalent.
  - `add_cubemap_texture_view`: partial. Fallback texture behavior exists in
    renderer bind-group construction, but the reusable source-owner helper is
    still split across renderer fragments.
  - `binding_arrays_are_usable`: partial. Feature and limit checks are ported,
    while Bevy's GLSL feature and Adreno-specific guard are not represented.
  - `environment_map.rs::EnvironmentMapIds`: complete for mgstudio handle IDs.
  - `environment_map.rs::RenderViewEnvironmentMapBindGroupEntries` and
    `get_bind_group_layout_entries`: partial. Binding-array and single binding
    paths exist, but source ownership is split between `pbr/light_probe` facade
    helpers and `render/renderer/mesh3d_bind_groups.mbt`.
  - `EnvironmentMapViewLightProbeInfo`: complete after adding `rotation`.
  - `ExtractInstance for EnvironmentMapIds`: partial. Asset handle extraction
    happens through mgstudio camera/render extraction rather than a Bevy-style
    `ExtractInstancesPlugin`.
  - `LightProbeComponent for EnvironmentMapLight`: complete for concrete
    reflection-probe behavior: IDs, intensity, flags, rotation transform, and
    parallax bounds are mapped.

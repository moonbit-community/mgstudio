## Description
`mgstudio-engine/examples/3d/tonemapping/main.mbt` is only a partial source
port of `bevy/examples/3d/tonemapping.rs`.

The runtime tonemapping path, color-grading data model, LUT assets, camera fog,
environment map, basic scene, image viewer, and most keyboard controls are
present. The strict source gap is that Bevy's second scene is a custom material
test pattern:

- `MaterialPlugin::<ColorGradientMaterial>::default()`;
- `ColorGradientMaterial` as an `Asset`, `TypePath`, and `AsBindGroup` owner;
- `impl Material for ColorGradientMaterial::fragment_shader`;
- `SHADER_ASSET_PATH = "shaders/tonemapping_test_patterns.wgsl"`;
- `setup_color_gradient_scene` spawning a hidden rectangle with that material.

The current mgstudio example has an empty `setup_color_gradient_scene()` and a
comment that the custom material path is unavailable. That is not source
parity. It is local implementation work unless a precise language or dependency
blocker is discovered while porting the owner.

The example also misses Bevy's `AssetPlugin { unapproved_path_mode:
UnapprovedPathMode::Allow }` shape for drag-and-drop path loading, and several
systems approximate Bevy `Single`/UI/image resize ownership with helper
functions and local marker components.

## Design
Port the example directly from `bevy/examples/3d/tonemapping.rs`:

- preserve the Bevy plugin graph, including the asset-plugin path-loading
  configuration and the custom material plugin owner;
- implement a source-shaped `ColorGradientMaterial` owner for this example or
  extract a reusable Bevy-shaped 3D custom-material API if the engine requires
  it;
- wire `tonemapping_test_patterns.wgsl` through the custom material's fragment
  shader hook;
- implement `setup_color_gradient_scene` with the rectangle mesh, material,
  camera-forward transform, hidden visibility, and `SceneNumber(2)`;
- remove the empty scene stub and unavailable-API comment after the real owner
  exists;
- tighten `Single`, UI, and image-resize system shapes where the current ECS
  API can express the Bevy owner directly;
- record a precise blocker only if MoonBit or a dependency cannot express a
  required source anchor.

This issue is related to ISS-083 because both expose the missing Bevy-shaped
custom 3D material surface, but the tonemapping color-gradient scene must still
be audited and fixed as its own source owner.

## Acceptance Criteria
- [ ] `MaterialPlugin<ColorGradientMaterial>` has a source-shaped mgstudio
      equivalent in this example or a precise blocker is recorded.
- [ ] `ColorGradientMaterial` is a real custom material owner rather than an
      empty/stubbed scene marker.
- [ ] `tonemapping_test_patterns.wgsl` is loaded through the custom material
      fragment shader hook.
- [ ] `setup_color_gradient_scene` spawns the Bevy rectangle scene with hidden
      visibility and `SceneNumber(2)`.
- [ ] The empty `setup_color_gradient_scene()` stub and unavailable-API comment
      are removed.
- [ ] Asset-plugin path-loading configuration is represented or a precise
      engine blocker is recorded.
- [ ] Remaining `Single`/UI/image-resize approximations are either source-shaped
      or explicitly classified with a follow-up owner.
- [ ] A fresh `examples/3d/tonemapping/reference.png` is captured after the
      corrected example runs.

## Notes
- 2026-06-16: Created from the ISS-105 symbol audit. The major local gap is the
  empty color-gradient scene and missing `ColorGradientMaterial` owner; this is
  not an external blocker unless implementation proves a concrete MoonBit or
  dependency limitation.
- 2026-06-18: Rechecked the existing material APIs before implementing. The
  available 3D path is `ExtendedMaterial<StandardMaterial, E>` metadata, which
  can attach shader paths to the standard-material family but does not provide
  Bevy's standalone `MaterialPlugin<M>` / `Assets<M>` / `AsBindGroup` owner
  shape required by `ColorGradientMaterial`. This remains local engine parity
  work and is now tracked as ISS-132 instead of being faked inside this example.

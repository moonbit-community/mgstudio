## Description
`examples/3d/voxels3/reference.png` is currently fully transparent, but a standard 90-frame native capture produces an unusable replacement: the scene is nonblank, yet all visible content is reduced to a tiny point near the center of the frame.

The example sets its camera at `(-100, 100, -100)` looking at `(0, 0, 0)`, while the spawned dynamic bodies are distributed across a `0..64` X/Z area. The resulting capture is not a useful visual regression baseline even though it passes a naive nonblank image sanity check.

## Design
Do not refresh `voxels3/reference.png` until the example framing has been checked against the intended example behavior. If this example has a Bevy source owner, fix the camera and scene setup by porting that source shape. If it is mgstudio-local, choose a deterministic framing that actually captures the spawned voxel/physics content and record the local ownership decision.

- [x] The fix is documented in ISS-060 or the relevant visual parity issue before `voxels3/reference.png` is refreshed.

- 2026-06-19: Claimed. No same-named Bevy source owner exists under `./bevy/examples`, so this is treated as a mgstudio-local physics3d example. The visible bodies are distributed over a `0..64` X/Z field, while the old camera looked at the origin; the fix should frame the local field center deterministically.
- 2026-06-19: A 1-frame diagnostic capture showed the spawned bodies at the intended scale, while the 90-frame capture collapsed to tiny scattered content. The root cause was the heightfield collider setup: `ColliderBuilder3D::heightfield` expects whole-field X/Z scale, but the example passed a single-voxel size of `(1, 1, 1)` and positioned the field at `(0.5, 0, 0.5)`.

## Description
Several interactive or dynamic examples failed screenshot capture. These are not
obviously screenshot-ineligible and may need deterministic capture setup,
input-independent initial state, or runtime fixes.

Failed packages:

- `examples/games/breakout`
- `examples/math/bounding_2d`
- `examples/movement/physics_in_fixed_timestep`
- `examples/transforms/transform`

## Design
Inspect the Bevy source-equivalent behavior for each example, then decide
whether mgstudio should produce a static reference screenshot or use a
different deterministic gate. Avoid workaround rendering or placeholder
screenshots.

## Acceptance Criteria
- [x] Each listed package is classified as screenshot-required, interactive-needs-fixture, or screenshot-excluded.
- [x] Screenshot-required packages produce `reference.png`.
- [x] Interactive packages define the required deterministic input or delay policy.
- [x] Any source-parity bug discovered during triage is split into a follow-up issue or fixed before closure.

## Notes
- 2026-06-07: `examples/games/breakout` is a notable failure because other game examples did produce screenshots.
- 2026-06-19: Started triage. Each listed package will be checked against the
  current Bevy source owner before deciding whether it needs a reference
  screenshot, deterministic fixture, or exclusion.
- 2026-06-19: Fixed the first concrete failure in
  `examples/transforms/transform`. The capture aborted with
  `SystemParamValidationError.Invalid` because ECS system access validation did
  not treat required components from query data as implicit `With` constraints.
  Bevy accepts the source-shaped pair
  `Query<(&Transform, &CubeState), Without<Center>>` and
  `Query<(&mut Transform, &Center)>`; mgstudio now records query-data required
  components and uses them for disjoint query compatibility. A fresh
  `examples/transforms/transform/reference.png` was captured.
- 2026-06-19: `examples/math/bounding_2d` also had a source-shape startup bug:
  it explicitly added `StatesPlugin` while `DefaultPlugins` already installs
  it. Current Bevy `examples/math/bounding_2d.rs` only initializes the state,
  so the duplicate plugin was removed. After that fix, the example still aborts
  during capture with an empty run log; this is a separate remaining failure.
- 2026-06-19: Fixed the remaining `examples/math/bounding_2d` failure. The
  example was mutating archetypes directly from `update_volumes` while iterating
  its query; Bevy uses `Commands` for this `CurrentVolume` insertion path, so
  mgstudio now does the same. A second issue hid the visual output: dynamic
  gizmos were flushed into the main world, but the 2D render execute stage was
  draining `GizmoStorage` from the render world. `render_execute_system` now
  drains gizmos from `render_source_world(world)`, matching the existing
  source-world extraction model used by sprites, cameras, and meshes.
  `examples/math/bounding_2d/reference.png` has been captured successfully.
- 2026-06-19: Fixed `examples/games/breakout` as a source-shape migration
  problem, not a screenshot-only problem. The old mgstudio example combined
  movement and collision in one system and directly conflicted with ECS query
  access validation; current Bevy splits this into chained `apply_velocity`,
  `move_paddle`, and `check_for_collisions` systems. The example now follows
  the Bevy entity/resource/event shape for walls, bricks, scoreboard UI,
  `BallCollided`, and audio playback, and `examples/games/breakout/reference.png`
  has been captured at frame 90. Two engine bugs surfaced and were fixed while
  validating this example: `Sprite::from_color` used an invalid placeholder
  image handle instead of the engine white texture, and audio playback inserted
  sink/marker components directly into `World` while iterating queued audio
  queries instead of using deferred `Commands` like Bevy. Remaining parity gap:
  Bevy's optional showcase stepping overlay plugin is not wired into this
  example yet; it should be handled as a source-parity follow-up, not as a
  screenshot blocker.
- 2026-06-19: Fixed `examples/movement/physics_in_fixed_timestep`. The capture
  aborted in `translate_camera` with
  `SystemParamValidationError.Invalid` because the mgstudio player query read
  `Transform` with `With<AccumulatedInput>` but omitted Bevy's
  `Without<Camera>` disjoint filter while the camera query wrote `Transform`.
  The example now uses Bevy-shaped `Single` params and direct mutable query
  writes for `accumulate_input`, `advance_physics`, and `translate_camera`.
  `examples/movement/physics_in_fixed_timestep/reference.png` has been captured
  successfully at frame 90.

## Description
Bevy stores `MaterialExtension::enable_prepass()` through the prepared material
properties for `ExtendedMaterial<B, E>`. Mgstudio currently represents standard
material extensions as `ExtendedMaterialMetadata3d` attached to
`MeshMaterial3d`, so the type-level false case is not yet carried into
`MaterialProperties.prepass_enabled`.

ISS-106 removed the incorrect mapping from `enable_prepass()` to
`requires_depth_prepass` and `requires_deferred_prepass`, because those fields
made the main pass skip otherwise drawable extended-material meshes. This issue
tracks the remaining source-parity work: express the Bevy prepass-enabled
property without reintroducing a main-pass skip condition or local workaround.

## Design
Audit Bevy `bevy_pbr::extended_material` and `bevy_pbr::material` as the source
owners. The MoonBit mapping should keep `MaterialExtension::enable_prepass()`
as material prepass participation state, not as a camera prepass requirement.
If MoonBit cannot express the generic `MaterialPlugin<ExtendedMaterial<B, E>>`
shape directly, record the exact language/API blocker before changing the API.

## Acceptance Criteria
- [x] `ExtendedMaterial` metadata or typed material ownership can represent
      `enable_prepass=false` without affecting main-pass drawing.
- [x] PBR prepass queue/specialization uses the represented value in the same
      place Bevy uses `PreparedMaterial.properties.prepass_enabled`.
- [x] Regression tests cover both `enable_prepass=true` and
      `enable_prepass=false`.
- [x] No `requires_*_prepass` field is used as a substitute for Bevy's material
      prepass-enabled property.

## Notes
- 2026-06-23: Discovered while fixing clustered_decals. The immediate bug was
  that `enable_prepass=true` incorrectly skipped the main pass; the remaining
  work is the inverse false-case parity.
- 2026-06-23: Closed by adding a dedicated `prepass_enabled` field to
  `ExtendedMaterialMetadata3d`, wiring `MaterialExtension::enable_prepass()`
  into it, and combining it with the global PBR prepass flag when constructing
  `MaterialProperties`.

`MaterialExtension::enable_prepass()` independently from camera prepass

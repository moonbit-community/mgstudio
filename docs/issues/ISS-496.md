# ISS-496: glTF loader drops KHR_materials_emissive_strength

## Description

`scene/gltf_loader.mbt` parsed `emissiveFactor` but ignored the
`KHR_materials_emissive_strength` extension entirely, so every glTF
emissive material rendered at 1x strength regardless of the declared
multiplier. Any emissive asset authored with the extension is affected.

Exposed during ISS-495 verification on the AnisotropyBarnLamp: the
"Lamp Filament" material declares `emissiveFactor [1, 0.5, 0.25]` with
`emissiveStrength: 25`. Once the bulb became transparent, our filament
showed as dim copper-orange (the un-multiplied factor) while pinned
Bevy's glows blown-out white through the glass.

Bevy folds the strength into the emissive color at load
(`bevy_gltf` `loader/mod.rs:1414-1415`):
`base_emissive * material.emissive_strength().unwrap_or(1.0)`, where
`LinearRgba`'s `Mul<f32>` is componentwise over
`[red, green, blue, alpha]` (alpha scales too).

## Acceptance Criteria
- [x] The loader parses `KHR_materials_emissive_strength.emissiveStrength`
  (default 1) and multiplies it into the emissive color componentwise,
  alpha included, mirroring Bevy.
- [x] The anisotropy example's filament glows through the glass as in
  the Bevy spot.

## Fix

Commit `e5e8f2294` (2026-08-06), shared with ISS-495:

- `scene/gltf_loader.mbt`: new `gltf_parse_material_emissive_strength`
  helper (guard-chained like the other `gltf_parse_material_*`
  extension parsers, default 1); the materials loop now computes
  `emissive = base_emissive * strength` componentwise with alpha
  scaled, matching `LinearRgba`'s
  `impl_componentwise_vector_space!([red, green, blue, alpha])`.
- Regression wbtest: filament-shaped payload asserting
  (25, 12.5, 6.25, 25), plus the absent-extension 1x path.

## Description
Bevy `extract_volumetric_fog` copies `VolumetricFog` onto retained render-view
entities and removes stale `VolumetricFog`, `ViewVolumetricFogPipelines`, and
`ViewVolumetricFog` when a main-world view no longer has volumetric fog.

## Design
Audit only the view extraction/cleanup path in this slice. Do not use
source-world discovery during camera execution as evidence for this Bevy
render-world owner.

## Notes
- 2026-07-05: Split from ISS-238 so view cleanup is independent from
  fog-volume sync and volumetric-light extraction.
- 2026-07-09: Audit complete against Bevy
  `bevy_pbr/src/volumetric_fog/render.rs::extract_volumetric_fog`. Mgstudio's
  `extract_volumetric_fog_from_worlds` matches the Bevy source shape for this
  slice: it extracts source-world `VolumetricFog` onto linked render-view
  entities, and when no `VolumetricLight` exists it removes render-world
  `VolumetricFog`, `ViewVolumetricFogPipelines`, and `ViewVolumetricFog` from
  extracted volumetric-fog views, plus `FogVolume` from extracted fog volumes.
  The existing white-box test
  `pbr volumetric fog: no-light extract cleans render-world fog state only`
  covers this cleanup and verifies that source-world components are not
  deleted. The original issue description overstated Bevy behavior: the
  current Bevy source does not perform a separate per-view cleanup when a
  specific main-world view no longer has `VolumetricFog` while volumetric
  lights still exist. Mgstudio should not add that behavior in this Bevy-parity
  slice unless upstream Bevy changes first.

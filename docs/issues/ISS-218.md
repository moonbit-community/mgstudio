## Description
The `scrolling_fog` light shaft requires the pillar mesh to be visible to the
directional shadow caster. A valid cascade and target still will not produce
occluder content if visible-entity extraction, render-layer filtering, or
shadow-caster flags diverge from Bevy.

## Design
Compare Bevy's `RenderShadowMapVisibleEntities`, `VisibleMeshEntities`,
render-layer filtering, and `RenderMeshInstanceFlags::SHADOW_CASTER` handling
against mgstudio's extraction and shadow-map visible entity lookup. Verify the
pillar and ground entities separately so the test can identify whether the
occluder or the receiver path is missing.

## Acceptance Criteria
- [x] The Bevy source-shape anchors for shadow visible-entity extraction are
      classified.
- [x] The `scrolling_fog` pillar entity is present in the directional shadow
      visible set for at least one active cascade.
- [x] Render layers and shadow-caster flags are applied with Bevy-equivalent
      semantics.
- [x] A focused white-box test proves the pillar is not dropped before the
      shadow phase queue.

## Close Notes
Closed on 2026-07-04.

Source-shape classification:

- `bevy/crates/bevy_light/src/lib.rs::check_dir_light_mesh_visibility`:
  `complete` for the in-scope CPU-visible directional shadow mesh filtering.
  Mgstudio now preserves the Bevy query semantics that exclude
  `NotShadowCaster` and `NoCpuCulling`, apply render-layer intersection, and
  treat `NoFrustumCulling` as a frustum-test bypass rather than as a
  shadow-caster override.
- `bevy/crates/bevy_pbr/src/render/light.rs::extract_lights` directional
  shadow visible extraction: `complete` for the in-scope
  `RenderShadowMapVisibleEntities` subview population boundary. Mgstudio keeps
  per-retained-view mesh-visible pairs keyed by the same mesh visibility class
  before shadow phase queueing.
- `bevy/crates/bevy_render/src/view/visibility/mod.rs` GPU-culling transfer:
  `partial`. This issue verified that `NoCpuCulling` is not incorrectly added
  to the CPU-visible shadow set; broader GPU-culling parity remains owned by
  the existing render visibility issues.

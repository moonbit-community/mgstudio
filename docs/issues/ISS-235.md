## Description
After the `scrolling_fog` pillar is queued into the shadow phase, mgstudio must
execute the same retained-view shadow pass boundary that Bevy executes in
`view_shadow_pass`. This group keeps the remaining work split by source owner
and failure mode so a queued ECS item, cached pipeline id, draw payload, shadow
target, and final capture are not treated as one opaque task.

## Design
Keep this issue as the tracker. The executable child issues isolate the pass
execution chain:

- ISS-242 records and minimizes the current `wgpuQueueSubmit` validation
  failure so the real bug is pinned before code changes.
- ISS-243 restores shadow-pass pipeline specialization so queued shadow phase
  items never carry a prepass-view-layout pipeline into a shadow-view pass.
- ISS-244 verifies shadow draw payload and retained target identity against
  Bevy `view_shadow_pass`.
- ISS-245 reruns the standard no-retry `scrolling_fog` visual gate and closes
  the group only after the capture completes cleanly.

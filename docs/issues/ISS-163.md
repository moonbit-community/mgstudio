## Description
Bevy gates several expensive `StandardMaterial` texture surfaces behind
separate Cargo features:

- `pbr_transmission_textures`
- `pbr_multi_layer_material_textures`
- `pbr_anisotropy_texture`
- `pbr_specular_textures`

Mgstudio currently has the anisotropy texture feature surface enabled by
default in the main PBR mesh pipeline and descriptor layout. The generic
material payload can represent the full non-bindless binding-number surface
through binding 30, and the descriptor layout can now be derived from an
explicit feature set. The remaining gap is that material bind-group creation
and renderer-side prepared binding creation do not yet consume that same
feature set, so the optional ranges must not be globally enabled.

During `ISS-155`, unconditionally enabling transmission, multi-layer, and
specular texture shader defs and expanding the non-bindless StandardMaterial
layout to bindings 0..30 made `examples/3d/pbr` stop drawing meshes. The native
run log showed:

```text
Too many bindings of type Samplers in Stage ShaderStages(FRAGMENT), limit is 16, count was 23.
```

That failure is expected for the wrong feature shape. Bevy treats these as
optional features because the combined non-bindless sampler surface can exceed
device limits. Mgstudio needs a source-shaped feature gate and bindless-aware
layout path before these surfaces can be enabled faithfully.

## Design
Port the Bevy feature owner shape instead of adding global shader defs:

- Represent the four optional PBR material texture features as explicit
  engine-level feature state that maps back to Bevy's Cargo feature names.
- Keep the default runtime feature surface at the currently working
  anisotropy-only shape unless a requested example/package explicitly requires
  another Bevy feature.
- When a feature would exceed non-bindless sampler limits, route through the
  Bevy-shaped bindless StandardMaterial path if the render device supports it;
  otherwise report a precise unsupported-feature blocker instead of silently
  dropping textures or leaving a broken pipeline.
- Make `standard_material_bind_group_layout_descriptor`,
  `StandardMaterial::bind_group`, `MeshPipeline::specialize`, and the renderer
  bind-group creation path consume the same feature state.

Do not collapse samplers, merge unrelated texture bindings, or globally enable
shader defs as a workaround.

## Acceptance Criteria
- [x] The enabled StandardMaterial optional texture feature set is represented
      explicitly and maps to Bevy's feature names.
- [x] The main PBR mesh pipeline only defines
      `PBR_TRANSMISSION_TEXTURES_SUPPORTED`,
      `PBR_MULTI_LAYER_MATERIAL_TEXTURES_SUPPORTED`,
      `PBR_ANISOTROPY_TEXTURE_SUPPORTED`, and
      `PBR_SPECULAR_TEXTURES_SUPPORTED` when the corresponding feature is
      enabled.
- [x] The StandardMaterial descriptor layout is derived from the same feature
      state as the main PBR mesh pipeline shader defs.
- [x] `StandardMaterial::bind_group` and renderer-side prepared bind-group
      creation consume that same feature state instead of assuming one global
      optional texture surface.
- [ ] Enabling a feature set that exceeds non-bindless sampler limits either
      uses the Bevy-shaped bindless path or reports an explicit unsupported
      feature condition before pipeline creation.
- [x] `examples/3d/pbr` still renders meshes after the default feature state is
      applied.
- [ ] Feature-specific examples such as anisotropy, clearcoat, specular tint,
      and transmission are audited against their Bevy required features.

## Notes
- 2026-07-01: Created after a failed attempt to globally enable all optional
  StandardMaterial texture shader defs. The failure proved that this must be a
  feature-gated owner migration, not a blanket shader-def/layout expansion.
- 2026-07-01: Added `StandardMaterialTextureFeatureSet` with fields matching
  Bevy's four optional PBR material texture feature names. The PBR material
  pipeline specializer now derives the corresponding shader defs from that
  feature set, and `standard_material_bind_group_layout_descriptor` derives the
  descriptor layout from the same feature set. The default feature set remains
  anisotropy-only, preserving the current native sampler-limit-safe runtime
  behavior. Remaining work: pass the same feature set into
  `StandardMaterial::bind_group` and renderer bind-group creation before
  enabling additional optional features.
- 2026-07-01: Extended `MaterialBindGroupContext` so
  `PreparedMaterial::from_material`, `StandardMaterial::bind_group`, and
  `StandardMaterial::bind_group_layout_descriptor` consume the same
  `StandardMaterialTextureFeatureSet`. The default context remains
  anisotropy-only, and white-box coverage verifies that default bind-group
  payload and uniform texture flags omit disabled transmission, multi-layer,
  and specular texture ranges while an explicit all-features context restores
  the full Bevy binding-number surface through binding 30.
- 2026-07-01: Verified the default anisotropy-only feature state with
  `examples/3d/pbr` native screenshot capture at
  `/tmp/mgstudio_iss163_context_payload_pbr.png`; the capture renders the PBR
  material sphere grid and the run log contains no sampler-limit or pipeline
  creation errors.

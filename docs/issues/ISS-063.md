## Description
The near-black reference refresh pass found two examples that produce deterministic screenshots through the native capture script, but fail the current default image sanity thresholds because their intended scenes are mostly black: `examples/animation/animation_events` and `examples/ui/styling/transparency_ui`.

`animation_events` captures a dark scene with a fading `HELLO` text. `transparency_ui` captures a black-background UI scene with low-alpha button text and a purple button.

## Design
Do not lower global sanity thresholds blindly. Classify these examples against their intended visual behavior and either add an explicit dark-scene review path to the reference workflow or adjust the examples only if the dark output diverges from their source intent. Any accepted reference must still come from `p0_visual_capture_native.sh` and must not be a placeholder.

## Acceptance Criteria
- [x] `examples/animation/animation_events/reference.png` is either accepted with an explicit dark-scene note or replaced by a source-correct capture that passes sanity.
- [x] `examples/ui/styling/transparency_ui/reference.png` is either accepted with an explicit dark-scene note or replaced by a source-correct capture that passes sanity.
- [x] The sanity workflow distinguishes intentional dark UI/text scenes from accidental black frames without allowing blank placeholders.
- [x] ISS-060's bad-reference count no longer treats these two examples as unresolved opaque-black placeholders.

# ISS-043: Unblock Bevy parallel animation target evaluation

## Description
Bevy's `bevy_animation::animate_targets` evaluates animation targets with
`targets.par_iter_mut()`. Mgstudio currently evaluates the same source-shaped
per-target work serially because the MoonBit ECS/runtime has no Bevy-equivalent
parallel query executor or parallel command scope.

The latest many_foxes evidence shows that mgstudio's per-frame curve lookup is
not the bottleneck: the frame curve cache reports `25` entries, `24975` hits,
and `25` misses. The remaining cost is `20000` real sampled curves and `20000`
transform writes across `1000` foxes, which is the source-equivalent workload
that Bevy parallelizes.

## Design
Do not add mgstudio-specific shared-sampling shortcuts for this issue. Exact
Bevy parity requires a parallel ECS query path that can run target evaluation
safely and a command scope equivalent for triggered animation events.

Blocked until MoonBit/mgstudio can express:
- parallel iteration over disjoint query items;
- safe per-worker local animation evaluation state;
- a parallel command/event emission scope equivalent to Bevy's `ParallelCommands`;
- deterministic integration with ECS change ticks and component mutation rules.

## Acceptance Criteria
- [ ] ECS exposes a Bevy-shaped parallel target iteration API suitable for `animate_targets`.
- [ ] Animation target evaluation uses that API without changing Bevy source semantics.
- [ ] Targeted animation events preserve command/event ordering guarantees defined for the engine.
- [ ] many_foxes profile shows animation target evaluation below `4 ms/frame` at `1000` foxes, or a new source-backed limit is documented.
- [ ] Relevant animation and ECS tests pass with `--release`.

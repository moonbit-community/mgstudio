## Description
`mgstudio-engine/examples/3d/order_independent_transparency/main.mbt` and the
underlying OIT runtime owners are only partial migrations of Bevy's
order-independent transparency path.

The example can toggle an OIT settings component, but the runtime is not
Bevy-shaped. Bevy's `OrderIndependentTransparencySettings` defaults differ from
mgstudio's defaults. Bevy's plugin installs extraction, dynamic OIT buffers,
per-view settings offsets, camera depth-usage preparation, MSAA validation, OIT
resolve pipeline queueing, bind-group preparation, and a Core3d resolve pass
after the transparent pass. Mgstudio currently has WGSL assets and scaffolding,
but the renderer layout/specialization call sites still force
`oit_supported=false`, and no source-shaped OIT buffer/offset/resolve owner is
wired into render execution.

This is a local source-parity gap. Do not treat a visually plausible transparent
scene as OIT parity until the Bevy runtime owner is present.

## Design
Restore OIT by following these Bevy source owners symbol-by-symbol:

- `bevy/examples/3d/order_independent_transparency.rs`
- `bevy/crates/bevy_core_pipeline/src/oit/mod.rs`
- `bevy/crates/bevy_core_pipeline/src/oit/resolve/mod.rs`
- `bevy/crates/bevy_core_pipeline/src/oit/resolve/node.rs`
- `bevy/crates/bevy_core_pipeline/src/core_3d/main_transparent_pass_3d_node.rs`
- `bevy/crates/bevy_pbr/src/render/mesh.rs`
- `bevy/crates/bevy_pbr/src/render/mesh_view_bindings.rs`
- `bevy/crates/bevy_pbr/src/deferred/mod.rs`

Required implementation direction:

- Correct `OrderIndependentTransparencySettings` defaults to Bevy values:
  `sorted_fragment_max_count = 8`, `fragments_per_pixel_average = 4.0`,
  `alpha_threshold = 0.0`.
- Port Bevy's OIT plugin topology: shader library load, extract component
  plugin equivalent, resolve plugin, `check_msaa`, render startup buffers,
  prepare-view depth usage, prepare-resource OIT buffers, and Core3d resolve
  pass placement.
- Implement the Bevy-shaped `OitBuffers` resource, `OitFragmentNode`,
  `OrderIndependentTransparencySettingsOffset`, buffer resize policy, dynamic
  uniform upload, and per-view offset insertion.
- Wire adapter/device capability checks into the render pipeline instead of
  forcing `oit_supported=false`.
- Restore mesh-view bindings for OIT settings, node capacity, nodes, heads, and
  atomic counter when OIT is supported.
- Restore the resolve pipeline key, queue system, bind group preparation, and
  fullscreen resolve pass.
- Restore the example source shape: UI `Text`/`Node`/`TextSpan`, `TextUiWriter`,
  `Local<usize>`, `Query<Entity, With<Mesh3d>>` despawn/respawn scene cycling,
  `Rectangle` quads, Bevy primitive builders, and `spawn_batch`.

If the backend lacks a concrete capability required by Bevy OIT, record that as
a separate external blocker with the exact missing API and keep this issue
blocked on it. Do not keep silent renderer-local disabled paths.

## Acceptance Criteria
- [ ] `OrderIndependentTransparencySettings` defaults match Bevy.
- [ ] OIT plugin installation matches Bevy's source-owner topology.
- [ ] OIT buffer allocation, upload, resize, and per-view offset insertion are
      implemented through Bevy-shaped resources/components.
- [ ] The renderer no longer hardcodes `oit_supported=false` at OIT-capable
      mesh-view layout and pipeline call sites.
- [ ] The OIT resolve pipeline queue, bind group preparation, and Core3d resolve
      pass are source-shaped.
- [ ] PBR transparent materials with OIT enabled call the OIT draw path only in
      the Bevy-equivalent alpha pass.
- [ ] The `order_independent_transparency` example matches Bevy's systems,
      UI hierarchy, scene cycling, primitive builders, and batch-spawn behavior.
- [ ] A new reference screenshot is captured after the example first runs with
      real OIT enabled.

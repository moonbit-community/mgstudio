## Description
ISS-141 moved retained gizmo extraction and queue ownership into
`gizmos_render`, but mgstudio still does not replicate Bevy's deeper
`bevy_gizmos_render` GPU asset and specialized pipeline owner. Bevy prepares
`GizmoAsset` into `GpuLineGizmo`, stores line-list and line-strip GPU buffers,
specializes 2D/3D line and joint pipelines, and queues phase items that draw
those prepared render assets. mgstudio currently converts extracted retained
gizmo data back into the existing line drawing runtime instead of owning
`GpuLineGizmo` buffers and Bevy-shaped phase items.

## Design
Port the remaining `bevy_gizmos_render/src/lib.rs`, `pipeline_2d.rs`, and
`pipeline_3d.rs` owner symbols that are not covered by ISS-141. This includes
the `GpuLineGizmo` render asset shape, line uniform bind-group preparation,
line-list/line-strip vertex buffer ownership, line-joint handling, and the 2D
and 3D queue systems that add source-shaped phase items. Do not replace this
with another runtime bridge; if a lower-level render phase or GPU API is
missing, record that exact blocker.

## Acceptance Criteria
- [x] `GizmoAsset` is prepared into a mgstudio `GpuLineGizmo` render asset with
      separate list and strip vertex/color buffers or a documented blocker for
      the missing GPU-buffer API.
- [x] 2D and 3D line gizmo queue systems create Bevy-shaped phase entries rather
      than relying on the shared immediate gizmo line queue.
- [x] Line-style, line-joint, perspective, and render-layer specialization are
      represented in pipeline keys or recorded as precise blockers.
- [x] `examples/gizmos/3d_gizmos/reference.png` remains visually valid after
      replacing the bridge with the render-asset pipeline.

## Description
The pinned Bevy `examples/3d/transparency_3d` program builds and exits normally
on the current macOS development machine, but Bevy's own
`bevy_ci_testing` screenshot path produces a fully black `2560x1440` PNG.
This prevents a faithful official-Bevy visual baseline from being used for the
final mgstudio comparison. It does not block source-level render/PBR migration
or mgstudio-native screenshot capture.

The failure reproduces at both frame 90 and frame 240. The later reproduction
uses a fixed `0.016667` second frame duration, requests `Screenshot` at frame
240, and sends `AppExit` separately at frame 250, so the all-black result is
not explained by an early capture or `ScreenshotAndExit` ordering.

## Design
Diagnose the pinned Bevy native screenshot owner on macOS and obtain a nonblack
artifact from the official example. Preserve the official example source and
renderer output. Do not substitute an mgstudio screenshot, the existing black
`bevy/screenshot-90.png`, a web image from a different Bevy revision, or a
hand-adjusted scene as the official baseline.

Acceptable fixes include repairing the pinned Bevy screenshot readback path or
documenting and using another deterministic capture path that records the
unmodified pinned Bevy window output. Any alternative must retain the exact
Bevy revision, fixed frame timing, viewport dimensions, and capture frame.

## Acceptance Criteria
- [ ] The pinned Bevy `examples/3d/transparency_3d` produces a nonblack native screenshot on the current macOS development machine.
- [ ] The capture uses Rust `1.95.0`, Bevy commit `1413bc4e3632233b8fa610a6cf14b90258556c51`, fixed frame timing, and a recorded capture frame.
- [ ] The official Bevy run exits cleanly and the capture log contains no renderer or screenshot failure.
- [ ] The accepted artifact is retained as the official side of the `transparency_3d` visual parity packet.
- [ ] ISS-060 and the active render/PBR migration issue are updated with the accepted baseline or the exact remaining external failure.

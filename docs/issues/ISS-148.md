# ISS-148: Unblock sampler binding-array rendering for Bevy lightmaps

## Description
Bevy's PBR lightmap shader uses a texture binding array and a sampler binding
array together:

`binding_array<texture_2d<f32>, 4>` at mesh bind group binding 4 and
`binding_array<sampler, 4>` at binding 5. The shader dynamically indexes both
arrays from the high 16 bits of
`material_and_lightmap_bind_group_slot`.

Mgstudio now builds Bevy-shaped lightmap slabs and per-slab draw bind groups,
but native macOS/Metal rendering still drops every lightmapped mesh when the
binding-array shader path is active. Forcing the non-binding-array lightmap
layout restores the static meshes with the same textures, UV rects, materials,
and draw data.

## Design
Do not rewrite the Bevy lightmap WGSL to avoid sampler arrays, and do not
disable binding arrays as a local workaround. The dependency needs a regression
test and fix for native rendering with dynamically indexed sampler binding
arrays, and mgstudio must only enable Bevy's binding-array shader path when
the current device limits actually allow both texture and sampler binding
arrays.

Mgstudio should keep the Bevy-shaped slab/slot path in place and close this
blocker only after `wgpu_mbt` can render or otherwise verify:

- `binding_array<texture_2d<f32>, N>`;
- `binding_array<sampler, N>`;
- dynamic indexing from a uniform or storage value;
- `textureSampleLevel(textures[index], samplers[index], uv, 0.0)`.

## Acceptance Criteria
- [x] `wgpu_mbt` has a native regression test for fragment-stage sampling from
      dynamically indexed texture and sampler binding arrays.
- [x] Mgstudio's `examples/3d/mixed_lighting` renders the static lightmapped
      chair/scenery and plane through the Bevy-shaped lightmap path selected by
      the current device limits.
- [x] `examples/3d/mixed_lighting/reference.png` is refreshed only after the
      selected lightmap path is visually correct.

## Notes
- 2026-06-23: Filed upstream as
  https://github.com/moonbit-community/wgpu-mbt/issues/31. Local evidence:
  `RealTime` renders the glTF scene correctly; disabling GPU preprocess does
  not change the failure; temporarily forcing the non-binding-array lightmap
  layout restores the static lightmapped meshes; the Bevy-shaped local slab,
  slot, batch-key, and draw-bind-group data flow now exists.
- 2026-06-30: Rechecked against `wgpu_mbt@0.14.6`. The dependency contains a
  native regression test for dynamically indexed texture and sampler binding
  arrays. Mgstudio still needs a fresh `examples/3d/mixed_lighting` capture
  through the binding-array path before this issue can close.
- 2026-06-30: Fresh capture showed the current native macOS device reports
  `max_binding_array_sampler_elements_per_shader_stage == 0`; enabling
  `MULTIPLE_LIGHTMAPS_IN_ARRAY` on that device is invalid and produced
  `Too many bindings of type BindingArraySamplerElements` validation errors.
  Mgstudio's capability predicate now checks the sampler binding-array limit
  before selecting the Bevy lightmap binding-array path. With the legal
  non-array lightmap path selected, `examples/3d/mixed_lighting` renders the
  chair/scenery and plane and the run log is clean.

## Close Notes
- 2026-06-30: Closed as no longer an external `wgpu_mbt` blocker. The upstream
  regression coverage exists, and mgstudio now gates the binding-array shader
  path on the current device limits instead of enabling it unconditionally.

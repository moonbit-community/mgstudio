## Description
`examples/3d/lightmaps/reference.png` is still an unusable transparent
baseline. A standard native capture of the current example produced a
numerically nonblank image, but manual review rejected it: the output is only a
dark square on the default background, not Bevy's visible CornellBox scene with
baked lightmaps.

Bevy's `examples/3d/lightmaps.rs` loads
`models/CornellBox/CornellBox.glb`, sets `GlobalAmbientLight::NONE`, optionally
enables deferred prepasses, waits for `GltfMeshName` meshes, assigns
`Lightmap` components with KTX2/zstd lightmap images, and raises material
`lightmap_exposure` for the large box, small box, and room mesh. Mgstudio's
current example has the same high-level intent, but the captured frame shows
that the scene/lightmap pipeline is not producing the expected visible result.

## Design
Audit and port Bevy `examples/3d/lightmaps.rs` and the required scene, glTF,
asset, and PBR lightmap owners as the migration unit:

- `WorldAssetRoot` / scene-root readiness and `SceneInstanceReady` semantics;
- `GltfMeshName` propagation for glTF primitives;
- `Lightmap` component insertion on the correct mesh entities;
- `StandardMaterial.lightmap_exposure` mutation for the matched material
  handles;
- KTX2/zstd lightmap image loading and texture format support;
- deferred-mode argument path and prepass component insertion.

Do not accept a dark-square capture, fake lightmap texture, or constant-color
stand-in as parity. If the missing behavior is caused by a real MoonBit or
dependency limitation, record the precise blocker before leaving the example
partial.

## Acceptance Criteria
- [x] Every source-shape anchor in Bevy `examples/3d/lightmaps.rs` is
      classified as complete, partial, facade, blocked, or intentionally
      excluded.
- [x] The CornellBox glTF scene is visibly rendered in the standard native
      capture.
- [x] Lightmap images are loaded and bound through real `Lightmap` components,
      with material `lightmap_exposure` matching Bevy's example behavior.
- [x] `examples/3d/lightmaps/reference.png` is refreshed only after the
      CornellBox/lightmap visual signal is present.
- [x] The standard native capture command succeeds without validation, fatal,
      missing-resource, or asset decode errors.

## Close Notes
- 2026-06-14: Fixed the actual render path instead of accepting the dark-square
  capture. The migration now propagates `GltfMeshName`, imports `TEXCOORD_1`
  into `MeshVertexAttribute::uv_1`, loads CornellBox KTX2 lightmaps as
  `RG11_B10_UFLOAT`, applies Bevy-shaped `Lightmap` components and material
  `lightmap_exposure`, and refreshes the reference screenshot after the
  CornellBox is visible.
- Root cause: the base PBR material pipeline omitted Bevy's `LIGHTMAP` and
  `LIGHTMAP_BICUBIC_SAMPLING` shader defs, so meshes had `Lightmap`
  components and lightmap texture handles but still compiled an unlightmapped
  fragment path. The base specializer now also registers same-frame material
  pipeline descriptors, matching the prepass path.
- Verified with `moon -C mgstudio-engine check --target native --deny-warn
  --package-path asset`, `mesh`, `scene`, `pbr`, `render`, and
  `examples/3d/lightmaps`; `moon -C mgstudio-engine test --target native
  --release pbr`; `moon -C mgstudio-engine test --target native --release
  asset`; `moon -C mgstudio-engine fmt`; `moon -C mgstudio-engine info`; and
  the standard 90-frame native capture for `examples/3d/lightmaps`.

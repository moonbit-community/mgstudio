## Description
Bevy's volumetric fog pass samples the depth texture for the same view that just
completed the main 3D pass. Mgstudio has multiple camera/pass-state boundaries,
so it must prove the post-main volumetric fog step receives the active camera's
depth view rather than a stale backend-global view or a view from another
camera.

## Design
Audit Bevy's `ViewDepthTexture` flow into the `volumetric_fog` render command
against mgstudio's camera depth target, main pass state, post-main pass state,
and renderer API boundary. Keep the ownership source-shaped: the active view
depth identity should be carried by camera/pass data, not rediscovered from
global renderer state during draw.

## Acceptance Criteria
- [x] The volumetric fog pass state carries the depth view that belongs to the
      active camera main pass.
- [x] Multi-camera or repeated-camera execution cannot accidentally reuse a
      previous camera's depth view.
- [x] Focused coverage checks depth-view identity across the main-pass to
      volumetric-fog boundary.

## Close Notes
2026-07-04: Bevy's `volumetric_fog` render command receives
`&ViewDepthTexture` from the active view query and binds
`view_depth_texture.view()` directly into the volumetric fog group. Mgstudio had
a real source-shape divergence: `mesh3d_pass_view_depth_view` ignored
`GpuPassState` and returned `backend.depth_view`, a renderer-global mutable
slot that can be replaced by later pass setup.

Fixed the ownership boundary by adding `view_depth_texture_id` and
`view_depth_view` to `GpuPassState`. `begin_pass_3d` records the depth texture
identity and `TextureView` selected for the active pass, and volumetric fog now
reads the depth view from `pass_state` rather than from `backend.depth_view`.
This matches Bevy's view-local `ViewDepthTexture` flow and prevents later
camera/pass setup from changing the depth view used by the already prepared
volumetric fog draw.

# ISS-162: Request Bevy PBR sampler limits through wgpu_mbt

## Description
Bevy's default `WgpuSettingsPriority::Functionality` requests the adapter's
supported limits before creating the render device. This is required for PBR
pipelines that enable `pbr_anisotropy_texture` and
`pbr_multi_layer_material_textures`: the combined PBR view/material layout can
exceed WebGPU's default `max_samplers_per_shader_stage` value of 16.

Mgstudio's Bevy-shaped StandardMaterial binding work now reaches the correct
PBR material specialization path for `examples/3d/anisotropy`, but native
pipeline layout creation fails with:

```text
Too many bindings of type Samplers in Stage ShaderStages(FRAGMENT), limit is 16, count was 17.
```

`wgpu_mbt@0.14.3` exposes adapter/device getters for
`max_samplers_per_shader_stage` and
`max_sampled_textures_per_shader_stage`, but
`Adapter::request_device_sync_with_features_and_limits` cannot request those
limits. Mgstudio therefore cannot source-match Bevy's functionality-priority
device creation without an upstream API addition.

## Design
Do not merge samplers, disable PBR feature shader defs, collapse material
bindings, or add project-local native stubs. Keep the Bevy-shaped material
layout and require `wgpu_mbt` to expose safe request-device overrides for the
missing limits.

Once the upstream API exists, mgstudio should request the adapter-supported
sampler and sampled-texture per-stage limits during backend initialization,
mirroring Bevy's functionality-priority `adapter.limits()` behavior.

## Acceptance Criteria
- [ ] `wgpu_mbt` exposes safe request-device limit overrides for
      `max_samplers_per_shader_stage`.
- [ ] `wgpu_mbt` exposes safe request-device limit overrides for
      `max_sampled_textures_per_shader_stage`.
- [ ] Mgstudio backend initialization requests the adapter-supported sampler
      and sampled-texture per-stage limits when available.
- [ ] `examples/3d/anisotropy` creates the PBR material pipeline layout without
      exceeding the default sampler limit and renders the model again.

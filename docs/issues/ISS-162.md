# ISS-162: Request Bevy PBR sampler limits through wgpu_mbt

## Description
Bevy's default `WgpuSettingsPriority::Functionality` requests the adapter's
supported limits before creating the render device. This is required before
mgstudio can faithfully enable Bevy-shaped PBR material texture features such
as `pbr_anisotropy_texture`.

Before `wgpu_mbt@0.14.4`, mgstudio's Bevy-shaped StandardMaterial binding work
reached the correct PBR material specialization path for
`examples/3d/anisotropy`, but native pipeline layout creation failed with:

```text
Too many bindings of type Samplers in Stage ShaderStages(FRAGMENT), limit is 16, count was 17.
```

`wgpu_mbt@0.14.3` exposed adapter/device getters for
`max_samplers_per_shader_stage` and
`max_sampled_textures_per_shader_stage`, but
`Adapter::request_device_sync_with_features_and_limits` could not request those
limits. Mgstudio therefore could not source-match Bevy's
functionality-priority device creation without an upstream API addition.

## Design
Do not merge samplers, collapse material bindings, or add project-local native
stubs. Keep the Bevy-shaped material layout for the enabled Bevy feature set
and require `wgpu_mbt` to expose safe request-device overrides for the missing
limits.

Once the upstream API exists, mgstudio should request the adapter-supported
sampler and sampled-texture per-stage limits during backend initialization,
mirroring Bevy's functionality-priority `adapter.limits()` behavior.

## Acceptance Criteria
- [x] `wgpu_mbt` exposes safe request-device limit overrides for
      `max_samplers_per_shader_stage`.
- [x] `wgpu_mbt` exposes safe request-device limit overrides for
      `max_sampled_textures_per_shader_stage`.
- [x] Mgstudio backend initialization requests the adapter-supported sampler
      and sampled-texture per-stage limits when available.
- [x] `examples/3d/anisotropy` creates the PBR material pipeline layout without
      exceeding the default sampler limit and renders the model again.

## Notes
- 2026-06-29: Filed upstream as
  https://github.com/moonbit-community/wgpu-mbt/issues/33 after confirming that
  the local failure is a device-limit request gap, not a shader binding index
  mismatch or a material specialization propagation bug.
- 2026-06-30: `wgpu_mbt@0.14.4` added the required request-device limit
  overrides. Rechecking the Bevy source showed that
  `pbr_anisotropy_texture` and `pbr_multi_layer_material_textures` are separate
  optional features; `examples/3d/anisotropy` requires only
  `pbr_anisotropy_texture`. Mgstudio now enables the anisotropy texture layout
  and shader def without also enabling multi-layer material texture bindings.
  The remaining StandardMaterial bindless / sampler binding-array work remains
  tracked in ISS-145.

## Close Notes
Closed after updating to `Milky2018/wgpu_mbt@0.14.4`, requesting adapter
sampled-texture and sampler limits during backend initialization, and restoring
the Bevy-shaped anisotropy material texture bindings for the anisotropy example
feature set. Verified with `moon -C mgstudio-engine check --target native
--deny-warn`, `moon -C mgstudio-engine test --release pbr --deny-warn`, and
`MGSTUDIO_PARITY_CAPTURE_DELAY_FRAMES=90
MGSTUDIO_PARITY_RUN_TIMEOUT_SECONDS=240
mgstudio-engine/scripts/p0_visual_capture_native.sh examples/3d/anisotropy
/tmp/mgstudio_wgpu_mbt_0144_anisotropy.png`.

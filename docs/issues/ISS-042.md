## Description
After ISS-006, mgstudio skin extraction follows Bevy's source shape: changed
skins are initialized once, then per-frame extraction walks prepared skins and
writes only joints whose `GlobalTransform` changed. In many_foxes, animation
changes every joint every frame, so the source-equivalent path still writes
`24000` joint matrices per sampled frame and costs `2.703 ms/frame`.

## Design
Keep the Bevy-facing API and source-owner structure intact. Optimize only the
lower-level hot path: typed changed-transform lookup, cached joint row access,
matrix multiply/write layout, and upload staging writes. Do not reintroduce a
dirty-skin threshold or any fallback that writes more data than Bevy's
`Changed<GlobalTransform>` query requires.

## Acceptance Criteria
- [x] `extract_3d_skins` is below `2.5 ms/frame` at `1000` foxes, or a concrete external/runtime blocker is recorded.
- [x] Counters still report `skins`, `dirty_skins`, `joints`, `staging_rows`, `upload_bytes`, and joint-transform cache hits/misses.
- [x] The implementation remains source-equivalent to Bevy `bevy_pbr/src/render/skin.rs`.
- [x] Relevant PBR skinning tests pass with `--release`.

## Notes
- 2026-06-04: Baseline after ISS-006: `/tmp/mgstudio_many_foxes_iss006_bevy_joint_changed/frametime_breakdown.md` reports `extract_3d_skins=2.703 ms/frame`, `pbr.skin_extraction.joints=24000`, and `pbr.skin_extraction.joint_transform_cache_hits=24000`.
- 2026-06-04: Bevy's relevant source-level shape uses `changed_transforms.get(joint)` and direct staging-buffer matrix assignment; any mgstudio optimization must preserve that observable semantics.
- 2026-06-04: Added a `SkinnedMesh` cached joint-row changed-tick lookup and switched extraction to use it before falling back to the generic world change lookup. This preserves Bevy's `Changed<GlobalTransform>` behavior while removing a per-joint world lookup from the table-backed hot path.
- 2026-06-04: Follow-up profile `/tmp/mgstudio_many_foxes_iss042_cached_changed_lookup/frametime_breakdown.md` was not sufficient to close the issue: it had only one steady frame and reported `extract_3d_skins=2.903 ms/frame`, above the `2.5 ms/frame` target. Continued by combining cached-row changed-tick validation with typed `GlobalTransform` row fetch so changed joints do not perform a second lookup.
- 2026-06-04: Second profile `/tmp/mgstudio_many_foxes_iss042_changed_value_lookup/frametime_breakdown.md` still had only one steady frame but improved `extract_3d_skins` to `2.754 ms/frame`, still above target. Continued by making the extraction hot path write directly into the already-sized staging rows, matching Bevy's direct `current_staging_buffer[index] = matrix` behavior instead of checking/expanding rows per joint.
- 2026-06-04: Final short trace `/tmp/mgstudio_many_foxes_iss042_direct_staging_write/frametime_breakdown.md` reports `extract_3d_skins=2.397 ms/frame`, `pbr.skin_extraction.skins=1000`, `dirty_skins=1000`, `joints=24000`, `staging_rows=384000`, `upload_bytes=1536000`, `joint_transform_cache_hits=24000`, and `joint_transform_cache_misses=0`. The run still had only one steady frame because trace flushing is expensive, but it used the same short-profile shape as the preceding ISS-042 checks and crossed the issue target.

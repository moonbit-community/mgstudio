## Description
ISS-217 verified the `scrolling_fog` single-directional-light target/pass
boundary, but Bevy's `prepare_lights` supports up to `MAX_DIRECTIONAL_LIGHTS`
directional lights. Mgstudio's current camera shadow execution path is still
shaped around one active directional light in `Render3dLightingState` and
hardcodes directional shadow pass names with light index `0`.

This is a local source-parity gap, not an external blocker.

## Design
Audit Bevy `bevy_pbr/src/render/light.rs::prepare_lights` and the mgstudio PBR
light collection/shadow execution path. Port the multi-directional-light target
and shadow-view flow source-faithfully: per-light cascade ranges, cumulative
directional depth texture array indices, stable retained view identity, pass
names using the real light index, GPU directional light cascade metadata, and
volumetric-fog shadow sampling indices. Do not collapse multiple lights into a
single selected directional light.

## Acceptance Criteria
- [x] The active camera can prepare shadow views for more than one
      shadow-enabled directional light.
- [x] Directional cascade target layers are assigned cumulatively across
      directional lights before spot-light layers, matching Bevy.
- [x] Pass names and retained view identities include the real directional
      light index/cascade identity rather than a hardcoded `0`.
- [x] GPU directional light cascade metadata and volumetric-fog shadow sampling
      remain consistent with the target layers.
- [x] Focused tests cover at least two shadow-enabled directional lights with
      different cascade counts.

## Close Notes
2026-07-06: Ported the camera directional shadow preparation path from a
single selected directional light to a Bevy-shaped visible directional light
list. Shadow views now preserve visible light indices in pass names, retain
per-light/cascade identity, assign cumulative target layers across all
directional cascades, and place spot-light layers after the full directional
cascade range. GPU light cascade matrices are resolved by each light's
`depth_texture_base_index` and per-light `num_cascades`, preserving each
directional light's existing cascade overlap metadata.

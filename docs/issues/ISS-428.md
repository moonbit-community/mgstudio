# ISS-428: Add cancellable wgpu map-read futures

## Description
`PendingCommandBuffers::cancel()` cannot safely cancel a submitted map-read future when the caller omitted `RenderDevice` or `RenderInstance`. The current `wgpu_mbt` native API exposes status, read, and clear operations, but `mbt_wgpu_queue_map_read_async_clear` deliberately returns without clearing while the future is unfinished. Releasing mgstudio's `PendingMapReadFuture` state in that condition would orphan the native async slot and its retained buffer.

## Design
Add an explicit cancellation operation to `wgpu_mbt` that safely detaches or completes an unfinished map-read slot according to WebGPU callback lifetime rules. The operation must release the slot's retained buffer exactly once, remove its wait-any registration, and make a later native callback harmless. Keep mgstudio's current shutdown drain path for futures that have device and instance handles; use the new cancellation operation only when deterministic draining is unavailable. Do not make `map_read_async_clear` silently pretend that an unfinished future was cleared.

## Acceptance Criteria
- [ ] `wgpu_mbt` exposes a native and MoonBit map-read cancellation API with documented idempotent semantics.
- [ ] Cancelling before completion releases the retained native buffer and wait-any slot exactly once.
- [ ] A callback arriving after cancellation cannot access freed slot memory or release the buffer again.
- [ ] Focused `wgpu_mbt` tests cover cancel-before-complete, cancel-after-complete, and repeated cancellation.
- [ ] mgstudio `PendingCommandBuffers::cancel()` leaves `map_read_futures` empty even when `submit()` was called without `RenderDevice` or `RenderInstance`.
- [ ] A focused renderer shutdown test reports zero retained buffers and map-read futures after the fallback cancellation path.

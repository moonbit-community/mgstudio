# ISS-416: Release Mesh3d and PBR pipeline owners

## Metadata

## Description
Mesh3d layouts, pipelines, shadow resources, material caches, draw slots, skin/morph buffers, fog, decals, probes, and per-view bind-group caches retain native handles until process exit.

## Design
Implement release operations at existing Mesh3d aggregate and cache-entry ownership boundaries, then invoke one Mesh3d/PBR area release operation from backend shutdown.

## Acceptance Criteria
- [x] Mesh3d layouts, pipelines, shadow resources, and material caches release their owned handles.
- [x] Per-view, draw-slot, skin, morph, fog, decal, probe, and wireframe resources are released.
- [x] Shared handles are released once per owned reference, with add-ref aliases documented by construction sites.
- [x] Native WGPU report coverage exercises representative Mesh3d/PBR owners.

## Notes

Material pipeline-layout cache entries now own one reference for every stored native layout. When a cache entry stores the backend's base draw/material layouts, construction adds explicit references; shutdown can therefore release every entry uniformly without ownership heuristics.

Cluster buffers supplied by the render world are borrowed at the API boundary. `GpuBackend::use_mesh3d_cluster_buffers` now acquires its own references before releasing the previous backend-owned references.

## Close Notes

Integrated Mesh3d/PBR layouts, pipelines, shadow resources, material/view caches, per-frame uniforms, draw slots, skin/morph resources, clustered lighting/decal buffers, fog/probe buffers, and wide-wireframe resources into backend shutdown. Replaced per-frame raw cache `clear()` calls with owner-aware release operations, fixing a continuous frame-to-frame buffer and bind-group leak. Material render-pipeline replacement now releases the superseded pipeline.

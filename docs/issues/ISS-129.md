## Description
`mgstudio-engine/examples/3d/shadow_biases/main.mbt` is not a symbol-level port
of `bevy/examples/3d/shadow_biases.rs`.

The current example has working shadow-bias controls and uses the same bias
defaults, light intensities, filtering modes, camera placement, light-position
keys, and render-side shadow data path. However, the source owner is replaced
with local scaffolding:

- Bevy's `Lights` marker component is replaced by entity ids stored in a global
  `ShadowBiasesState` `Ref`;
- Bevy's parent `Lights` transform with child point and directional light
  components is replaced by two independent light entities;
- Bevy's sphere row uses `Sphere::new(0.25)`, while mgstudio uses cuboid proxy
  meshes;
- Bevy's UI `Text` root plus `TextSpan` children and `TextUiWriter` span
  updates are replaced by a world-space `Text2dBundle` and full-string
  replacement;
- Bevy's five update systems are collapsed into one monolithic world system
  that mutates global state and replaces components.

These are local source-parity gaps. Mgstudio already has shadow-bias fields,
shadow filtering, free camera support, and render-side bias extraction.

## Design
Port the example directly from `bevy/examples/3d/shadow_biases.rs`:

- add a real `Lights` marker component and move light-position updates through
  `Query<&mut Transform, With<Lights>>`;
- spawn the point and directional lights as children of the parent light entity;
- use a sphere mesh equivalent to `Sphere::new(0.25)` for the test row;
- preserve the Bevy `Text`/`Node`/`TextSpan` UI hierarchy and span-index
  updates via the closest source-shaped writer API;
- split the monolithic `update(world)` back into source-shaped systems:
  `cycle_filter_methods`, `adjust_light_position`,
  `adjust_point_light_biases`, `toggle_light`, and
  `adjust_directional_light_biases`;
- remove `ShadowBiasesState`, tracked entity ids, global bias fields, and
  component-replacement helpers from the source-parity path;
- keep numeric constants and key mappings identical to Bevy.

If the current ECS cannot express one of these system-param or UI writer shapes,
record a precise ECS/UI blocker instead of keeping the global-state workaround.

## Acceptance Criteria
- [x] `Lights` is represented as an ECS marker component.
- [x] Point and directional lights are children of one parent light entity with
      the source light transform.
- [x] The test row uses a sphere mesh equivalent to Bevy's `Sphere::new(0.25)`.
- [x] UI uses the source-shaped `Text` root, `TextSpan` children, and span
      updates rather than full-string `Text2d` replacement.
- [x] The five Bevy update systems are represented separately with
      source-shaped queries and system params.
- [x] Point-light and directional-light bias updates mutate the light
      components directly through queries.
- [x] Shadow-filter cycling mutates `ShadowFilteringMethod` directly through a
      query.
- [x] Light-position controls mutate the `Lights` parent transform and call
      `look_at(Vec3::ZERO, Vec3::Y)`.
- [x] `ShadowBiasesState`, tracked light/camera/help-text entity ids, and the
      monolithic world update are removed unless precise blockers are recorded.
- [x] A fresh `examples/3d/shadow_biases/reference.png` is captured after the
      source-shaped port still renders correctly.

# ISS-005: Make skinned mesh bounds Bevy-shaped and joint-cache backed

## Metadata

- Updated: 2026-06-04

## Description
Dynamic skinned bounds cost about `8.587 ms/frame` in the original breakdown.
Every fox with a skinned mesh walks joint bounds and fetches joint global
transforms, which duplicates part of the pressure already present in skin
extraction.

## Design
Port the current Bevy skinned-bounds recomputation behavior as closely as
possible. Current Bevy recomputes `DynamicSkinnedMeshBounds` every frame, so the
target is a source-shaped recompute path that uses maintained joint row caches
as the primary fetch route and avoids extra changed ticks when the resulting
`Aabb` is unchanged.

## Acceptance Criteria
- [x] The bounds system reports skinned entities processed, joint bounds
      processed, joint cache hits/misses, and AABB writes.
- [x] Joint table-row caches are the normal fetch path, not a fallback.
- [x] Bevy source semantics are preserved: dynamic skinned mesh bounds are
      recomputed every frame, while unchanged AABB values are not marked
      changed in mgstudio.
- [x] Bounds remain visually and functionally correct for animated foxes.
- [x] At `1000` foxes, skinned mesh bounds are reduced below `3 ms/frame` or a
      follow-up issue documents the remaining blocker.
- [x] Relevant mesh and visibility tests pass with `--release`.

## Notes
- Current evidence: `mgstudio.visibility.update_skinned_mesh_bounds=8.587 ms/frame`.
- 2026-06-04: Bevy `update_skinned_mesh_bounds` was rechecked. Current Bevy
  source recomputes every entity with `DynamicSkinnedMeshBounds` each frame via
  `par_iter_mut`; it is not dirty-driven. The original "do not recalculate when
  unchanged" acceptance item is therefore not source-equivalent for dynamic
  bounds. The local fix keeps the per-frame recompute semantics, aggregates
  trace counters once per system run instead of once per skinned entity, and
  avoids marking `Aabb` changed when the computed value is unchanged.
- 2026-06-04: many_foxes short trace after aggregate counters:
  `counter` events dropped from per-entity reporting to one event per counter
  per frame. `update_skinned_mesh_bounds` measured around `6.25 ms/frame`.
- 2026-06-04: Direct cached joint traversal removed the per-joint fetch
  callback from the cached path. many_foxes still reports about
  `5.8 ms/frame`, with `skinned_entities=1000`,
  `joint_bounds_processed=22000`, `joint_transform_cache_hits=22000`,
  `joint_transform_cache_misses=0`, and `aabb_writes=1000`.
  Reaching the `<3 ms/frame` target likely requires a source-equivalent
  parallel iteration or SIMD math capability comparable to Bevy's
  `par_iter_mut`, or a separate non-Bevy policy decision for dynamic bounds.

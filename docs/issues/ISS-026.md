# ISS-026: Move UI render overlay paths out of sprite render

## Description
UI render currently routes through sprite render overlay APIs. `ui_render/ui_render.mbt`
calls `sprite_render.render2d_clear_overlay_ui_rects`,
`render2d_clear_overlay_ui_box_shadows`, `render2d_push_ui_rect_uv_scissor`,
`render2d_push_ui_box_shadow_scissor`, and
`render2d_push_ui_texture_slice_scissor`. The corresponding payload and draw
logic is still present inside `sprite/render2d.mbt`.

Bevy has `bevy_ui_render` owners for UI nodes, boxes, texture slices, materials,
gradients, text, and render passes. Routing UI through sprite render is a local
bridge, not source-level parity.

## Design
Move UI extraction, queueing, batching, and draw payload ownership into
`ui_render/*`, then connect it to render phases in a Bevy-shaped way. Sprite
render should not expose UI overlay push APIs as the normal UI render path.

## Acceptance Criteria
- [ ] UI rectangles, box shadows, texture slices, and UI image/text draw payloads are owned by `ui_render/*`.
- [ ] `ui_render` no longer depends on `sprite_render.render2d_push_ui_*` APIs for normal rendering.
- [ ] Sprite render no longer contains UI overlay payload structs or UI pass draw loops.
- [ ] Representative UI examples pass after the move.

## Notes
- 2026-06-03: The current bridge hides UI render parity behind the sprite render monolith and makes `bevy_ui_render` source updates hard to apply.
- 2026-06-12: Added `ui_render/runtime` as the owner for extracted UI
  sprite, rect, box-shadow, and texture-slice payload resources. `ui_render`
  now writes UI rect/box-shadow/texture-slice payloads into that resource
  instead of calling sprite render `render2d_push_ui_*` APIs, and
  `sprite_render` no longer exposes those UI push/clear facades. This is still
  partial: sprite render remains the temporary consumer/draw executor for the
  UI payloads until `TransparentUi` phase ownership and UI render pass execution
  are moved out.

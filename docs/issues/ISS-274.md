## Description
Bevy `VolumetricFogPlugin::build` embeds `volumetric_fog.wgsl`, initializes
`FogAssets`, initializes `SpecializedRenderPipelines<VolumetricFogPipeline>`,
and initializes `VolumetricFogUniformBuffer`.

## Design
Classify these resource and asset initialization anchors against mgstudio's
`pbr/volumetric_fog` implementation. Fix local public facade or lifecycle
drift in this slice when possible.

## Acceptance Criteria
- [x] Embedded WGSL registration is classified.
- [x] `FogAssets` plane/cube mesh construction and resource ownership are
      classified.
- [x] Pipeline and uniform-buffer resource initialization is classified.
- [x] Remaining partial/facade anchors have follow-up ISS or direct fixes.

## Notes
- 2026-07-05: Split from ISS-237 so resource initialization can be audited
  before schedule placement.
- 2026-07-09: Fixed the resource-owner drift found by this audit. Mgstudio now
  creates the Bevy plane/cube fog hull mesh handles in the main world like
  Bevy, then stores `FogAssets`, `VolumetricFogPipeline`, and
  `VolumetricFogUniformBuffer` in the RenderApp world instead of the main
  world. The volumetric fog render execute path now reads fog hull handles from
  the render world, matching Bevy's `Res<FogAssets>` render-world ownership.
  The embedded WGSL registration remains in `VolumetricFogPlugin::build`, and
  actual pipeline specialization remains tracked by ISS-279 and ISS-280.
  Verified with `moon -C mgstudio-engine test --release pbr/volumetric_fog`,
  `moon -C mgstudio-engine test --release
  pbr/volumetric_fog_execute_wbtest.mbt`, `moon -C mgstudio-engine check
  --target native`, `moon -C mgstudio-engine fmt`, and `moon -C
  mgstudio-engine info`.

## Close Notes
Closed after moving the resource initialization anchors for this slice to the
RenderApp world and updating focused tests to assert that ownership directly.

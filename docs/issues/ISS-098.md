# ISS-098: Expose Bevy binding-array capability checks through wgpu_mbt

## Description
Bevy gates PBR binding arrays with
`binding_arrays_are_usable(RenderDevice, RenderAdapter)`, which checks adapter
info, render-device limits, and the device features
`TEXTURE_BINDING_ARRAY` plus
`SAMPLED_TEXTURE_AND_STORAGE_BUFFER_ARRAY_NON_UNIFORM_INDEXING`.
Clustered decals are then gated by `clustered_decals_are_usable`, which
currently delegates to the binding-array gate plus the clustered-decals feature.

`wgpu_mbt@0.14.3` now exposes the feature, limit, adapter-info, and
device-request APIs needed for this source owner. Mgstudio can source-match the
real capability gate instead of forcing the capability on or keeping the gate
globally disabled.

## Design
Do not hard-code binding-array support and do not keep local shader or renderer
fallbacks. Mgstudio should port Bevy's capability gate directly:

- render-device feature query for `TEXTURE_BINDING_ARRAY`;
- render-device feature query for
  `SAMPLED_TEXTURE_AND_STORAGE_BUFFER_ARRAY_NON_UNIFORM_INDEXING`;
- render-device limit query for `max_storage_textures_per_shader_stage`;
- adapter info access sufficient for the Bevy Adreno exclusion;
- device-request support for the required native features when available.

## Acceptance Criteria
- [x] `wgpu_mbt` exposes the feature, limit, adapter-info, and device-request
      APIs needed to implement Bevy's `binding_arrays_are_usable` gate.
- [x] Mgstudio computes `binding_arrays_are_usable` from the real device and
      adapter instead of using a fixed default.
- [x] Mgstudio computes `clustered_decals_are_usable` from the binding-array
      gate and the clustered decal feature flag.
- [x] `examples/3d/clustered_decal_maps` can enable Bevy's clustered decal
      shader path only on adapters that actually support the required
      capability.

## Notes
- 2026-06-13: Enabling clustered decal shader defs without the real feature
  gate made the native run log report unsupported
  `TEXTURE_AND_SAMPLER_BINDING_ARRAY` capability and invalid
  `mgstudio_mesh3d_binding_arrays_bgl` bind groups. This confirmed that the
  local default must remain disabled until the upstream capability API exists.
- 2026-06-13: Filed upstream as
  https://github.com/moonbit-community/wgpu-mbt/issues/27.
- 2026-06-13: Mgstudio now keeps both the PBR runtime capability bits and the
  renderer default mesh-view layout disabled for clustered decal binding arrays.
  `examples/3d/clustered_decal_maps` captures a non-black plane with an empty
  run log; decals remain absent until the upstream capability gate can be
  implemented.
- 2026-06-16: The symbol audit for `examples/3d/clustered_decals` found the
  same capability dependency. Exact parity must wait for the real binding-array
  gate, but the current proxy-mesh path is a local approximation tracked by
  ISS-106.
- 2026-06-22: Rechecked against `wgpu_mbt@0.14.3`. The dependency now exposes
  texture binding-array, non-uniform indexing, storage texture limit, adapter
  info, and device-request support. Mgstudio requests the available binding
  array features at device creation and computes the runtime gate from real
  device and adapter data, including Bevy's Adreno <= 610 exclusion.

## Close Notes
Closed on 2026-06-22. The external blocker has been resolved by
`wgpu_mbt@0.14.3`, and mgstudio now uses the real device/adapter capability
gate. Remaining clustered-decal source/visual parity work is local parity work
tracked separately, not this dependency blocker.

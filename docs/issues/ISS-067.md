# ISS-067: Unblock Bevy atmosphere multiscattering compute dispatch on native Metal

## Metadata
- Type: bug
- Status: closed
- Priority: 0
- Labels: external, wgpu_mbt, pbr, atmosphere, compute, metal
- Assignee: unassigned
- Created: 2026-06-11
- Updated: 2026-07-01
- External ref: https://github.com/moonbit-community/wgpu-mbt/issues/26

## Description
Bevy's `bevy_pbr/src/atmosphere/multiscattering_lut.wgsl` compute shader is
required for source-level atmosphere parity. In mgstudio through
`Milky2018/wgpu_mbt@0.14.2`, the multiscattering compute pipeline and bind
group can be created successfully, but dispatching the shader on macOS native
prevents the atmosphere example from producing the engine-native RGBA8 capture
blob. The app process remains alive until the capture wrapper kills it, and the
run log is empty.

## Design
Do not replace Bevy's shader with a local approximation and do not fake the
multiscattering LUT. Keep ISS-065 blocked at the multiscattering dispatch
subtarget until the wgpu_mbt, wgpu-native, or Metal backend behavior is
understood and fixed. After the external blocker is resolved, restore the Bevy
`atmosphere_luts` dispatch shape and continue with sky-view, aerial-view, and
render-sky passes.

## Acceptance Criteria
- [x] The upstream blocker is resolved or a verified local API usage correction
      is identified.
- [x] Dispatching Bevy's exact `multiscattering_lut.wgsl` shader succeeds on

- [x] `examples/3d/atmosphere` produces a capture with the multiscattering

- [x] The `ISS-067` TODO in the renderer is removed and ISS-065 is unblocked.

## Notes
- 2026-06-11: Diagnostic captures showed that creating the multiscattering
  compute pipeline and bind group is not enough to fail the example: omitting
  dispatch allows a 1-frame capture to complete. Dispatching the Bevy shader
  stalls capture even when reduced to `dispatch_workgroups(1, 1, 1)`, so the
  current evidence points at shader execution on the native backend rather than
  pipeline creation, bind group validation, or the full 32x32 workload size.
- 2026-06-11: With the dispatch omitted and marked by the renderer TODO, the
  standard 90-frame atmosphere capture completes and its run log has no
  validation or fatal output. This confirms the blocker is isolated to the
  Bevy multiscattering shader dispatch subtarget, not the surrounding
  transmittance LUT, medium LUT, atmosphere bind group, or screenshot capture
  path.
- 2026-06-30: Rechecked after updating to `wgpu_mbt@0.14.6`. Mgstudio still
  contains the `TODO(ISS-067)` path that releases the multiscattering bind
  group without dispatching Bevy's multiscattering LUT shader, so the issue
  cannot be considered resolved by the dependency update alone.
- 2026-06-30: The upstream `wgpu-mbt` repository issue
  moonbit-community/wgpu-mbt#26 is closed. The remaining action is local:
  restore Bevy's multiscattering dispatch path and validate
  `examples/3d/atmosphere` against `wgpu_mbt@0.14.6`.
- 2026-07-01: Fresh mgstudio-vs-Bevy capture confirms this is still a runtime

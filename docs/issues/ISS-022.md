# ISS-022: Restore Bevy source-owner boundaries for non-faithful ports

## Description
Some mgstudio modules contain Bevy-derived behavior but do not preserve Bevy's
source-owner boundaries. The clearest case is `mgstudio-engine/sprite/render2d.mbt`,
which is 9553 lines and combines camera, core 2D pipeline, sprite render,
mesh2d material, tilemap, UI overlay, shape conversion, bundles, extraction,
queueing, postprocess, and runtime draw execution in one local owner.

This is not source-level parity even when individual tests pass, because future
Bevy updates cannot be mapped cleanly to one MoonBit owner and runtime bugs can
cross module boundaries invisibly.

## Design
Use Bevy source files as the unit of ownership. Split MoonBit packages and files
to match Bevy's owners as closely as the language allows, then delete legacy
facades and monolithic execution paths. Do not keep compatibility wrappers whose
only purpose is to preserve the old `sprite/render2d.mbt` shape.

## Acceptance Criteria
- [ ] Every known child issue for non-faithful source-owner topology is closed, deferred with a concrete language blocker, or replaced by a more specific issue.
- [ ] `sprite_render/*`, `ui_render/*`, `core_pipeline/core_2d/*`, `camera/*`, and `sprite/*` contain real owner implementations instead of delegating back to a shared render2d monolith.
- [ ] `docs/ROADMAP_CHECKLIST.md` no longer gives completion credit for code that exists only as a facade over a non-Bevy-shaped owner.
- [ ] Representative 2D examples still pass their visual gates after owner boundaries are restored.

## Description
The `volumetric_fog` skybox uses
`environment_maps/pisa_specular_rgb9e5_zstd.ktx2`. A loaded image asset alone
does not prove Bevy parity: mgstudio must decode it with the expected format,
layer count, mip count, and cube texture view used by the skybox bind group.

## Design
Audit Bevy's KTX2/RGB9E5 environment-map loading expectations and the mgstudio
asset/renderer texture path. Prefer runtime white-box evidence that the real
example asset reaches the renderer as a cube view consumed by the skybox bind
group. Do not replace the asset or convert it to a different container.

## Acceptance Criteria
- [x] The Bevy asset path and checked-in mgstudio asset bytes are compared.
- [x] Mgstudio's KTX2 decode path is proven to create a six-layer cubemap with
      the expected renderer texture view dimension and sample view.
- [x] The skybox bind group is proven to consume that cubemap view, or a
      precise source-owner divergence is recorded.

## Close Notes
Closed on 2026-07-05 by auditing and testing the Bevy Pisa specular cubemap
asset path through mgstudio's KTX2 decoder, renderer cube texture upload, and
the real `examples/3d/volumetric_fog` skybox bind-group gate.

Bevy source anchors:
- `bevy/examples/3d/volumetric_fog.rs` loads
  `environment_maps/pisa_specular_rgb9e5_zstd.ktx2` into `Skybox.image`.
- `bevy/crates/bevy_core_pipeline/src/skybox/mod.rs::prepare_skybox_bind_groups`
  consumes the loaded `GpuImage.texture_view` and rejects images whose
  `texture_view_descriptor.dimension` is not `TextureViewDimension::Cube`.
- `bevy/crates/bevy_image/src/ktx2.rs` maps KTX2
  `E5B9G9R9_UFLOAT_PACK32` to `TextureFormat::Rgb9e5Ufloat`.

Mgstudio implementation fragments:
- `mgstudio-engine/asset/host_io.mbt::ktx2_decode_2d_payload` reads KTX2
  `layer_count * face_count`, marks `face_count > 1` as cube, decodes all mip
  levels, and returns the `RGB9_E5_UFLOAT` format.
- `mgstudio-engine/asset/host_io.mbt::load_texture_bytes_with_container`
  routes `payload.is_cube && payload.slice_count == 6` to
  `asset_texture_backend_create_texture_cube_with_format`.
- `mgstudio-engine/render/renderer/texture.mbt::GpuBackend::create_texture_cube_with_format`
  creates a 2D texture with six array layers and a
  `TEXTURE_VIEW_DIMENSION_CUBE` sample view stored as `sample_view`.
- `mgstudio-engine/render/renderer/gpu_skybox.mbt::GpuBackend::prepare_skybox_bind_group`
  refuses to create a skybox bind group unless the texture has
  `texture.sample_view is Some(cube_view)`, then binds that cube view at
  binding 0.

Evidence:
- `shasum -a 256 bevy/assets/environment_maps/pisa_specular_rgb9e5_zstd.ktx2 mgstudio-engine/assets/environment_maps/pisa_specular_rgb9e5_zstd.ktx2`
  produced the same hash for both files:
  `b5eddbb37839319b5604a7bd97c6916e9351f73d872138d91b0917169285e42d`.
  Both files are 6,792,052 bytes.
- Added `asset host io: bevy pisa specular environment map decodes as rgb9e5
  cubemap`, proving the real asset decodes as `512x512`, `is_cube=true`,
  `slice_count=6`, `levels.length=9`, level 0 size `6291456`, and
  `TEXTURE_FORMAT_RGB9_E5_UFLOAT`.
- Added `renderer: rgb9e5 cube texture upload creates a cubemap sample view`,
  proving renderer cube upload stores a `sample_view` for RGB9E5 cube textures.
- Existing `volumetric_fog: camera render entity prepares Bevy skybox draw
  state` proves the real example's render entity obtains a skybox bind group
  and reaches `draw_prepared_skybox`; because `prepare_skybox_bind_group`
  returns `None` without `texture.sample_view`, this proves the real example
  uses a cubemap sample view.

Validation:
- `moon -C mgstudio-engine test asset --target native --release --filter 'asset host io: bevy pisa specular environment map decodes as rgb9e5 cubemap'`
  passed `1/1`.
- `moon -C mgstudio-engine test render/renderer --target native --release --filter 'renderer: rgb9e5 cube texture upload creates a cubemap sample view'`
  passed `1/1`; duplicate `-lobjc` linker warnings were emitted.
- `moon -C mgstudio-engine test examples/3d/volumetric_fog --target native --release --filter 'volumetric_fog: camera render entity prepares Bevy skybox draw state'`
  passed `1/1`; duplicate `-lobjc` and `-lz` linker warnings were emitted.

Conclusion: the Pisa cubemap texture-view path is classified as complete for
this audit and is not a remaining candidate root cause for the current
`examples/3d/volumetric_fog` near-grey visual failure. Brightness, exposure,
and view-input evidence remains tracked by ISS-353.

## Description

`examples/3d/lightmaps` (Cornell Box lit exclusively by baked lightmaps,
ambient zero) renders BLACK except the emissive ceiling quad and the
clear-color margins: the lightmap contribution never reaches the shaded
result. Wall samples that should be the red/green/white lightmapped
surfaces read ~(1,0,0)/(1,1,1) (dither noise around zero) where both the
old committed reference and pinned Bevy show (108,3,2)-class walls.

NOT caused by the ISS-483 tonemapping slice: a bisect capture at
`908dad3a3` (the commit before the tonemapping work) shows the identical
black box ((0,0,0) at all sampled wall points — no dither yet, hence
exact zero). The old committed reference is nearly Bevy-perfect
(mean_abs_rgb 2.69 vs a fresh pinned-Bevy frame-90 capture), so the
feature worked when that reference was captured; the break lies between
that reference's vintage and `908dad3a3`. Same silent-breakage family as
ISS-482 (anisotropy) — quite possibly the same owner; the run log is
clean, nothing crashes, the contribution is just zero.

## Suspect surface

The lightmap data path from `Lightmap` component extraction through slab
allocation to the draw payload (`lightmap_texture_id`, slab index/uv
rect, `LIGHTMAP` define) — the same feature-variant plumbing window as
ISS-482's `MaterialDrawData3d` refactor suspects. Needs staged probes
(extract -> prepare -> draw payload -> define set) per the diagnose
discipline; no root-cause claim yet.

## Description
The near-black reference refresh pass found four visual 3D examples whose existing `reference.png` files are unusable and whose standard native capture runs do not produce `MGSTUDIO_PARITY_CAPTURE_RGBA8_BLOB`: `examples/3d/blend_modes`, `examples/3d/clustered_decals`, `examples/3d/specular_tint`, and `examples/3d/wireframe`.

## Design
Diagnose the capture boundary before editing rendering behavior. These examples build and launch under `p0_visual_capture_native.sh`, but both the normal 90-frame capture and the fresh-process 1-frame retry exit without a blob and with empty run logs. Compare their app setup, camera/render graph participation, and screenshot capture hook against nearby 3D examples that now capture correctly, such as `examples/3d/motion_blur`.

Do not replace these references with hand-made images or unrelated screenshots.

## Notes
- 2026-06-10: Reproduced with `MGSTUDIO_PARITY_CAPTURE_DELAY_FRAMES=90 MGSTUDIO_PARITY_RUN_TIMEOUT_SECONDS=240 mgstudio-engine/scripts/p0_visual_capture_native.sh`. All four examples failed with capture exit code 5 after the built-in retry with `delay_frames=1`; their per-example run logs under `/tmp/mgstudio_near_black_recapture/*.run.log` were empty.
- 2026-06-10: Updated `mgstudio-engine/scripts/p0_visual_capture_native.sh` so the standard capture harness also accepts the winit screenshot PNG path as a valid output, not only the renderer parity RGBA8 blob. This fixes the harness for a known static control case: `examples/3d/3d_scene` now completes with `capture_mode: "window-screenshot-png"` and passes `visual_image_sanity.py`.
- 2026-06-10: The four ISS-062 examples still fail after the capture harness improvement. `examples/3d/blend_modes` also fails when run directly with `MGSTUDIO_SCREENSHOT_PATH=/tmp/mgstudio_blend_modes_debug_path.png MGSTUDIO_SCREENSHOT_EXIT_ON_SAVE=1 MGSTUDIO_SCREENSHOT_FRAME=1`; no PNG is produced and logs remain empty until the process is terminated. Retried `examples/3d/clustered_decals`, `examples/3d/specular_tint`, and `examples/3d/wireframe` with the updated standard capture script; all still exit with capture code 5.
- 2026-06-10: The `blend_modes` and `clustered_decals` failures were caused by later PBR main-pass reopens dropping the camera MSAA sample count. The first opaque pass used the correct sample count, but transmissive/transparent/wireframe follow-up passes defaulted to single-sample depth attachments while reusing multisampled color attachments. Passing the camera `msaa_sample_count` through every reopened pass fixes the wgpu sample-count validation failure and both examples now capture nonblank references.
- 2026-06-10: The `specular_tint` failure exposed a default-material descriptor bug. `material_descriptor=None` means the default PBR material pipeline, not an explicit no-material-layout descriptor; treating it as empty created an invalid `mgstudio_mesh3d_empty_material_bg`. The material bind-group path now only skips group 3 for an explicit descriptor with no material layout, and `specular_tint` now captures a nonblank reference.
- 2026-06-10: The `wireframe` failure was a PBR vertex-buffer layout mismatch in the local wireframe approximation. Generated line-list meshes were uploaded through the generic sprite/render2d mesh path with a compact 20-byte vertex layout, while the default PBR pipeline validated them as the full 80-byte 3D layout, producing `Vertex 72 extends beyond limit 18`. Wireframe-generated 3D line-list meshes are now uploaded with `host_gpu_create_mesh3d_xyznuvrgba`, matching the PBR pipeline's vertex ABI. This restores capture but does not complete Bevy `Wireframe3d` phase parity; that follow-up is tracked by ISS-064.

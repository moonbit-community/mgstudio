## Description
`mgstudio-engine/mesh/primitives/dim2.mbt` now routes primitive asset authoring
through the Bevy-shaped `Meshable -> Mesh` path for the `examples/2d/2d_shapes`
gate, but the owner has not yet been audited symbol by symbol against
`bevy/crates/bevy_mesh/src/primitives/dim2.rs`.

The file still contains local helper surfaces such as `Mesh2dGeometry` conversion
helpers and ring helper traits. These may be legitimate MoonBit implementation
fragments, but they must not be counted as complete parity until every Bevy
source-shape anchor has been classified and every local-only helper has been
removed, rehomed, or justified as private implementation detail.

## Design
Build a symbol inventory from Bevy `dim2.rs` first, then map each Bevy struct,
enum, builder, trait impl, method, constant, conversion, and test-relevant
behavior to the MoonBit implementation. Do not infer completion from visual
success in `2d_shapes`; each source symbol must be marked complete, facade,
partial, or blocked.

## Acceptance Criteria
- [ ] Inventory every in-scope symbol from `bevy/crates/bevy_mesh/src/primitives/dim2.rs`.
- [ ] Map each inventory item to the corresponding `mgstudio-engine/mesh/primitives/dim2.mbt` symbol or record why it is intentionally out of scope.
- [ ] Remove or make private any local `Mesh2dGeometry` / ring helper surface that is not a Bevy-equivalent public API.
- [ ] Add focused tests for primitive mesh topology, vertex attributes, indices, winding, and UV behavior where Bevy has source-level expectations.
- [ ] Validate with `moon -C mgstudio-engine test mesh/primitives --release`, `moon -C mgstudio-engine check --target native`, `moon -C mgstudio-engine fmt`, and `moon -C mgstudio-engine info`.

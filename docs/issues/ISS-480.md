## Description

`Text2d` runs and renders correctly today (`examples/2d/text2d` shows anchors,
wrapping, transforms and per-glyph layout), but every piece of it lives in the
wrong owner. Bevy's ownership:

| Bevy owner | owns |
| --- | --- |
| `bevy_sprite/src/text2d.rs` | `Text2d`, `Text2dShadow`, `update_text2d_layout`, `calculate_bounds_text2d` |
| `bevy_sprite_render/src/text2d/mod.rs` | `extract_text2d_sprite` |
| `bevy_text` | the pipeline proper: buffers, spans, fonts, glyph layout -- and no sprite knowledge at all |

mgstudio has all of it inside `text/`, and the dependency edge is inverted:
`text` imports `sprite` (for `Anchor`) and `sprite_render` (for the render2d
extract/queue surface), while Bevy's `bevy_sprite` depends on `bevy_text` and
`bevy_text` knows nothing of sprites. `sprite_render/text2d/top.mbt` is a
41-line facade forwarding back into `@text`.

## Inventory

- `text/ecs_keys.mbt` (1727 lines): `Text2d`, `Text2dShadow`, their keys and
  `Component` impls, `Text2dBundle`, the rerender-comparison helpers, and the
  ECS bridge queries that assemble bundles from entities.
- `text/pipeline.mbt` (2281 lines): the text pipeline proper, plus 29 uses of
  `@sprite_render.*` -- the render2d extraction and queueing
  (`render2d_push_sprite_uv_scissor_batch`, cull context, extract/prepare/queue
  set registrations) that Bevy has in `bevy_sprite_render/src/text2d/mod.rs`.
- `text/state.mbt` (1324 lines): layout state; 4 `@sprite_render.*` uses.
- `text/components.mbt` (875 lines): shared text components (spans, fonts);
  mostly true `bevy_text` material.
- `text/lib.mbt`: plugin wiring.
- External consumers of `@text.Text2d`/keys: dozens of examples plus UI code;
  any move must keep `@text` re-exports until the final step, then migrate
  callers.

## Phased plan

Each phase must end green: `moon check` zero warnings, text/sprite/sprite_render
tests passing, and `examples/2d/text2d` byte-identical to its pre-phase capture
(the visual output must not change at any point -- this is a pure ownership
move).

1. **Data model.** `Text2d`, `Text2dShadow`, keys, `Component` impls and the
   pure comparison helpers move to `sprite/text2d.mbt`. `text` re-exports
   through its existing `sprite` import so all consumers keep compiling. The
   `@sprite.Anchor` uses in the bundle move with it, deleting that reason for
   the `text -> sprite` edge.
2. **Layout systems.** `update_text2d_layout` and `calculate_bounds_text2d`
   equivalents (currently inside `text/state.mbt`/`ecs_keys.mbt` bridge code)
   move to `sprite/text2d.mbt`, keeping their calls into the `text` pipeline --
   the direction Bevy has (`bevy_sprite -> bevy_text`).
3. **Render extraction.** The `@sprite_render` consumers inside
   `text/pipeline.mbt` and `text/state.mbt` move into `sprite_render/text2d/`,
   replacing the forwarding facade with the real owner. This is the largest
   slice and removes `text -> sprite_render`.
4. **Edge removal.** Drop `text -> sprite` and `text -> sprite_render` from
   `text/moon.pkg`; migrate external `@text.Text2d` consumers to
   `@sprite.Text2d` (mechanical sweep, ISS-476-style); delete the re-exports.

## Progress

Phase 1 complete: `Text2d` (struct, constructors), `Text2dShadow` (struct,
constructors, `with_offset`/`with_color`, Bevy's `(4, -4)`/black default), both
ECS keys and both `Component` impls now live in `sprite/text2d.mbt`. `text`
re-exports the types and re-binds the keys, so all consumers compile
unchanged. The keys register once, in `sprite`, under the original debug
names. Gate: zero warnings, text/sprite/sprite_render tests 30/30,
`examples/2d/text2d` byte-identical to the pre-phase capture.

The `@sprite.Anchor` bundle uses stay in `text` for now; the bundle itself is
phase 2/3 material.

## Acceptance Criteria

- [ ] `examples/2d/text2d` byte-identical after every phase.

## Description

`Text2d` runs and renders correctly today (`examples/2d/text2d` shows anchors,
wrapping, transforms and per-glyph layout), but every piece of it lives in the
wrong owner. Bevy's ownership:

| Bevy owner | owns |
| --- | --- |
| `bevy_sprite/src/text2d.rs` | `Text2d`, `Text2dShadow`, `update_text2d_layout`, `calculate_bounds_text2d` |
| `bevy_sprite_render/src/text2d/mod.rs` | `extract_text2d_sprite` |
| `bevy_text` | the pipeline proper: buffers, spans, fonts, glyph layout -- and no sprite knowledge at all |

mgstudio has all of it inside `text/`, and the dependency edge is inverted:
`text` imports `sprite` (for `Anchor`) and `sprite_render` (for the render2d
extract/queue surface), while Bevy's `bevy_sprite` depends on `bevy_text` and
`bevy_text` knows nothing of sprites. `sprite_render/text2d/top.mbt` is a
41-line facade forwarding back into `@text`.

## Inventory

- `text/ecs_keys.mbt` (1727 lines): `Text2d`, `Text2dShadow`, their keys and
  `Component` impls, `Text2dBundle`, the rerender-comparison helpers, and the
  ECS bridge queries that assemble bundles from entities.
- `text/pipeline.mbt` (2281 lines): the text pipeline proper, plus 29 uses of
  `@sprite_render.*` -- the render2d extraction and queueing
  (`render2d_push_sprite_uv_scissor_batch`, cull context, extract/prepare/queue
  set registrations) that Bevy has in `bevy_sprite_render/src/text2d/mod.rs`.
- `text/state.mbt` (1324 lines): layout state; 4 `@sprite_render.*` uses.
- `text/components.mbt` (875 lines): shared text components (spans, fonts);
  mostly true `bevy_text` material.
- `text/lib.mbt`: plugin wiring.
- External consumers of `@text.Text2d`/keys: dozens of examples plus UI code;
  any move must keep `@text` re-exports until the final step, then migrate
  callers.

## Phased plan

Each phase must end green: `moon check` zero warnings, text/sprite/sprite_render
tests passing, and `examples/2d/text2d` byte-identical to its pre-phase capture
(the visual output must not change at any point -- this is a pure ownership
move).

Phase order revised after phase 1: the original plan put the layout systems
(phase 2) before the render extraction, but the layout systems must call back
into the `text` pipeline (`sprite -> text`, Bevy's direction), and MoonBit
forbids import cycles -- so that move can only land atomically with dropping
`text -> sprite`, which in turn needs the re-exports and every remaining
`Text2d`/`Anchor` reference out of `text` first. The extraction move has no
such constraint (`sprite_render/text2d -> text` is already legal), so it goes
first and the layout move becomes the final atomic edge flip.

1. **Data model.** `Text2d`, `Text2dShadow`, keys, `Component` impls move to
   `sprite/text2d.mbt`; `text` re-exports so all consumers keep compiling.
2. **Render extraction.** `text_render_system` (the `extract_text2d_sprite`
   equivalent), both queue systems, the slice-batch machinery, the render-side
   runtime state/diagnostics, the render set definitions and the render-app
   plugin registration move from `text/pipeline.mbt` into
   `sprite_render/text2d/top.mbt`, replacing the forwarding facade with the
   real owner and removing `text -> sprite_render` (and `text -> render`).
3. **Consumer sweep.** Migrate external `@text.Text2d`/`Text2dShadow`/key
   consumers to `@sprite` (mechanical, ISS-476-style) while the re-exports
   still exist -- pure caller change.
4. **Layout systems + edge flip.** `update_text2d_layout` and
   `calculate_bounds_text2d` equivalents (the ECS bridge in
   `text/state.mbt`/`ecs_keys.mbt`) and `Text2dBundle` move to
   `sprite/text2d.mbt`, calling into the `text` pipeline; in the same commit
   the `text` re-exports are deleted and `text -> sprite` flips to
   `sprite -> text` (no cycle at any commit boundary).

   Execution notes (scoped during the groundwork step):
   - `text` gains a sprite-free spawn boundary: a `pub(all)` spawn-data
     struct mirroring the de-sprited `TextInstance` head fields (content,
     font, color, decorations, layout, bounds, line height, hinting,
     `TextShadow?`, transform, layers, `anchor : @math.Vec2`, y_axis,
     no_frustum_culling, logical_viewport_size) plus
     `text_spawn_data(data) -> TextHandle` that keeps the id/index/cull
     bookkeeping in `text`. `Text2dBundle::spawn` (in `sprite`) converts.
   - `Text2dBundle` + builders + `text_bundle` + the sprite-typed
     `text_set_anchor`/`text_set_shadow` veneers and
     `text_shadow_opt_from_2d` move to `sprite/text2d.mbt`; `text` keeps
     `Vec2`/`TextShadow`-typed setters.
   - The 2d half of `text/ecs_keys.mbt` (bundle assembly from
     `@sprite.ecs_key_text2d` queries, `anchor_eq`/`text2d_eq`/shadow eq,
     rerender diffing, required-components registration for `Text2d`) moves
     to `sprite/text2d.mbt`; the UI `Text` bridge stays. The 2d sync system
     registration moves to a sprite-side plugin hook (Bevy:
     `update_text2d_layout` is registered by `SpritePlugin`).
   - Re-exports die: `@text.Text2d`, `@text.Text2dShadow`, both key
     re-binds, and the `text_bundle` helper; the remaining
     `@text.Text2dBundle`/`@text.text_bundle` consumers (roughly 50 example
     files skipped by phase 3) sweep to `@sprite`.
   - `text/moon.pkg` drops `sprite`; `sprite/moon.pkg` gains `text`.

## Progress

Phase 1 complete: `Text2d` (struct, constructors), `Text2dShadow` (struct,
constructors, `with_offset`/`with_color`, Bevy's `(4, -4)`/black default), both
ECS keys and both `Component` impls now live in `sprite/text2d.mbt`. `text`
re-exports the types and re-binds the keys, so all consumers compile
unchanged. The keys register once, in `sprite`, under the original debug
names. Gate: zero warnings, text/sprite/sprite_render tests 30/30,
`examples/2d/text2d` byte-identical to the pre-phase capture.

The `@sprite.Anchor` bundle uses stay in `text` for now; the bundle itself is
phase 4 material.

Phase 2 complete: `sprite_render/text2d/top.mbt` is now the real owner --
`text_render_system` (walks `@text.text_instances()` and extracts span
background/underline/strikethrough quads plus glyph slice batches, resolving
per-span styling the way Bevy's `text_colors`/`decoration_query` lookups do),
both queue systems, the `OverlaySpriteUvScissorSlices` batch machinery, the
render-side runtime state and diagnostics, the render set definitions
(same name strings, so set identity is unchanged), and a new
`Text2dRenderPlugin` registered in `DefaultPlugins` right after `TextPlugin`.
The `text_set_sync_ecs -> render_prepare` ordering edge moved to the render
plugin's side (`after=` instead of `before=`), same constraint. `text` exposes
its data surface for this: `TextInstance`/`TextSpanInstance` went
`priv -> pub` (readonly) with a `text_instances()` accessor -- the retained
analog of the public `bevy_text` component data Bevy's extractor queries --
plus `pub` `text_pipeline_safe_scale_factor`. `text/moon.pkg` dropped
`sprite_render` AND `render` (the render-app wiring left with the extraction;
`render` remains as a wbtest-only import). The old facade's
`text_runtime_plugin` forward died with the facade (nothing imported it).
The render-gating halves of two `ecs_runtime_wbtest` tests relocated to
`sprite_render/text2d/render_gating_test.mbt` via the retained pub API; the
bridge-sync assertions stayed. `many_text2d` now reads the four render
diagnostics from `@sprite_render_text2d`. Gates: `moon check` zero warnings;
text 19/19, sprite 9/9, sprite_render 2/2, text2d 1/1 tests;
`examples/2d/text2d` AND `examples/ui/scroll_and_overflow/scroll` (UI-text
path) byte-identical to pre-phase captures.

Inventory corrections found during phase 2: the `sprite_render/text2d` facade
had zero importers (dead code -- `DefaultPlugins` wired `@text.TextPlugin`
directly), and `text/state.mbt` had no `@sprite_render` uses (all 29 were in
`pipeline.mbt`).

Phase 3 complete: 114 `@text.Text2d`/`Text2dShadow`/`ecs_key_text2d*`
references across 33 example files (plus the relocated render-gating test)
swept to `@sprite.*`; 14 example `moon.pkg`s gained the `sprite` import and
one dropped a now-unused `text` import. `Text2dBundle` consumers deliberately
still point at `@text` -- the bundle moves in phase 4. Gate: zero warnings,
text2d package test green, `examples/2d/text2d` byte-identical.

Phase 4 groundwork complete: `TextInstance` is now sprite-free, matching
`bevy_text`'s ignorance of sprite types -- `text : Text2d` became
`content : String`, `anchor : @sprite.Anchor` became `anchor : @math.Vec2`
(the `as_vec` value; conversion happens at the retained-API boundary), and
`shadow : Text2dShadow?` became the text-owned `TextShadow?` (identical
offset/color fields and default). The extractor reads the vec directly, the
way Bevy's `extract_text2d_sprite` computes from `anchor.as_vec()`. What
still holds the `text -> sprite` edge: `Text2dBundle` (+ builders and the
sprite-typed `text_spawn`/`text_set_anchor`/`text_set_shadow` boundary), the
2d ECS bridge in `ecs_keys.mbt`, and the re-exports -- all moving in the
phase-4 edge flip. Gate: zero warnings, text 19/19 + text2d tests green,
`examples/2d/text2d` and the UI scroll example byte-identical.

Phase 4 complete -- the edge is flipped. `text` now owns a sprite-free
boundary: `TextSpawnData` (pub(all), the de-sprited bundle mirror) +
`text_spawn_data`, with `text_set_anchor_vec`/`text_set_text_shadow` as the
text-typed setters. `sprite/text2d.mbt` owns `Text2dBundle` (+ builders,
`text_spawn`, `text_bundle`, and the `text_set_anchor`/`text_set_shadow`
veneers that convert at the boundary), the required-components registration
(Bevy's `#[require(...)]` list on `Text2d`), and the full 2d ECS bridge
(`text_sync_ecs_system` -- the `update_text2d_layout` equivalent -- plus its
entry stores, per-field diffing and sync diagnostics), registered by
`SpritePlugin` in `@text.text_set_sync_ecs` (Bevy: `SpritePlugin` registers
`update_text2d_layout`). The UI bridge stayed in `text` and now builds
`TextSpawnData` directly, which also removed the old
`TextShadow -> Text2dShadow -> TextShadow` round trip. The shared world-reset
stays behind `text`'s tracker (`prepare_text_runtime_world`); the sprite
bridge tracks its own world id for its own stores, so reset order is
independent. `text`'s per-field eq helpers and bridge utilities went pub (the
public PartialEq surface of `bevy_text` types); six 2d-bridge wbtests moved
to `sprite/text2d_ecs_wbtest.mbt`; 50 `@text.Text2dBundle`-family references
across 36 example files swept to `@sprite`. `text/moon.pkg` imports neither
`sprite` nor `sprite_render`; `sprite/moon.pkg` imports `text`, matching
Bevy's `bevy_sprite -> bevy_text` direction. Gate: zero warnings; text
13/13, sprite 15/15, sprite_render/text2d, ui 61/61 tests green;
`examples/2d/text2d`, the UI scroll example, AND the mixed
`examples/animation/easing_functions` (Text2d + UI text in one app,
stash-pair baseline) byte-identical.

Known deviation recorded in the new owner file: Bevy splits UI text extraction
into `bevy_ui_render` (`extract_text_sections`); mgstudio's extractor is fused
over Text2d and UI text instances, so the UI half is co-located in
`sprite_render/text2d` until that split lands.

## Description
`mgstudio-engine/examples/3d/rect_light/main.mbt` only contains a Bevy source
anchor comment, so `bevy/examples/3d/rect_light.rs` is effectively unported.

The underlying runtime owner is also only partial. Mgstudio has a `RectLight`
component and shader-side WGSL for area lights, but the audit did not find
Bevy-shaped `ExtractedRectLight`, `GpuRectLight`, `MAX_RECT_LIGHTS`,
`SyncComponent<PbrPlugin> for RectLight`, or CPU upload into
`Lights.rect_lights`. This means the shader has consumers for rect lights, but
the ECS/render extraction path needed to feed them is missing.

ISS-017 remains responsible for exact Bevy LTC LUT asset/resource
initialization. This issue covers RectLight's component sync, extraction, GPU
light upload, and the `rect_light` example source shape.

## Design
Port the Bevy source owners directly:

- Restore `bevy_light/src/rect_light.rs` semantics, including required
  transform/visibility/class ownership or a documented ECS limitation issue if
  required components cannot be expressed yet.
- Port the `PbrPlugin` RectLight sync owner from `bevy_pbr/src/lib.rs`.
- Add Bevy-shaped `ExtractedRectLight`, `GpuRectLight`, and `MAX_RECT_LIGHTS`
  CPU-side owners.
- Extract rect lights from `RectLight`, `GlobalTransform`, and
  `ViewVisibility`, using Bevy's effective width/height and
  `intensity / (effective_width * effective_height * PI)` calculation.
- Populate `gpu_lights.n_rect_lights` and `gpu_lights.rect_lights[index]`
  during view light preparation.
- Preserve Bevy's warning path when area light LUTs are unavailable, while
  keeping ISS-017 responsible for the actual LUT resource initialization.
- Implement `examples/3d/rect_light` from Bevy source: plugin setup,
  `FloorMaterial`, `RoughnessDisplay`, floor/sphere scene, two `RectLight`
  entities with `ShowLightGizmo`, free camera, UI text, `adjust_roughness`, and
  `toggle_gizmos`.

Do not approximate rect lights with point/spot lights, emissive meshes, or
hard-coded shader constants.

## Acceptance Criteria
- [ ] RectLight extraction creates an `ExtractedRectLight` equivalent from
      source-world `RectLight`, `GlobalTransform`, and `ViewVisibility`.
- [ ] CPU-side `GpuRectLight` packing and `MAX_RECT_LIGHTS = 8` match Bevy.
- [ ] View light preparation writes `n_rect_lights` and rect-light data consumed
      by `pbr_lighting.wgsl`.
- [ ] Area-light LUT resource use is wired to the Bevy-shaped binding path or
      explicitly blocked by ISS-017.
- [ ] `examples/3d/rect_light` contains the Bevy scene, systems, controls, UI,
      free camera, and gizmo toggle behavior.
- [ ] A new reference screenshot is captured after the example first renders
      real RectLight illumination.

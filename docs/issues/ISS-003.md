## Description
Transform propagation costs about `11.677 ms/frame` in the current
`many_foxes` profile. The dense path still pays generic component-column and
table-row lookup overhead while walking a large hierarchy.

## Design
Compare `mgstudio-engine/transform/systems.mbt` against the current Bevy
transform propagation source and port the traversal shape more directly. The
goal is a typed node-fetch traversal with cached entity row locations where
hierarchy maintenance can keep those locations valid.

Non-goals:

- Do not weaken change tracking semantics.
- Do not skip propagation for animated nodes just to reduce cost.
- Do not add compatibility paths for the old ECS payload model.

## Acceptance Criteria
- [ ] The transform traversal uses a typed node-fetch path instead of repeated generic storage lookup in the descendant inner loop.
- [ ] Root scan cost and descendant traversal cost are separately visible in the performance report.
- [ ] Cached child table-row locations are maintained by hierarchy changes or invalidated explicitly when they cannot be trusted.
- [ ] Unchanged computed `GlobalTransform` values do not mark rows changed unnecessarily.
- [ ] At `1000` foxes, transform propagation is reduced below `5 ms/frame` in the timeline profile or a follow-up issue documents the remaining blocker.
- [ ] Relevant transform tests pass with `--release`.

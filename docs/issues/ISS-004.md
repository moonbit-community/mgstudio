## Description
`mgstudio.animation.animate_targets` costs about `8.793 ms/frame`, and its
transform writes amplify downstream transform propagation and previous-transform
sync. The current system is typed, but its target mutation shape is not yet
close enough to Bevy's direct target-entity update path.

## Design
Read the current Bevy animation target evaluation code and port the ownership
and mutation flow as directly as MoonBit allows. Keep output semantics intact:
animations must still update transforms, morph weights, text colors, and events
where the source requires them.

## Acceptance Criteria
- [ ] `animate_targets` is split into player preparation, target iteration, curve sampling, target writes, and event emission spans.
- [ ] The system avoids rebuilding broad per-player prepared state when direct lookup can preserve source-equivalent semantics.
- [ ] Unchanged animation outputs avoid marking target components changed.
- [ ] The transform-write counter explains how many downstream transform updates are caused by animation each frame.
- [ ] At `1000` foxes, animation target evaluation is reduced below `4 ms/frame` or a follow-up issue documents the remaining blocker.
- [ ] Relevant animation tests pass with `--release`.

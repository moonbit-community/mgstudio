## Description
`bevy/examples/shader_advanced/custom_shader_instancing.rs` is a low-level
custom render path. Mgstudio currently approximates it with many ordinary mesh
entities, a shared material, local transform animation, and an extension
fragment shader path. That is not source-level parity.

The Bevy owner renders one mesh entity with `InstanceMaterialData`, extracts
that component into the render world, prepares a GPU instance vertex buffer,
queues a `Transparent3d` phase item with a specialized `CustomPipeline`, and
executes `DrawMeshInstanced`.

## Design
Port the Bevy owner directly. Keep the single source mesh entity and
per-instance data component. Use mgstudio's render-app, extraction, sync-world,
pipeline cache, mesh allocator, render mesh instances, and phase APIs where
they already match Bevy. If a required render command API is still missing,
add the missing Bevy-shaped owner instead of reusing material extension paths.

Do not keep the current ordinary-entity grid as a fallback or compatibility
path.

## Acceptance Criteria
- [ ] `examples/shader_advanced/custom_shader_instancing/main.mbt` removes the
      256 ordinary mesh entity approximation and local `animate_instances`
      system.
- [ ] The setup system spawns one cuboid `Mesh3d` entity with
      `InstanceMaterialData` containing Bevy's 10x10 instance positions,
      scales, and HSLA-derived linear colors.
- [ ] `NoFrustumCulling` is attached to the mesh entity and `NoIndirectDrawing`
      is attached to the camera for the same reasons as Bevy.
- [ ] `InstanceMaterialData`, `InstanceData`, and render-world sync/extraction
      follow Bevy's component ownership and clone semantics.
- [ ] `CustomMaterialPlugin` installs the extract component plugin, custom
      transparent draw command, `SpecializedMeshPipelines<CustomPipeline>`
      resource, render startup pipeline init, queue system, and prepare
      instance-buffer system in the Bevy-shaped render schedules.
- [ ] `CustomPipeline` specializes from the base mesh pipeline, swaps both
      vertex and fragment shaders to `shaders/instancing.wgsl`, and appends the
      instance-rate vertex buffer layout at shader locations 3 and 4.
- [ ] `prepare_instance_buffers` creates a vertex buffer from packed
      `InstanceData` with `VERTEX | COPY_DST` usage and stores `InstanceBuffer`
      on the render entity.
- [ ] `queue_custom` uses view key cache, render mesh instances, render assets,
      and transparent phase insertion with the same skip conditions and sorting
      data as Bevy.
- [ ] `DrawMeshInstanced` binds mesh vertex buffer 0, instance buffer 1,
      optional index buffer, and draws with instance count equal to
      `InstanceBuffer.length`.
- [ ] The standard native capture for
      `examples/shader_advanced/custom_shader_instancing` renders visible
      custom shader instancing content with no missing shader loader,
      validation, fatal, unsupported, panic, or abort output.

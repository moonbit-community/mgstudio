## Description
`bevy/examples/shader_advanced/custom_shader_instancing.rs` is a low-level
custom render path. Mgstudio currently approximates it with many ordinary mesh
entities, a shared material, local transform animation, and an extension
fragment shader path. That is not source-level parity.

The Bevy owner renders one mesh entity with `InstanceMaterialData`, extracts
that component into the render world, prepares a GPU instance vertex buffer,
queues a `Transparent3d` phase item with a specialized `CustomPipeline`, and
executes `DrawMeshInstanced`.

## Design
Port the Bevy owner directly. Keep the single source mesh entity and
per-instance data component. Use mgstudio's render-app, extraction, sync-world,
pipeline cache, mesh allocator, render mesh instances, and phase APIs where
they already match Bevy. If a required render command API is still missing,
add the missing Bevy-shaped owner instead of reusing material extension paths.

Do not keep the current ordinary-entity grid as a fallback or compatibility
path.

## Acceptance Criteria
- [x] `examples/shader_advanced/custom_shader_instancing/main.mbt` removes the
      256 ordinary mesh entity approximation and local `animate_instances`
      system.
- [x] The setup system spawns one cuboid `Mesh3d` entity with
      `InstanceMaterialData` containing Bevy's 10x10 instance positions,
      scales, and HSLA-derived linear colors.
- [x] `NoFrustumCulling` is attached to the mesh entity and `NoIndirectDrawing`
      is attached to the camera for the same reasons as Bevy.
- [ ] `InstanceMaterialData`, `InstanceData`, and render-world sync/extraction
      follow Bevy's component ownership and clone semantics.
- [ ] `CustomMaterialPlugin` installs the extract component plugin, custom
      transparent draw command, `SpecializedMeshPipelines<CustomPipeline>`
      resource, render startup pipeline init, queue system, and prepare
      instance-buffer system in the Bevy-shaped render schedules.
- [ ] `CustomPipeline` specializes from the base mesh pipeline, swaps both
      vertex and fragment shaders to `shaders/instancing.wgsl`, and appends the
      instance-rate vertex buffer layout at shader locations 3 and 4.
- [ ] `prepare_instance_buffers` creates a vertex buffer from packed
      `InstanceData` with `VERTEX | COPY_DST` usage and stores `InstanceBuffer`
      on the render entity.
- [ ] `queue_custom` uses view key cache, render mesh instances, render assets,
      and transparent phase insertion with the same skip conditions and sorting
      data as Bevy.
- [ ] `DrawMeshInstanced` binds mesh vertex buffer 0, instance buffer 1,
      optional index buffer, and draws with instance count equal to
      `InstanceBuffer.length`.
- [ ] The standard native capture for
      `examples/shader_advanced/custom_shader_instancing` renders visible
      custom shader instancing content with no missing shader loader,
      validation, fatal, unsupported, panic, or abort output.

## Notes
- 2026-06-19: `SpecializedMeshPipelines` now supports multi-buffer vertex
  layouts, so the specific `mesh vertex buffer + instance vertex buffer`
  descriptor shape is no longer blocked by the material specialization cache.
  The remaining work is the actual render owner and draw-command path.
- 2026-06-19: Implementation started against
  `bevy/examples/shader_advanced/custom_shader_instancing.rs`. The mgstudio
  mesh3d backend already receives specialized descriptors, but it only used
  `descriptor.vertex.buffers[0]` and only bound vertex buffer slot 0, so exact
  parity requires the native draw path to preserve and bind instance buffer
  slot 1.
- 2026-06-19: The example now uses one Bevy-shaped cuboid mesh entity with
  `InstanceMaterialData`, `NoFrustumCulling`, camera `NoIndirectDrawing`, a
  specialized `shaders/instancing.wgsl` descriptor, and a renderer-side
  instance vertex buffer bound at slot 1. The native capture renders the 10x10
  colored instanced cube grid and the current reference screenshot is saved at
  `mgstudio-engine/examples/shader_advanced/custom_shader_instancing/reference.png`.
- 2026-06-19: While fixing this owner, two shared shader/pipeline bugs were
  found and fixed: WGSL runtime source registration was incorrectly returning
  all loaded WGSL sources instead of the root shader dependency closure, which
  let `core_pipeline/mip_generation/downsample.wgsl` poison unrelated shader
  composition; and transient missing shader sources were cached as permanent
  mesh3d custom pipeline failures instead of being retried like Bevy's pending
  pipeline-cache state.
- 2026-06-19: Remaining parity gap: mgstudio still routes this through
  material-extension metadata plus a thin `Mesh3dInstanceVertexBufferData`
  bridge. The Bevy owner symbols `CustomMaterialPlugin`, `CustomPipeline`,
  `queue_custom`, `prepare_instance_buffers`, and `DrawMeshInstanced` are not
  yet represented as source-shaped render-world systems/commands.
- 2026-06-20: Moved the local instance-buffer bridge out of `setup` and into a
  source-shaped `CustomMaterialPlugin` slice. The example now installs
  `ExtractComponentPlugin<InstanceMaterialData>`, derives
  `Mesh3dInstanceVertexBufferData` from `InstanceMaterialData` in a
  `prepare_instance_buffers` system, and keeps `setup` limited to the Bevy
  authoring components. This removes the static GPU payload authoring shortcut
  but does not close the issue: exact Bevy parity still requires the shared
  render/PBR phase owner work from ISS-015 and ISS-019 so `queue_custom` and
  `DrawMeshInstanced` can be real `Transparent3d` render commands instead of
  being consumed through the current PBR mesh draw payload path. Validation:
  `moon -C mgstudio-engine check --target native --package-path
  examples/shader_advanced/custom_shader_instancing`, `moon -C mgstudio-engine
  check --target native`, `moon -C mgstudio-engine fmt`, `moon -C
  mgstudio-engine info`, and native capture
  `/tmp/mgstudio_iss134_custom_shader_instancing_prepare_owner.png`.

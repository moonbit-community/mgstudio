## Description
The mgstudio `examples/3d/atmosphere` screenshot renders the water surface
without the mountain reflection that appears in the Bevy baseline. The copied
`assets/shaders/water_material.wgsl` is byte-identical to Bevy and only perturbs
the water normal before returning deferred output; the reflection itself is
owned by the deferred PBR lighting and screen-space reflections pipeline.

Bevy enables `AtmosphereEnvironmentMapLight` and `ScreenSpaceReflections` on
the atmosphere camera. `ScreenSpaceReflectionsPlugin` runs the SSR render node
after deferred lighting and before the main opaque pass, using
`ViewTarget::post_process_write()` as the source/destination pair. Mgstudio had
a render-world/source-world split bug: frame configuration read
`DefaultOpaqueRendererMethod::deferred()` from the source world, but mesh
collection prepared materials by re-reading the default opaque method from the
render world, where the resource was absent and therefore fell back to forward
rendering. The terrain then entered the main opaque pass after SSR instead of
the deferred prepass before SSR, so the water raymarch could not sample the
mountain depth/color as a reflection source.

## Design
Audit and repair the Bevy source owner
`bevy/crates/bevy_pbr/src/ssr/mod.rs` together with the mgstudio fragments that
implement it:

- `mgstudio-engine/pbr/render_execute_frame_config.mbt`
- `mgstudio-engine/pbr/render_execute.mbt`
- `mgstudio-engine/pbr/render_execute_mesh_collect.mbt`
- deferred prepass and main-pass fragments that consume prepared material
  render-method classification

Do not change the water shader or add a custom water-reflection shortcut. The
fix must preserve Bevy's deferred material contract: the water material writes
deferred data, deferred lighting runs, and SSR uses the postprocess source,
view bind groups, prepass textures, and blue-noise texture to produce the final
reflection.

## Acceptance Criteria
- [x] `examples/3d/atmosphere` water visibly reflects the mountain/terrain in
      the same way as the Bevy baseline.
- [x] Mesh material collection uses the same source-world-derived
      `DefaultOpaqueRendererMethod` as camera frame planning, so terrain and
      water both enter the deferred prepass before SSR.
- [x] The water material shader remains byte-identical to Bevy.
- [x] The fix is validated with a native screenshot capture of
      `examples/3d/atmosphere`.
- [x] `moon -C mgstudio-engine check --target native`, `moon -C mgstudio-engine fmt`,
      and `moon -C mgstudio-engine info` complete after the change.

## Notes
- 2026-07-04: Initial diagnosis: the water shader is not responsible for
  sampling scene reflections. The missing mountain reflection points to a local
  SSR/deferred/postprocess target parity gap.
- 2026-07-04: Root cause confirmed with an environment-gated diagnostic
  capture: before the fix, `examples/3d/atmosphere` had one deferred mesh and
  one forward main-pass mesh; after passing frame-config material routing into
  mesh collection, both meshes enter the deferred prepass and main opaque no
  longer draws terrain after SSR. The same capture also reported the existing
  volumetric fog pipeline gap tracked by ISS-104.

## Close Notes
- 2026-07-04: Fixed by passing the source-world-derived frame configuration
  `DefaultOpaqueRendererMethod` and prepass flag into mesh material collection
  instead of re-reading them from the render world. This makes both the terrain
  and water prepare as deferred in `examples/3d/atmosphere`, so SSR runs after
  deferred lighting with the mountain already represented in the prepass/deferred
  inputs. Updated `mgstudio-engine/examples/3d/atmosphere/reference.png` from

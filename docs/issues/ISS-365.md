## Description
Bevy selects the textureless or density-textured volumetric-fog bind-group
layout per `ViewFogVolume`. Audit that mgstudio selects the same variant for
the real `examples/3d/volumetric_fog` volume and preserves the density texture
slots needed by `fog_volumes` and `scrolling_fog`.

## Design
Compare Bevy density-image lookup and bind-group layout key construction in
`bevy_pbr/src/volumetric_fog/render.rs::volumetric_fog` against mgstudio's
`ViewFogVolume.density_texture`, render asset lookup, bind-group layout index,
and optional texture view/sampler bindings. This issue owns only bind variant
selection and slot shape; ISS-358 owns composed shader specialization.

## Close Notes
Closed on 2026-07-05 after auditing textureless and density-textured
volumetric-fog bind-group variants. No renderer semantics, shader code, assets,
or example scene authoring changed for this issue.

Bevy owner anchors:

- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs::ViewVolumetricFogPipelines`
  stores both `textureless` and `textured` cached pipeline ids.
- `queue_view_volumetric_fog_pipelines` specializes and inserts both pipeline
  variants for each eligible view: one with `DENSITY_TEXTURE` absent and one
  with `DENSITY_TEXTURE` present.
- `volumetric_fog` requires both cached render pipelines to be available before
  drawing any volumes.
- Per volume, Bevy computes `density_image` with
  `view_fog_volume.density_texture.and_then(|density_texture|
  image_assets.get(density_texture))`. A missing or absent render asset means
  the textureless pipeline and bind-group layout are used, not a fallback
  density texture.
- Bevy adds group 1 bindings 2 and 3 only when `density_image` is present:
  binding 2 is the 3D density texture view and binding 3 is the filtering
  sampler.

Mgstudio implementation fragments:

- `mgstudio-engine/pbr/volumetric_fog/render.mbt` carries the optional density
  texture handle on `ViewFogVolume`, exposes `has_density_texture()` and
  `density_texture_id()`, and preserves `DENSITY_TEXTURE` in
  `VolumetricFogPipelineKey` and `VolumetricFogBindGroupLayoutKey`.
- `mgstudio-engine/pbr/volumetric_fog_execute.mbt` prepares both Bevy pipeline
  variants for an active volumetric-fog view and records valid
  `ViewVolumetricFogPipelines` on the render view.
- `mgstudio-engine/render/renderer/mesh3d_pipeline_build.mbt` maps
  `has_density_texture` to the same layout-key bit, shader def, and pipeline
  cache key.
- `mgstudio-engine/render/renderer/mesh3d_bind_groups.mbt` creates group 1
  layouts with bindings 2 and 3 only for the density-textured layout variants.
- `mgstudio-engine/render/renderer/mesh3d_volumetric_fog_pass.mbt` resolves a
  density texture id through the render asset table. A negative id or missing
  texture returns `None`, matching Bevy's `RenderAssets<GpuImage>::get`
  absence behavior. The bind group is then built with two entries for
  textureless volumes or four entries for density-textured volumes.

Evidence:

- `mgstudio-engine/examples/3d/volumetric_fog/main_wbtest.mbt` proves the real
  `volumetric_fog` example has a textureless `ViewFogVolume` and valid
  textureless/textured pipeline ids on the render view.
- `mgstudio-engine/pbr/volumetric_fog/render_test.mbt` proves density texture
  metadata is carried from `FogVolume` into `ViewFogVolume` and the uniform
  buffer.
- `mgstudio-engine/pbr/volumetric_fog_execute_wbtest.mbt` proves both Bevy
  pipeline variants are prepared and that textured keys include
  `DENSITY_TEXTURE` while textureless keys do not.
- `mgstudio-engine/render/renderer/gpu_wbtest.mbt` proves layout index mapping
  for `(MSAA, density texture)` bits and proves missing density render assets
  select absence instead of a fallback texture.

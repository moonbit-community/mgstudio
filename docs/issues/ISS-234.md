## Description
After shadow specialization succeeds, mgstudio must enqueue a Bevy-shaped
shadow phase item for the `scrolling_fog` pillar. A valid specialization cache
entry is not enough if material bind group selection, mesh slab lookup, render
layer filtering, or phase bin keys diverge from Bevy `queue_shadows`.

## Design
Audit Bevy `queue_shadows` against mgstudio's
`render3d_queue_shadow_phase_data_for_visible_entities` path. Verify
`ShadowBatchSetKey`, `ShadowBinKey`, material bind-group handling, mesh slab
lookup, render-layer filtering, and phase insertion. Fix local divergences
source-faithfully.

## Acceptance Criteria
- [x] The `scrolling_fog` pillar produces one queued shadow phase item for each
      Bevy-equivalent retained shadow view where it is visible.
- [x] The queued item uses the expected pipeline id, draw function, material
      bind group index, mesh slab id, and mesh asset id.
- [x] Render-layer and `SHADOW_CASTER` filtering match Bevy `queue_shadows`.
- [x] A focused test proves the phase item exists before pass execution.

## Close Notes
2026-07-04: Closed after restoring the render-world mesh allocator state that
Bevy `queue_shadows` requires. Diagnostics showed the `scrolling_fog` pillar
passed specialization cache, render mesh instance, shadow-caster flag,
render-layer, material instance, material resolution, and material binding
checks, but failed exactly at `MeshAllocator::mesh_slabs`.

The root cause was that mgstudio prepared `RenderMeshAssets` from the
remaining legacy `ExtractedMesh3d` adapter without also updating the
render-world `MeshAllocator`. Bevy's owner runs mesh allocation in
`MeshAllocatorPlugin` during `RenderSystems::PrepareAssets` before
`prepare_assets<RenderMesh>`, so `queue_shadows` can read slab IDs from the
allocator resource. Mgstudio now prepares unique render mesh assets once,
allocates missing mesh slabs from the prepared `RenderMesh` host vertex layout,
and then writes the prepared assets.

The focused `scrolling_fog` test now verifies that the pillar appears in the
shadow phase and that the queued item carries a valid pipeline id, draw
function id, Bevy depth-only material-bind-group semantics (`None`), vertex
slab id, and mesh asset bin key.

## Description
Bevy `volumetric_fog/render.rs` owns `VolumetricFogPipeline`,
`VolumetricFogPipelineKey`, `VolumetricFogBindGroupLayoutKey`, shader defs, and
specialization layout selection. Mgstudio must prove this owner is
source-shaped after recent renderer-side fixes.

## Design
Use this issue as the parent for pipeline audits:

- ISS-279 audits `VolumetricFogPipeline`, bind-group layout keys, and
  initialization.
- ISS-280 audits pipeline-key construction and specialization descriptor
  parity.

## Acceptance Criteria
- [x] ISS-279 and ISS-280 are closed.
- [x] Renderer backend caches are confirmed to be implementation details behind
      the Bevy-shaped owner, or follow-up ISS are created.

## Notes
- 2026-07-04: Split from ISS-195 so pipeline/layout semantics can be audited
  independently from uniforms and pass execution.
- 2026-07-05: Split further into ISS-279 and ISS-280 so resource/layout
  ownership is independent from specialization descriptor parity.
- 2026-07-09: ISS-279 is closed after moving volumetric fog bind-group layout
  descriptor ownership back into `VolumetricFogPipeline`. Remaining child is
  ISS-280 for specialization descriptor parity.

## Close Notes
Closed 2026-07-09. ISS-279 and ISS-280 are complete. `VolumetricFogPipeline`
now owns both bind-group layout descriptor construction and specialization
descriptor construction. Renderer backend cache keys remain native
materialization details, while shader definitions, shader path, layout
selection, blend state, culling, and color target state come from the
Bevy-shaped PBR owner.

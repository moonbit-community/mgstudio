## Description
Bevy's volumetric-fog pass reuses `MeshViewBindGroup` for camera, lighting,
shadow, and atmosphere inputs. Audit that mgstudio's pass binds the same
mesh-view resources and dynamic offsets for the real `examples/3d/volumetric_fog`
camera.

## Design
Compare Bevy `MeshViewBindGroup` consumption in
`bevy_pbr/src/volumetric_fog/render.rs::volumetric_fog` against mgstudio's
mesh-view bind-group cache, pass state, and volumetric-fog renderer call. Cover
group 0 bind identity, main offsets, directional cascade resources, point/spot
shadow resources, and atmosphere flags only as they flow through the mesh-view
group.

## Acceptance Criteria
- [x] Bevy mesh-view bind-group anchors are mapped to mgstudio symbols.
- [x] Focused evidence proves the real example binds the current camera's
      mesh-view group and offsets into group 0.
- [x] Focused evidence proves directional, point, and spot shadow resources
      are present or absent according to Bevy-shaped scene state.
- [x] Any local divergence is assigned to ISS-359.

## Close Notes
Closed on 2026-07-05 after auditing the mesh-view light and shadow input
surface used by the volumetric-fog pass. This issue added only pass-local
timeline evidence for point and directional/spot shadow bindings; it did not
change renderer semantics, shader code, assets, or example scene authoring.

Bevy owner anchors:

- `bevy/crates/bevy_pbr/src/volumetric_fog/render.rs::volumetric_fog` queries
  `&MeshViewBindGroup` and binds `view_bind_group.main` at group 0 with
  `view_bind_group.main_offsets`.
- `bevy/crates/bevy_pbr/src/render/mesh_view_bindings.rs::MeshViewBindGroup`
  stores `main`, `main_offsets`, `binding_array`, and `empty`.
- `bevy/crates/bevy_pbr/src/render/mesh_view_bindings.rs::prepare_mesh_view_bind_groups`
  builds the group 0 entries from view uniforms, lights, point-light shadow
  depth texture binding 2, point-light comparison sampler binding 3,
  directional and spot shadow depth texture binding 5, directional comparison
  sampler binding 6, clustered light buffers, globals, light probes, fog,
  visibility ranges, and optional atmosphere resources.
- `bevy/crates/bevy_pbr/src/render/light.rs` prepares a point-light depth
  texture/view for point-light cubemap shadows and a directional-light depth
  texture/view whose array layers include directional cascades plus spot-light
  shadow maps. Both views are inserted into `ViewShadowBindings`, which is
  later consumed by `prepare_mesh_view_bind_groups`.

Mgstudio implementation fragments:

- `mgstudio-engine/pbr/render_execute_camera_main_pass.mbt` passes
  `Render3dViewShadowBindings` point and directional texture ids plus
  directional cascade data into `render3d_begin_pass_3d`, then prepares the
  mesh-view bind group with `host_gpu_prepare_mesh3d_view_bind_group`.
- `mgstudio-engine/pbr/render/view.mbt::render3d_begin_pass_3d` folds
  directional cascade data into the GPU lights uniform through
  `render3d_gpu_lights_with_directional_shadow_cascades`.
- `mgstudio-engine/pbr/render_shadow_view.mbt` produces
  `Render3dViewShadowBindings` from the point, spot, and directional shadow
  pass plans.
- `mgstudio-engine/pbr/volumetric_fog_execute.mbt` forwards the same point and
  directional shadow texture ids into `host_gpu_draw_mesh3d_volumetric_fog`.
  The added timeline counters prove the real example reaches the volumetric
  pass with point and directional/spot shadow bindings.
- `mgstudio-engine/render/renderer/mesh3d_volumetric_fog_pass.mbt` uses
  `mesh3d_volumetric_fog_view_material_pipeline_id()` to select the default
  mesh-view owner, calls `mesh3d_frame_view_bg_cache_get_or_create`, then binds
  the returned `view_bg` and `view_offsets` at group 0.
- `mgstudio-engine/render/renderer/mesh3d_bind_groups.mbt` maps the Bevy
  mesh-view shadow slots into the view bind group: binding 2 for the point
  shadow sample view, binding 3 for the point comparison sampler, binding 5
  for the directional/spot shadow sample view, and binding 6 for the comparison
  sampler.

Evidence:

- `mgstudio-engine/render/renderer/gpu_wbtest.mbt` proves group 0 uses the
  default mesh-view bind group owner, dynamic offsets mirror Bevy's
  view/lights/light-probes order, shadow slots are present in the layout, and
  explicit shadow texture identities are preserved rather than silently falling
  back.
- `mgstudio-engine/pbr/render_shadow_view_wbtest.mbt` proves directional
  shadow bindings carry cascade data and target identity for the volumetric-fog
  pass.
- `mgstudio-engine/examples/3d/volumetric_fog/main_wbtest.mbt` now proves the
  real example reaches the volumetric-fog pass with point shadow resources and
  directional/spot shadow resources, and that the render-world lighting state
  has directional cascades plus point and spot light indices.

# ISS-452: Remove redundant per-entity component membership indexes

## Metadata
- Type: task
- Status: closed

- Assignee: codex
- Created: 2026-07-15
- Updated: 2026-07-16
- External ref: none

## Description

Entity storage keeps component-id arrays and presence bitsets in addition to
the entity's archetype and table location. Determine which queries still need
per-entity membership data and remove copies already proven by archetype
membership.

## Design

Remove `entity_component_local_ids` and
`entity_component_local_id_presence` together as one persistent-membership
variable. Spawned-entity membership is read from the entity's current
archetype, matching pinned Bevy `EntityMeta`/`EntityLocation` and
`UnsafeEntityCell::contains_id`. The existing `ComponentWriteSet` remains the
transient authority for components inserted before the entity migrates to its
target archetype. Membership counts and generations remain explicit side
indexes updated only at actual add, remove, and despawn boundaries. Table and
sparse payload owners are unchanged.

## Acceptance Criteria

- [x] Every current reader of per-entity component IDs or presence is
      classified as required, replaceable by archetype membership, or sparse
      storage specific.
- [x] Table-component presence is not duplicated per entity after the retained
      change.
- [x] Sparse-set, hooks, removal, and dynamic bundle behavior remain correct.
- [x] One focused ECS structural test runs at a time with
      `MOONBIT_NEW_NATIVE=1`.
- [x] `examples/scene/scene` is the only runtime example gate.
- [x] The retained/rejected decision follows the `ISS-444` experiment protocol.

## Notes

- 2026-07-16: Pinned Bevy entity metadata stores generation, location, and
  spawn/despawn diagnostics; component membership belongs to the referenced
  archetype. `UnsafeEntityCell::contains_id` calls `archetype().contains`, and
  bundle insertion classifies existing versus added components against the
  current archetype.
- 2026-07-16: Reader classification found no external consumer of mgstudio's
  per-entity arrays. Persistent presence reads in queries, component columns,
  raw table access, and default filters are replaceable by archetype presence.
  Despawn enumeration is replaceable by the archetype component list. Dynamic
  bundle/required-component recursion needs only the already-existing active
  `ComponentWriteSet` until the final archetype migration. Sparse-set
  components remain members of the archetype even though their payloads are
  stored outside the table.
- 2026-07-16: The experiment will not remove component membership
  counts/generations. Those are query-planning side indexes rather than
  per-entity membership copies and will continue to update at structural
  add/remove/despawn boundaries.
- 2026-07-16: The retained implementation removes both persistent per-entity
  containers and all synchronization helpers. `entity_local_components` and
  `entity_has_component_local_id` now resolve through the live entity's
  archetype. Inserts use the active `ComponentWriteSet` until migration;
  removals use the cached archetype edge; despawn enumerates the current
  archetype. Membership counts/generations still update exactly once at the
  structural boundary.
- 2026-07-16: Three focused native release invocations passed separately with
  `MOONBIT_NEW_NATIVE=1`: table/sparse add-remove-despawn structural migration,
  batch insertion with recursive required components, and remove-hook ordering
  with the old payload visible during callbacks.
- 2026-07-16: `scene/scene` required a temporary
  `StressDiagnosticsPlugin` import and registration to emit timeline traces;
  the identical two-line profiling fixture was used on both sides and removed
  before commit. Baseline traces were `8.373` and `8.367 ms/frame` (`8.370 ms`
  mean); archetype-owned membership traces were `8.329` and `8.354 ms/frame`
  (`8.342 ms` mean, `0.34%` improvement). `Main` improved from `1.415` to
  `1.373 ms` mean (`2.97%`).
- 2026-07-16: Fixed-frame-90 baseline and retained `scene/scene` captures were
  byte-identical with SHA-256
  `a78806e289201906bbd937111d2ffac157ea320dafb1cc6fd909a858c93e847d`.
  The native builds introduced no warning class beyond warning 0083 already
  tracked by `ISS-443` and existing native dependency/linker warnings.

## Close Notes

Retained archetype-owned entity membership. Every entity no longer allocates or
maintains a component-ID array plus presence bitset duplicating its archetype;
the existing write transaction supplies the only necessary pre-migration
membership overlay. Focused structural, required-component, and hook semantics
passed, the runtime gate improved slightly, and fixed-frame output was
byte-identical.

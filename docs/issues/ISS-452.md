## Description

Entity storage keeps component-id arrays and presence bitsets in addition to
the entity's archetype and table location. Determine which queries still need
per-entity membership data and remove copies already proven by archetype
membership.

## Acceptance Criteria

- [ ] Every current reader of per-entity component IDs or presence is
      classified as required, replaceable by archetype membership, or sparse
      storage specific.
- [ ] Table-component presence is not duplicated per entity after the retained
      change.
- [ ] Sparse-set, hooks, removal, and dynamic bundle behavior remain correct.
- [ ] One focused ECS structural test runs at a time with
      `MOONBIT_NEW_NATIVE=1`.
- [ ] `examples/scene/scene` is the only runtime example gate.
- [ ] The retained/rejected decision follows the `ISS-444` experiment protocol.

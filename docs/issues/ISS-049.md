## Description
App, headless, logging, and hello-world examples failed the screenshot batch
because they did not emit an RGBA8 capture blob. Most of these packages are
probably not visual gates, but they still need explicit classification so the
batch result is not ambiguous.

Failed packages:

- `examples/app/custom_loop`
- `examples/app/empty`
- `examples/app/headless`
- `examples/app/headless_renderer`
- `examples/app/log_layers`
- `examples/app/log_layers_ecs`
- `examples/app/logs`
- `examples/app/no_renderer`
- `examples/app/without_winit`
- `examples/hello_world/hello_world`
- `examples/hello_world`

## Design
For each package, inspect whether it creates a window/render graph and whether a
screenshot is meaningful. Exclude true headless or console-only packages from
visual capture, and keep any visual app package in the screenshot gate.

## Acceptance Criteria
- [x] Every listed package has an explicit screenshot policy classification.
- [x] True non-visual packages are excluded from all-example screenshot capture with a documented reason.
- [x] Any package that does create a visual frame produces `reference.png`.
- [x] The all-example capture summary separates expected exclusions from real failures.

## Description
`examples/3d/custom_system_setup3/reference.png` is fully transparent. A standard 90-frame native capture produced an opaque image, but the visual result was only the default dark background with no visible scene content.

The generated image passed the current luma-based sanity script because the background is not near black, so this example exposes a false positive class for empty captures.

## Design
Audit the example against its intended source owner before refreshing the checked-in reference. The fix should identify whether the missing content is caused by example setup, schedule/system registration, camera framing, asset loading, or render extraction.

Do not accept a non-transparent background-only capture as a valid visual reference.

## Acceptance Criteria
- [x] `examples/3d/custom_system_setup3` captures visible scene content, not only the clear color.
- [x] The example setup and schedule path are audited against the source owner.
- [x] The refreshed `reference.png` is produced by `mgstudio-engine/scripts/p0_visual_capture_native.sh`.
- [x] ISS-060 is updated after the reference is refreshed or the example is reclassified.

## Notes
- 2026-06-12: Standard command `MGSTUDIO_PARITY_CAPTURE_DELAY_FRAMES=90 MGSTUDIO_PARITY_RUN_TIMEOUT_SECONDS=600 mgstudio-engine/scripts/p0_visual_capture_native.sh examples/3d/custom_system_setup3 mgstudio-engine/examples/3d/custom_system_setup3/reference.png` produced `alpha_mean=1`, `gray_mean=0.387908`, `size=2560x1440`, but the visual content was only a uniform dark background. The generated image was discarded.
- 2026-06-14: Claimed for diagnosis. Initial source search found no direct
  Bevy example with this name, so the audit must focus on the mgstudio custom
  setup example and its Bevy-shaped scene, camera, schedule, and render
  boundaries.
- 2026-06-14: Diagnosis found that frame 1 had visible boxes, while frame 90
  was only the clear color. The custom despawn query included the ground
  because it selected every entity with `RigidBody3d` and `Collider3d`; removing
  the ground let the stack fall out of the camera view. The example also had
  stale `PostUpdate` physics set configuration even though the 3D physics plugin
  owns those systems in `FixedUpdate`.

## Close Notes
Fixed `examples/3d/custom_system_setup3` by making the custom setup explicit:
it disables the default `Physics3dPlugin`, manually installs the 3D physics
systems, keeps the debug render plugin, and marks only spawned boxes as despawn
targets. Refreshed `examples/3d/custom_system_setup3/reference.png` with
`MGSTUDIO_PARITY_CAPTURE_DELAY_FRAMES=90 MGSTUDIO_PARITY_RUN_TIMEOUT_SECONDS=600
mgstudio-engine/scripts/p0_visual_capture_native.sh examples/3d/custom_system_setup3
/tmp/mgstudio_iss077_custom_system_setup3_fixed.png`, then copied that capture
to the checked-in reference. Validation: `moon -C mgstudio-engine check --target
native --deny-warn --package-path examples/3d/custom_system_setup3`, `moon -C
mgstudio-engine fmt`, and `moon -C mgstudio-engine info`.

## Description

`examples/stress_tests/many_animated_sprites` no longer matches its checked-in
reference under the standard native capture path. A fresh row-query build shows
only one center sprite at frame 1 and only the background at frame 90, while
`reference.png` shows the expected field of animated sprites.

The symptom predates and is independent of the ISS-456
`mark_newly_hidden_entities_invisible_system` batch migration: fresh fixed-frame
row and batch frame-90 captures are byte-identical with SHA-256
`8c4e68b35228f8c4473bc86b4ab74c71d94c141ef9478caffd1ac762c3a39afa`.

## Design

Trace the first frames through deferred spawn application, transform
propagation, inherited/view visibility, camera visible-entity collection, and
render-world sprite extraction. Compare the ownership and schedule boundaries
with the pinned Bevy baseline. Do not refresh the reference or special-case the
stress example.

## Acceptance Criteria

- [ ] A focused test or deterministic capture reproduces the transition from
      partially visible to empty output.
- [ ] The first frame at which sprites disappear is identified together with
      the responsible source owner and schedule boundary.
- [ ] The fix preserves Bevy visibility change-detection semantics and does not
      disable culling.
- [ ] The standard frame-90 native capture again matches the checked-in
      reference by human review and image metrics.
- [ ] The retained fix has a focused regression test and a separate commit.

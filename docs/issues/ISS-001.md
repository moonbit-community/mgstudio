## Description
The current `examples/stress_tests/many_foxes` release run is CPU-bound at about
`15 FPS` for `1000` foxes. The latest breakdown shows frame time growing with
fox count, so the work is dominated by per-entity and per-joint CPU paths rather
than a fixed startup or windowing cost.

This epic tracks the detailed optimization goals needed to recover the
`1000`-fox performance budget while preserving Bevy-shaped behavior and current
visual correctness.

## Design
Use the latest evidence in `docs/MANY_FOXES_PERFORMANCE_BREAKDOWN.md` as the
baseline. Optimize only source-owned engine hot paths, avoid temporary
workarounds, and keep performance probes either permanent and useful or removed
before closing their issue.

Primary target:

- `1000` foxes: at least `30 FPS` in a no-trace release run from the
  `mgstudio-engine` working directory.
- `1000` foxes: average stable-frame interval at or below `33.3 ms`, allowing
  trace overhead to be reported separately when timeline tracing is enabled.

## Acceptance Criteria
- [ ] `many_foxes` with `1000` foxes reaches at least `30 FPS` in a no-trace release run on the current development machine.
- [ ] The timeline profile identifies no remaining single CPU-owned hot path above `5 ms/frame` without an open follow-up issue.
- [ ] Count scaling for `250`, `500`, and `1000` foxes is recorded after optimization.
- [ ] Visual correctness is preserved: foxes remain lit and animated, camera/output are not degraded, and no optimization disables required rendering behavior.
- [ ] `docs/MANY_FOXES_PERFORMANCE_BREAKDOWN.md` is updated with final before/after evidence.
- [ ] Child issues `ISS-002` through `ISS-011` are closed or explicitly deferred with blocker notes.

## Notes
- Initial decomposition is based on the June 2, 2026 many_foxes performance breakdown.
- 2026-07-15: Replaced blanket `ViewVisibility` production with pinned-Bevy
  camera/GPU/light producers and preserved the two-bit change-detection
  lifecycle. The comparable traced release profile improved from
  `/tmp/mgstudio_visibility_perf_20260715/frametime_breakdown.md` at
  `114.466 ms` / `8.736 FPS` to
  `/tmp/mgstudio_visibility_perf_after_20260715/frametime_breakdown.md` at
  `69.798 ms` / `14.327 FPS` (39.0% lower frame interval, 64.0% higher FPS).
  The old blanket system (`12.351 ms/frame`) disappeared; reset improved from
  `9.116` to `5.134 ms/frame`, and mark-newly-hidden from `9.150` to
  `3.560 ms/frame`. Camera visibility is now the largest visibility owner at
  `18.153 ms/frame`; source-shaped parallel query execution remains tracked by
  `ISS-154`.
- 2026-07-15: `ISS-456` replaced the camera candidate row materialization with
  source-shaped dense table batches while preserving Bevy's visibility filters,
  two-bit change detection, class queues, and sorting. In a comparable
  `many_foxes` trace, `check_visibility_visible_entities` improved from
  `13.856` to `3.332 ms/frame`, Main from `39.066` to `29.715 ms`, and steady
  frame interval from `54.555` to `46.087 ms` (`15.52%`). Exact before/after
  frame-90 captures were byte-identical, so the CPU gain did not alter output.

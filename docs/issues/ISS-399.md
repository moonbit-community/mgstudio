## Description
The 3D PBR material path and 2D mesh material path maintain similar typed keys,
prepared-asset resources, runtime registries, plugin setup, and entity
extraction logic independently. Bevy has separate `Material` and `Material2d`
owners, but both are backed by common render-asset and render-resource
concepts. The duplicated local plumbing is an architecture debt.

## Design
After ISS-396 and ISS-398 settle the key and lookup shape, extract the shared
typed-material runtime pieces into a common render material support layer. Keep
domain-specific pipeline specialization and phase selection separate for PBR and
2D.

## Acceptance Criteria
- [ ] Shared material-runtime responsibilities are factored out of PBR and 2D
      without changing public material authoring behavior.
- [ ] PBR-specific material properties and 2D-specific phase/pipeline logic
      remain in their source-owner packages.
- [ ] Existing 2D and 3D material tests pass.
- [ ] `moon fmt`, `moon info`, and `moon check` pass.

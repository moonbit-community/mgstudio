## Description
`examples/3d/volumetric_fog` is not a source-shaped port of Bevy's
`bevy/examples/3d/volumetric_fog.rs`. The mgstudio example currently documents
itself as an interactive distance-fog lighting example that avoids the
unfinished voxel volumetric-fog render path. It replaces Bevy's
`WorldAssetRoot` glTF scene, `VolumetricFog` camera component, `FogVolume`,
`VolumetricLight` component toggles, `AppSettings` resource, and
`MoveBackAndForthHorizontally` component with local corridor geometry, proxy
distance fog, tracked entities, and light intensity changes.

This is a local approximation, not a valid blocker.

## Design
After the volumetric fog render owner is ready, restore the example by copying
Bevy's source shape directly. Do not keep proxy fog or hand-authored corridor
geometry as the parity path.

## Acceptance Criteria
- [ ] The example loads `models/VolumetricFogExample/VolumetricFogExample.glb`
      through the source-shaped scene root path.
- [ ] The camera owns Bevy's `VolumetricFog { ambient_intensity: 0.0 }`,
      `Skybox`, `Tonemapping::TonyMcMapface`, and `Bloom` components.
- [ ] The example spawns the Bevy point light, spot light, default fog volume,
      and help text source shape.
- [ ] `AppSettings` and `MoveBackAndForthHorizontally` are represented as
      Bevy-shaped resource/component owners.
- [ ] `tweak_scene`, `move_directional_light`, `move_point_light`, and
      `adjust_app_settings` match Bevy's query and component mutation semantics,
      including inserting/removing `VolumetricLight` instead of using proxy
      intensity changes.
- [ ] `reference.png` is refreshed only after ISS-104 is source-shaped enough
      to render the true volumetric path without validation/fatal output.

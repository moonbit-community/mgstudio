## Description

Hot world-parameter systems construct `@ecs.Query` values during every run even
though the app system-parameter path already owns persistent `QueryCache`
state. Test whether moving the pinned-Bevy visibility queries to registered
query system parameters removes measurable per-frame planning and cache setup.

## Design

- Use the existing typed `SystemParam for Query[D, F]` path; do not add global
  caches or world-id keyed static state.
- Preserve the exact visibility query shape, ordering, and two-bit
  `ViewVisibility` lifecycle.
- Measure only `examples/stress_tests/many_foxes` for the runtime gate.
- Revert production code if the epic retention gate is not met.

## Acceptance Criteria

- [ ] A pre-change `many_foxes` trace records the affected visibility system
      costs and total steady-frame interval.
- [ ] A focused app query-system-parameter test passes with
      `MOONBIT_NEW_NATIVE=1`.
- [ ] The same `many_foxes` trace shape records the post-change result.
- [ ] The retained/rejected decision follows the `ISS-444` experiment protocol.
- [ ] Query and visibility semantics remain aligned with the pinned Bevy source.

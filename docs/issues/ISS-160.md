# ISS-160: Remove DirectionalLight cascade config field authoring

## Description
Bevy stores directional cascade configuration as an independent
`CascadeShadowConfig` component required by `DirectionalLight`. Mgstudio still
has a legacy `DirectionalLight.cascade_shadow_config` field and builder methods
that write into that field. Several examples still configure cascades through
the field-shaped API.

This is a local source-shape gap, not an external blocker. It can make light
owner systems and PBR extraction disagree unless every runtime path reads the
component-owned configuration.

## Design
Remove the field-shaped cascade authoring surface from `DirectionalLight`.
Examples and tests should insert `CascadeShadowConfig` as a component next to
`DirectionalLight`, matching Bevy's required-component model. Do not add a sync
system from the old field to the component and do not preserve compatibility
builder methods.

## Acceptance Criteria
- [ ] `DirectionalLight` no longer stores `cascade_shadow_config`.
- [ ] `DirectionalLight::with_cascade_shadow_config` and
      `DirectionalLight::with_cascade_shadow_config_builder` are removed.
- [ ] All examples and tests insert `CascadeShadowConfig` as a component when
      they need non-default cascade settings.
- [ ] PBR extraction and light cascade building both read the same
      component-owned `CascadeShadowConfig`.
- [ ] Targeted light/PBR tests and a representative shadowed 3D example
      screenshot pass after the cleanup.

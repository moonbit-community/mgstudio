## Description
`mgstudio-engine/examples/3d/spherical_area_lights/main.mbt` is only a partial
port of `bevy/examples/3d/spherical_area_lights.rs`.

The underlying `PointLight.radius` render path is present: the component field,
extraction, clustered light packing, and PBR shader code consume the radius.
The example itself still diverges from Bevy by adding local
`mapped_point_light_range` and `mapped_point_light_intensity` fallback behavior,
using different UV sphere segment counts, manually spawning child lights, and
duplicating `PointLight` and `Parent` component insertion.

This is a local source-parity bug, not an external blocker.

## Design
Restore the example directly from `bevy/examples/3d/spherical_area_lights.rs`:

- Keep `GlobalAmbientLight { brightness: 60.0, ..default() }` as an app-level
  resource insertion.
- Keep the camera, plane, material, count, position range, and radius range
  values unchanged from Bevy.
- Use a shared sphere mesh equivalent to `Sphere::new(1.0).mesh().uv(120, 64)`.
- For each light sphere, spawn one mesh/material/transform entity and attach one
  child `PointLight` with only `radius`, `color`, and Bevy defaults.
- Remove `mapped_point_light_range`, `mapped_point_light_intensity`,
  `clamp01`, and all range/intensity fallback behavior.
- Remove duplicated `set_by_key` calls for `PointLight` and `Parent`.
- Preserve the source-shaped child relationship as closely as the current ECS
  command API allows.

## Acceptance Criteria
- [ ] The example varies only `PointLight.radius` and leaves range/intensity at
      Bevy defaults.
- [ ] The duplicate point-light and parent insertions are removed.
- [ ] Sphere mesh generation matches Bevy's `uv(120, 64)` source parameters or
      records a focused primitive-builder issue if this cannot be expressed.
- [ ] The point light is a single child of each visible sphere, matching Bevy's
      scene topology.
- [ ] A new reference screenshot is captured after the corrected example first
      runs.

# ISS-460: Preserve render-world cluster buffer ownership

## Description

After the camera main pass switched the renderer backend to the compact cluster
buffers owned by `GlobalClusterableObjectMeta` and `ViewClusterBindings`, the
older begin-pass path continued uploading its fixed-size legacy cluster data.
From the second frame onward, wgpu therefore copied more bytes than the
source-owned destination buffers could hold.

## Design

Record the ownership handoff in `GpuBackend`. Legacy cluster uploads remain
valid until render-world buffers are installed. Once
`use_mesh3d_cluster_buffers` installs those buffers, only their Bevy-shaped
render-world owners may write them; `prepare_mesh3d_cluster_buffers` must no
longer overwrite them.

Do not clip writes to the destination size or resize source-owned buffers to
fit legacy data. Either workaround would preserve the conflicting ownership
model instead of matching Bevy's buffer ownership.

## Acceptance Criteria

- [x] A focused wgpu validation test reproduces the legacy overwrite of a
      source-owned cluster buffer.
- [x] Legacy uploads remain available before the render-world ownership
      handoff.
- [x] After the handoff, legacy uploads do not write the source-owned buffers.
- [x] The focused test passes with `MOONBIT_NEW_NATIVE=1`.
- [x] `examples/3d/despawn3` reaches frame 5 without an uncaptured wgpu
      validation error.

## Notes

- 2026-07-16: The failing `despawn3` run reported three validation errors per
  affected frame: 16,320 bytes copied into an 80-byte buffer, 65,536 bytes
  copied into 644/880-byte buffers, and 131,072 bytes copied into a
  110,592-byte buffer. These are the legacy padded cluster uploads targeting
  compact render-world buffers.
- 2026-07-16: The red regression test installs three 16-byte source-owned
  buffers, attempts three 32-byte legacy uploads under a wgpu validation error
  scope, and observes a validation error before the fix.
- 2026-07-16: After the ownership guard, the focused test passes. A frame-5
  `despawn3` capture with `MGSTUDIO_WGPU_UNCAPTURED_ERROR_STDERR=1` produced an
  empty run log. Physics debug lines are still absent from that frame and are
  therefore a separate render-path defect, not evidence that this ownership
  fix failed.

## Close Notes

`GpuBackend` now records when mesh3d cluster buffers are render-world owned.
The legacy prepare path returns without writing after that handoff, while the
initial legacy path remains unchanged. Validation passed with the focused
renderer wgpu test and a native `despawn3` frame-5 capture.

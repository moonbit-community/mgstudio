# ISS-168: Reclassify WGSL 0.15.x compose hang as a new-native backend issue

## Description
Upgrading the WGSL dependency family from `0.15.0` to `0.15.1` and `0.15.2`
initially appeared to make the smallest mgstudio shader compile import test
hang on native release.

The failing mgstudio test is
`shader/compile` filtered to `compile package composes registered embedded
shader graph`. The test registers a tiny import module with
`#define_import_path test::util` and a root shader with
`#import test::util::value`, then calls the normal shader compile path through
`load_preprocessed_wgsl`.

The same test passes with the `0.15.0` dependency family. With the default new
native backend, `moon_wgsl_naga_oil@0.15.1` and `0.15.2` keep running without
output. Sampling shows the process burning CPU in
`moon_wgsl_naga_oil` import-use identifier scanning and WGSL lexer XID
code-point helpers.

The important correction is that this does not reproduce when the stable native
backend is selected with `MOONBIT_NEW_NATIVE=0`. With `0.15.2` and
`MOONBIT_NEW_NATIVE=0`, the minimal filtered test passes and the full
`shader/compile` native release suite passes. Mgstudio's native-backend policy
is to use the stable native backend, so the WGSL dependency family can be
upgraded to `0.15.2`.

## Design
Do not locally rewrite shader sources, disable imports, or add a mgstudio-side
compose workaround. Use `0.15.2` with `MOONBIT_NEW_NATIVE=0`.

The default new native backend hang should be treated as a MoonBit native
backend issue, not as a `moon_wgsl` library blocker. The upstream `moon_wgsl`
issue created during the initial diagnosis has been corrected and closed.

## Notes
- 2026-07-02: Attempted to upgrade the WGSL family from `0.15.0` to `0.15.1`.
  `moon -C mgstudio-engine fmt`, `moon -C mgstudio-engine info`, and a native
  check of shader/PBR/render packages completed, but the targeted
  `shader/compile` release test hung. The first and smallest test case
  (`compile package composes registered embedded shader graph`) alone
  reproduced the hang.
- 2026-07-02: Version matrix: all four WGSL packages at `0.15.0` passed in
  about 5.4s; only `Milky2018/wgsl@0.15.1` with the remaining packages at
  `0.15.0` passed in about 5.2s; `Milky2018/moon_wgsl_naga@0.15.1` with
  `moon_wgsl_naga_oil@0.15.0` passed; `Milky2018/moon_wgsl_naga_oil@0.15.1`
  reproduced the hang. This points to `moon_wgsl_naga_oil@0.15.1`, not the
  lexer package alone.
- 2026-07-02: A macOS `sample` of the hanging process showed top frames in
  `wgsl__xid__range__contains`, `wgsl__code__point__at`,
  `wgsl__naga__oil__import__use__identifier__end`,
  `wgsl__naga__oil__import__use__code__point__at`, and
  `wgsl__xid__continue__code__point`.
- 2026-07-02: Reported upstream as
  https://github.com/moonbit-community/moon_wgsl/issues/16.
- 2026-07-03: Rechecked `0.15.2` after refreshing the registry. The dependency
  family resolved and downloaded, but the same minimal
  `shader/compile` filtered test still hung for more than 60 seconds. Sampling
  again showed the same hotspot shape:
  `wgsl__xid__range__contains`, `wgsl__code__point__at`,
  `wgsl__naga__oil__import__use__identifier__end`, and
  `wgsl__naga__oil__import__use__code__point__at`. The dependency family was
  restored to `0.15.0`, and the same minimal test passed again in about five
  seconds.
- 2026-07-03: Repeated the `0.15.2` check after `moon -C mgstudio-engine clean`.
  The clean rebuild reached the test executable, then `compile.blackbox_test.exe
  compile_test.mbt:0-1` again ran for more than 60 seconds without output.
  Sampling still showed the same `moon_wgsl_naga_oil` import-use scanner
  hotspot. Restoring all four WGSL packages to `0.15.0` after the clean made
  the same filtered test pass again in about five seconds.
- 2026-07-03: Rechecked `0.15.2` with `MOONBIT_NEW_NATIVE=0` after
  `moon -C mgstudio-engine clean`. The minimal filtered test passed in about
  22 seconds, and the full `shader/compile` native release test passed all
  five tests. This narrows the hang to the default new native backend path
  interacting with `moon_wgsl_naga_oil@0.15.2`, rather than a pure source-level
  infinite loop that reproduces on both native backends. Mgstudio still should
  not upgrade its default dependency set until the default native backend path
  is fixed or the project explicitly changes its native-backend policy.
- 2026-07-03: The project native-backend policy is to use the stable native
  backend with `MOONBIT_NEW_NATIVE=0`; the default new native backend is known
  buggy for this path. Reclassified this issue from an upstream WGSL library
  blocker into a native-backend diagnosis record and upgraded mgstudio to the
  WGSL `0.15.2` family.

## Close Notes
Closed after reclassification. The dependency upgrade is valid under
`MOONBIT_NEW_NATIVE=0`, and the `moon_wgsl` upstream issue was corrected as a
new-native backend interaction rather than a source-level library regression.

# ISS-464: Make ViewVisibility value updates migration-safe

## Metadata
- Type: bug
- Status: closed
- Priority: 0
- Labels: visibility, ecs, api, change-detection, migration
- Assignee: codex
- Created: 2026-07-18
- Updated: 2026-07-18
- External ref: none

## Description

The value-type conversion changed `ViewVisibility::update` from an in-place
`Unit` method to a method returning a replacement `ViewVisibility`. Existing
downstream `value.update()` calls still compiled, discarded the result, and
silently stopped advancing the previous-frame visibility bit.

Earlier visibility work also removed the public value-level `set_visible`
method and the blanket `check_visibility_system` without recording explicit
migration paths.

## Design

Remove the ambiguous `update` name and expose the pure replacement operation as
`advance_frame`, forcing old call sites to fail at compile time. Add
`with_visible` as the explicit value-level replacement for the former mutating
`set_visible`; ECS component writers continue to use the existing
`SetViewVisibility` trait so change-detection semantics remain centralized.

Do not restore `check_visibility_system`. The blanket scan bypassed the
source-owned camera, layer, range, frustum, and light visibility producers and
was removed for correctness as well as performance. Document plugin and custom
producer migration instead.

## Acceptance Criteria

- [x] The public interface no longer contains `ViewVisibility::update`.
- [x] `advance_frame` preserves the current/previous-frame bit semantics.
- [x] `with_visible` preserves the previous bit while setting the current bit.
- [x] All in-repository value call sites use the explicit replacement APIs.
- [x] Migration notes cover the removed value-level `set_visible` and blanket
      `check_visibility_system` APIs.
- [x] One focused visibility test passes with `MOONBIT_NEW_NATIVE=1`.
- [x] `moon info` records the intended public interface change.

## Close Notes

Closed on 2026-07-18. `ViewVisibility::update` was replaced by the explicitly
value-returning `advance_frame`, and `with_visible` now provides the local-value
migration for the former mutating `set_visible`. The blanket visibility system
remains removed and its source-owner migration is documented.

The focused visibility bit-state test and the focused camera visible-entities
test each passed independently in native release mode with
`MOONBIT_NEW_NATIVE=1`. `moon info visibility --target native` regenerated the
public interface with `advance_frame` and `with_visible` and without `update`.
A temporary downstream-style compile probe confirmed that `value.update()` now
fails with compiler error E4015, `ViewVisibility has no method update`; the
probe was removed after verification.

## Description
Bevy marks views with `VolumetricFog` so their depth texture can be sampled by
the later volumetric fog pass. Mgstudio must prove the same usage request is
made before camera depth target creation, otherwise the renderer may create a
depth texture that cannot be bound as the fog shader's sampled view depth.

## Design
Compare Bevy `prepare_view_depth_textures_for_volumetric_fog` and
`ViewDepthTexture` usage flags against mgstudio's camera depth-usage extraction
and target creation path. The fix, if needed, belongs in the render preparation
chain that decides depth texture usages, not in the volumetric fog shader or
example code.

## Acceptance Criteria
- [x] Cameras with `VolumetricFog` request the Bevy-equivalent sampled depth
      usage before depth target creation.
- [x] Cameras without `VolumetricFog` do not gain unrelated depth usage changes.
- [x] Focused coverage proves the usage request is present in the prepared
      camera/depth-target data flow.

## Close Notes
2026-07-04: Bevy source audit confirmed that
`prepare_view_depth_textures_for_volumetric_fog` runs in `RenderSystems::Prepare`
before `prepare_core_3d_depth_textures` and ORs `TextureUsages::TEXTURE_BINDING`
into every `Camera3d.depth_texture_usages` when any `VolumetricFog` exists.

Mgstudio already mirrors this before depth target creation:
`render3d_execute_collect_cameras` computes
`Camera3dViewPayload.depth_texture_usages` through
`render3d_prepare_view_depth_texture_usage_for_sampled_depth`, and
`render3d_prepass_targets_get_or_create` later converts that payload to
depth-target usage bits and includes those bits in the cache key. The logic
does not mutate the source-world `Camera3d`, which matches mgstudio's
render-world extraction model.

Validation:
- `moon -C mgstudio-engine test pbr/render_execute_collect_atmosphere_wbtest.mbt --target native --release`
  passed: 5 tests.
- `moon -C mgstudio-engine test pbr/volumetric_fog_execute_wbtest.mbt --target native --release`
  passed: 12 tests.

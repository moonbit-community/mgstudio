## Description
`examples/3d/motion_blur` now renders and its CI screenshot exit path works, but
the example itself is still not source-level equivalent to Bevy's
`bevy/examples/3d/motion_blur.rs`. Bevy models the example with ECS resources
and components: `CameraMode`, `Moves`, `CameraTracked`, `Rotates`, typed
queries, `Text` plus `TextSpan` children, `ButtonInput<KeyCode>`, and
`TextUiWriter`. Mgstudio currently keeps most runtime state in a process-global
`Ref[MotionBlurExampleState]`, including camera/tracked entities, car and wheel
arrays, motion blur values, and camera mode.

## Design
Re-port the example from the Bevy source owner, symbol by symbol. The MoonBit
version may use explicit keys and package-specific constructors, but the runtime
ownership must match Bevy: persistent example state should live in ECS resources
or components, systems should query ECS data instead of global arrays, and input
should mutate the camera's `MotionBlur` component and `CameraMode` resource.
Do not preserve the current global-state compatibility layer.

## Acceptance Criteria
- [ ] `CameraMode`, moving car phase, tracked camera marker, and wheel rotation marker are represented as ECS resource/components rather than fields in a global `Ref`.
- [ ] `keyboard_inputs`, `move_cars`, and `move_camera` operate through ECS queries and resources matching Bevy's source shape, not through stored entity arrays.
- [ ] UI text remains a `Text` root with `TextSpan` children and is updated through the text writer path.
- [ ] Generated ground texture data and sampler behavior remain byte/semantic equivalent to Bevy.
- [ ] `CI_TESTING_SCREENSHOT_AND_EXIT_FRAME=30 CI_TESTING_FIXED_FRAME_TIME_MS=16 moon -C mgstudio-engine run examples/3d/motion_blur --release` exits successfully and captures a nonblank screenshot after the refactor.

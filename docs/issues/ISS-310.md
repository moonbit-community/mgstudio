## Description
`VolumetricFogExample.glb` includes a `Sun` light node, and Bevy's glTF loader
has distinct behavior for light and camera node content. Mgstudio must prove
that these child import semantics match Bevy for this scene so lighting or
camera-side data is not silently blamed on the mesh path.

## Design
Use this issue as the parent for light/camera child import parity. The
executable work is split into smaller source-owner slices:

- ISS-319 audits Bevy glTF light-node import and mgstudio's matching loader
  and spawner fragments.
- ISS-320 audits Bevy glTF camera-node import and proves whether the source
  asset has relevant imported camera content.
- ISS-321 records runtime evidence for the imported `Sun` node component set,
  hierarchy, and transform.

## Acceptance Criteria
- [x] ISS-319, ISS-320, and ISS-321 are closed.
- [x] Light-node import, camera-node import, and runtime `Sun` node evidence
      are each classified as complete, partial, facade, or blocked.
- [x] Any discovered divergence is either fixed in the leaf issue that proves
      it or assigned to ISS-305 with exact source-owner evidence.

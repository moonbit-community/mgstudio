## Description
`examples/3d/scrolling_fog` still has a fully transparent checked-in
`reference.png`. A standard native capture run succeeds and passes generic
nonblank image statistics, but manual review rejects the generated frame: the
Bevy example is about a scrolling `FogVolume` density texture interacting with
volumetric light behind a pillar, while the mgstudio capture only shows the
black pillar and gray ground with no visible fog volume, density texture, or
light-scattering signal.

Accepting this capture would preserve a missing PBR/fog visual path as the
baseline.

## Design
Audit `mgstudio-engine/examples/3d/scrolling_fog/main.mbt` against
`bevy/examples/3d/scrolling_fog.rs` and then trace the relevant engine owners:

- `FogVolume` extraction and density texture loading for `volumes/fog_noise.ktx2`;
- `VolumetricFog` camera extraction, jitter, and TAA interaction;
- `VolumetricLight` extraction for the directional light;
- volumetric fog render pass scheduling and texture consumption;
- bloom and shadow-map interactions needed for the visible light shaft.

Do not accept a merely nonblank pillar/ground capture. Do not replace the fog
effect with an unlit overlay or screenshot-only fallback. If the exact visual
path requires a missing dependency or backend API, record that blocker with the
deletion condition for any local TODO.

## Acceptance Criteria
- [ ] `examples/3d/scrolling_fog` renders a visible fog/light-scattering
      signal consistent with the Bevy source example.
- [ ] The refreshed `reference.png` passes automated image sanity and manual
      visual inspection.
- [ ] The run log contains no validation, fatal, missing-resource, unsupported,
      or renderer error output.
- [ ] ISS-060 is updated with the accepted refresh metrics.

## Description
`examples/ui/text/text_debug` now runs and produces a reference screenshot, but
the Bevy source uses a root `Text::default()` with `TextSpan` children and
`TextUiWriter` updates. Mgstudio maps that source shape, yet the captured image
does not visibly show the final dynamic text block in the bottom-right region.

This must be audited against Bevy's current `bevy/examples/ui/text/text_debug.rs`
and the UI text source owners:

- `bevy/crates/bevy_ui/src/widget/text.rs`
- `bevy/crates/bevy_ui/src/measurement.rs`
- `bevy/crates/bevy_ui/src/layout/mod.rs`
- `bevy/crates/bevy_text/src/pipeline.rs`

## Design
Do not change the example layout heuristically. First compare a fresh Bevy
reference capture with the mgstudio reference, then classify the mismatch as one
of:

- correct Bevy-equivalent overflow/framing,
- a UI text measurement scheduling gap,
- a root `Text` plus child `TextSpan` extraction/layout bug,
- a required-components gap,
- or a screenshot framing issue.

If the mismatch is real, port the corresponding Bevy source-owner behavior
directly.

## Acceptance Criteria
- [ ] A current Bevy `text_debug` screenshot is captured or a reproducible capture blocker is recorded.
- [ ] The mgstudio `text_debug` reference is compared against Bevy for the dynamic bottom-right text block.
- [ ] Every source-shape anchor involved in UI text measurement/layout is classified as complete, partial, facade, or blocked.
- [ ] Any fix preserves Bevy's root `Text` plus `TextSpan` child structure and uses `TextUiWriter`.
- [ ] `examples/ui/text/text_debug/reference.png` is refreshed only after the source-level cause is resolved or explicitly classified.

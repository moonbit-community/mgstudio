# ISS-030: Restore Bevy motion blur runtime wiring

## Metadata
- Type: bug
- Status: closed

- Assignee: codex

- Updated: 2026-06-03
- External ref: none

## Description
`examples/3d/motion_blur --release` can now acquire and capture the macOS
surface after `wgpu_mbt@0.14.1`, but the rendered result is still not Bevy
equivalent. The latest gate captures a nonblank surface containing only UI text
and repeatedly logs `motion_blur skip: no settings buffer`, proving that the
motion blur GPU resource and settings preparation path is not wired into the
runtime before the draw node consumes it.

## Design
Read the pinned Bevy source owner for motion blur before editing mgstudio. Port
the Bevy ownership shape directly: component/settings extraction, prepare
resources, bind group layout/pipeline ownership, prepass texture consumption,
and render node execution must each have an explicit mgstudio mapping. Do not
add draw-path fallback resource creation or local approximation logic.

## Acceptance Criteria
- [x] Bevy motion blur source-owner inventory is recorded in the notes with
      every in-scope struct, resource, system, render node, and draw-time
      dependency classified as ported, blocked, or out of scope.
- [x] `examples/3d/motion_blur --release` no longer logs
      `motion_blur skip: no settings buffer` when `MotionBlur` is enabled.
- [x] The motion blur settings buffer is created and written from the
      Bevy-shaped prepare/extract data flow before render-node consumption.
- [x] Runtime draw consumes prepass motion-vector and depth textures plus
      settings resources through Bevy-equivalent ownership, without fallback
      descriptors or local draw-path patches.
- [x] `moon -C mgstudio-engine check --target native`, `moon -C mgstudio-engine
      test pbr --release`, `moon -C mgstudio-engine fmt`, and
      `moon -C mgstudio-engine info` pass.
- [x] A fresh `examples/3d/motion_blur --release` screenshot gate captures the
      3D scene and records remaining visual differences, if any, as follow-up
      issue notes.

## Notes
- 2026-06-03: Created after `wgpu_mbt@0.14.1` resolved NSView surface capture
  but exposed the local `no settings buffer` runtime gap.
- 2026-06-03: Bevy source-owner inventory for
  `bevy_post_process/src/motion_blur/mod.rs`: `MotionBlur` component with
  `#[require(MotionVectorPrepass)]` is ported as `post_process/motion_blur`
  plus PBR pass-config gating; `Default` values are ported; `SyncComponent` and
  `ExtractComponent` are mapped to camera extraction payload fields because
  MoonBit does not have Bevy's derive/plugin extraction machinery; hidden
  `MotionBlurUniform { shutter_angle, samples }` is mapped to renderer uniform
  bytes; `MotionBlurPlugin` maps to embedded WGSL registration, renderer
  prepare API, and PBR postprocess scheduling; `motion_blur` render system maps
  to `host_gpu_prepare_motion_blur` plus `host_gpu_draw_motion_blur`;
  `prepare_view_depth_texture_usages_for_motion_blur` maps to dedicated
  prepass-depth texture creation with texture-binding usage.
- 2026-06-03: Bevy source-owner inventory for
  `bevy_post_process/src/motion_blur/pipeline.rs`: `MotionBlurPipeline`
  sampler/layout/layout_msaa/shader ownership maps to `GpuBackend` fields and
  `ensure_motion_blur_layouts`; `init_motion_blur_pipeline` maps to lazy
  renderer resource construction because mgstudio does not yet have a full
  RenderStartup resource stage; `MotionBlurPipelineKey { target_format,
  samples }` maps to current-pass format plus motion-vector sample count;
  `SpecializedRenderPipeline::specialize` maps to
  `motion_blur_pipeline_for_current_pass` with `MULTISAMPLED` shader defs;
  `MotionBlurPipelineId` and `prepare_motion_blur_pipelines` map to
  `prepare_motion_blur`, which prepares the pipeline and uniform buffers before
  draw consumption.
- 2026-06-03: Bevy source-owner inventory for
  `bevy_render/src/view/mod.rs` and `bevy_render/src/texture/texture_attachment.rs`:
  `ViewTarget` main textures are now mapped as unsampled source/destination
  textures plus an optional sampled MSAA attachment; `ColorAttachment::get_attachment`
  maps to `target_color_attachment` plus a render pass descriptor with
  `resolveTarget`; `PostProcessWrite` maps to mgstudio's existing scene and
  postprocess target handoff. `ViewPrepassTextures.motion_vectors` remains a
  multisampled `Rg16Float` prepass texture with no resolve target, matching
  Bevy's prepass texture ownership.
- 2026-06-03: The local runtime bug had two parts: motion blur resources were
  only consumed at draw time without a Bevy-shaped prepare step, and the MSAA
  scene texture was incorrectly used as the postprocess source. The fix splits
  prepare/draw ownership and ports Bevy's MSAA resolve shape: main scene color
  renders to a sampled attachment and resolves into an unsampled texture, while
  motion vectors stay multisampled for the motion blur shader.
- 2026-06-04: `wgpu_mbt@0.14.2` exposes
  `RenderPassDescBuilder::set_color_attachment_resolve_target`, resolving the
  render-pass `resolveTarget` API gap tracked upstream. The project-local
  `render_pass_resolve_stub.c` bridge has been removed and the renderer now
  begins MSAA resolve passes through the upstream builder API.

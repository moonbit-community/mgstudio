## Description
The current profile identifies the dominant systems, but several hot paths still
need finer counters before structural optimization can be validated. Without
repeatable counters, improvements can accidentally move cost between systems or
hide work behind broad spans.

## Design
Extend the existing many_foxes profiling flow with stable counters for the
known hot paths: transform propagation, animation target writes, skinned bounds,
skin extraction, render execution, previous-transform sync, and redraw handling.
Keep the counters engine-owned and useful for future profiling rather than
one-off probes.

## Acceptance Criteria
- [x] The timeline or generated report records roots scanned, descendants visited, table-row fetches, and `GlobalTransform` writes for transform propagation.
- [x] The animation report records players prepared, targets processed, sampled curves, transform writes, morph weight writes, and text color writes.
- [x] The skinned-bounds report records skinned entities, joint bounds processed, joint transform cache hits/misses, and AABB writes.
- [x] The skin extraction report records skins, joints, dirty skins, staging rows, and upload bytes.
- [x] Render execution is split into CPU collection, shadow phase construction, main pass construction, pipeline lookup, command encoding, submission, and present/wait spans.
- [x] The no-trace run and timeline run can both be reproduced with documented commands.
- [x] Temporary diagnostic toggles are removed before closing unless they are promoted to documented profiling features.

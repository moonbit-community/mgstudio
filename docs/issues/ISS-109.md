## Description
`examples/3d/fog_volumes` is not a source-shaped port of Bevy's
`bevy/examples/3d/fog_volumes.rs`. Bevy renders the Stanford bunny as a
`FogVolume` backed by `volumes/bunny.ktx2`, lit by a `VolumetricLight`, and
viewed by a camera with `VolumetricFog { step_count: 64, ambient_intensity:
0.0 }`.

The current mgstudio example is a distance-fog proxy scene with translucent
mesh geometry approximating a bunny silhouette. It does not spawn a real
`FogVolume`, does not load the bunny density texture, and does not attach
camera `VolumetricFog` or light `VolumetricLight`.

## Design
After ISS-104 provides the Bevy-shaped volumetric fog render path, replace the
proxy scene with a direct port of the Bevy example. Do not keep translucent
proxy geometry, dynamic distance-fog coloring, or non-source camera orbit
behavior as the parity path.

## Acceptance Criteria
- [ ] The example spawns a real `FogVolume` with
      `density_texture: volumes/bunny.ktx2`, `density_factor: 1.0`, and
      `scattering: 1.0`.
- [ ] The directional light owns `VolumetricLight` and matches Bevy's transform,
      shadow, and illuminance values.
- [ ] The camera owns `Hdr` and
      `VolumetricFog { step_count: 64, ambient_intensity: 0.0 }`.
- [ ] `rotate_camera` follows Bevy's per-frame query and quaternion translation
      update semantics.
- [ ] Proxy bunny geometry and distance-fog workaround code are removed from
      the parity path.
- [ ] `reference.png` is refreshed only after ISS-104 is source-shaped enough
      to render the true fog-volume density texture path.

## Description
`volumetric_fog.wgsl` consumes per-volume uniform data through a dynamic uniform
offset. Mgstudio must prove that `VolumetricFogUniform`, packed host bytes, and
`ViewFogVolume.uniform_buffer_offset` match Bevy's `ShaderType` layout and
dynamic-offset semantics.

## Design
Compare Bevy `VolumetricFogUniform`, `prepare_volumetric_fog_uniforms`, and
`DynamicUniformBuffer` usage against mgstudio's uniform data shape, packing
function, byte-offset recording, upload boundary, and renderer dynamic-offset
binding. Fix local byte layout, matrix order, alignment, or offset bugs
source-faithfully.

## Acceptance Criteria
- [x] Uniform byte layout matches the WGSL host layout expected by Bevy's
      `VolumetricFogUniform`.
- [x] `ViewFogVolume.uniform_buffer_offset` is a byte offset and is passed as a
      dynamic offset to the same bind group binding used by Bevy.
- [x] Matrix values, far planes, density values, and inverse/extinction values
      are packed in the order consumed by `volumetric_fog.wgsl`.
- [x] A focused white-box test covers at least one nonzero dynamic offset.

## Close Notes
Closed on 2026-07-04.

Audited Bevy `VolumetricFogUniform`,
`VolumetricFogUniformBuffer`, `prepare_volumetric_fog_uniforms`, and the
`volumetric_fog` render command in
`bevy/crates/bevy_pbr/src/volumetric_fog/render.rs`. Mgstudio's
`VolumetricFogUniform::bytes` packs the same WGSL host layout: two column-major
mat4 values, three far-plane vec4 values, vec3 fields with Bevy-equivalent
padding, scalar fog controls, density texture offset, and final scalar fields
within a 288-byte uniform body padded to a 512-byte dynamic stride.

No production logic change was needed for this slice. Added a white-box
assertion that two prepared fog volumes produce byte offsets `0` and `512`, so
`ViewFogVolume.uniform_buffer_offset` is proven to be a dynamic byte offset and
not a logical array index. Renderer-side dynamic binding was already covered by
`mesh3d_volumetric_fog_dynamic_offsets`, which passes the offset array to group
1 just like Bevy's `render_pass.set_bind_group(1, ..., &[offset])`.

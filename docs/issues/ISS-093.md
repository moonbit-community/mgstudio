## Description
`examples/3d/ssao` still has a transparent checked-in `reference.png`.
Retrying the standard native capture reached the renderer but logged
`unsupported binding 17` every frame and produced a uniform dark frame.

In current Bevy, `bevy_pbr/src/ssao/mod.rs` owns SSAO extraction, resource
textures, pipelines, bind groups, and compute dispatch. The main mesh view
bind group then adds binding `17` for the screen-space ambient occlusion
texture in `bevy_pbr/src/render/mesh_view_bindings.rs`. Mgstudio has partial
SSAO component and WGSL surfaces, but the capture proves the renderer does not
yet provide the Bevy-equivalent binding 17 resource path to mesh3d.

## Design
Port the Bevy SSAO source owners directly. Do not accept a dark reference, do
not disable the SSAO mesh pipeline key, and do not fake the occlusion texture.
The fix should map Bevy's `ScreenSpaceAmbientOcclusionPlugin`, settings
extraction, texture resource preparation, pipeline specialization, bind-group
preparation, compute passes, and mesh-view binding 17 insertion into mgstudio.
If a required texture/cache/compute feature is missing from MoonBit or
wgpu_mbt, record that exact blocker before leaving the issue blocked.

## Acceptance Criteria
- [ ] Every in-scope source-shape anchor in `bevy_pbr/src/ssao/mod.rs` is
      classified as complete, partial, facade, blocked, or intentionally
      excluded.
- [x] `bevy_pbr/src/render/mesh_view_bindings.rs` binding `17` is supported
      by real SSAO resources when `ScreenSpaceAmbientOcclusion` is present.
- [x] `examples/3d/ssao` no longer logs `unsupported binding 17` or other
      renderer fatal output under the standard native capture command.
- [ ] The refreshed `examples/3d/ssao/reference.png` is accepted only after
      manual review confirms visible scene content and SSAO-relevant shading.
- [ ] Focused PBR/SSAO checks and the standard capture run have no validation,
      fatal, missing-resource, unsupported, or error output.

  Bevy-shaped `ScreenSpaceAmbientOcclusionResources`, `SsaoBindGroups`, and
  Hilbert LUT helper surface, and the renderer owns real per-view SSAO
  textures plus the thickness uniform buffer. Mesh view binding `17` now binds
  `screen_space_ambient_occlusion_texture` from those resources and the view
  bind-group cache keys include the SSAO resource revision. Standard capture:
  `MGSTUDIO_PARITY_CAPTURE_DELAY_FRAMES=90 MGSTUDIO_PARITY_RUN_TIMEOUT_SECONDS=600 mgstudio-engine/scripts/p0_visual_capture_native.sh examples/3d/ssao /tmp/mgstudio_iss093_ssao.png`
  completed without `unsupported binding 17`, fatal, validation, missing
  resource, or error output. The screenshot is visible, not transparent or
  uniform dark. Remaining partial source anchors: `SsaoPipelines`,
  `SsaoPipelineKey` specialization into real compute pipelines,
  `prepare_ssao_bind_groups`, and the `ssao` Core3d compute pass dispatch are
  not yet source-complete.
- 2026-06-13: Follow-up source audit found a local prepass-owner gap that must
  be fixed before exact SSAO compute parity: Bevy's SSAO pass consumes
  `ViewPrepassTextures.depth` and `ViewPrepassTextures.normal` as distinct
  resources, but mgstudio's current camera prepass path only creates and
  returns a depth prepass target. This is not an external blocker; it is a
  local render/PBR source-shape gap. Do not treat the current visible SSAO
  capture as final parity until normal prepass texture ownership and the three
  SSAO compute passes are ported.

# ISS-093: Port SSAO render resources and mesh-view binding 17 before reference refresh

## Description
`examples/3d/ssao` still has a transparent checked-in `reference.png`.
Retrying the standard native capture reached the renderer but logged
`unsupported binding 17` every frame and produced a uniform dark frame.

In current Bevy, `bevy_pbr/src/ssao/mod.rs` owns SSAO extraction, resource
textures, pipelines, bind groups, and compute dispatch. The main mesh view
bind group then adds binding `17` for the screen-space ambient occlusion
texture in `bevy_pbr/src/render/mesh_view_bindings.rs`. Mgstudio has partial
SSAO component and WGSL surfaces, but the capture proves the renderer does not
yet provide the Bevy-equivalent binding 17 resource path to mesh3d.

## Design
Port the Bevy SSAO source owners directly. Do not accept a dark reference, do
not disable the SSAO mesh pipeline key, and do not fake the occlusion texture.
The fix should map Bevy's `ScreenSpaceAmbientOcclusionPlugin`, settings
extraction, texture resource preparation, pipeline specialization, bind-group
preparation, compute passes, and mesh-view binding 17 insertion into mgstudio.
If a required texture/cache/compute feature is missing from MoonBit or
wgpu_mbt, record that exact blocker before leaving the issue blocked.

## Acceptance Criteria
- [x] Every in-scope source-shape anchor in `bevy_pbr/src/ssao/mod.rs` is

- [x] `bevy_pbr/src/render/mesh_view_bindings.rs` binding `17` is supported

- [x] Focused PBR/SSAO checks and the standard capture run have no validation,
      fatal, missing-resource, unsupported, or error output.

# ISS-319: Audit volumetric_fog glTF light-node import

## Description
`VolumetricFogExample.glb` contains a `Sun` light node. Mgstudio must prove
that Bevy's glTF light-node import semantics are preserved before light or fog
visual differences are assigned to the volumetric render pass.

## Design
Compare Bevy's glTF light import branches against mgstudio's loader and scene
spawner. Focus on child entity placement, identity child transforms, node names,
extras, directional-light data, intensity/color conversion, range/spot fields
where applicable, and required component insertion.

## Acceptance Criteria
- [x] Bevy source anchors for glTF light import are listed.
- [x] Mgstudio fragments implementing light import and spawn are listed.
- [x] The `Sun` node import behavior is proven source-aligned or the exact
      divergence is assigned to ISS-305.
- [x] Any discovered local divergence is fixed here or assigned to ISS-305
      with exact source-owner evidence.

## Notes
- 2026-07-05: Split from ISS-310 so light-node import can be audited without
  camera-node concerns.
- 2026-07-05: Bevy source anchors:
  - `bevy/crates/bevy_gltf/src/loader/mod.rs:1754-1777` imports directional
    glTF punctual lights by spawning a light child under the glTF node,
    mapping srgb color, using glTF intensity as directional illuminance,
    inserting optional light name/extras, and invoking directional light
    extension hooks.
  - `bevy/crates/bevy_gltf/src/loader/mod.rs:1779-1800` imports point lights by
    mapping srgb color, converting glTF candela to luminous power with
    `intensity * PI * 4`, defaulting range to `20`, setting radius to `0`, and
    invoking point light extension hooks.
  - `bevy/crates/bevy_gltf/src/loader/mod.rs:1802-1828` imports spot lights by
    using the same intensity conversion and range default, setting radius to
    `range.unwrap_or(0)`, preserving inner/outer cone angles, and invoking
    spot light extension hooks.
- 2026-07-05: Mgstudio source anchors:
  - `mgstudio-engine/scene/gltf_loader.mbt:1186-1194` reads the per-node
    `KHR_lights_punctual.light` index.
  - `mgstudio-engine/scene/gltf_loader.mbt:1283-1347` parses root
    `KHR_lights_punctual.lights` entries into light name, extras, srgb color,
    intensity, optional range, and directional/point/spot kind.
  - `mgstudio-engine/scene/gltf_loader.mbt:2835-2899` maps parsed lights to
    `DirectionalLight`, `PointLight`, or `SpotLight`, including Bevy's
    directional illuminance rule, point/spot `intensity * PI * 4` conversion,
    range defaults, radius defaults, and spot cone angles.
  - `mgstudio-engine/scene/gltf_loader.mbt:3895-3908` creates a separate
    identity-transform light `SceneNode3d` parented to the glTF node when
    lights are enabled.
  - `mgstudio-engine/scene/scene.mbt:25-27` carries optional light component
    payloads on `SceneNode3d`.
  - `mgstudio-engine/scene/scene_spawner.mbt:632-645` inserts directional,
    point, and spot light components during scene spawn when present.
- 2026-07-05: `VolumetricFogExample.glb` contains
  `KHR_lights_punctual.lights[0] = { name: "Sun", type: "directional",
  color: [1, 0.9894999861717224, 0.8705254793167114], intensity: 68300 }`,
  and node `0` named `Sun` references that light. The built-in light import
  behavior is source-aligned for this asset: the imported light is a
  directional light child of the `Sun` glTF node with identity local transform,
  light name `Sun`, the glTF srgb color, and illuminance `68300`.
- 2026-07-05: General extension callback parity is partial: Bevy invokes
  `on_spawn_light_directional`, `on_spawn_light_point`, and
  `on_spawn_light_spot`, while mgstudio's extension handler API currently does
  not expose light-spawn callbacks. This is a local source-parity gap recorded
  as ISS-322. It is not assigned to ISS-305 because no light-spawn extension
  handler participates in `VolumetricFogExample.glb`, so it is not evidence for
  the current scene render-space divergence.
